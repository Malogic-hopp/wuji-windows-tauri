## 1. 目的

本文冻结领域对象、依赖方向、不变量和生命周期，不绑定具体 Rust module 或 SQL DDL。所有“必须/不得”遵循 [README.md](./README.md#3-规范用语)。

## 2. 领域依赖图

```text
Raw Observation（仅内存）
        ↓ privacy + normalization
Foreground Observation（事实）
        ↓ segmentation
Activity Segment ───────────→ App Usage
        ├────────────────────→ Work Block
        └→ Classification → Context Segment → Transition Decision
                                             ├→ Interruption
                                             └→ Effective Context Switch

Data Quality Interval ──────→ Daily Data Quality
Calendar Generation ────────→ Hourly/Daily bucket boundaries
```

强制依赖：

- Work Block 依赖 Activity Segment 和连续性边界，不得引用 Context Segment 作为身份或边界来源；
- Context 规则变化不得改变 Activity Segment 或 Work Block；
- Segmentation 变化可以改变 Activity Segment、Work Block、App usage 及其下游分析；
- Calendar 变化只改变桶归属，不改变事实 UTC 边界。

## 3. 值对象

### 3.1 时间

- `TimestampUtc`：UTC epoch milliseconds；
- `DurationMs`：非负整数；
- `CaptureSequence`：由 Capture Loop 在尝试捕获时单调分配，不由 Writer 到达顺序分配；
- `FactCursor`：Single Writer 在提交事实/质量输入时从数据库全局单调分配，跨 Runtime Instance 永不重置；
- `TimeEpochId`：UTC 单调区间；时间倒退、休眠恢复异常或运行实例重置时产生新 epoch；
- `TimeEpochOrdinal`：数据库内随新 Time Epoch 单调增加的顺序号，只用于建立事实位置全序，不替代 `TimeEpochId`。

Capture Sequence 只用于发现同一 Runtime Instance 内的丢弃、迟到和重复；Generation、Result Set、Snapshot 和投影水位一律使用 Fact Cursor，不得使用裸 Capture Sequence。Fact Cursor 与输入行在同一事务提交，回滚不产生可见水位。任何 `end < start` 都是非法。不同 Time Epoch 之间不得推导持续时间。

### 3.1.1 Fact Boundary 与 Slice 顺序

Native v2 的覆盖边界不是互不关联的 UTC 与 cursor 字段，而是一个不可拆分值对象：

```text
FactBoundary {
  timeEpochOrdinal,
  capturedAtUtcMs,
  factCursor
}
```

比较使用 `(timeEpochOrdinal, capturedAtUtcMs, factCursor)` 字典序。Result Set 和 Native Slice 使用半开区间 `[startBoundary, endBoundary)`；`endBoundary.factCursor` 表示该位置第一条被排除的事实。因此同一 epoch、同一毫秒内可以在两个 Fact Cursor 之间切 Slice，且不产生复合位置重叠。边界的三个字段在领域、DTO 和 SQL 中必须成组出现、成组比较，禁止只比较 UTC 或只用 cursor 修补 UTC overlap。

Time Epoch 变化强制切 Slice；不同 epoch 即使 UTC 数值因时钟回拨重叠，也按 ordinal 有序且不得推导跨 epoch 时长。Legacy Summary 没有 v2 Fact Boundary，只能使用 UTC 半开区间；与 Native 范围相遇时由 Snapshot Builder 以 Native 为优先级裁剪整个冲突毫秒，禁止伪造 Legacy Fact Cursor。

### 3.2 Activity State

`Active | Idle | Unknown`。一个 Activity Segment 恰好有一个状态和一个 `duration`。

### 3.3 版本标识

以下均为不可变标识，不使用浮点版本：

```text
SegmentationVersion
FeatureSchemaVersion
RuleVersion
ClassifierVersion
AnalysisAlgorithmVersion
CalendarVersion
SettingsRevision
SegmentationProfileId
WorkProfileId
AnalysisProfileId
SchemaVersion
```

### 3.4 Rebuild Capability

`SafeFeaturesOnly | IdentityOnly | SummaryOnly | Excluded | Mixed`，语义见产品词典。

## 4. 事实对象

### 4.1 Raw Observation

Win32 adapter 产生的仅内存对象：

```text
captureSequence
capturedAtUtc
timeEpochId
pid
processName
executablePath
windowTitle
idleDuration
captureStatus
```

Raw Observation 必须经过隐私判定后立即清除敏感字符串。它不得进入日志、IPC、SQLite 或 panic payload。

### 4.2 Foreground Observation

通过隐私和标准化后可持久化的不可变事实：

```text
observationId
factCursor
runtimeInstanceId
captureSequence
capturedAtUtc
timeEpochId
appIdentityId
activityState
privacyMode
safeFeatureSetId?
titleFeatureAvailable
captureQuality
captureSettingsRevision
```

第一版不持久化 PID、原始标题或完整路径。`appIdentityId` 必须存在，无法识别映射到 `app:unknown`。

### 4.3 Data Quality Interval

表示不能作为正常行为事实使用的区间或点事件：

```text
kind = CaptureFailure | QueueDrop | OutOfOrder | TimeEpochBreak |
       PrivacyExcluded | AgentUnavailable | TitleUnavailable
startedAtUtc
endedAtUtc?
firstSequence?
lastSequence?
firstFactCursor?
lastFactCursor?
count
safeReasonCode
```

Privacy Excluded 只保存时间、类型和安全原因码；不得保存被排除 App、标题、路径或 PID。它取代未落库的 `SuppressedObservationEvent` 概念。

### 4.4 Tracking Expectation Interval

用于构造质量分母的意图事实：

```text
state = Expected | UserPaused | UserStopped | ScheduledOff |
        ExclusiveMaintenance | SystemSleepOrLogoff | UnknownEligibility
startedAtUtc
endedAtUtc?
source = Command | Schedule | RuntimeRecovery | SystemSignal
```

只有 Expected 进入 `expectedTrackingDuration`。Agent 重启时必须根据上次已持久化意图关闭开放区间：若上次为 Expected，无法解释的离线 gap 记为 Data Quality `AgentUnavailable`；若为 UserPaused/UserStopped/ScheduledOff/ExclusiveMaintenance，则只保留 Tracking Expectation，不生成同名质量区间，也不惩罚覆盖率。无法可靠区分休眠/注销时将 Tracking Expectation 标为 UnknownEligibility 并单列。不存在 Data Quality `AgentStopped`、`Paused` 或 `Maintenance`；在线维护导致的实际丢弃使用 QueueDrop/CaptureFailure 表达。

## 5. 身份对象

### 5.1 Identity Generation 与 App Identity

```text
IdentityGeneration {
  identityGenerationId, fingerprintKeyVersion, state,
  createdAtUtc, retiredAtUtc?, predecessorId?, protectionScheme
}
```

`state = Active | Retired | Lost`。每个 channel 同时只能有一个 Active Identity Generation。数据库只保存受保护密钥的版本和摘要，不保存明文盐。

```text
appIdentityId
identityGenerationId
appKey
canonicalDisplayName
normalizedProcessName
executableFingerprint?
fingerprintKeyVersion?
firstSeenAtUtc
lastSeenAtUtc
```

`appKey` 在 Identity Generation 内稳定且唯一；显示名可变。Fingerprint 盐按 channel 生成、使用 Windows DPAPI 保护并版本化；盐丢失后关闭旧世代并创建新世代，不尝试跨设备或跨盐自动关联。

新旧 App 只有在轮换时仍持有可信内存身份或用户显式确认时，才能创建 `IdentityLink { fromAppId, toAppId, kind, createdAtUtc }`；fingerprint 相等本身不能跨世代建立链接。

跨世代查询使用独立、不可变的 `IdentityResolutionGeneration`：

```text
IdentityResolutionGeneration {
  identityResolutionGenerationId, predecessorId?, createdAtUtc, state
}
IdentityResolutionMember {
  identityResolutionGenerationId, appIdentityId, canonicalAppIdentityId
}
```

每个 App Identity 在一个 Resolution Generation 中恰好解析到一个 canonical App Identity；未出现在 member 映射中的身份按恒等规则解析到自身，因此新发现 App 不要求创建新 Resolution。Identity Link 必须构成无环、单终点的受信任关系；新 Link 创建新 Resolution Generation，不原地修改旧映射。App Projection Result Set 必须绑定具体 Resolution Generation；Apps、Top Apps、Hourly/Daily App Usage 按 `canonicalAppIdentityId` 聚合。未链接的同名 App 保持不同 canonical ID。Activity Segment 和 Raw App Switch 仍绑定采集时的 App Identity；Identity Generation 边界关闭 Segment 且不产生切换，后来的 Link 不改写旧事件。

### 5.2 Context Definition 与 Alias

```text
ContextDefinition { contextId, canonicalKey, displayName, kind, lifecycleState }
ContextAlias { aliasKey, targetContextId, validFrom, validTo?, ruleVersion }
```

同一 `contextId` 才是天然等价；alias 只在有效期和分析版本内建立等价。merge 保留来源，split 创建新身份。

## 6. Activity Key 与 Activity Segment

### 6.1 Activity Key

逻辑组成：

```text
appIdentityId
stableWindowKey?
privacyMode
activityKeySchemaVersion
```

持久化时既保存组成字段，也保存用于索引的 hash。Activity State 不属于 Activity Key，但状态变化切断 Segment。

### 6.2 去抖

Activity Key 候选变化只有同时达到 `confirm_duration` 和 `min_samples` 才提交。提交时边界回溯到第一个候选 Observation。Writer 必须允许重写一个有界尾部；在确认前不能把候选期间永久计入旧 Segment。

### 6.3 Activity Segment

```text
segmentId
segmentationGenerationId
timeEpochId
activityKey components/hash
activityState
startedAtUtc
endedAtUtc
durationMs
firstObservationSequence
lastObservationSequence
closeReason
```

Segment 是闭区间结果；实时开放尾部保存在 Writer 内存或 tail state，不伪装成一个 `endedAtUtc NOT NULL` 的完成行。每次事务可以删除并重建有界 tail 内的闭合 Segment。

Rebuild v0.1 有意偏离本条：open Segment/Work/gap 直接持久化并在启动事务关闭遗留行，不引入 tail delete/rebuild。见 09 §6.7 与 §15 偏离登记。

`durationMs = endedAtUtc - startedAtUtc`，且一个 Segment 不含多状态时长。

## 7. Segment Classification

对一个 Activity Segment 在一个 Analysis Generation 下的分类结论：

```text
classificationId
analysisGenerationId
segmentationGenerationId
activitySegmentId
contextId?
confidence
decisionState
reasonCode
evidenceRefs[]
inheritanceSource?
```

`decisionState = Classified | LowConfidence | Unknown | Excluded`。证据引用只指向安全特征和规则命中，不保存原始标题。

Composite identity 必须保证 Classification 与被引用 Segment 属于同一个 Segmentation Generation。

## 8. Context Segment

相邻分类结果在同一 canonical Context 下形成的分析区间：

```text
contextSegmentId
analysisGenerationId
contextId
startedAtUtc
endedAtUtc
durationMs
firstActivitySegmentId?
lastActivitySegmentId?
confidence
decisionState = Provisional | Final
closeReason
```

实时 provisional 尾部允许在有界窗口内替换；持久化完成行的 `endedAtUtc` 必须非空。Context Segment 来源引用允许在保留期清理后置空，安全快照字段仍能解释历史结果。

## 9. Transition Decision

每个候选上下文链的决策记录，无论最终是否形成事件：

```text
transitionDecisionId
analysisGenerationId
fromContextId?
candidateContextId?
nextContextId?
candidateStartedAtUtc
candidateEndedAtUtc?
state = Pending | Noise | Interruption | EffectiveSwitch | Unknown
reasonCode
confidence
decidedAtUtc?
```

它承载“为什么没有形成 Switch/Interruption”的负向证据。`Pending` 只存在于当前可重写尾部；历史 Final 日不得有 Pending。

## 10. Interruption 与 Effective Context Switch

### 10.1 Interruption

只由满足 `A → B → A'` 规则的 Transition Decision 产生：

```text
interruptionId
analysisGenerationId
startedAtUtc
endedAtUtc
durationMs
fromContextId
interruptionContextId?
returnedContextId
reasonCode
confidence
sourceSegmentIds?   // 可空、同 generation
```

必须有返回证据；与同一候选的 Effective Context Switch 互斥。

### 10.2 Effective Context Switch

```text
switchId
analysisGenerationId
switchedAtUtc
confirmedAtUtc
fromContextId
toContextId
reasonCode
confidence
sourceSegmentIds?   // 可空、同 generation
```

`switchedAtUtc` 回溯到目标候选开始，`confirmedAtUtc` 表示决策水位。事件保存 Context 安全快照，因此在 90 天 Segment 被清理后仍可保留一年。

每个长期事件必须关联不可变 `DecisionEvidenceSnapshot`：规则 ID/版本、算法版本、候选边界、Context 安全快照、源 Segment 数和聚合边界、reason、confidence、创建时的 explanation capability。它不保存原始标题或路径。源明细存在时能力为 FullEvidence；源明细清理后降为 DecisionSummary，但仍可解释命中规则和边界摘要。

完整序列判定只由算法规范定义，领域层只执行不变量。

## 11. Work Block

```text
workBlockId
workGenerationId
startedAtUtc
endedAtUtc
activeDurationMs
shortIdleDurationMs
firstActivitySegmentId?
lastActivitySegmentId?
closeReason
```

强制不变量：

- 不包含 Context Segment ID、primary Context 或 switch count 作为身份/边界字段；
- 引用的 Activity Segment 必须属于绑定的 Segmentation Generation；
- Idle 达阈值后回溯结束于 Idle 开始/最后输入时刻；阈值后的 Idle 不进入 Work Block；
- `Gap | PrivacyExcluded | Pause | Stop | Sleep | TimeEpochBreak | Clear | OfflineMigration` 立即关闭；
- 崩溃恢复只结束到最后一个已确认边界，不把最后 Observation 之后的未知时间补为工作。

Context 占比、Switch 数等是查询时或读模型中的关联指标，不写回 Work Block 实体。

## 12. Profile、Generation、Result Set 与 Query Snapshot

### 12.1 Derivation Job

一次有限执行任务：`Queued → Running → Completed | Failed | Cancelled`。它有输入水位、目标水位、错误码和开始/结束时间。在线处理也由一系列有限批次 Job 表示，不存在永远 Running 的 run。

### 12.2 Segmentation Generation

Activity Segment 的算法世代，绑定不可变 `SegmentationProfile`、Feature Schema 和 Schema 版本。Profile 只包含真正影响 gap、Activity Key 和去抖的设置，不绑定整个 Settings Revision。状态：`Building | Advancing | Ready | Superseded | Failed`。Advancing 可以长期存在，水位使用 Fact Cursor。

### 12.3 Work Generation

Work Block 的独立算法世代，绑定一个 Segmentation Generation 和不可变 `WorkProfile`（Idle 阈值、强制边界规则、work algorithm version）。Context rule、alias 或 classifier 变化不得创建或改变 Work Generation。

### 12.4 Analysis Generation

Classification、Context、Transition 和事件的算法世代，绑定 Segmentation Generation、Rule、Classifier 和 Analysis Profile；不包含 Work Block 或 Calendar。Context 变化不得改变 Work Block 身份。

### 12.5 Settings Effectivity

`SettingsRevision` 表示完整用户文件；`CaptureSettingsRevision` 是每条事实的采集时配置；Segmentation/Work/Analysis Profile 是从 Settings 中投影出的不可变算法配置。`SettingsEffectivityInterval` 记录某个完整 revision 从哪个 Fact Cursor 起生效，以及对应的 capture/segmentation/work/analysis/calendar profile。

只改变采样间隔或隐私规则时，创建新的 Capture Settings Revision；Effectivity 从该 revision 实际采集到的第一条 Fact Cursor 开始，相关算法 Profile 未变则 Generation 继续 Advancing。Capture revision、采样质量口径或 rebuild capability 变化仍必须切开 Result Set/Snapshot Slice，使查询能准确报告每段能力。若 revision 在产生事实前又被替换，它保留审计状态但不产生空/重叠 Effectivity Interval。算法 Profile 变化时，从实际生效 cursor 创建新 Generation/Result Set Slice；不要求复制或重建生效点之前的历史。

### 12.6 Result Set

Result Set 是查询可见的不可变发布单元：

```text
resultSetId
resultKind = Segmentation | Work | Analysis | Projection
coverageStartBoundary?   // Native v2 only
coverageEndBoundary?     // Native v2 only, exclusive
legacyCoverageStartUtc?  // LegacySummary only
legacyCoverageEndUtc?    // LegacySummary only, exclusive
sealedThroughFactCursor? // inclusive publication watermark, Native v2 only
sourceSegmentationGenerationId?
sourceWorkGenerationId?
sourceAnalysisGenerationId?
sourceSegmentationResultSetId?
sourceWorkResultSetId?
sourceAnalysisResultSetId?
identityResolutionGenerationId?
calendarGenerationId?
dataKind = NativeV2 | NativeV2Summary | LegacySummary
projectionDependencyMask?
availableGranularities
rebuildCapability
explanationCapability
validationDigest
state = Building | Sealed | Garbage
```

只有 `Sealed` Result Set 可被查询。Sealed 后其明细、读模型行、边界、水位和版本引用全部不可变。Advancing Generation 只能写 staging；发布时为受影响的有界时间范围生成新 Result Set，不原地更新已发布行。

`resultKind` 只表示组件类型，`dataKind` 只表示保真度/来源，两者正交；不存在 `Summary` 或 `Legacy` resultKind。NativeV2/NativeV2Summary 必须有完整 Fact Boundary 和 sealed-through 水位；LegacySummary 只有 UTC coverage，并以 import job watermark 追溯。

Result Set 按组件 Seal：Segmentation Set 保存 Activity/App 来源或其守恒摘要，Work Set 保存 Work Block，Analysis Set 保存 Context/Event/Evidence，Projection Set 保存读模型。NativeV2Summary 压缩必须按实际保留能力分别创建 Segmentation、Work、Analysis、Projection Set，不创建一个混合“Summary Set”；LegacySummary 第一版只允许 `resultKind=Projection`，不伪造 Segmentation/Work/Analysis 组件。

Work/Analysis Set 必须绑定其实际使用的 `sourceSegmentationResultSetId`。Projection Set 必须用 `projectionDependencyMask` 声明所需组件，并绑定构建时使用的**具体** Segmentation/Work/Analysis Result Set ID，而不只绑定 Generation ID；其来源 Set 必须 Sealed、coverage 包含 Projection coverage、data kind/capability 兼容。组件可以跨 Snapshot Slice 复用；只改 Context 时必须复用原 Work Set。

### 12.7 Query Snapshot 与 Slice

Query Snapshot 是不可变的发布清单，而不是对一个可变 Generation 的别名：

```text
querySnapshotId
publishedThroughFactCursor?  // inclusive; empty Snapshot is null
publishedThroughUtc?
defaultCalendarGenerationId
createdUnderSettingsRevision
emptyReason? = NoFacts | Cleared
emptyAtFactCursor?
createdAtUtc
state = Preparing | Active | Superseded | Collectable

QuerySnapshotSlice {
  ordinal,
  nativeStartBoundary?, nativeEndBoundary?,
  legacyCoverageStartUtc?, legacyCoverageEndUtc?,
  segmentationResultSetId?, workResultSetId?,
  analysisResultSetId?, projectionResultSetId,
  dataKind
}
```

Native Slice 使用 Fact Boundary 半开区间并按复合位置判定不重叠；相邻 Slice 可以具有相同 UTC 毫秒，只要前一个 end boundary 等于后一个 start boundary。Legacy Slice 只使用 UTC 半开区间，cursor/epoch 全为空；Builder 必须裁剪与 Native 冲突的整个毫秒。各组件 Result Set 必须覆盖 Slice 全范围且处于 Sealed。Slice 中每个非空组件 ID 必须与 Projection Set 的 dependency mask 和具体 `source*ResultSetId` 完全相等；Generation 相同但 Result Set 不同不能通过验证。

一个 Snapshot 可以组合：最近 90 天的新算法组件、91–730 天旧原生 v2 Summary 组件，以及更早或不重叠的 v1 Legacy Projection Set。因此 Mixed capability 是清单结果，不要求把旧历史复制到新 Generation。相邻 Slice 可以使用不同 Generation、Identity Resolution 或 Calendar，但必须显式返回版本和能力。

一个时刻只有一个 Active Snapshot。页面只读取同一 Snapshot 的 Slice；不能自行选择“最新 Generation”。Superseded Snapshot 的清单和 Result Set 在回收前保持可重现。

### 12.8 空 Snapshot 与无事实范围

Query Snapshot 允许零个 Slice，但仅当 Header 的 `emptyReason` 非空。新安装、一直 UserStopped 或尚无事实使用 `NoFacts`；Clear 成功后使用 `Cleared`，并将清理前数据库最后 Fact Cursor 记录到 `emptyAtFactCursor`。空 Snapshot 的 `publishedThroughFactCursor/publishedThroughUtc` 必须为 null，不能用 0 冒充已发布事实；数据库全局 `lastFactCursor` 不因 Clear 回退或重置。

空 Snapshot 不创建零行 Projection Result Set。Header 固定 `defaultCalendarGenerationId` 与 `createdUnderSettingsRevision`，使 Today/Settings 在无事实时仍能返回稳定的 Empty DTO。非空 Snapshot 中某个请求范围没有命中事实时，同样返回 Empty + Snapshot/Calendar/Settings 元数据，不创建空 Slice。

## 13. 历史重建与切换

历史重建必须执行：

1. 捕获数据库全局 Fact Cursor `W0`；
2. 旁路构建新 Generation 到 `W0`；
3. 追平实时新增事实到 `W1`；
4. 请求 Writer 短暂进入 cutover barrier；
5. 追到 barrier 水位 `W2` 并完成守恒校验；
6. Seal 新 Result Set，并以旧 Snapshot 未受影响 Slice + 新 Slice 组成新 Snapshot；
7. 单事务激活新 Snapshot；
8. 释放 barrier，旧 Snapshot 标为 Superseded。

切换前 Desktop 继续读旧 Snapshot。旧算法与新算法只通过新 Snapshot 中不重叠的时间 Slice 共存，不存在同一时间范围的隐式混合。

## 14. Settings Revision

Settings 是数据库外的用户配置。每条 Observation 关联 Capture Settings Revision；Generation 关联其算法 Profile；`created_under_settings_revision` 只可作为审计信息，不参与结果语义。Agent 只有在完整读取、Schema 验证和语义验证全部成功后，才原子替换内存快照并创建 Effectivity Interval；不允许部分字段成功。

设置影响矩阵：

| 变化 | 必须重建 |
|---|---|
| 采样间隔 | 新 Capture Revision/Effectivity；算法 Generation 不变，不追溯 |
| gap cap / Activity 去抖 | 新 Segmentation Profile/Generation；从生效点切 Slice，按需重建可保留历史 |
| Idle/Work Block 阈值 | 新 Work Profile/Generation；不创建 Context Analysis Generation |
| 隐私规则 | 新 Capture Revision；只影响未来事实与 capability |
| Context 规则/alias | 新 Analysis Profile/Generation；Work Generation 不变 |
| reporting time zone | 新 Calendar Generation 与投影 Result Set；事实/Work/Context 明细不变 |

Identity Link 不是 Settings 变化；它创建新的 Identity Resolution Generation，只重建 App Projection Result Set，并通过新 Snapshot Slice 发布。

## 15. 聚合与数据质量不变量

- `active + idle + unknown ≤ 可归属时长`；
- App 日桶等于其小时桶之和；
- Context classified + unclassified 不超过 classifiable；
- 同一候选的 Switch 与 Interruption 互斥；
- Final 日没有 Pending transition；
- Result Set 的 sealed-through Fact Cursor 不超过其来源 Generation staging 水位；
- Query Snapshot Native Slice 按完整 Fact Boundary 不重叠且只能引用 Sealed Result Set；
- Projection dependency mask、source Result Set ID 与 Slice 组件 ID 逐项一致；Generation 相同不能替代此约束；
- Active Snapshot 的 published-through 不超过当前尾部 Slice 的 sealed 水位；
- 空 Active Snapshot 恰好零个 Slice、published-through 为空且携带 Calendar/Settings Header；
- 质量 gap、Time Epoch、隐私排除和 Stop 边界不可跨越归属时长；
- SummaryOnly 数据不得生成明细或当前算法事件。

## 16. 失败语义

- Capture 失败：记录质量事实，不补算；
- Queue drop：序号出现缺口，关闭可归属连续性并记录质量事实；
- Out-of-order：Writer 拒绝进入事实流，记录质量事实；不得重排已提交事实；
- Writer 可恢复失败：事务回滚并由 Runtime 退避重试；
- 不可恢复 Schema/完整性错误：停止采集，保留 IPC 状态查询与安全退出能力；Writer 不可用时先锁存 GC suspension，再允许无 Lease 历史只读；
- 重建失败：新 Generation 标为 Failed，Active Query Snapshot 不变。

## 18. 测试分类

- **领域不变量测试**：状态/时长单一性、Work Block 独立、事件互斥、守恒；
- **算法黄金样本**：去抖、Idle 回溯、`A→B→A`、`A→B→C`、Unknown/质量 gap；
- **Schema/migration 门禁**：Projection 具体组件 FK、复合 Boundary、空 Snapshot、Summary 正交化、保留清理、原子切换、字段 drift；
- **Runtime fault injection**：队列满、SQLite busy/full/corrupt、Writer Degraded Lease/GC、崩溃恢复、维护抢占；
- **IPC 兼容与安全**：握手矩阵、Desktop binary/signature/session capability、原生确认、去重和超时查询；
- **端到端/soak/UI 验收**：90 天数据、长期运行、时区/DST、门禁文案。

## 19. 首版非目标

Focus Block、碎片时间、Plaintext 持久化、ML、云端同步和跨设备 Context 均不属于首版领域模型。
