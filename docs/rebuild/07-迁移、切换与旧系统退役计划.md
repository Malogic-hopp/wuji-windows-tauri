# WUJI v2 迁移、切换与旧系统退役计划

状态：Draft
最后更新：2026-07-18
适用范围：从当前 WPF / C# Agent / `.NET Bridge` 过渡实现迁移到 React 19 + Tauri 2 + Rust Agent/Core + SQLite v2
关联文档：[ADR-002](./ADR-002-React-Tauri-Rust目标架构.md)、[04-SQLite-v2与持久化读模型.md](./04-SQLite-v2与持久化读模型.md)、[06-本地接口与错误合同.md](./06-本地接口与错误合同.md)、[08-验收门禁与测试矩阵.md](./08-验收门禁与测试矩阵.md)、[migration-status.md](./migration-status.md)

## 1. 目的与权威范围

本文定义迁移顺序、切换条件、回滚边界和旧系统退役门禁。它不重新定义产品指标、领域不变量、SQLite Schema、Agent 运行时或 IPC 合同；发生冲突时，应回到 [README.md](./README.md#1-文档层级与适用范围) 指定的权威文档修订。

迁移完成的含义不是“Rust 工程能够编译”，而是：

- prod channel 的长期进程仅剩 Tauri Desktop 与独立 Rust Agent；
- 正常运行时由 Rust Agent 单写 SQLite v2，Desktop 只读；
- React 只调用稳定语义 command，不再依赖 `.NET Bridge`；
- v1 数据按可审计规则导入或保留为 Legacy Summary；
- 生产切换、升级、崩溃恢复和回滚经过 [08](./08-验收门禁与测试矩阵.md) 的对应门禁；
- WPF、C# Agent、C# 业务/基础设施和 Bridge 在稳定观察期后，获得产品明确批准才可退役。

## 2. 迁移强制原则

1. **以新系统重建边界，不逐行翻译旧状态机。** Rust Agent 按 Capture、Processor、Single Writer、Command Server、Heartbeat、Maintenance 拆分。
2. **新旧数据库物理隔离。** v1 Agent 与 v2 Agent 不得同时写同一数据库；v2 major migration 使用新文件，不原地破坏 v1 库。
3. **单一写入所有权。** 正常运行时只有 Rust Agent Writer 可写 v2 数据库。导入器仅在 Agent 停止、Desktop reader 关闭并持有独占锁时运行。
4. **dev 先于 prod。** 原型、shadow、故障注入和 UI 验收只能先在 dev channel 完成；不得用 prod 数据执行破坏性验证。
5. **每一步可观察、可停止、可回滚。** 每一阶段都要保留入口条件、产物、退出证据和最近安全回滚点。
6. **设计接受与实现完成分离。** Draft/Proposed 只表示设计候选；实施状态由 [migration-status.md](./migration-status.md) 记录，验证结论由 [08](./08-验收门禁与测试矩阵.md) 的证据包证明。
7. **语义 parity 不等于旧数值逐项相等。** 对有意改变的 Activity、Work、Context 和质量语义，比较守恒、边界、差异原因和隐私，不把旧错误复制到 v2。
8. **旧资产最后删除。** 在生产稳定观察期、回滚窗口和数据恢复演练结束前，WPF、C# Agent、Bridge、合同生成链和现有测试都属于迁移资产。

## 3. Channel、进程与数据隔离

| 维度 | dev | prod |
|---|---|---|
| 产品名/启动项 | `WUJI Dev` | `WUJI` |
| 用途 | 原型、shadow、故障和 UI 验收 | 已批准的稳定版本 |
| 数据根目录 | 独立 dev root | 独立 prod root |
| SQLite | 独立 v1/v2 文件与 pointer | 独立 v1/v2 文件与 pointer |
| Named Pipe / mutex | 按用户和 dev channel 隔离 | 按用户和 prod channel 隔离 |
| 日志/诊断 | 可提高安全诊断粒度，仍不得记录敏感原文 | 受限、安全、默认最少化 |

channel 由受控宿主配置决定，React 不得传入 channel、数据库路径、Pipe 名或 Agent 路径。任何切换前都必须验证 mutex、Pipe、数据根、启动项和日志目录没有跨 channel 冲突。

注：Rebuild v0.1 使用独立第三命名空间 `rebuild-v01-dev`（09 §4.1），与本表的 dev/prod channel 并存，互不共享 data root、Pipe、mutex、启动项与数据库；本表不描述 rebuild 命名空间。

## 4. 分阶段路线

阶段必须顺序通过退出门禁；允许阶段内并行开发，但不得越过其依赖的硬门禁。

| 阶段 | 目标与主要产物 | 入口条件 | 退出门禁 | 安全回滚点 |
|---|---|---|---|---|
| M0 设计与测试基座 | 接受语义、领域、算法、Schema、运行时、合同；建立 manifest、黄金样本和证据模板 | 当前仓库可构建、旧系统仍可运行 | ADR 接受门禁；`schema-v2-manifest.yaml` 可校验；08 中设计类 P0 关闭 | 不改变运行时，继续使用旧系统 |
| M1 Rust Workspace/Core | `wuji-core`、稳定错误、Settings/Profile、协议 DTO、纯领域算法骨架 | M0 的类型和版本术语稳定 | Core 不依赖 Tauri/rusqlite/Win32；领域不变量与 DTO 合同测试通过 | 删除未接入的原型 crate，不影响旧系统 |
| M2 Win32 Capture Adapter | 前台窗口、标题超时、PID/进程身份、idle、隐私内存边界 | M1 安全类型可用 | 真实 Windows 集成、卡死窗口、权限不足、敏感日志扫描通过 | dev 继续使用 C# capture；不写 prod |
| M3 SQLite v2 基座 | migration harness、正式 DDL、checksum、Fact Cursor、独占 migrator、版本化数据库 pointer | DDL 门禁已通过 | manifest drift、FK、事务、崩溃、Windows 文件切换通过 | pointer 保持指向旧文件；保留失败的新文件供诊断 |
| M4 Rust Agent 流水线 | bounded capture queue、Processor、Writer lanes、Profile/Effectivity、heartbeat、恢复 | M2、M3 通过 | 原子 Observation/派生 staging、背压、Degraded、重启恢复和短 soak 通过 | dev 停 Rust Agent，恢复 C# Agent；数据库不共写 |
| M5 派生与查询发布 | Segmentation/Work/Analysis Generation、具体组件依赖的 Projection Result Set、复合 Fact Boundary、Snapshot Slice、读模型和 Query Service | M4 事实链稳定 | 黄金样本、W0/W1/W2、Projection→具体 Set FK、同毫秒 Slice、Summary 正交化、空 Snapshot、Sealed 不可变、Lease/GC 三态和查询性能通过 | Active Snapshot 不变；丢弃 Building Set |
| M6 IPC 与 Settings | Named Pipe v2、Desktop binary 验签/session capability、可信原生确认、幂等、Process/Capture 分离、Settings 对账 | M4、M5 状态模型稳定 | 协议兼容、WebView/同用户伪造客户端拒绝、原生确认不可由 React 自动完成、超时最终状态、revision/digest 冲突测试通过 | Desktop 不连接 v2；旧 IPC/Bridge 保持 |
| M7 Tauri 去 Bridge | Rust query/IPC client、语义 commands、React 接入、删除运行时 Bridge 依赖的候选变更 | M5、M6 通过 | Dashboard/Settings/Lifecycle 及目标页面 E2E；Agent 离线历史可读；打包不需 Bridge sidecar | dev 构建切回 Bridge 版本 |
| M8 v1→v2 导入与 shadow | 离线导入器、Legacy Summary、差异报告、shadow parity 报告 | M3–M7 可端到端运行 | 导入幂等/中断恢复、隐私、守恒、时间范围、语义差异评审通过 | 删除未激活 v2 候选库；pointer 仍指 v1 |
| M9 dev cutover | dev 默认运行 Rust Agent + bridge-free Tauri，完整手工验收与 soak | M8 通过 | dev cutover gate 全绿；升级/回滚演练完成 | dev pointer/binary 回退；保留候选库 |
| M10 prod canary/cutover | 受控生产候选、v1 备份、v2 导入、健康观察、逐步推广 | M9 稳定且产品批准 | production cutover gate；无 P0/P1；回滚仍可执行 | 按兼容矩阵回滚 binary/pointer，或进入 NeedsAttention |
| M11 旧系统退役 | 先停产、再移除打包、最后删除源码/合同与旧测试 | M10 稳定观察期结束 | retirement gate、恢复演练、产品明确批准、文档归档完成 | 退役前 tag/artifact/source archive；退役后不承诺即时回滚 |

任何阶段若出现数据损坏、隐私泄露、跨用户访问、Snapshot 混读或不可解释的指标守恒失败，均停止向后推进并回到最近安全回滚点。

## 5. Shadow 与 parity 策略

### 5.1 允许的 shadow 输入

shadow 只允许以下两种模式：

- **Capture fan-out：** 一个受控采集源在内存中产生脱敏后的测试输入，分别喂给旧/新处理器；生产数据库仍各自单写；
- **Snapshot replay：** 对 v1 数据库只读快照或脱敏黄金输入离线重放到隔离的 v2 候选库。

不得同时启动 v1/v2 Agent 去争用前台采集并写同一数据库，也不得让 Desktop 或对比脚本成为第二个 v2 写入者。对 prod 数据做离线比较时，应先复制到受控临时位置并清除敏感输出。

### 5.2 parity 比较层次

| 层次 | 必须比较 | 允许差异 |
|---|---|---|
| Capture | 时间范围、采样成功/失败、App identity、idle、隐私排除 | 调度抖动、明确记录的权限/超时差异 |
| Activity | active/idle/gap/filtered 守恒、Segment 边界 | v2 去抖和 gap 规则导致的可解释边界变化 |
| Work | 工作时长、长离开边界、Work Block 数 | 与旧 App Session 不同的领域定义 |
| Context | 规则命中、confidence、reason、版本 | v1 没有对应语义时不要求数值相等 |
| Projection | 小时/日守恒、时区/DST、published-through | Legacy capability 不支持的指标为空或明确降级 |
| 安全质量 | 丢弃、超时、质量缺口、敏感原文扫描 | 不允许无说明差异 |

每个差异必须归为：预期语义变化、旧系统缺陷修正、输入不可比、实现缺陷或尚未裁决。最后两类阻断切换。

## 6. v1→v2 数据迁移

### 6.1 迁移前条件

- Rust Agent 已受控停止并释放写连接；
- Desktop 已进入迁移页并关闭所有 SQLite reader；
- v1 数据库完成只读备份、checksum 和基本完整性检查；
- migrator 获得当前用户、channel 和数据库 generation 的独占锁；
- 目标 v2 文件名全新且不被 active pointer 引用；
- 磁盘空间满足源库、备份、候选库、WAL 和导入报告的容量预算。

### 6.2 导入规则

- 有可靠 Sample 的范围导入为 v2 Observation，再按 v2 Profile 重建派生数据；
- 只有聚合数据或语义不足的范围导入为隔离的 Legacy Summary，不伪造 Context、Switch、Work 明细或 v2 Fact Cursor；
- v1 原始标题、完整路径、PID 等敏感字段不得因为迁移而扩大持久化；
- UTC、本地日期、时区来源和 DST 不确定性必须写入导入报告；
- 每个 import job 保存源 checksum、源范围、目标 database generation、工具版本、规则版本、水位、计数和最终状态；
- 重跑必须幂等：复用已完成结果或清理未激活候选库后重建，不得向 Active v2 库重复追加。

### 6.3 激活顺序

```text
stop Agent and close Desktop readers
→ verify v1 backup
→ build a new v2 database file
→ run integrity/FK/conservation/query checks
→ persist migration receipt
→ atomically update trusted database pointer
→ start compatible Rust Agent
→ wait for DatabaseReady{databaseGeneration, schemaVersion}
→ reopen Desktop read-only query service
```

任何检查失败时 pointer 保持指向旧库。Desktop 不扫描目录猜测“最新”数据库，也不得在收到 `DatabaseReady` 前打开新 reader。

## 7. Result Set / Snapshot 在线切换

算法、Profile、Calendar 或历史重建不通过替换数据库文件发布，而使用 [02](./02-行为分析领域模型.md#13-历史重建与切换) 定义的水位流程：

1. 记录当前全局 Fact Cursor `W0`，旁路构建新 Generation；
2. 重建追到 `W0` 后继续追赶实时事实到 `W1`；
3. Writer 建立短时 cutover barrier，Capture Thread 可以继续采集但提交不能越过屏障；
4. 追到 barrier 水位 `W2`，执行守恒、版本、coverage、Slice 不重叠和 capability 校验；
5. Seal 发生变化的 Result Set，复用旧 Snapshot 的未变化组件和未受影响 Slice；
6. 在一个事务中激活新 Snapshot 并 Supersede 旧 Snapshot；
7. 释放 barrier，Desktop 新查询使用新 Snapshot，已持有 lease 的分页继续读旧 Snapshot。

失败只废弃 Building/Staging 结果，Active Snapshot 不变。Context-only 重建必须复用 Work Result Set；不得用同一 UTC 范围内的新旧 Generation 隐式拼接。

## 8. dev 切换流程

dev cutover 是首次改变默认 dev 运行路径，不改变 prod：

1. 固定候选版本、migration checksum、协议版本和 Profile；
2. 对独立 dev 数据执行备份、导入和 pointer 激活演练；
3. 禁用 dev Bridge 自动准备和 C# Agent 自动启动，启用 Rust Agent controller；
4. 验证 Desktop 关闭不停止 Agent、CaptureStop 不退出进程、Agent 离线仍可读历史；
5. 完成 960×640、1280×800、宽屏、100%–200% DPI、Light/Dark/High Contrast、键盘和读屏验收；
6. 完成 crash、断电近似、队列背压、WAL、Writer Degraded 无 Lease 查询/GC 恢复宽限、空库/Clear 后 Empty、更新、卸载取消和长时 soak；
7. 验证 prod 候选的 Desktop Authenticode/签名清单、同用户伪造进程拒绝、WebView 子进程拒绝，以及 Clear/导出/隐私削弱只能由原生确认继续；
8. 保存证据包并由技术、产品和测试责任人签署 dev gate。

dev 切换失败时，停止 Rust Agent、关闭 reader、恢复旧 dev pointer/二进制组合。失败候选库不得被旧 Agent 打开。

## 9. prod canary 与正式切换

### 9.1 发布前

- 冻结候选 artifact 和依赖清单；
- 验证签名、安装、升级、自启动、卸载和修复路径；
- 为每个受支持的旧版本确认 binary/protocol/schema/import 兼容项；
- 明确 canary 范围、观察期、停止条件、支持入口和数据恢复负责人；
- 在用户确认和磁盘预算满足后创建 v1 可恢复备份。

### 9.2 canary 停止条件

任一条件触发即停止扩大范围：

- 数据库完整性、FK、守恒或 pointer 不一致；
- 隐私排除失效、日志出现敏感原文或 Pipe 跨用户访问；
- 未认证同用户进程/WebView 能连接业务 Pipe，或破坏性动作能绕过原生确认；
- Agent crash loop、无法恢复写入、Snapshot 无法发布；
- Today/Timeline/Trends 出现跨 Snapshot 混读或严重性能退化；
- 升级后无法回滚且没有受控 NeedsAttention 恢复方案；
- 新增 P0，或未被接受的 P1。

### 9.3 正式切换完成

只有 canary 观察期达标、08 的生产门禁全部通过且产品明确批准，才能把 Rust v2 设为 prod 默认。此时旧运行时进入“停产但保留”状态，而不是立即删除。

## 10. 回滚兼容矩阵

| 情况 | 自动回滚 | 操作 |
|---|---|---|
| 新 Agent 尚未激活 v2 pointer | 可以 | 停新进程，恢复旧 binary/启动项 |
| v2 候选库校验失败，pointer 未切换 | 可以 | 保持 v1 pointer，隔离候选库并输出安全诊断 |
| pointer 已切换，v1 仍是完整备份，且没有只存在于 v2 的新事实 | 可以受控执行 | 关闭 reader/Agent，恢复兼容 binary 与 v1 pointer |
| pointer 已切换且 v2 已产生新事实 | 不得静默自动回滚 | 停止采集，导出安全恢复包；由受控 migrator 决定前向修复或经批准的数据回迁 |
| minor 升级未改变不可逆 Schema | 可以在健康门禁内执行 | 回滚 Desktop/Agent 到明确兼容版本，保留 v2 pointer |
| major Schema 已前进，旧 binary 不兼容 | 不可以 | 进入 `NeedsAttention`，使用新 migrator/前向修复；旧 Agent 不得打开新 Schema |
| 仅新 Snapshot 有缺陷 | 可以 | 重新激活仍在回滚保留集合中的旧 Snapshot；不替换数据库 pointer |
| Clear History 已成功提交 | 不可以 | Clear 不保留历史回滚集合；只能恢复用户事先独立持有且明确选择的备份 |

所有回滚都必须记录 request/import/upgrade receipt、源目标 generation、操作者可见结果和安全错误码；禁止通过手工改 JSON 或复制正在打开的数据库完成回滚。

## 11. 旧系统退役顺序

退役按“停止依赖 → 停止发布 → 移除打包 → 删除源码”执行：

1. **冻结功能：** WPF/C# Agent/Bridge 只接受迁移阻断和安全修复，不再新增产品能力；
2. **停止默认运行：** prod 默认改为 Rust v2，但保留可选择的受控回滚 artifact；
3. **停止新包携带：** 观察期通过后，新安装包不再启动或打包 Bridge/WPF/C# Agent；仍保留独立恢复包；
4. **归档合同与证据：** 保存最后兼容版本、Bridge 合同、v1 Schema/导入样本、测试结果、恢复说明和校验值；
5. **删除源码依赖：** 按 Bridge sidecar → Bridge ContractGen/合同 → C# Client/Application → C# Infrastructure/Agent → WPF App 的依赖顺序清理；每一步保持主分支可构建；
6. **删除遗留测试：** 只有对应生产代码删除且 v2 等价风险已由新测试覆盖后，才删除旧测试；迁移/导入回归样本长期保留；
7. **更新解决方案与发布脚本：** 最后移除 C# 项目、dotnet 发布步骤和旧启动项处理。

依赖顺序不是允许提前删除的清单。若某个旧模块仍承担 v1 导入、回滚、parity 或证据生成职责，应先提取稳定 fixture/工具，再删除模块。

## 12. 退役硬门禁

以下条件必须同时满足：

- ADR-002 及 01–08 的实施基线已 Accepted，未决项不影响退役；
- Rust v2 已完成 prod canary 和约定的稳定观察期，期间无未关闭 P0/P1；
- 至少完成一次升级、一次数据库 pointer 回滚和一次恢复包演练；
- v1→v2 导入对受支持的所有 v1 Schema 版本有固定 fixture 和自动回归；
- 安装包、启动项、进程列表和运行目录证明不再依赖 `.NET Bridge`、WPF 或 C# Agent；
- Rust v2 测试覆盖已经接替旧系统承担的领域、IPC、SQLite、生命周期、隐私和 UI 风险；
- 用户数据备份/恢复政策、支持期限和旧版本兼容政策已发布；
- 产品负责人、技术负责人和测试负责人明确批准退役；
- 退役前 tag、可验证 artifact、checksum 和恢复文档已归档。

“新代码能编译”“单次手工运行成功”“dev 已切换”或“旧 UI 不再打开”均不构成退役批准。

## 13. 迁移记录与证据

每个阶段至少保存：

- 版本、commit、依赖锁文件和构建 artifact checksum；
- channel、数据库 generation、Schema/migration checksum、协议和算法/Profile 版本；
- 自动测试、故障注入、性能、容量、soak 和手工验收结果；
- shadow/import 差异报告及每个非预期差异的处置；
- 切换/回滚开始结束时间、pointer 前后值的安全标识和 receipt；
- P0/P1 清单、豁免决策、批准人和有效期。

证据不得包含用户名、SID、完整路径、原始标题或真实隐私数据。[migration-status.md](./migration-status.md) 只链接或摘要这些证据，不用“计划中”冒充“已验证”。
