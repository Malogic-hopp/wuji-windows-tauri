## 总体不变量

所有阶段都必须遵守：

1. 不修改或删除旧 WPF/C#/Bridge 回滚入口。
2. 不读写、迁移或清理旧 WUJI/WUJI-Dev 数据库。
3. 运行时测试只使用唯一随机 `rebuild-v01-test-*` channel。
4. 不回滚用户现有未提交修改，不使用破坏性 Git 命令。
5. 不 commit、不 push，除非用户明确要求。
6. 每个阶段结束时仓库必须可格式化、可编译、专项测试通过。
7. 不提前实施下一阶段；必要的兼容适配必须最小化并写入完成说明。
8. 不通过增加随机 sleep、扩大 timeout、跳过测试或降低错误语义换取绿色。
9. package、正式 8 小时 soak、真实 Lock/Sleep 和 UI 人工门禁在 4.7 前保持 NotRun/Pending。
10. 任一阶段未通过复审，不得进入下一阶段，也不得把 S2-03/S2-04 标记完成。

## 阶段交付规则

每个阶段完成后，Agent 必须在本目录新增：

```text
阶段4.x-完成说明-YYYY-MM-DD.md
```

完成说明至少包含：

1. 阶段目标与审核编号；
2. 修改文件；
3. 实际行为与失败语义；
4. 新增/更新测试；
5. 首次测试结果与最终结果；
6. 明确未做事项；
7. 遗留风险；
8. `git status --short`；
9. 是否建议进入下一阶段。

进入下一阶段前，新的 Agent 必须先完整阅读上一阶段完成说明并核对实际代码，
不能只相信“已完成”的文字结论。

## 最终完成边界

4.7 结束也只能写“第四阶段整改完成，等待复审”。以下结论仍需新的审核或人工证据：

- S2-03/S2-04 最终关闭；
- Rebuild v0.1 全部验收通过；
- package/8 小时 soak 覆盖当前代码；
- 真实 Lock/Sleep、DPI、High Contrast、键盘和读屏通过。
