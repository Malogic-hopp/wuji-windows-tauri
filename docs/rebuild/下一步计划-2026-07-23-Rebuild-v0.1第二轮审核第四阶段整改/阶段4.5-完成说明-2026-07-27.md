## 3. 实现细节

### 3.1 状态模型

```text
desired (用户命令设置的 CaptureState)
  × transition (控制操作进行中)
  × fault (lifecycle 提交失败安全冻结)
  × writer_fault (Writer/Process fatal，不可由用户解除)
  × lifecycle_monitor_fault (事件泵永久失效，4.5 新增)
  × lock.active (会话锁定抑制)
  × sleep.active (系统睡眠抑制)
  = effective capture gate
```

**effective Running** 当且仅当：desired == Running 且所有 suppression 均为 false。

### 3.2 平台无关四态输入

```rust
pub enum SystemLifecycleEvent {
    Lock { at_utc_ms: i64 },
    Unlock { at_utc_ms: i64 },
    Sleep { at_utc_ms: i64 },
    Resume { at_utc_ms: i64 },
}
```

Windows adapter 只产生四态输入；状态叠加、Barrier、Writer 和发布语义由唯一
Coordinator 决定。

### 3.3 每个来源独立状态

Lock 与 Sleep 各自维护 `LockSleepState { active, first_at_utc_ms, committed }`：

| 事件 | active | first_at_utc_ms | committed | 行为 |
|---|---|---|---|---|
| 首次 Lock | true | Some(at) | false | freeze + Barrier + WriterControl(Lifecycle) |
| Lock 后重复 Lock | true | Some(at) | true | 幂等成功 |
| Unlock (lock active) | false | None | false | 清 suppression → publish (若无可恢复) |
| Writer ack 成功 | true | Some(at) | true | mark_committed |
| Barrier/control 失败 | true | Some(at) | false | 保留首次时间，可重试 |
| Writer ack unknown | (锁存 writer_fault) | — | — | 沿用 4.3.1 unknown fencing |

### 3.4 进入事件流程 (Lock/Sleep)

```text
transition lock
→ 检查 writer_fault / monitor_fault
→ 检查 lock/sleep state：已 active+committed → 幂等返回
→ 首次进入：activate(at) 记录 first_at_utc_ms
→ begin_transition：freeze effective capture (transition suppression)
→ inject Barrier + wait injected ack
→ send WriterControl::Lifecycle(event) + wait Writer ack (8s)
→ mark_committed
→ end_transition：解除 transition suppression
→ publish (suppression 仍 active → Paused)
```

### 3.5 解除事件流程 (Unlock/Resume)

```text
transition lock
→ 检查 writer_fault / monitor_fault
→ lock/sleep state：not active → 幂等 no-op
→ reset()：清除 active/first_at_utc_ms/committed
→ publish：若 desired=Running 且所有 suppression 均解除 → Running
```

**Unlock/Resume 不创建反向数据库边界，不修改 desired。**

### 3.6 重叠 gap 语义

```text
Lock → Sleep → Resume → Unlock
  SessionLocked gap → SystemSleep gap
  Resume：只清 sleep suppression（lock 仍 active → Paused）
  Unlock：清最后一个 suppression → Running
  恢复后首条有效 Observation 关闭最后一个 open gap
```

Lock/Sleep 的 `EngineEvent::SessionLocked/SystemSleep` 提交为新 kind gap；
release 不改写 gap kind。

## 4. 失败闭环

| 失败点 | committed 可能 | 行为 |
|---|---|---|
| freeze 发布失败 | 否 | latch force_stopped；不发送 Barrier/control |
| Barrier send/injected ack 失败 | 否 | 保持 suppression；end_transition；LifecyclePump 诊断；首次时间保留可重试 |
| control send 失败 | 否（保证未入队） | 保持 suppression；可重试 |
| Writer 明确错误 | 否 | 保持 suppression；保留 Writer 精确诊断 |
| Writer ack timeout/closed | 未知 | 沿用 writer_fault fencing；不得重试或被迟到 ack 解除 |
| 提交成功后 publish 失败 | 已提交 | 保留 committed；安全停止，不回滚 |
| 事件泵永久退出 | 无后续事件 | `latch_monitor_fault()` —— 不可由普通 Start/Resume 清除，仅 Agent 重启恢复 |

## 11. 阶段 4.5 复审补修（2026-07-27）

### 11.1 P1-01：自定义 WndProc 处理 sent message

**根因**：WM_POWERBROADCAST 是 sent message，直接调用窗口过程，不进入 GetMessageW
返回队列。原 `DefWindowProcW` 注册无法在消息循环中识别这类事件。

**修复**：实现自定义 `unsafe extern "system" fn wnd_proc`，在窗口过程中处理
`WM_POWERBROADCAST`（PBT_APMSUSPEND/PBT_APMRESUME_AUTOMATIC）和
`WM_WTSSESSION_CHANGE`（WTS_SESSION_LOCK/UNLOCK），通过 `GWLP_USERDATA`
关联的 `WindowContext` 转发事件。所有消息（含已处理的事件消息）继续走
`DefWindowProcW`。

### 11.2 P1-02：受监督的 pump/bridge/consumer 与 shutdown 信号

**根因**：pump 线程句柄未返回、bridge 退出被静默视为正常、consumer 把 receiver
关闭统一当成正常退出、bridge 线程创建失败没有 latch_monitor_fault。

**修复**：
- `start_session_power_bridge` 现在返回 `(consumer, pump_thread, shutdown_tx)`
- `run_session_power_events` 接收 `shutdown_rx`：bridge channel 关闭时检查
  shutdown 信号——已发送 → 正常退出；未发送 → latch_monitor_fault
- bridge 线程创建失败时调用 `coordinator.latch_monitor_fault()`
- `main.rs` 在 shutdown 序列中：先 `shutdown_tx.send(true)` 正常关闭信号，
  再 abort consumer task，最后 join pump thread
- 新增 `SessionPowerBridge` 类型别名消除 clippy type_complexity

### 11.3 P1-03：重试使用首次事件时间

**根因**：`commit_enter_boundary` 从 `event.to_engine_event()` 构造 EngineEvent，
使用本次事件的时间戳。失败重试时 gap 起点会推迟到重试时刻。

**修复**：`commit_enter_boundary` 现在从 `LockSleepState.first_at_utc_ms` 读取
首次事件时间，据此构造 `EngineEvent::SessionLocked/SystemSleep`。新增
`LockSleepSource::lock_sleep_mut_read()` 只读访问器。

### 11.4 P1-04/P1-05：Clippy 零警告、测试清理

- 移除 lock_sleep_lifecycle 测试中全部未使用导入
- Wiring 结构体中未读字段加 `_` 前缀
- `map_session_power_event` 生产函数供测试共用（不再手写 match）
- `cargo clippy --workspace --all-targets -- -D warnings` 通过

### 14.2 shutdown 有界所有权模型

生产与测试共用 `shutdown_session_power(SessionPowerShutdownOps, timeouts)` 状态机：

```text
signal normal shutdown
→ request_stop(PostMessageW)
  → 失败则 request_fallback(PostThreadMessageW/WM_QUIT)
→ await consumer supervisor (3s)
  → timeout: abort → 再 await 1s 确认
→ await pump exited (5s)
  → timeout 且尚未 fallback: WM_QUIT → 再 await 5s
→ 仅 exited && is_finished 时同步 join pump
→ await bridge exited (5s)
→ 仅 exited && is_finished 时同步 join bridge
→ 返回 ShutdownReport；不完整或含异常诊断时锁存 LifecyclePump fault
```

`SessionPowerBridge::shutdown(&mut self)` 的 timeout 不移动未完成 Tokio/std handle；
未结束句柄仍由 bridge 持有。同步 join 只负责回收已经结束的线程，不承担等待。

| 场景 | 结果 | 句柄/诊断 |
|---|---|---|
| 正常 stop | Complete | consumer/pump/bridge 全部退出并回收；无 LifecyclePump |
| `PostMessageW` 失败、fallback 成功 | Complete 但含 stop 错误 | `fallback_used=true`，锁存 LifecyclePump，不伪装无故障 |
| pump 永不 exited | Incomplete，有界返回 | pump/bridge 不执行同步 join，pending ownership 留在 bridge |
| bridge 永不 exited | Incomplete，有界返回 | bridge 不执行同步 join |
| consumer 自然退出 timeout | abort 后再次有界确认 | 确认 Cancelled 后才记 consumer_exited；记录超时诊断 |
| pump/bridge join 报 panic | Incomplete | 精确错误 + LifecyclePump fault |
| consumer panic | supervisor 捕获 | 生产 helper 锁存 LifecyclePump 并强制 Stopped |

新增 Agent lib 测试：

- `shutdown_state_machine_normal_path_reaps_all_layers`；
- `shutdown_state_machine_stop_failure_uses_fallback_and_reports_fault`；
- `shutdown_state_machine_pump_timeout_returns_without_joining_pending_threads`；
- `shutdown_state_machine_consumer_timeout_aborts_then_confirms_exit`；

### 15.2 启动事务与回滚时序

```text
start real pump
→ create bounded bridge channels
→ spawn bridge thread
  ├─ success: hand off pump + bridge + consumer/supervisor to SessionPowerBridge
  └─ failure: latch LifecyclePump
             → request_stop(PostMessageW)
             → bounded wait
             → request_quit_fallback(WM_QUIT) when needed
             → bounded wait
             → only if is_finished: join
             → unregister window class
             → return original spawn error + cleanup result
```

启动回滚使用两个独立 2 秒上限；不会在错误路径执行未确认 finished 的同步 join，也
不会把 pump handle 交给 `Drop` 后静默 detach。
