# 专注中断洞察独立页面方案（2026-07-07）

## 背景

`scripts/analyze_context_switches.py` 已经证明：仅展示 Dashboard 指标不足以解释用户真实体验。

当前脚本可以回答更有价值的问题：

```text
为什么今天切换频繁？
哪些应用把我从工作中拉走？
为什么明明有长时间 coding block，却没有形成连续专注？
明天可以做什么具体调整？
```

这些内容不适合继续塞进 Dashboard。

Dashboard 当前已经包含：

```text
Agent overview
Today Insight
Activity Heatmap
Today 24h
7-Day Trend
Top Apps
App Share
Top Windows
Messages
```

如果继续往 Dashboard 加“深度解释型内容”，页面会变得拥挤，用户也难以区分“概览”和“复盘分析”。

因此建议新增一个独立页面：

```text
Insights / 洞察
```

Dashboard 继续负责快速概览；Insights 页面负责解释原因、指出中断源、给出行动建议。

---

## 产品定位

新页面名称建议：

```text
Insights
```

中文语义：

```text
专注中断洞察 / 工作复盘
```

一句话目标：

```text
把 foreground_samples 和 app_sessions 转换成“今天为什么分散、被什么打断、下一步怎么调整”的本地洞察。
```

页面不做“评分审判”，只做事实复盘和温和建议。

文案风格应避免：

```text
你效率很差
你今天不专注
你浪费了时间
```

推荐风格：

```text
你今天有两段较长的开发块，但 Communication 和 System 插入较多。
可以尝试安排一个 45 分钟 Code-only 块，把微信和文件查找集中到块前后处理。
```

---

## 为什么不放在 Dashboard

### Dashboard 的职责

Dashboard 应回答：

```text
现在状态是什么？
今天大概怎样？
有没有明显异常？
```

适合内容：

```text
今日活跃时间
状态热力图
7 天趋势
Top Apps
简短建议
```

### Insights 的职责

Insights 应回答：

```text
为什么？
具体被什么打断？
哪些工作块被破坏？
下一次怎么做？
```

适合内容：

```text
工作块分析
中断源排名
语境切换方向
工具内切换 vs 真正语境切换
行动建议
```

## MVP 页面结构

建议新增一个 Tab：

```text
Dashboard | Apps | Sessions | Samples | Diagnostics | Settings | Insights
```

如果担心 Tab 太多，也可以后续再整理导航；MVP 先新增 Tab 即可。

页面布局建议采用高密度、工具型布局，不做大幅营销式 hero。

### 顶部摘要区

显示 4 个关键指标：

```text
Meaningful switches
Raw tool hops
Longest work block
Top interruption source
```

示例：

```text
365 context switches
777 raw hops
100m longest block
WeChat 57 interruptions
```

### 主要解释卡片

一张主卡片，给出当天最重要结论：

```text
你今天有 2 段超过 90 分钟的开发块，但微信、Edge 和资源管理器频繁插入。
主要问题不是没有工作时间，而是工作块中断频率较高。
```

### 工作块列表

展示最长或最重要的 2-4 个 work blocks。

字段建议：

```text
开始 - 结束
持续时间
主语境 / 主应用
语境切换次数
中断源摘要
是否形成有效专注
```

示例：

```text
15:24 - 16:54 · 90m · Development / Code
106 context switches · WeChat 38, Edge 24, Explorer 18
未识别为连续专注：平均约 51 秒一次语境切换
```

### 中断源排名

展示把用户从主要工作语境拉走的应用。

示例：

```text
Explorer       59
WeChat         57
Edge           23
```

区分：

```text
Communication
System
Research
Entertainment
Development
Other
```

### 语境切换方向

展示最常见的 context transition。

示例：

```text
Development ↔ Communication   14%
Development ↔ System          13%
Development ↔ Research         6%
```

MVP 可以先用列表，不必做 Sankey 图。

### 行动建议

给出 1-3 条建议。

示例：

```text
1. 明天先试一个 45 分钟 Code-only 块，微信静音。
2. 把文件查找集中在工作块开始前 5 分钟处理。
3. Edge 查资料保留，但娱乐站点建议放到休息段。
```

## 数据与算法来源

### MVP 输入

优先复用已有数据库数据：

```text
foreground_samples
app_sessions
```

不要在 App 里调用 Python 脚本。

`scripts/analyze_context_switches.py` 作为算法参考和验算工具保留。

### 推荐服务

新增服务：

```text
FocusInterruptionInsightService
```

职责：

```text
读取某天 foreground samples
分类应用 / 浏览器标题
计算 raw tool hops
计算 meaningful context switches
识别 work blocks
识别 interruption sources
生成 summary / action text
```

### 推荐 ViewModel

新增：

```text
InsightsViewModel
```

职责：

```text
加载指定日期洞察
保存日期选择状态
暴露页面展示集合
处理 refresh command
处理空数据 / 加载失败
```

### 推荐 View

新增：

```text
src/QuantifiedSelf.Windows.App/Views/InsightsView.xaml
src/QuantifiedSelf.Windows.App/Views/InsightsView.xaml.cs
```

如果当前页面仍主要写在 `MainWindow.xaml`，MVP 可以先内联 Tab 内容；但更推荐直接拆为独立 View，避免 MainWindow 继续膨胀。

## 推荐模型

### FocusInterruptionInsight

```csharp
public sealed class FocusInterruptionInsight
{
    public DateOnly Date { get; init; }
    public int ActiveSampleCount { get; init; }
    public TimeSpan EstimatedActiveTime { get; init; }
    public int RawToolHopCount { get; init; }
    public int MeaningfulContextSwitchCount { get; init; }
    public IReadOnlyList<WorkBlockInsight> WorkBlocks { get; init; } = [];
    public IReadOnlyList<InterruptionSourceInsight> TopInterruptionSources { get; init; } = [];
    public IReadOnlyList<ContextTransitionInsight> TopContextTransitions { get; init; } = [];
    public string SummaryText { get; init; } = string.Empty;
    public string ActionText { get; init; } = string.Empty;
}
```

### WorkBlockInsight

```csharp
public sealed class WorkBlockInsight
{
    public DateTime StartLocal { get; init; }
    public DateTime EndLocal { get; init; }
    public TimeSpan Duration { get; init; }
    public string PrimaryContext { get; init; } = string.Empty;
    public string PrimaryApp { get; init; } = string.Empty;
    public int ContextSwitchCount { get; init; }
    public TimeSpan AverageSwitchInterval { get; init; }
    public IReadOnlyList<InterruptionSourceInsight> TopInterruptions { get; init; } = [];
    public bool IsRecognizedFocusBlock { get; init; }
    public string ExplanationText { get; init; } = string.Empty;
}
```

### InterruptionSourceInsight

```csharp
public sealed class InterruptionSourceInsight
{
    public string AppName { get; init; } = string.Empty;
    public string Context { get; init; } = string.Empty;
    public int Count { get; init; }
    public string DisplayText { get; init; } = string.Empty;
}
```

### ContextTransitionInsight

```csharp
public sealed class ContextTransitionInsight
{
    public string FromContext { get; init; } = string.Empty;
    public string ToContext { get; init; } = string.Empty;
    public int Count { get; init; }
    public double Ratio { get; init; }
    public string DisplayText { get; init; } = string.Empty;
}
```

```text

PowerShell

Codex

```

### Research / Learning


### Communication

```text

```

### Entertainment


## Work Block 识别建议

MVP 规则建议：

```text
只看 Active 样本
相邻 Active 样本间隔 <= 5 分钟则属于同一个 block
block 持续时间 >= 25 分钟才进入候选工作块
按持续时间或 context switch count 排序展示前 4 个
```

有效专注段规则可保守：

```text
block >= 25 分钟
meaningful context switch count <= 3
主语境占比 >= 70%
```

不要把工具内跳转等同于中断：

```text
Development 内部工具切换：raw hop
Development -> Communication：meaningful switch
Development -> Entertainment：meaningful switch
Development -> Research：需要结合 title，技术资料可弱化
```

## UI 边界

### 本阶段不做

```text
不把全部脚本文本报告塞进 UI
不做 Sankey 图
不做复杂交互图表
不做 AI 总结
不联网
不改 Dashboard 现有图表
不改 Samples / Sessions / Apps 页面
不改 Agent 采样逻辑
不改 SQLite 表结构
不改 IPC 协议
```

### 本阶段允许

```text
新增 Insights tab
新增 InsightsViewModel / View / Service
新增只读查询
复用现有样本查询服务或新增只读 query method
新增少量单元测试
```

## 测试建议

至少覆盖：

```text
1. Code ↔ Codex ↔ Terminal 不应被计算为高风险 meaningful switch。
2. Code ↔ WeChat 应计为 Development ↔ Communication。
3. Edge 技术标题归 Research；Bilibili / 微博 / 小红书等标题归 Entertainment。
4. 能识别 90 分钟 work block，并统计其中中断源。
5. 无数据时返回安全空 insight，不崩溃。
6. InsightsViewModel LoadAsync 不覆盖 Dashboard 数据。
```

可选：

```text
和 scripts/analyze_context_switches.py 对同一天做抽样对比，确认核心指标数量级一致。
```

## 推荐实施顺序

### 阶段 A：服务层 MVP

```text
新增模型
新增 FocusInterruptionInsightService
迁移核心分类和 work block 识别
补服务层测试
```

### 阶段 B：独立页面 MVP

```text
新增 InsightsViewModel
新增 InsightsView
MainWindow 增加 Insights Tab
展示摘要 / 工作块 / 中断源 / 切换方向 / 建议
```

### 阶段 C：文案与验收

```text
根据真实数据调整文案
避免“责备式”表达
验证无数据 / 低活跃 / 高活跃 / 高中断场景
```

## 验收标准

MVP 完成后：

```text
1. App 中出现 Insights 独立页面。
2. 页面能展示当天专注中断洞察。
3. 能识别并展示主要 work blocks。
4. 能展示主要中断源和语境切换方向。
5. 能给出 1-3 条温和、具体、可执行建议。
6. Dashboard 不再新增该分析内容，保持概览职责。
7. build 0 warnings / 0 errors。
8. 相关测试通过。
```
