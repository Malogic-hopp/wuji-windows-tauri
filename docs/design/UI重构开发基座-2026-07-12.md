# UI 重构开发基座说明

> 目标：允许 UI 重构开发版与当前稳定版并行存在，避免开发版误操作现用 App、Agent、状态文件和开机自启配置。

## 推荐目录

```text
C:\Users\WangZhenchi\work\WUJI\Win       稳定版 main
C:\Users\WangZhenchi\work\WUJI\Win-ui    UI 重构开发版 feature/ui-redesign
```

建议用 Git worktree 创建开发版：

```powershell
cd C:\Users\WangZhenchi\work\WUJI\Win
git worktree add ..\Win-ui -b feature/ui-redesign
```

如果分支已存在：

```powershell
git worktree add ..\Win-ui feature/ui-redesign
```

## 开发通道启动

稳定版仍按原方式启动：

```powershell
dotnet run --project src\QuantifiedSelf.Windows.App
```

UI 重构开发版使用 Dev Channel：

```powershell
dotnet run --project src\QuantifiedSelf.Windows.App -- --channel dev --ui-preview
```

需要保留 Agent 调试窗口时：

```powershell
dotnet run --project src\QuantifiedSelf.Windows.App -- --channel dev --ui-preview --show-agent-console
```

## 已隔离的运行时资源

| 资源 | 稳定版 | 开发版 |
| --- | --- | --- |
| 数据目录 | `%LOCALAPPDATA%\WUJI\WindowsAgent` | `%LOCALAPPDATA%\WUJI-Dev\WindowsAgent` |
| Named Pipe | `QuantifiedSelf.Windows.Agent.{sidHash}` | `QuantifiedSelf.Windows.Agent.dev.{sidHash}` |
| Agent mutex | `QuantifiedSelf.Windows.Agent.{sid}` | `QuantifiedSelf.Windows.Agent.dev.{sid}` |
| HKCU Run Key value | `WUJI` | `WUJI Dev` |
| App 窗口标题 | `WUJI 吾迹` | `WUJI Dev - WUJI 吾迹` |

App 使用 `--channel dev` 启动 Agent 时，会继续向 Agent 传递 `--channel dev`，并设置 `WUJI_RUNTIME_CHANNEL=dev`。

## 初期施工约束

1. Dev Channel 默认使用独立数据目录，不直接读写生产目录。
2. UI 重构初期优先使用复制出来的数据快照做展示验证。
3. 不在 Dev Channel 中注册生产 `WUJI` 开机自启项。
4. 不把 Dev App 的 Start / Stop / Pause 连接到生产 Agent。
5. 新 UI 使用 `--ui-preview` 开关进入；未传该开关时继续保留旧 UI。

## 后续 UI 重构入口

`--ui-preview` 目前只完成启动参数基座，尚未切换到新 Shell。后续重构建议按以下顺序接入：

1. 新增 Preview Shell 和左侧导航。
2. 先只读展示“今天 / 时间线 / 洞察 / 趋势”。
3. 保留旧 Dashboard 与 Diagnostics 作为回退路径。
4. 页面稳定后再迁移设置、数据清理和高级诊断入口。

## 已知问题（待后续修复）

### P2 — `RuntimeChannel.DisplaySuffix` 对空字符串无防御

`DisplaySuffix` 在 `Name` 为空字符串时 `Name[0]` 会越界。当前 `Normalize` 已保证空输入返回 `"prod"`，正常路径不会触发，但若代码绕过 `Normalize` 直接 `new RuntimeChannel("")` 会崩。

**建议**：加 `Name.Length == 0 ? "Unknown" : ...` 防御。

### P2 — `RuntimeChannel` 未实现值相等

`Parse` 对非 prod/dev 名称每次创建新实例，`==` 比较会失败（未重写 `Equals`）。当前使用场景只涉及 `IsDefault` 判断（字符串比较），不会出 bug。但若后续有 `channel == RuntimeChannel.Parse("staging")` 会踩坑。

**建议**：加静态 `ConcurrentDictionary` 缓存同 name 返回同实例，或重写 `Equals` / `GetHashCode`。
