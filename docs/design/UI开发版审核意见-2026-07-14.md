## 需要先处理的事项

### P0 — 洞察页面把应用级推断包装为“任务/工作块”

**类别：产品语义与用户信任**  
**证据**：`Views/InsightsView.xaml:81-124, 163-335` 展示“任务切换”“最长工作块”“工作块”“任务切换方向”等结论；但当前迁移状态明确记录 `ContextSegment`、`WorkBlock`、上下文分类均未实现，且 Today 页面已经对应用级数据做了诚实说明。

这会让用户把基于应用、会话或样本的估算误解为已识别的真实任务，直接违背“应用不是任务”和“工具跳转不等于任务切换”的产品原则。

**修复方向**：在上下文/工作块数据模型落地前，洞察页只能使用“应用会话”“工具跳转”“记录活跃度”等可证实术语，或完整切换为“数据积累中 / 分析引擎升级后可用”的状态。

**验收标准**：页面任何“任务、上下文切换、工作块、专注/碎片化”结论均有对应可解释的数据来源；否则不显示结论及正负标签。

### P0 — 今天页摘要仍以“专注 / 跨任务”解释应用级会话

**类别：产品语义与用户信任**  
**证据**：`ViewModels/DashboardViewModel.cs:720-739` 将 `LongestFocusSession` 和 `ContextSwitchCount` 生成“最长专注”“暂未检测到完整专注段”“跨任务切换较为频繁”；`Views/TodayView.xaml:161` 同时告知用户“当前指标基于应用级别统计”。`TodayPageViewModel` 只是对该 Dashboard ViewModel 的包装，因此该文案会直接出现在“今天”页。

同一屏中一边声明能力尚未实现、一边给出任务和专注结论，会使用户难以判断什么是事实、什么是推断。这比单独的洞察页风险更高，因为“今天”是默认高频入口。

**修复方向**：在 ContextSegment / WorkBlock 落地前，摘要仅陈述可追溯事实（活跃时长、应用会话数、前台应用）；将“专注”“任务”“碎片化”改为明确的能力占位，不从 `ContextSwitchCount` 推导心理或任务状态。

**验收标准**：Today 与 Insights 页面对同一数据能力使用一致且保守的术语；任何推断都有“依据是什么、置信边界是什么”的可查看说明。

### P1 — 三个页面保留禁止的 Hero 与控制台式卡片栅格

**类别：信息层级与视觉一致性**  
**证据**：`Views/TrendsView.xaml:24,69-100`、`Views/PrivacyView.xaml:18,33-54`、`Views/DiagnosticsView.xaml:26,69-94` 仍使用 `HeroCardBorderStyle`，并分别有 5、3、4 张低信息摘要卡。`Themes/Cards.xaml:53` 仍定义该旧样式。

这些页面与新的轻量顶栏重复标题，制造“标题 → Hero → 卡片标题”的三级层级；趋势和诊断尤其像运维仪表盘，偏离“安静、精确、数据优先”的桌面工具感。

**修复方向**：删除 Hero 样式和卡片摘要行；趋势改为范围切换 + 热力图/趋势图 + 周度文字总结，隐私改为首屏隐私承诺 + SettingRows，诊断改为 4 个健康状态 + 操作 + 默认收起的技术详情。

**验收标准**：全项目页面 XAML 对 `HeroCardBorderStyle` 的引用为 0；没有 3 张以上仅展示单一文本指标的并列卡片。

### P1 — 紧凑布局仅改变侧栏，内容会在目标最小尺寸失效

**类别：自适应布局 / WPF 可用性**  
**证据**：`MainWindow.xaml:15` 的最小宽度是 1120 DIP，而规范目标是 960×640；`AdaptiveLayout.Mode` 的 XAML 使用点全部位于 `MainWindow.xaml`，页面未消费该状态。Today 和 Timeline 的四列指标、Today/Privacy/Diagnostics 的多列布局没有 Compact 模板或堆叠规则。

目前即使侧栏收起，页面内容仍会在较窄窗口挤压、裁切或保留过密信息，不能满足 125%–200% DPI 下的现代 Windows 桌面使用体验。

**修复方向**：先将 960×640 作为可实际到达的最小客户端尺寸，再用 `AdaptiveLayout.Mode` 为 MetricStrip 提供 2×2 模板、将双栏模块堆叠，并为热力图提供可控的横向滚动。

**验收标准**：在 960×640、100/125/150/200% DPI 下，文本无裁切，指标为 2×2，双栏改为单栏；1280×800 保持四列和双栏。

### P1 — 当前“主题系统”并不具备深色与高对比模式

**类别：主题与可访问性**  
**证据**：`App.xaml:7-16` 只加载一组固定颜色/画刷字典；工作区未发现 Dark 或 High Contrast 资源切换实现。`Themes/Brushes.xaml` 的资源也以 `StaticResource` 固定指向单一浅色调色板。

这不等同于“Light/Dark/High Contrast 可用”。深色模式与 Windows 高对比模式下的对比度、选中态和热力图边界仍完全未验证。

**修复方向**：实现可替换的 Light/Dark Brush 字典，并提供以 `SystemColors` 为基础的高对比回退；页面中的画刷继续使用 `DynamicResource`。

**验收标准**：可在运行时切换三种主题；高对比下可辨认焦点、选中态、禁用态和热力图单元格边界。

### P1 — 设计令牌尚未真正收口，旧页面破坏一致性与换肤能力

**类别：设计系统**  
**证据**：页面 XAML 仍有硬编码颜色（`InsightsView.xaml`、`PrivacyView.xaml`、`SettingsView.xaml`）、字体、圆角和内边距；例如 `PrivacyView.xaml:20-29` 直接使用颜色与 `White`，`InsightsView.xaml:55-59` 直接使用 `#E3EBF3` 与英文 “Insights”。`TrendsView.xaml:72-97` 仍依赖 `LegacyMetric*` 样式。

这会让不同页面有不同视觉语言，也阻断后续暗色/高对比主题。页面中还存在不应面向普通用户的中英混排。

**修复方向**：页面仅引用语义 Brush、Typography、Spacing、Radius 与组件样式；旧样式只作为临时迁移清单，不再扩散到新页面。

**验收标准**：`Themes/` 之外不含十六进制颜色；页面不直接设置 `FontSize`、`CornerRadius`、`Padding`；产品标题和说明均为中文（品牌、真实应用名和高级技术标识除外）。

### P1 — 今日页仍保留被目标规范淘汰的“每小时柱状概览”，且存在嵌套卡片

**类别：产品信息架构**  
**证据**：`Views/TodayView.xaml:121-139` 的“每小时活动概览”是小时柱图；`TodayView.xaml:108-169` 的外层卡内再放两个带圆角与背景的子 Border。页面模式要求该位置是未来的工作上下文时间线 + 单一结论，并明确禁止用小时柱图重复热力图。

当前已诚实标注数据限制，这比伪造上下文好；但同屏柱图和热力图仍重复回答“什么时候活跃”，降低首屏信息密度。

**修复方向**：在上下文时间线不可用时，用轻量的“应用会话时间线（暂代）”或单一说明占位替换柱图；摘要保持为一个 Panel 而不是套卡。

**验收标准**：Today 不再存在 24 小时柱图；不存在卡片内再用视觉卡片承载主要内容的结构。

### P2 — 焦点可见性被显式关闭，图表与图标的无障碍语义不完整

**类别：键盘可访问性**  
**证据**：`Themes/DataGrid.xaml:54` 将 `FocusVisualStyle` 设为 `{x:Null}`；`Themes/Buttons.xaml:73-106` 的 Agent 状态按钮重写模板后没有焦点态；Today 热力图仅为 LiveCharts 图表，没有单元格键盘导航或 `AutomationProperties.Name`。Timeline 日期按钮使用字符箭头（`TimelineView.xaml:42,53`），虽有名称，但不符合本项目导航按钮的无箭头约束。

**修复方向**：定义全局可见的高对比焦点样式并应用于按钮、导航、DataGrid；热力图改为可逐格访问的呈现或提供等价表格/摘要；日期导航改用带自动化名称的图标资源。

**验收标准**：仅用键盘可完成导航、日期切换、打开 Agent 菜单和表格选择；焦点在默认、暗色和高对比主题中始终可见。

### P2 — 页面状态模型不统一，加载与错误体验无法被系统性验证

**类别：状态设计 / MVVM**  
**证据**：未发现 Today、Trends、Privacy 的 `PageState (Empty | Loading | Ready | Error)`；Timeline 以分散的布尔可见性实现局部空/错态。Settings 仍由约 1630 行 ViewModel 同时承载应用设置、Agent 配置、维护与 UI 状态。

**修复方向**：为每个数据页建立统一的 PageState 与可恢复错误操作；将 Settings 按常规、记录、通知、外观和高级拆分为专用子 ViewModel/服务。

**验收标准**：每一页可演示 Empty、Loading、Ready、Error 四态；错误文案不暴露原始异常并提供重试或下一步操作。

### P2 — 页面标题在 Shell 与内容区重复，削弱紧凑桌面布局

**类别：信息密度 / Windows 桌面层级**  
**证据**：`MainWindow.xaml:344-350` 已在顶栏显示当前页面标题与副标题；`Views/TodayView.xaml:34-42` 又以相同层级显示“今天”和页面说明。

顶栏已经承担页面定位时，内容区再次使用完整页面标题会在有限高度内重复消耗一行信息空间，并与“顶栏标题 + 页面内容”的 Shell 规则相冲突。

**修复方向**：保留顶栏作为唯一页面标题；内容区从第一个数据模块或带具体行动含义的区段标题开始。若保留页面内标题，应去除顶栏的重复标题并重新定义 Shell 责任。

**验收标准**：每个页面的名称和通用说明只出现一次；1280×800 首屏能优先呈现一组可操作或可解释的数据内容。

### P2 — “数据与隐私”首屏直接呈现绝对路径，技术细节压过隐私承诺

**类别：隐私沟通 / 信息架构**  
**证据**：`Views/PrivacyView.xaml:83-96` 常显数据根目录、配置目录、数据库、日志和运行目录，绑定值可包含 Windows 用户名；相同路径也在 `SettingsView.xaml:390-403` 重复展示。

对普通用户而言，五条文件系统路径既不能解释“采集了什么、如何排除、如何删除”，也会在截图和屏幕共享中泄露本机账户线索。它们更适合高级诊断，而不是隐私页的主要内容。

**修复方向**：隐私页首屏只说明本地存储、排除规则、保留期限与可逆的数据操作；用“打开数据位置”代替常显路径，必要的路径信息放入默认收起的高级诊断，并在显示前脱敏用户名。

**验收标准**：默认界面不显示绝对用户路径；用户仍能通过清晰的按钮定位数据目录、查看存储说明和执行受确认保护的清理操作。

### P2 — 全量测试的完成时间不可预测，降低开发版验收的可靠性

**类别：测试质量 / 交付门槛**  
**证据**：本次 `dotnet test .\\QuantifiedSelf.Windows.sln --no-build` 在 60 秒执行窗口内未完成；仅 `DataFlowTests` 中已观察到 `MainWindowViewModel_HiddenStartupThenShowDoesNotReinitialize` 耗时 15 秒，且该筛选集同样未在窗口内结束。相反，新加的 `AdaptiveLayoutTests` 与 `TodayPageTests` 共 26 项在 0.503 秒内通过。

开发版 UI 需要反复进行构建、测试和多 DPI 验证。依赖真实时间等待或无法收敛的后台生命周期会让回归结果不稳定，也会拖慢设计迭代。

**修复方向**：为轮询/计时器注入可控时钟或等待策略，确保 ViewModel/服务在测试结束时停止后台活动；把慢集成测试与快速单元测试分组，并设置明确的超时。

**验收标准**：默认全量测试可在 CI 规定时限内稳定结束并给出汇总结果；核心 UI ViewModel 测试不依赖秒级真实等待。

## 建议实施顺序
