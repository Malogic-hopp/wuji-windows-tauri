# 下一步建议：阶段 7「数据清理 MVP」

既然阶段 6 已经完成配置闭环，下一步最自然就是之前后移出来的：

```text
阶段 7：PruneData / ClearHistory 数据清理 MVP
```

目标一句话：

```text
让用户能通过 Agent 安全清理历史数据，并且清理过程可观测、可恢复、可诊断。
```

这个阶段要非常谨慎，因为它第一次真正涉及“删除数据”。完整重构方案里也一直强调：WPF 不直接写采集数据、不直接删除 SQLite / JSONL，数据管理命令应由 Agent 执行，并通过 runtime / health / agent_events 保持可观测。

## 7.2 先做 Maintenance 状态骨架

第一步只做状态和事件，不做真实删除。

建议流程：

```text
收到 PruneData / ClearHistory
    ↓
CommandDetected
    ↓
CommandAccepted
    ↓
AgentActualState = Maintenance
    ↓
写 runtime_state / health_state
    ↓
模拟完成
    ↓
CommandCompleted
    ↓
恢复 Running 或 Paused
```

验收：

```text
Diagnostics 能看到 Maintenance
runtime_state 能看到 Maintenance
失败时能从 Maintenance 退出
不会卡死
```

先把“维护状态”跑稳，再做删除。

---

## 7.3 再做 PruneData MVP

`PruneData` 风险比 `ClearHistory` 小，应该先做。

建议语义：

```text
按 retentionDays 删除早于 cutoff 的历史数据
```

建议删除范围：

```text
foreground_samples:
    sample_time_utc < cutoff

app_sessions:
    ended_at_utc IS NOT NULL
    AND ended_at_utc < cutoff
    不删除 open session

agent_events:
    event_time_utc < cutoff

JSONL:
    删除早于 cutoff 日期的 agent_events_YYYYMMDD.jsonl
    如果已有 foreground_samples_YYYYMMDD.jsonl，也按同样规则处理
```

暂时不要做：

```text
VACUUM
压缩数据库
复杂按表选择清理
```

PruneData 应写事件：

```text
DataPruned
CommandCompleted
```

payload 只记录数量：

```json
{
  "foregroundSamplesDeleted": 1234,
  "sessionsDeleted": 56,
  "agentEventsDeleted": 20,
  "jsonlFilesDeleted": 3
}
```

不要记录具体窗口标题、路径、文件完整内容。

---

## 7.4 最后做 ClearHistory MVP

`ClearHistory` 风险最高，建议放到阶段 7 后半段。

我建议第一版 ClearHistory 采用更保守语义：

```text
ClearHistory 执行后 Agent 保持 Paused
```

原因是：如果清空后立即恢复 Running，Agent 很快又会写入新 sample，用户可能误以为没清干净。

建议流程：

```text
用户点击 清空所有历史数据
    ↓
第一次确认
    ↓
输入 CLEAR 二次确认
    ↓
WPF 发送 ClearHistory 命令
    ↓
Agent 进入 Maintenance
    ↓
关闭当前 session
    ↓
清空 foreground_samples / app_sessions / agent_events
    ↓
删除历史 JSONL
    ↓
重写 runtime_state / health_state
    ↓
写 HistoryCleared 事件
    ↓
进入 Paused
```

注意一个细节：如果清空了 `agent_events`，要在清空后重新写入一条 `HistoryCleared`，否则 Diagnostics 里看不到发生了什么。

# 阶段 7 必须坚持的边界

```text
WPF 不直接删除 SQLite
WPF 不直接删除 JSONL
WPF 不直接清空 runtime 目录
WPF 只发送 PruneData / ClearHistory 命令
Agent 负责 Maintenance / 删除 / 事件 / heartbeat
失败时必须退出 Maintenance
ClearHistory 必须二次确认
```

这一点非常重要。

---

# 阶段 7 验收标准建议

完成后至少满足：

```text
1. build 0 warning / 0 error
2. test 全部通过
3. PruneData 只能由 Agent 执行
4. ClearHistory 只能由 Agent 执行
5. 清理期间 runtime_state = Maintenance
6. 清理成功写 DataPruned / HistoryCleared
7. 清理失败写 CommandFailed，且不泄露路径
8. PruneData 不删除 open session
9. PruneData 不删除 retentionDays 内数据
10. ClearHistory 后 Samples / Sessions / Apps 显示空态
11. ClearHistory 后 runtime_state / health_state 仍可读
12. ClearHistory 后 Agent 保持 Paused，用户手动 Resume
13. Dashboard / Diagnostics / Settings 不崩溃
```

# 阶段 7 之后再做什么

阶段 7 完成后，我建议再进入：

```text

```

原因是到那时 WUJI 已经具备：

```text

诊断
数据浏览
配置应用

```

这些产品主链路都完整了，再升级控制通道就很合适。现在文件 fallback 已经支撑到这个阶段，但进入托盘、开机自启、长期常驻之前，确实应该把 IPC 做稳。
