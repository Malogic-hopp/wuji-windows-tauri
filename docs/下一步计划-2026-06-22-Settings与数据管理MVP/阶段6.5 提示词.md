实施要求：

1. WPF Settings 页新增 ReloadConfig 入口，但只在 Agent 运行或暂停时可用。
2. Agent NotRunning / Stopped 时：
   - ReloadConfig 不可用
   - UI 明确提示“配置已保存，将在下次 Agent 启动时生效”
3. 推荐提供两个动作：
   - Save Agent Options：只保存文件，不 Reload
   - Save and Reload：先保存文件，再发送 ReloadConfig
   如果当前结构更适合，也可以提供独立 Reload Config 按钮；但 UI 文案必须清楚区分“已保存”与“已应用”。
4. ReloadConfig 命令必须走现有 `AgentControlService` / control file 机制，不要绕开 Agent。
5. ReloadConfig 前必须确保当前 Agent Options 草稿合法；如果 Save and Reload，则先保存并备份，再发送 ReloadConfig。
6. Agent 端处理 ReloadConfig 时，必须复用 `AgentOptionsValidator` 校验读取到的新 `windows-agent.json`。
7. 如果 Agent 端 ReloadConfig 校验失败：
   - 不替换当前运行中的 `_options`
   - 写入 `CommandFailed`
   - errorCode 建议使用 `ReloadConfigValidationFailed`
   - payload/message 不泄露路径或敏感配置内容
8. 如果 Agent 端 ReloadConfig 读取 JSON 失败或文件无效：
   - 不替换当前运行中的 `_options`
   - 写入 `CommandFailed`
   - errorCode 建议使用 `ReloadConfigReadFailed` 或等价明确阶段码
   - 错误消息要走已有安全格式化/脱敏方式
9. ReloadConfig 成功后：
   - Agent 替换运行中的 `_options` 为 Validator 归一化后的 options
   - 写入 `ConfigReloaded`
   - 保持当前运行状态语义：Running 仍 Running，Paused 仍 Paused
   - WPF 显示“配置已应用”
10. Save / Restore Backup 仍然不自动 Reload，除非用户明确点击 Save and Reload 或 Reload Config。
11. Restore Backup 后如果用户点击 ReloadConfig，应应用恢复后的文件。
12. 不要实现 PruneData / ClearHistory。
13. 不要引入 `windows-agent.pending.json`。
14. 不要新增托盘、主题假入口。
