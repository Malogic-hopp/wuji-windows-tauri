# 阶段 13.1：DailyStatsService 与今日聚合

## 阶段目标

新增只读统计服务，把已有原始数据聚合成“今日活动摘要”，为 Dashboard 洞察、趋势和建议提供稳定数据基础。

一句话目标：

```text
先让系统能可靠回答“今天时间花到哪里了”。
```

## 实施范围

建议新增或扩展：

```text
DailyStatsService
DailyActivitySummary
DailyAppUsageSummary
DailyWindowUsageSummary
```

优先聚合：

```text
TotalActiveDuration
FirstSeenAt
LastSeenAt
SessionCount
SampleCount
TopApps
TopWindows
```

数据来源优先级：

```text
1. app_sessions：应用时长、session 数量、开始/结束时间。
2. foreground_samples：窗口标题、样本数、细粒度补充。
```

## 行为要求

```text
1. DailyStatsService 必须是只读服务，不写 SQLite。
2. 统计逻辑不得放进 ViewModel。
3. 日期边界使用本地日期展示语义，但查询时要明确 UTC / Local 转换策略。
4. TopApps 必须有稳定排序：时长降序，其次名称升序。
5. TopWindows / Titles 必须遵守现有隐私过滤策略，不显示敏感原文。
6. 没有数据时返回空摘要，不抛未处理异常。
7. 查询错误返回安全错误，不泄露完整本机路径、SQL、原始异常堆栈。
8. 不新增 Agent 写入逻辑。
9. 不引入缓存表，除非现有查询性能无法接受且有测试证明。
10. 不改变 Dashboard 现有 UI，本阶段只提供服务和测试。
```

## 验收标准

```text
1. build/test 通过，0 warnings / 0 errors。
2. DailyStatsService 可返回今日摘要。
3. 空数据库或无今日数据时返回空摘要。
4. TopApps / TopWindows 排序稳定。
5. 隐私过滤后的标题展示安全。
6. 统计服务不触发 Agent 状态刷新，不触发页面状态写入。
```

## 建议测试

```text
DailyStatsService_ReturnsEmptySummaryWhenNoData
DailyStatsService_ComputesTodayTotalActiveDuration
DailyStatsService_ComputesTopAppsFromSessions
DailyStatsService_ComputesTopWindowsFromSamples
DailyStatsService_UsesStableOrdering
DailyStatsService_RedactsSensitiveTitles
DailyStatsService_DoesNotWriteDatabase
```

## 不做什么

```text
不改 Dashboard 布局
不做 7 天趋势
不做 focus session
不做建议文案
不做复杂图表
不新增 Agent 写入表
不改 RefreshService
```
