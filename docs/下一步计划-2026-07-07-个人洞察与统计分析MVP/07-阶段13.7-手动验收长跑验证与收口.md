# 阶段 13.7：手动验收、长跑验证与收口

## 阶段目标

对阶段 13 的统计、趋势、建议和 UI 展示做完整验收，确认 WUJI 已经能提供稳定、可信、可行动的个人洞察。

## 自动化验收

完成后应满足：

```text
1. build 0 warning / 0 error。
2. test 全部通过。
3. DailyStatsService 测试覆盖空数据、今日数据、排序、隐私过滤。
4. Focus / Context Switch 测试覆盖 gap、idle、切换频繁。
5. 7 天趋势测试覆盖缺失日期、平均值、今日比较。
6. Insight Suggestions 测试覆盖生成、限制数量、数据不足。
7. Dashboard 测试覆盖刷新路径和 status polling 不触发重查询。
8. 阶段 12 发布脚本不回归。
9. 阶段 11 开机自启不回归。
10. 阶段 10 托盘不回归。
11. 阶段 9 RefreshService 不回归。
```

建议命令：

```powershell
dotnet build QuantifiedSelf.Windows.sln --no-restore -p:BaseOutputPath=.codex/build-output/
dotnet test QuantifiedSelf.Windows.sln --no-restore -p:BaseOutputPath=.codex/test-output/
powershell -NoProfile -ExecutionPolicy Bypass -File .\publish\scripts\publish.ps1
```

测试后清理 `.codex` 输出目录。

## 手动验收

建议至少验证：

```text
1. 启动 App 后 Dashboard 正常显示。
2. 启动 Agent 后等待一段时间，今日活跃时长会更新。
3. Top Apps 与 Apps 页面大致一致。
4. Top Windows / Titles 不显示敏感原文。
5. 点击 Refresh 后 Today Insight 更新。
6. 2 秒 status polling 时 Dashboard 不频繁卡顿。
7. Sessions / Samples / Apps 切换不影响顶部 Agent 状态。
8. 今日无数据时显示空状态。
9. 查询失败时 Dashboard 不崩溃，旧数据不被清空。
10. 最长专注段显示合理。
11. 上下文切换次数显示合理。
12. 7 天趋势包含最近 7 个本地日期。
13. 缺失日期显示为 0 或明确空值。
14. 今日 vs 7 天平均文案不误导。
15. 高切换场景能生成温和建议。
16. 数据不足时不生成硬凑建议。
17. 建议显示依据和行动。
18. 建议不使用负面羞辱表达。
19. Settings dirty 状态下 status polling 不覆盖配置草稿。
20. 托盘隐藏 / Show 后 Dashboard 仍能刷新。
21. release exe 中统计功能可用。
```

## 长跑验证

建议做：

```text
1. 后台运行 30-60 分钟，Dashboard 数据持续更新。
2. 托盘隐藏 15-30 分钟后 Show，Today Insight 正常。
3. Pause / Resume 后统计不出现明显异常。
4. Stop / Start Agent 后统计可恢复。
5. 跨本地日期边界前后，今日统计切换合理。
6. release exe 运行 15-30 分钟，Agent 和 Dashboard 正常。
```

## 风险复核

收口前需要确认：

```text
1. 统计查询不会明显卡 UI。
2. status polling 不被统计查询阻塞。
3. 页面刷新失败不会清空旧洞察。
4. 隐私过滤没有回归。
5. 建议文案不产生心理压力或负面评价。
6. 统计日期边界清晰。
7. release exe 运行正常。
8. 不新增 Agent 写入竞争。
9. 不引入联网依赖。
10. 不破坏阶段 8-12 已完成能力。
```
