## 架构原则

### 1. 当前用户级自启，不做系统服务

阶段 11 MVP 使用当前用户范围：

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
```

目标：

```text
不需要管理员权限
不影响其他 Windows 用户
容易启用和禁用
容易手动排查
适合桌面 App MVP
```

不要在本阶段引入：

```text
Windows Service
HKLM Run Key
计划任务高级配置
管理员权限写入
安装器写注册表
```

### 2. App 自启和 Agent 自启严格分开

建议新增 AppSettings 字段：

```text
StartAppOnWindowsLogin: bool
```

现有字段继续保留：

```text
AutoStartAgentWhenAppStarts: bool
```

语义必须是：

```text
StartAppOnWindowsLogin=false:
    Windows 登录后不自动启动 WPF App。

StartAppOnWindowsLogin=true:
    Windows 登录后自动启动 WPF App。

AutoStartAgentWhenAppStarts=false:
    WPF App 启动后不自动启动 Agent。

AutoStartAgentWhenAppStarts=true:
    WPF App 启动后按现有逻辑自动启动 Agent。
```

组合示例：

```text
StartAppOnWindowsLogin=true
AutoStartAgentWhenAppStarts=false
    登录后 WUJI 进托盘，但不启动 Agent。

StartAppOnWindowsLogin=true
AutoStartAgentWhenAppStarts=true
    登录后 WUJI 进托盘，并启动 Agent。

StartAppOnWindowsLogin=false
AutoStartAgentWhenAppStarts=true
    用户手动打开 WUJI 时启动 Agent。
```

### 3. StartupRegistrationService 管 OS 状态

建议新增服务：

```text
StartupRegistrationService
```

负责：

```text
读取 HKCU Run Key
注册当前 App 自启
取消当前 App 自启
检测注册项是否指向当前 App
检测参数是否包含自启启动参数
返回 StartupRegistrationStatus
脱敏错误文案
```

不负责：

```text
启动 Agent
停止 Agent
创建托盘图标
刷新页面数据
读写 SQLite
修改 AgentStateMachine
弹 UI 对话框
```

### 4. 注册项必须可安全更新和删除

Run Key 建议使用固定 value name：

```text
WUJI
```

注册 command 建议形态：

```text
"<current app executable path>" --from-autostart --start-hidden
```

要求：

```text
可执行路径必须加引号。
参数必须可解析。
当前 App 可执行路径必须由 StartupCommandBuilder 或等价组件集中解析。
优先使用 Environment.ProcessPath / Process.MainModule.FileName 等运行时入口路径。
如果检测到当前路径不是 WUJI App .exe，例如 dotnet.exe、dll、空路径或无法确认的 host 路径，不得注册 Run Key，应返回 Error / UnsupportedInCurrentLaunchMode。
重复启用应幂等。
禁用只删除 WUJI 自己的 value，不碰其他 Run Key。
如果 value 存在但命令不匹配当前 App，应显示 Mismatch / Needs repair。
如果禁用时 value 不存在，应视为成功。
```

Run Key command 比较不能只做简单字符串完全相等。MVP 至少要求：

```text
解析 registered command。
规范化 exe 路径后比较是否指向当前 WUJI App。
必须包含 --from-autostart。
必须包含 --start-hidden。
引号、大小写和多余空格不应造成误判。
未知额外参数可以忽略或判为 Mismatch，但必须在实现说明中明确。
```

### 5. 自启启动默认进入托盘

手动启动和登录自启行为应不同：

```text
手动启动:
    显示主窗口。

--from-autostart --start-hidden:
    创建 MainWindowViewModel。
    创建 TrayService。
    启动 status polling。
    不显示主窗口，或显示后立即无闪烁隐藏。
    托盘图标可见。
    用户可通过托盘 Show Main Window 打开窗口。
```

要求：

```text
登录自启不弹主窗口打扰用户。
隐藏到托盘不停止 status polling。
隐藏到托盘不 Dispose TrayService。
Exit App 语义保持阶段 10 现状。
--from-autostart --start-hidden 不应通过触发 Window.Closing / CloseToTray 来隐藏窗口。
应在启动流程中根据 StartupLaunchOptions 直接决定是否调用 window.Show()。
AutoStartHidden 模式下，启动期错误不得弹 MessageBox 阻塞用户登录流程，应进入安全状态文本 / Diagnostics / 日志。
```

### 6. Settings Save 应处理注册失败

Settings 保存 App Settings 时，如果用户改变 StartAppOnWindowsLogin，应同步 OS 注册状态。

推荐 MVP 语义：

```text
启用:
    先尝试注册 HKCU Run Key。
    注册成功后再保存 AppSettings。
    注册失败则不宣称启用成功，显示安全错误。

禁用:
    先尝试删除 HKCU Run Key。
    删除成功后再保存 AppSettings。
    删除失败则不宣称禁用成功，显示安全错误。
```

如果现有保存流程难以做到严格事务，至少必须满足：

```text
StartAppOnWindowsLogin 的 UI 开关值是用户草稿。
StartupRegistrationStatus 是 OS 真实注册状态。
保存失败时 AppSettings 不应写成 true 并显示已启用。
SaveStatusText 明确说明注册失败。
StartupRegistrationStatus 不显示 Enabled。
下次 Refresh 能检测到 mismatch。
不得让 UI 显示“已启用”但 OS 实际未注册而完全无提示。
```

Settings dirty 规则：

```text
Settings IsDirty=true 时，status polling / diagnostics refresh 可以更新只读 StartupRegistrationStatusText。
Settings IsDirty=true 时，不得覆盖 StartAppOnWindowsLogin 草稿值。
Settings IsDirty=true 时，不得因为后台刷新触发注册表写入或删除。
Refresh 只能重新读取 OS 状态并更新只读提示，不能提交用户草稿。
```

### 7. Diagnostics 展示状态但不泄露敏感信息

Diagnostics / Settings 可以展示：

```text
Login startup: Enabled
Login startup: Disabled
Login startup: Mismatch
Login startup: Error
Startup launch mode: Manual / AutoStart
```

不要展示：

```text
完整本机路径
完整注册表异常原文
完整命令行
SID
用户名目录
```

可以展示安全摘要：

```text
Registered to current app
Registered command needs repair
Registration unavailable
Registered command points to a different app location
Required startup arguments are missing
```

### 8. 多实例问题先保守处理

开机自启会增加重复启动概率。阶段 11 至少要明确策略：

```text
如果已有单实例机制:
    复用它。

如果没有单实例机制:
    不在 11.1 就大改应用生命周期。
    在阶段 11.4 / 11.6 至少通过手动验收确认自启不会导致明显重复窗口。
    如果出现两个托盘图标、两个 status polling 或状态漂移，必须记录为阶段 12 前置风险，或在阶段 11.x 中以最小 named mutex 修复。
    可把轻量 single-instance guard 作为本阶段后半段候选，但不得影响自启主线。
```

建议后续增强：

```text
当前用户 named mutex
第二实例通知第一实例 Show
第二实例安全退出
```

但这不是阶段 11.1 的前置阻塞。

# 阶段 11.2：StartupRegistrationService 与 HKCU Run Key

## 阶段目标

新增用户级自启注册服务，能注册、取消注册、读取和检测当前 WUJI 自启状态。

## 行为要求

```text
StartupRegistrationService:
    RegisterAsync()
    UnregisterAsync()
    GetStatusAsync()

注册位置:
    HKCU\Software\Microsoft\Windows\CurrentVersion\Run

value name:
    WUJI

command:
    "<current app executable path>" --from-autostart --start-hidden
```

路径和命令构建：

```text
StartupCommandBuilder 必须集中封装 App 可执行路径解析。
如果当前运行入口是 dotnet.exe / dll / 空路径 / 非 WUJI App exe，不得注册 Run Key。
路径无效时 RegisterAsync 返回安全 Error / UnsupportedInCurrentLaunchMode。
GetStatusAsync 对已有 command 做规范化解析，不用简单字符串完全相等判断。
```

状态建议：

```text
Disabled:
    WUJI value 不存在。

Enabled:
    WUJI value 存在，且命令指向当前 App，并包含预期参数。

Mismatch:
    WUJI value 存在，但命令不指向当前 App 或参数不匹配。

Error:
    读取或写入注册表失败。
```

安全要求：

```text
错误文案必须脱敏。
不显示完整路径。
不显示注册表异常原文。
不显示 SID / 用户目录。
```

实现要求：

```text
通过 IStartupRegistry 或等价 adapter 抽象注册表，单元测试不写真实注册表。
生产实现只写 HKCU，不请求管理员权限。
Register / Unregister 幂等。
Unregister 只删除 WUJI 自己的 value。
Register 发现可执行路径无效时不得写入任何 Run Key。
```

## 验收标准

- build/test 通过。
- Register 写入正确 value name 和 command。
- Unregister 删除正确 value name。
- 重复 Register 不产生异常。
- 重复 Unregister 不产生异常。
- GetStatus 能区分 Disabled / Enabled / Mismatch / Error。
- 命令比较能处理引号、大小写、空格和必要参数。
- 当前可执行路径无效时不注册错误路径。
- 错误文案安全。

## 建议测试

```text
StartupRegistrationService_RegisterWritesRunKeyCommand
StartupRegistrationService_UnregisterDeletesRunKeyValue
StartupRegistrationService_RegisterIsIdempotent
StartupRegistrationService_UnregisterIsIdempotent
StartupRegistrationService_StatusDisabledWhenValueMissing
StartupRegistrationService_StatusEnabledWhenCommandMatches
StartupRegistrationService_StatusMismatchWhenCommandDiffers
StartupRegistrationService_RedactsRegistryErrors
StartupCommandBuilder_QuotesExecutablePath
StartupCommandBuilder_IncludesAutostartHiddenArgs
StartupCommandBuilder_RejectsDotnetHostPath
StartupCommandBuilder_UsesCurrentAppExePath
StartupRegistrationService_DoesNotRegisterWhenExecutablePathInvalid
StartupRegistrationService_NormalizesCommandBeforeComparing
```

## 不做什么

- 不写 HKLM。
- 不做计划任务。
- 不做 Startup 文件夹快捷方式。
- 不启动 Agent。
- 不改 App 启动流程。

# 阶段 11.3：Settings 自启开关与保存同步

## 阶段目标

在 Settings 中暴露登录自启开关，并把保存操作同步到 StartupRegistrationService。

## 行为要求

Settings App Settings 区域新增：

```text
startAppOnWindowsLogin
Startup registration status
```

UI 语义：

```text
StartAppOnWindowsLogin:
    控制 WPF App 是否登录后自动启动。

AutoStartAgentWhenAppStarts:
    控制 WPF App 启动后是否自动启动 Agent。
```

保存语义：

```text
用户开启 StartAppOnWindowsLogin:
    注册 HKCU Run Key。
    注册成功后保存 AppSettings。
    注册失败时显示安全错误，不宣称启用成功。

用户关闭 StartAppOnWindowsLogin:
    删除 HKCU Run Key。
    删除成功后保存 AppSettings。
    删除失败时显示安全错误，不宣称禁用成功。
```

刷新语义：

```text
Settings Refresh 时读取 StartupRegistrationStatus。
Settings IsDirty=true 时不覆盖正在编辑的开关草稿。
但可以更新只读注册状态文本，前提是不覆盖草稿。
Settings IsDirty=true 时不得触发注册表写入或删除。
AppSettings=true 但 OS Run Key 缺失时，应显示 Mismatch / Disabled with warning，不得静默改 UI 草稿。
```

## 验收标准

- Settings 显示两个独立开关。
- Save App Settings 能启用自启注册。
- Save App Settings 能禁用自启注册。
- 注册失败时显示安全错误。
- 注册 mismatch 时显示 Needs repair / Mismatch。
- Settings dirty 不被状态刷新覆盖。
- AppSettings 与 OS 注册状态不一致时有明确提示。
- AutoStartAgentWhenAppStarts 保存不回归。

## 建议测试

```text
SettingsViewModel_LoadsStartAppOnWindowsLogin
SettingsViewModel_SavesLoginStartupAndRegistersRunKey
SettingsViewModel_DisablesLoginStartupAndUnregistersRunKey
SettingsViewModel_StartupRegistrationFailureShowsSafeError
SettingsViewModel_ShowsStartupMismatchStatus
SettingsViewModel_LoginStartupDirtyDraftNotOverwritten
SettingsViewModel_DirtyRefreshDoesNotWriteStartupRegistry
SettingsViewModel_ShowsWarningWhenAppSettingsEnabledButRunKeyMissing
SettingsViewModel_AutoStartAgentSettingRemainsIndependent
```

## 不做什么

- 不直接从 Settings 启动或停止 Agent。
- 不改变 ReloadConfig。
- 不改变 PruneData / ClearHistory。
- 不新增管理员权限提示。

# 阶段 11.4：登录自启启动到托盘

## 阶段目标

让 App 通过自启参数启动时默认隐藏到托盘，并继续运行阶段 10 的托盘和状态刷新链路。

## 行为要求

启动参数：

```text
--from-autostart
--start-hidden
```

手动启动：

```text
没有 --from-autostart:
    window.Show()
    保持现有行为。
```

自启启动：

```text
有 --from-autostart 和 --start-hidden:
    创建 MainWindow / ViewModel / TrayService。
    启动 status polling。
    直接不调用 window.Show()，或通过启动策略确保无闪烁隐藏。
    托盘图标可见。
    托盘 Show Main Window 可恢复窗口。
    不通过 Window.Closing / CloseToTray 模拟隐藏。
```

Agent 自启：

```text
如果 AutoStartAgentWhenAppStarts=false:
    不自动启动 Agent。

如果 AutoStartAgentWhenAppStarts=true:
    按既有 App 启动流程启动 Agent。
```

安全要求：

```text
自启启动失败不写敏感路径到 UI。
自启模式不弹出阻塞式错误对话框。
自启模式启动期错误写入安全状态文本 / Diagnostics / 日志。
自启模式不改变 Exit App 语义。
```

## 验收标准

- 手动启动仍显示主窗口。
- 自启参数启动时默认隐藏到托盘。
- 自启参数启动后 status polling 正常。
- 托盘 Show 可恢复主窗口。
- AutoStartAgentWhenAppStarts=false 时不启动 Agent。
- AutoStartAgentWhenAppStarts=true 时启动 Agent。
- CloseToTray / MinimizeToTray / Exit App 不回归。

## 建议测试

```text
AppStartup_ManualLaunchShowsMainWindow
AppStartup_AutostartHiddenDoesNotShowMainWindow
AppStartup_AutostartHiddenCreatesTray
AppStartup_AutostartHiddenStartsStatusPolling
AppStartup_AutostartRespectsAutoStartAgentFalse
AppStartup_AutostartRespectsAutoStartAgentTrue
TrayService_ShowRestoresAutostartHiddenWindow
```

如果直接测试 `App.xaml.cs` 困难，可先抽出可测试协调器：

```text
AppStartupCoordinator
WindowStartupPolicy
```

阶段 11.4 优先对 `AppStartupCoordinator` / `WindowStartupPolicy` 做纯逻辑测试；不要为了自动化覆盖真实 WPF startup 而引入脆弱 UI 测试。真实托盘启动到隐藏状态留给手动验收覆盖。

## 不做什么

- 不做安装包启动入口。
- 不做 Windows Service。
- 不做复杂 single-instance 激活。
- 不改变托盘命令。

# 阶段 11.5：Diagnostics 自启状态与错误展示

## 阶段目标

让 Diagnostics 能解释登录自启当前是否启用、是否 mismatch、最近是否出现注册错误。

## 建议展示

```text
Login startup
    Enabled / Disabled / Mismatch / Error

Launch mode
    Manual / AutoStart

Startup registration
    Registered to current app / Needs repair / Not registered / Unavailable

Last startup registration error
    安全短句
```

Settings 中也可保留简短状态：

```text
Startup registration status: Enabled
```

安全要求：

```text
不展示完整 exe 路径。
不展示完整 Run Key command。
不展示 SID。
不展示用户名目录。
不展示注册表异常原文。
不展示 stack trace。
```

## 验收标准

- Diagnostics 显示登录自启 Enabled / Disabled。
- Mismatch 能显示安全修复提示。
- Error 能显示安全错误。
- LaunchMode 能显示 Manual / AutoStart。
- 不影响 RefreshHealth / IPC / Recent Events。
- 不新增高频日志。

## 建议测试

```text
Diagnostics_ShowsLoginStartupEnabled
Diagnostics_ShowsLoginStartupDisabled
Diagnostics_ShowsLoginStartupMismatch
Diagnostics_RedactsStartupRegistrationError
Diagnostics_ShowsLaunchModeManual
Diagnostics_ShowsLaunchModeAutoStart
Diagnostics_KeepsRefreshHealthVisible
```

## 不做什么

- 不把自启状态写入 agent_events。
- 不写 JSONL。
- 不做通知中心。
- 不显示完整注册表命令。

## 风险与对策

### App 自启和 Agent 自启混淆

风险：

```text
用户以为开启“登录后启动 WUJI”就一定启动 Agent，或以为 AutoStartAgentWhenAppStarts 会注册 Windows 自启。
```

对策：

```text
Settings 文案明确区分两个开关。
字段命名明确区分 StartAppOnWindowsLogin 与 AutoStartAgentWhenAppStarts。
测试覆盖两个开关四种组合。
完成说明中记录组合语义。
```

### 注册表写入失败导致 UI 假启用

风险：

```text
AppSettings 保存为 true，但 HKCU Run Key 没写成功。
```

对策：

```text
保存时先注册再保存。
注册失败显示安全错误。
StartupRegistrationStatus 显示 Error / Mismatch。
Refresh 能重新检测 OS 状态。
```

### 路径变化导致自启失效

风险：

```text
Debug / Release / 发布路径变化后，Run Key 仍指向旧路径。
```

对策：

```text
GetStatus 检测 command 是否指向当前 App。
Mismatch 显示 Needs repair。
保存时重写当前路径。
不在 UI 展示完整旧路径。
```

### 当前 App 路径解析错误

风险：

```text
使用 Assembly.Location 或错误的 ProcessPath，导致 Run Key 注册为 dotnet.exe、dll 或空路径。
```

对策：

```text
StartupCommandBuilder 集中解析当前 App exe 路径。
检测 dotnet.exe / dll / 空路径 / 非 WUJI App exe 时返回 UnsupportedInCurrentLaunchMode。
路径无效时 Register 不写 Run Key。
测试覆盖 RejectsDotnetHostPath / DoesNotRegisterWhenExecutablePathInvalid。
```

### 自启后弹主窗口打扰用户

风险：

```text
Windows 登录后 App 主窗口弹出，破坏托盘常驻体验。
```

对策：

```text
Run Key 带 --from-autostart --start-hidden。
AppStartupCoordinator 区分 Manual / AutoStart。
自启模式默认隐藏到托盘。
自启隐藏由启动策略决定，不触发 Window.Closing / CloseToTray。
AutoStartHidden 模式下不弹阻塞式 MessageBox。
手动验收覆盖无主窗口弹出。
```

### 禁用自启后注册项残留

风险：

```text
用户关闭设置，但 Run Key 仍存在。
```

对策：

```text
Unregister 幂等删除 WUJI value。
禁用后立即读取状态确认 Disabled。
手动验收检查 HKCU Run Key。
```

### 误删其他程序 Run Key

风险：

```text
Unregister 删除了不属于 WUJI 的注册项。
```

对策：

```text
只操作固定 value name WUJI。
不枚举删除其他 value。
测试验证 DeleteValue 参数。
```

### 注册表异常泄露本机信息

风险：

```text
错误文案包含完整路径、用户名、SID 或异常堆栈。
```

对策：

```text
统一 sanitizer。
StartupRegistrationStatus 只暴露安全短句。
Diagnostics 和 Settings 都使用安全文本。
测试断言不含路径分隔符、SID 片段、完整 command。
```

### 多实例体验

风险：

```text
登录自启和用户手动启动叠加，出现多个 App 实例或多个托盘图标。
```

对策：

```text
阶段 11 至少记录和手动验证。
11.6 手动验收必须覆盖重复启动行为。
如果出现双托盘图标或状态漂移，记录为阶段 12 前置风险，或以最小 named mutex 修复。
如果实现轻量 single-instance guard，必须单独小步提交并测试。
不要为了 single-instance 大改 IPC 或托盘主线。
```
