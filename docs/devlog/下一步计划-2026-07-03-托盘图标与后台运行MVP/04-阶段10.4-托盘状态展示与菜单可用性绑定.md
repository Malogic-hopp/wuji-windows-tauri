# 阶段 10.4：托盘状态展示与菜单可用性绑定

## 阶段目标

让托盘 tooltip 和菜单可用性跟随阶段 9 的 `AgentStatusSnapshot` / `AgentCommandAvailability`。

## 行为要求

托盘 tooltip 显示：

```text
WUJI
Agent: Running / Paused / NotRunning / Stale / Maintenance
IPC: NamedPipe / FileFallback / unavailable 简短状态
```

托盘菜单可用性：

```text
Start / Pause / Resume / Stop 与 MainWindow 一致
Maintenance 时控制项禁用
Stale + IsRunning=false 时 Start 可用
Stale + IsRunning=true 时 Stop 可用，Start 不可用
```

## TrayMenuState

建议先做纯模型，再接真实 `NotifyIcon`：

```text
TrayMenuState:
    TooltipText
    CanStart
    CanPause
    CanResume
    CanStop
    IsMaintenance
    IpcStatusText
    SafeStatusText

TrayMenuState.From(status, availability, ipcStatus):
    使用 AgentCommandAvailability
    不单独写一套状态规则
    不显示 FullPipeName / SID / 路径
```

TrayService 只负责把 `TrayMenuState` 渲染到 `NotifyIcon / ContextMenu`。

## 硬约束

```text
托盘不新增状态轮询。
托盘状态必须复用阶段 9 的 status polling。
托盘菜单状态必须来源于 AgentCommandAvailability。
托盘不直接读 runtime_state / health_state。
托盘不直接查询 SQLite。
```

## 建议测试

```text
TrayMenuState_FollowsRunningStatus
TrayMenuState_FollowsPausedStatus
TrayMenuState_DisablesCommandsDuringMaintenance
TrayMenuState_AllowsStartWhenStaleButProcessGone
TrayMenuState_StaysConsistentWithAgentCommandAvailability
TrayMenuState_DoesNotExposeSensitiveIpcDetails
MainWindowViewModel_StatusUpdateRefreshesTrayMenuState
```

## 验收标准

```text
MainWindow 和托盘菜单状态不漂移。
2 秒 status polling 后托盘 tooltip 自动更新。
Stop / Start / Pause / Resume 后 tooltip 和菜单快速恢复。
Settings dirty 不影响托盘状态更新。
不新增托盘专用状态轮询。
不显示完整 pipe name / SID / 本机路径。
```

## 不做什么

```text
不做复杂托盘通知
不直接查询 SQLite
不显示完整 pipe name / SID / 本机路径
不做真正状态流
```
