# 建议补强 1：优先复用 `MainWindowViewModel` command，但避免 UI 线程阻塞

建议补一句：

```text
如果托盘命令复用 MainWindowViewModel 的 ICommand，必须通过 Dispatcher 在 UI 线程执行；异步命令不得阻塞托盘回调或 UI 线程。
```

托盘菜单回调来自 WinForms `ContextMenuStrip`，要注意线程和 async。

---

# 建议补强 2：明确命令执行期间可以临时禁用对应菜单项

阶段 10.5 里，如果用户连续快速点击 Pause / Resume / Stop，可能重复发命令。建议补一句：

```text
命令执行中应避免重复触发同一命令；可以复用 MainWindowViewModel 的 IsBusy / command CanExecute，也可以在 TrayCommandBridge 内做轻量 in-flight guard。
```

这不是要新增复杂状态机，只是防重复点击。

---

# 建议补强 3：托盘错误提示第一版可以只写安全 StatusMessage / tooltip

你写了“错误可通过 tooltip 安全短句或轻量通知展示”，但 10.6 才是异常提示阶段。建议 10.5 固定为：

```text

```

避免 agent 提前实现 10.6 的通知逻辑。

---

# 建议补强 4：命令执行后“立即刷新状态”不要破坏 latest-wins

你写了可以触发一次轻量 status refresh，这合理。但要明确：

```text
如果命令执行后触发一次 RefreshStatusOnlyAsync / PerformStatusPollAsync，必须继续遵守阶段 9 latest-wins；旧结果不得覆盖新状态。
```

否则托盘命令后立即刷新可能引入阶段 9 已经修过的竞态。

# 建议补强 5：如果使用 TrayCommandBridge，明确它是薄桥

建议补一句：

```text
TrayCommandBridge 只能做可用性检查、调用现有命令/服务、记录安全错误和触发状态刷新；不得持久化状态，不得读写文件，不得自己判断 Agent 状态规则。
```

防止 `TrayCommandBridge` 膨胀成第二个控制中心。
