# 阶段 10.4 完成说明（2026-07-03）

Build: `0 warnings / 0 errors` | Test: `251 / 251 passed`（244 原有 + 7 新增）

## 阶段目标回顾

托盘 tooltip 和菜单可用性跟随阶段 9 的 `AgentStatusSnapshot` / `AgentCommandAvailability`，确保 MainWindow、Settings 和托盘菜单状态不漂移。

本阶段只实现状态展示和菜单可用性绑定，不实现托盘 Start / Pause / Resume / Stop 命令执行。

## 最终实现概览

- `TrayMenuState` 扩展为托盘状态纯模型，包含 tooltip、安全状态文本、IPC 安全文案、菜单可用性和 Maintenance 标记。
- `TrayMenuState.From(status, availability, ipcSource)` 复用 `AgentCommandAvailability` 推导 Start / Pause / Resume / Stop 可用性，不单独写一套规则。
- `NotifyIconTrayIconAdapter` 新增 Start / Pause / Resume / Stop 菜单项，使用稳定 key 更新菜单 enabled 状态。
- `TrayService` 实现 `ITrayStateSink`，负责把 `TrayMenuState` 渲染到 NotifyIcon / ContextMenu，并通过 Dispatcher 安全切回 UI 线程。
- `MainWindowViewModel` 依赖 `ITrayStateSink?`，在已应用状态后生成 `TrayMenuState` 并调用 `UpdateState`。
- 生产启动路径中，`App.xaml.cs` 创建 `TrayService` 后赋给 `viewModel.TrayStateSink`。

## 状态更新路径

最终状态同步路径：

```text
RefreshService / Status polling / RefreshAsync
→ MainWindowViewModel.ApplyStatusRefreshResult 或 RefreshWithServiceAsync
→ latest-wins 通过
→ RefreshCommonStatus(status, processInfo)
→ AgentCommandAvailability.FromStatus(status)
→ TrayMenuState.From(status, availability, safeIpcSource)
→ ITrayStateSink.UpdateState(trayState)
→ TrayService
→ NotifyIconTrayIconAdapter.UpdateMenuState
```

托盘不新增专用轮询，复用阶段 9 的 2 秒 status polling 和现有 refresh 路径。

## 安全与边界

- tooltip 不显示 `FullPipeName`、SID、本机路径、SQL、异常原文或原始 JSON。
- IPC 文案只显示 `NamedPipe` / `FileFallback` / `unavailable`。
- 菜单项 enabled 使用稳定 key，不依赖菜单显示文本查找。
- Start / Pause / Resume / Stop 菜单项本阶段只显示可用性，不绑定命令执行。
- 本阶段不调用 `AgentControlService` / `AgentProcessService` 执行托盘控制命令。
- 本阶段不写 `agent_control.json`。

### 第一次审核修复（2026-07-03）

审核发现 3 个问题：

1. `TrayService.UpdateMenuState` 直接调用 adapter，没有 Dispatcher / disposed / shutdown 保护。
2. adapter 未同步 `CanShowMainWindow` / `CanExitApp` 到 `show` / `exit` 菜单项。
3. 缺少 ViewModel 真实路径测试。

修复内容：

1. `TrayService.UpdateMenuState` 包裹 `TryPostToDispatcher`，增加 `CheckAccess`、disposed guard 和 Dispatcher shutdown 检查。
2. `NotifyIconTrayIconAdapter.UpdateMenuState` 补充 `show` / `exit` 的 `SetMenuItemEnabled`。
3. `FakeTrayIconAdapter.UpdateMenuState` 同步补充 `show` / `exit`。
4. 新增 `MainWindowViewModel_RefreshUpdatesTrayMenuState` 尝试覆盖托盘更新路径。

第一次修复后验证：build 0/0，test 250/250。

### 第二次审核修复（2026-07-04）

复审发现新增测试存在两个问题：

1. `MainWindowViewModel_RefreshUpdatesTrayMenuState` 为 `async Task`，但测试中创建真实 `TrayService(Dispatcher.CurrentDispatcher)` 后经过 `await` 再调用 `UpdateMenuState`。xUnit 测试环境没有 WPF 消息泵，`Dispatcher.Invoke` 可能卡死。
2. 该测试没有真正覆盖 ViewModel 路径，而是手动执行 `TrayMenuState.From` 后直接调用 `trayService.UpdateMenuState`。

临时修复：

1. 将测试改为同步 `void`，用 `.GetAwaiter().GetResult()` 避免 async continuation 切换线程。
2. 单测不再卡死。

复审结果：

- 单测可通过。
- 但 build 出现 2 个 xUnit1031 warning。
- 测试仍未真正覆盖 ViewModel 路径。

该修复未通过最终审核。

### 第三次审核修复（2026-07-04）

最终修复采用 `ITrayStateSink` 解耦：

1. 新增 `ITrayStateSink` 接口。
2. `TrayService` 实现 `ITrayStateSink`。
3. `MainWindowViewModel` 依赖 `ITrayStateSink?`，不再依赖具体 `TrayService`。
4. 生产路径中 `App.xaml.cs` 创建 `TrayService` 后注入 `viewModel.TrayStateSink`。
5. 测试新增 `FakeTrayStateSink`，不创建真实 `TrayService`，不接触 Dispatcher。
6. `MainWindowViewModel_RefreshCommonStatusUpdatesTrayStateSink` 使用 `async Task` 和 `await`，通过 `ApplyStatusRefreshResult` 触发真实 ViewModel 状态应用路径。
