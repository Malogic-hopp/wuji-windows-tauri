# 下一步建议

我建议下一阶段进入：

```text
阶段 11：开机自启 MVP
```

理由是：阶段 10 已经解决了“当前用户会话内后台常驻”的问题。下一步最自然的问题就是：

```text
开机 / 登录 Windows 后，WUJI 能不能自动进入托盘常驻？
是否自动启动 Agent？
用户能不能安全地打开/关闭这个行为？
失败时是否可诊断？
```

阶段 10 完成说明里也把“开机自启 MVP”列为最自然的下一步候选。

---

# 阶段 11 建议目标

阶段 11 不建议一上来做安装包或 Windows Service。建议先做：

```text
当前用户登录后自动启动 WPF App 到托盘的 MVP。
```

也就是：

```text
Windows 登录
    ↓
自动启动 QuantifiedSelf.Windows.App
    ↓
App 进入托盘常驻
    ↓
根据已有设置决定是否 AutoStartAgentWhenAppStarts
```

重点是“用户会话内自启”，不是 Windows Service。

---

# 阶段 11 建议边界

## 阶段 11 应该做

```text
1. Settings 中暴露“开机/登录后启动 WUJI”开关。
2. 使用当前用户级别的自启机制。
3. App 启动后可直接托盘常驻。
4. 复用已有 AutoStartAgentWhenAppStarts。
5. Diagnostics 显示自启配置状态。
6. 自启失败时有安全错误文案。
7. 不影响手动启动 App。
```

## 阶段 11 不建议做

```text
不做安装包
不做 Windows Service
不做管理员权限自启
不做计划任务高级配置
不做多用户服务化
不做自动更新
不做托盘 Exit App + Stop Agent
不改 IPC 协议
不改 AgentStateMachine
```

# 阶段 11 技术路线建议

优先考虑两种方案：

## 方案 A：注册表 Run Key

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
```

优点：

```text
实现简单
当前用户级
不需要管理员权限
适合 MVP
```

风险：

```text
路径变化 / 发布方式变化后需要更新
需要处理引号和参数
```

## 方案 B：Startup 文件夹快捷方式

优点：

```text
用户可见
容易手动删除
直观
```

风险：

```text
快捷方式创建逻辑稍复杂
路径和图标资源要处理
```

我的建议是：**阶段 11 MVP 优先使用 HKCU Run Key**，但在文档里保留 Startup Shortcut 作为替代方案。

# 阶段 11 推荐拆分

可以拆成：

```text
11.1 自启方案评估与边界确认
11.2 AutoStartService / StartupRegistrationService
11.3 Settings 开关与状态显示
11.4 启动参数：开机自启时最小化/隐藏到托盘
11.5 Diagnostics 自启状态与错误展示
11.6 手动验收与收口
```

其中 11.4 很关键。建议增加启动参数，例如：

```text
--minimized
--tray
--from-autostart
```

开机自启时默认不要弹主窗口，应该直接托盘常驻。

# 阶段 11 重点风险

需要提前控制：

```text
1. 自启后弹主窗口打扰用户。
2. 自启路径错误导致无法启动。
3. 用户关闭自启后注册表残留。
4. App 更新路径变化后自启失效。
5. AutoStartAgentWhenAppStarts 与 App 自启混淆。
6. 用户以管理员/普通权限切换导致路径和权限问题。
7. 自启启动多个 App 实例。
```

尤其是第 5 点要讲清楚：

```text
Start WUJI on login:
    登录 Windows 后启动 WPF App。

AutoStartAgentWhenAppStarts:
    WPF App 启动后是否自动启动 Agent。
```

这两个开关不能混为一谈。

```text

```
