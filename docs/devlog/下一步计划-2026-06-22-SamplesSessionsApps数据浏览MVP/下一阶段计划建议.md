# 五、阶段 6 推荐范围

## 6.1 Settings 读取与展示

先做只读展示，保证当前配置可见：

```text
windows-agent.json
app-settings.json
数据目录
数据库路径
日志目录
当前 Agent 状态
当前 ReloadConfig 状态
```

这一步不涉及写入，风险低。

## 6.2 Agent 配置编辑 MVP

优先支持这些字段：

```text
samplingIntervalSeconds
idleThresholdSeconds
heartbeatIntervalSeconds
staleThresholdSeconds
maskWindowTitles
excludedProcesses
excludedTitlePatterns
enableAgentEventJournal
retentionDays
```

但要注意边界：**WPF 不应直接覆盖采集域配置并假装已生效**。

推荐语义：

```text
WPF 编辑配置
    ↓
本地校验
    ↓
保存为待应用配置 / 或通过 Agent 命令请求应用
    ↓
Agent 校验、写入、ReloadConfig
    ↓
Diagnostics 记录 ConfigReloaded / CommandCompleted / CommandFailed
```

如果你暂时还没有 IPC，就可以先用 file fallback，但最好不要让 WPF 绕过 Agent 直接改采集域规则。

## 6.3 App 设置编辑

这类属于 WPF 自己的配置，可以由 WPF 直接保存：

```text
refreshIntervalSeconds
lastSelectedPage
autoStartAgentWhenAppStarts
theme，先可以只读或占位
```

这部分和 Agent 采集域无关，风险较低。

## 6.4 ReloadConfig 工作流

现在已有 `ReloadConfig` 事件和命令基础，可以继续扩：

```text
保存配置
    ↓
发送 ReloadConfig
    ↓
Agent 重新读取 windows-agent.json
    ↓
成功：ConfigReloaded + UI 提示
    ↓
失败：CommandFailed + Diagnostics 显示 errorCode
```

这里要重点防止：

```text
配置文件写坏
Agent 读失败
UI 显示已保存但 Agent 实际没生效
```

## 6.5 PruneData / ClearHistory

这两个可以作为阶段 6 的后半段，不建议一开始就做。

推荐先做：

```text
PruneData
```

再做：

```text
ClearHistory
```

因为 ClearHistory 风险更高。

边界必须保持：

```text
WPF 不直接 delete SQLite
WPF 不直接 delete JSONL
WPF 只发命令
Agent 进入 Maintenance
Agent 关闭当前 session
Agent 清理数据
Agent 写 DataPruned / HistoryCleared
Agent 重写 runtime_state 并 heartbeat
```

```text

11. ReloadConfig 失败能在 Diagnostics 看到 CommandFailed / errorCode
12. PruneData 只由 Agent 执行
13. ClearHistory 只由 Agent 执行
14. 清理后 runtime_state / health_state 仍可观测
15. Dashboard / Apps / Sessions / Samples / Diagnostics 不回归
```
