# 阶段 5.6：验收、稳定化与收口

## 阶段目标

对 Samples / Sessions / Apps 数据浏览 MVP 做最终验收，确认它没有破坏采样、诊断、Dashboard 和 Agent 控制链路。

## 手动验收流程

建议手动验证：

```text
1. 运行 Agent 10-15 分钟
2. 切换几个常用应用
3. 触发 Pause / Resume / Stop
4. 打开 SamplesView 查看最近样本
5. 打开 SessionsView 查看 session close_reason
6. 打开 AppsView 查看今日排行
7. 确认 Dashboard 仍正常
8. 确认 Diagnostics 仍正常
9. 确认 maskWindowTitles=true 时 SamplesView 不显示真实标题
10. 确认排除进程不进入 samples / sessions
```

## 最终验收标准

本阶段完成后，应满足：

```text
1. dotnet build 0 warning / 0 error
2. dotnet test 全部通过
3. Dashboard 原功能不回归
4. Diagnostics 原功能不回归
5. SamplesView 能显示最近 200 条样本
6. SamplesView 支持 ActivityState 基础筛选
7. SessionsView 能显示最近 session
8. SessionsView 能看到 close_reason
9. AppsView 能显示今日应用排行
10. AppsView 按 active duration 排序
11. AppsView display_name fallback 正确
12. 所有数据查询使用只读连接，例如 Mode=ReadOnly;Pooling=False
13. 所有列表查询有 LIMIT
14. Today Sessions 按本地日重叠查询
15. 空库 / 空表时 UI 显示友好空态
16. maskWindowTitles=true 时不泄露真实窗口标题
17. SamplesView 默认不展示完整 executable_path
18. excludedProcesses 命中时不出现对应 samples / sessions
19. 大量数据下刷新和滚动不卡顿
20. 新页面至少拆成 UserControl，优先独立 View + ViewModel
21. Dashboard Top Apps 与 AppsView Today 排行口径一致；允许 1 秒级 rounding 差异，不允许明显排序或时长偏差
```

## 统计口径收口待办

阶段 5.1 后存在一个短期可接受的实现差异：

```text
OverviewQueryService
    使用 C# 内存计算本地日重叠切分和 Top Apps 聚合

AppUsageQueryService
    使用 SQL CTE 完成本地日重叠切分、聚合、排序和 LIMIT
```

两者目标口径一致：

```text
本地日重叠
按 overlap / span 比例切分 duration
Apps 排行按 active duration DESC, total duration DESC, process_name ASC
```

收口时需要验证：

```text
1. Dashboard Top Apps 与 AppsView Today 的应用顺序一致
2. Active / Total / Idle / Unknown 时长没有明显偏差
3. open session 场景下没有明显偏差
4. 跨日 session 场景下没有明显偏差
```

如果出现明显差异，建议优先做：

```text
让 Dashboard Top Apps 复用 AppUsageQueryService.GetAppUsageForLocalDayAsync(DateOnly, limit)
```

或抽出共享统计查询实现，避免长期维护两套重叠切分逻辑。
