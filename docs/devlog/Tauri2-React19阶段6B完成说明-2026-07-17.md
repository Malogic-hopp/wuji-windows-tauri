## 1. 实施范围

阶段 6B 完成托盘、单实例与 dev channel 收口：

- 托盘增加 Agent 状态文本以及 start、pause、resume、stop 固定动作；
- 托盘增加显示、隐藏和真正退出，显示/隐藏动作会随窗口可见状态禁用；
- Agent 操作期间禁用冲突菜单，完成后立即刷新状态，防止重复提交；
- 启动后立即读取 Agent 状态，并每 4 秒刷新一次；错过的 tick 直接跳过，避免恢复后的刷新风暴；
- 增加固定 dev 单实例 mutex，第二实例只恢复并激活已有窗口后退出；
- Bridge 启动参数固定为 `--channel dev`，React 无法传入 channel、路径或数据根；
- Bridge initialize 后反向校验 `channelName == dev` 且 `isDefaultChannel == false`；身份不符时立即回收 Bridge，并返回安全协议错误；
- 增加 Rust、React 和 .NET 架构测试，证明 dev/prod pipe、Agent mutex、数据根和启动项名称互相隔离。

本批没有修改 IPC、SQLite、Agent 状态机、WPF `App.xaml.cs`、默认 WPF Shell、WPF 发布流程或启动项实现，也没有启动或停止真实 Agent。

## 2. 托盘菜单与状态映射

托盘使用原生单列菜单和固定中文文案。状态不依赖颜色表达，不可用动作使用原生 disabled 语义；退出与普通操作之间保留分隔线。

| Agent 状态 | 托盘文案 | 可用动作 |
|---|---|---|
| `not-running` / `stopped` | Agent：未运行 | 启动记录 |
| `running` | Agent：正在记录 | 暂停记录、停止记录 |
| `paused` | Agent：已暂停 | 继续记录、停止记录 |
| `stale` 且进程存在 | Agent：状态过期 | 停止记录 |
| `stale` 且进程不存在 | Agent：状态过期 | 无 |
| `starting` / `pausing` / `resuming` / `stopping` | 对应过渡中文文案 | 无 |
| `error` | Agent：服务异常 | 仅在进程存在时允许停止 |
| Bridge 未就绪或不可用 | Agent：正在连接… / 服务不可用 | 无 |
| Agent 命令执行中 | Agent：正在处理… | 无 |

托盘只发出固定方法：

```text
agent.getStatus
agent.start
agent.pause
agent.resume
agent.stop
```

托盘不会接收 React 传入的方法名、参数、channel、PID、可执行文件路径或数据位置，也不显示原始异常、窗口标题、路径、数据库信息或内部运行标识。

## 3. 单实例与窗口激活

Tauri dev Shell 使用固定宿主 mutex：

```text
Local\WUJI.Tauri.Dev.SingleInstance.v1
```

第一实例持有 mutex handle 直到进程退出。第二实例发现 mutex 已存在后：

1. 不创建 Tauri Builder、Bridge 或 WebView；
2. 最多等待 5 秒寻找标题为“吾迹 · 开发预览”的既有窗口；
3. 使用 Win32 `ShowWindowAsync(SW_RESTORE)` 恢复窗口；
4. 使用 `SetForegroundWindow` 请求激活；
5. 第二实例立即退出。

窗口重新获得焦点时，Rust `HostLifecycle` 会修正为 `Visible` 并发出固定生命周期事件，使隐藏到托盘后由第二实例恢复的状态保持一致。

该 mutex 只标识 Tauri dev 宿主，不复用 Agent mutex，也不由 React 或命令行提供名称。

## 4. dev channel 固化与反向校验

BridgeSupervisor 只以固定参数启动 sidecar：

```text
--channel dev
```

完成 `client.initialize` 后，Rust 必须同时确认：

- `channelName` 精确等于 `dev`；
- `isDefaultChannel` 为 `false`。

任一条件不满足时，该 Bridge 不会进入 ready 状态；Rust 会终止并回收子进程，向上层返回固定安全协议错误。React command/client 均没有 `channelName`、`executablePath`、`dataRoot` 或等价通用参数，因此 WebView 无法把 Shell 切换到 prod，也不能指定任意 Bridge 或数据位置。

## 5. dev/prod 隔离门禁

架构测试直接验证 Core 的 dev/prod 身份差异：

- Named Pipe 名称不同；
- Agent mutex 名称不同；
- 数据根目录不同；
- 登录启动注册表 value name 不同；
- dev Agent 启动参数固定为 `--channel dev`；
- Tauri 单实例 mutex 与 Agent mutex 不同；
- Tauri 不引入 autostart plugin，不新增或修改启动项；
- React 不包含 channel、路径或数据根输入能力。

这些门禁证明代码边界不会主动串到 prod；真实 Windows 环境中的 pipe、进程、数据和启动项前后状态仍需由合并 smoke 复核。
