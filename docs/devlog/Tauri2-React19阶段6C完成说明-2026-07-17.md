## 2. WPF/Tauri 托盘语义对照

Core `AppSettings` 的 WPF 默认值为：

```text
MinimizeToTray = true
CloseToTray = true
```

WPF 运行时语义：

- 最小化：窗口隐藏，WPF 与 Agent 保持运行；
- 点击关闭：窗口隐藏，WPF 与 Agent 保持运行；
- 托盘显示：恢复并激活同一窗口；
- 托盘退出：结束 WPF UI，不隐式停止 Agent。

Tauri 6C 语义：

- `WindowEvent::Resized` 检测到窗口已最小化时，执行固定 minimize-to-tray；
- 最小化不会清除 Settings dirty，不显示关闭确认；
- 如果关闭确认已经打开，最小化不能绕过或覆盖待确认意图；
- 点击关闭仍由 6A 的 `CloseIntent::Hide` 处理，dirty 时先确认；
- 托盘恢复会 show、unminimize、focus，并修正生命周期状态；
- 真正退出只关闭 Bridge，不调用 `agent.stop`。

Tauri dev 当前固定采用 WPF 默认的 close/minimize-to-tray 策略。Settings v1 继续不开放托盘配置字段，React 不能改变该宿主策略。

## 3. 生命周期 parity 与循环恢复 smoke

新增：

```text
pnpm smoke:lifecycle-parity
```

对应脚本：

```text
src/QuantifiedSelf.Windows.Tauri/scripts/lifecycle-parity-smoke.ps1
```

脚本按固定顺序完成：

1. 要求开始前没有 WPF、Tauri 或 Bridge，记录 prod Agent/pipe 只读数量基线；
2. 只接受带 `--channel dev --ui-preview` 的 WPF；
3. 验证 WPF minimize-to-tray、close-to-tray、托盘恢复和真正退出；
4. 验证 Tauri minimize-to-tray、close-to-tray、托盘恢复和 Bridge 持续存活；
5. 启动或复用唯一 `--channel dev` Agent，并要求唯一 dev pipe；
6. 正常退出 Tauri，确认 Bridge 退出而 Agent PID 不变；
7. 重启 Tauri，确认识别原 Agent；
8. 只结束经过 parent PID 和 `--channel dev` 双重校验的 Bridge，确认自动恢复；
9. 只结束拥有唯一 dev Bridge 子进程的 Tauri，确认 Bridge 随 stdin EOF 退出且 Agent 保持运行；
10. 再次启动 Tauri，确认没有重复 Agent；
11. 默认执行三次正常启动/退出循环，每次确认 Bridge 完整回收、Agent PID 不变；
12. 通过 UI 显式 stop，确认 Agent 正常退出；
13. 最终退出 Tauri，确认 Tauri/Bridge/dev Agent 均为零，prod Agent/pipe 数量与基线一致。

脚本不会使用 `Stop-Process -Name`，不会结束 Agent，也不会接受任意 PID、channel 或路径。崩溃注入只作用于脚本当场复核过的 dev Tauri/Bridge。

报告写入：

```text
%TEMP%\WUJI.Smoke\lifecycle-parity-smoke-<run-id>.md
```

报告不记录路径、SID、窗口标题、数据库内容或生产通道标识。

## 4. 资源与刷新频率 soak

新增入口：

```text
pnpm soak:lifecycle
pnpm soak:lifecycle:24h
```

`soak:lifecycle:24h` 固定参数：

```text
DurationMinutes = 1440
SampleIntervalSeconds = 60
WarmupMinutes = 5
AgentExpectation = Running
```

soak 工具只读观察已经运行的 Tauri dev 拓扑，不负责启动、停止或重启任何进程。每个采样周期检查：

- 恰好一个 Tauri；
- 恰好一个以 `--channel dev` 启动且 parent PID 正确的 Bridge；
- 最多一个 dev Agent；默认要求一个运行中的 dev Agent；
- Tauri、Bridge 和 Agent PID 在稳定 soak 中不变化；
- 没有孤儿 dev Bridge；
- 没有重复 dev Agent。

资源样本包括：

- working set；
- private memory；
- handle count；
- CPU 累计时间；
- Bridge read/write operation count。

默认门禁：

- warmup 后各进程 private memory 终点增长不超过 192 MiB；
- handle 终点增长不超过 200；
- Bridge I/O 按采样区间换算为 operations/minute；峰值同时超过 240 ops/min 和稳定中位数的 4 倍时判定为疑似刷新风暴；
- 结束时 prod Agent/pipe 数量必须与只读基线一致。

I/O 门禁用于发现随时间倍增的刷新风暴，不把文件 I/O 数量解释成精确 RPC 次数。精确代码节奏由架构门禁固定：托盘 `4s + MissedTickBehavior::Skip`，React Agent query `4s`，Dashboard 可见 `15s`、隐藏 `60s`。

报告和原始 CSV 写入：

```text
%TEMP%\WUJI.Soak\lifecycle-soak-<run-id>.md
%TEMP%\WUJI.Soak\lifecycle-soak-<run-id>.csv
```

## 5. 推荐执行顺序

### 5.1 准备 Bridge

```powershell
cd src\QuantifiedSelf.Windows.Tauri
pnpm bridge:prepare
```

### 5.2 执行完整 parity 与循环恢复

开始前关闭 WPF、Tauri 和 Bridge，然后执行：

```powershell
pnpm smoke:lifecycle-parity
```

脚本会逐步提示何时启动 WPF/Tauri、何时操作托盘；不要提前执行 stop 或关闭终端。

### 5.3 先执行短时资源检查

在独立终端保持 Tauri dev 和唯一 dev Agent 运行，然后执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\lifecycle-soak.ps1 `
  -DurationMinutes 15 `
  -SampleIntervalSeconds 30 `
  -WarmupMinutes 2 `
  -AgentExpectation Running
```

### 5.4 执行 24 小时 soak

短时检查通过、机器允许持续保持登录会话时执行：

```powershell
pnpm soak:lifecycle:24h
```

24 小时期间保持 UI/Agent 工作负载稳定，不手动切换 channel、反复刷新页面或执行破坏性动作；需要取消时使用 `Ctrl+C`，保留已写入的 checkpoint CSV 和失败/中止报告。
