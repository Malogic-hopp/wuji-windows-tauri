# 阶段 2：事件写入链路

## 阶段目标

让 Agent 具备统一、可追踪、best-effort 的事件写入能力。

这一阶段的核心是“事件落地”，但必须保证事件系统失败时，不影响采样主循环和控制命令执行。

## 解决的问题

- 采样主链路没有统一的审计事件。
- 命令处理过程缺少可诊断记录。
- 事件写入失败时，不能把 Agent 整体带崩。

## 交付物

- `AgentEventJournal`
- `AgentEventWriter`
- `AgentEventRateLimiter`
- Agent 生命周期事件接入
- 命令事件接入

## 实施范围

### 写入组件

建议新增：

- `src/QuantifiedSelf.Windows.Infrastructure/Events/AgentEventRepository.cs`
- `src/QuantifiedSelf.Windows.Infrastructure/Events/AgentEventJournal.cs`
- `src/QuantifiedSelf.Windows.Agent/Events/AgentEventWriter.cs`
- `src/QuantifiedSelf.Windows.Agent/Events/AgentEventRateLimiter.cs`

### 事件接入点

优先接入：

- `AgentStarted`
- `AgentStopped`
- `AgentPaused`
- `AgentResumed`
- `CommandDetected`
- `CommandAccepted`
- `CommandCompleted`
- `CommandFailed`
- `CommandInvalidJson`
- `ConfigReloaded`

### 写入语义

- SQLite 和 JSONL 采用 best-effort 双写
- SQLite 失败时仍尽量写 JSONL
- JSONL 失败时不影响 SQLite 和主流程
- 两者都失败时只记录最近一次写入错误，不递归写事件

### 命令来源

第一版只落：

- `commandSource = FileFallback`

后续再扩展：

- `NamedPipe`
- `Grpc`

## 验收标准

- Agent 启动后写入 `AgentStarted`
- Pause / Resume / Stop 能对应写入事件
- 命令链路能看到 `CommandDetected` / `CommandAccepted` / `CommandCompleted` / `CommandFailed`
- 坏 JSON 能写 `CommandInvalidJson`
- 写入失败不影响 `TickAsync`
- 事件写入失败不会导致 Agent 崩溃

## 不做什么

- 不做复杂事件 UI
- 不做 JSONL 浏览器
- 不做 IPC 控制通道
- 不做托盘或安装包
