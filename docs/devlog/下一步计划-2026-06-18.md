## 优先级 1：修复 JSON 契约与控制文件鲁棒性

问题：

当前 `System.Text.Json` 默认会把 enum 写成数字，而方案示例和长期可诊断性都要求字符串：

```json
{
  "command": "Pause",
  "desiredState": "Paused"
}
```

需要做：

```text
1. 在 Core 或 Infrastructure 提供统一 JsonSerializerOptions
2. 添加 JsonStringEnumConverter
3. RuntimeStateStore / AgentHealthStateStore / AgentControlFileStore 共用该配置
4. AgentControlFileStore.ReadAsync 处理 JsonException
5. AgentStateMachine 遇到坏 control 文件时：
   - 不崩溃
   - 写 health_state 错误信息
   - 保持 heartbeat 可观测
   - 可选择将坏文件重命名为 .bad
```

验收：

```text
1. agent_control.json 中 command 为字符串
2. runtime_state.json 中 state 为字符串
3. 手工写入无效 agent_control.json 后，Agent 继续运行
4. Diagnostics 能看到错误信息
```

## 优先级 2：实现采集阶段隐私规则

问题：

`WindowsAgentOptions` 已有：

```text
MaskWindowTitles = true
ExcludedProcesses = KeePass / 1Password / Bitwarden
ExcludedTitlePatterns
```

但 Agent 当前捕获 sample 后直接写入 SQLite 和 session，隐私规则没有在写入前生效。

需要做：

```text
1. 新增 ForegroundSamplePrivacyFilter 或类似服务
2. 在 AgentStateMachine Running tick 中：
   - Capture sample
   - Apply privacy rules
   - 被排除时不写 foreground_samples
   - 被排除时不创建或扩展 app_sessions
   - 标题脱敏后再写库
3. MaskWindowTitles=true 时，WindowTitle 写入固定脱敏值或 null
4. ExcludedProcesses 忽略大小写匹配
5. ExcludedTitlePatterns 在 MVP 可先做 contains / wildcard 简化匹配
```

验收：

```text
1. windows-agent.json 中 MaskWindowTitles=true 时，SQLite 不出现原始窗口标题
2. excludedProcesses 命中的进程不写 foreground_samples
3. excludedProcesses 命中的进程不写 app_sessions
4. 相关行为有单元测试
```

## 优先级 3：加入 Agent 单实例保护

问题：

方案要求 Agent 是唯一数据写入者。当前 WPF 会尽量避免重复启动，但 Agent 自身没有单实例保护，手动双开或竞态启动仍可能产生两个写入者。

需要做：

```text
1. 在 Agent Program.cs 增加 named Mutex
2. Mutex 名称包含当前用户维度，避免跨用户误伤
3. 第二个 Agent 启动时：
   - 写日志或控制台提示
   - 直接退出
4. WPF StartAgentAsync 保持现有进程检查逻辑
```

验收：

```text
1. 同一用户不能同时启动两个 Agent
2. 第二次启动不会写入 runtime_state 覆盖当前 Agent
3. 单实例逻辑有测试或至少有可手动验证步骤
```

## 优先级 4：修 SQLite 连接策略与错误暴露

问题：

SQLite 初始化连接设置了：

```sql
PRAGMA journal_mode=WAL;
PRAGMA busy_timeout=5000;
```

但 repository / query service 的新连接没有设置 busy_timeout。WPF 查询异常也直接返回空结果，容易把数据库锁或 schema 错误伪装成“没有数据”。

需要做：

```text
1. 抽一个 SQLiteConnectionFactory 或 shared OpenConnection helper
2. 每个读写连接打开后设置 busy_timeout
3. 写连接使用 ReadWrite，不要在 repository 中隐式 ReadWriteCreate
4. OverviewQueryService 不要裸 catch 后静默返回空
5. 将查询错误传给 ViewModel，Dashboard 保留上一次成功数据并显示错误消息
```

验收：

```text
1. Agent 写入时 WPF 周期刷新不容易撞锁失败
2. 数据库文件缺失时显示空数据是正常路径
3. 数据库存在但读取失败时 UI 能提示“数据库读取失败”
4. 错误可在 Diagnostics 或 Messages 中看到
```

## 优先级 5：修统计口径

问题：

当前今日统计按 UTC `started_at_utc` 过滤，且不切分跨天 session。Top Apps 当前按 total duration 排序，而方案要求主排行按 active duration。

需要做：

```text
1. 今日范围按本地日期计算，再转换为 UTC 查询边界
2. 今日总时长按 session 与今日时间窗口的重叠部分计算
3. 对跨天 session 做比例或精确切分
4. Top Apps 排序改为 active_duration_seconds DESC
5. 同时显示 total / active / idle / unknown / session_count
```

MVP 可接受的简化：

```text
先按 session 总时长比例分摊 active / idle / unknown 到今日重叠区间。
后续如果 sample 粒度更完整，再做更精确的分段统计。
```

验收：

```text
1. 昨天开始、今天结束的 session 会计入今天
2. 今天开始、明天结束的 open session 能计入今天已发生部分
3. 纯昨天 session 不计入今天
4. 应用排行按 active duration 排序
5. 增加统计测试用例
```
