## 架构原则

### 1. 安装包不改变双进程架构

WPF App 和 Agent 仍然是两个独立可执行文件。当前项目默认输出名为：

```text
QuantifiedSelf.Windows.App.exe
QuantifiedSelf.Windows.Agent.exe
```

品牌目标名可设为：

```text
WUJI.exe
WUJI.Agent.exe
```

阶段 12.1 需要先确认当前 publish 实际输出名，再决定是否通过 `AssemblyName` / publish 配置改名。安装包负责把它们放到同一安装目录，并创建开始菜单快捷方式。WPF App 仍通过相对路径或固定安装目录找到 Agent。

### 2. 数据与程序分离

程序文件放在安装目录：

```text
%LocalAppData%\Programs\WUJI
    或
C:\Users\<User>\AppData\Local\Programs\WUJI
```

用户数据继续放在：

```text
%LocalAppData%\WUJI\WindowsAgent
```

这样卸载时可以不删除用户数据，升级时数据自动保留。

### 3. 自启注册由 App 自己管理

安装包不直接写 HKCU Run Key（除非用户明确选择安装时启用自启）。推荐默认行为：

```text
安装时不写 Run Key。
用户首次启动 App 后，在 Settings 中开启 StartAppOnWindowsLogin。
App 启动后按阶段 11 的 StartupRegistrationService 注册 Run Key。
```

如果安装包提供"开机自启"选项，也应调用 App 提供的命令行接口或注册表写入逻辑，而不是安装包自己硬编码路径。

### 4. 卸载清理最小化

卸载时必须清理：

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run 中的 WUJI value
开始菜单快捷方式
桌面快捷方式（如果创建过）
安装目录
```

默认保留：

```text
%LocalAppData%\WUJI\WindowsAgent 数据目录
```

可选项：

```text
是否同时删除用户数据目录
```

### 5. 图标资源统一

MVP 阶段至少提供一套内嵌 .ico 资源：

```text
App 窗口图标
任务栏图标
托盘图标
安装包图标
```

图标风格保持简洁，不阻塞安装包主流程。如果已有品牌图标资源，优先复用。

### 6. 版本号统一

建议统一版本号来源：

```text
Directory.Build.props 或共享 AssemblyInfo.cs
安装包版本
App 关于页版本
Agent 版本（与 App 保持一致或独立管理）
```

MVP 阶段至少保证 App 和安装包版本一致。

## 安装包选型建议

推荐按以下顺序评估：

```text
1. MSIX（推荐优先评估）
   优点：Windows 原生、支持干净卸载、自动更新预留、权限模型清晰。
   缺点：对 .NET 自包含包体积敏感、签名证书要求、沙箱行为可能限制。

2. WiX / MSI
   优点：成熟、企业场景友好、卸载干净。
   缺点：学习曲线、XML 配置复杂、对 .NET 自包含包体积敏感。

3. Inno Setup
   优点：轻量、脚本简单、社区成熟、不要求签名。
   缺点：非微软官方、自定义卸载逻辑需脚本实现。

4. 单文件压缩包 + 手动安装脚本
   优点：最简单、无安装器依赖。
   缺点：无开始菜单快捷方式、卸载靠文档说明、体验差。
```

MVP 阶段建议：

```text
1. 阶段 12.3 必须先做选型 spike，验证以下 4 点：
   - 是否支持当前用户安装（默认无需管理员权限）。
   - 是否能满足托盘常驻、HKCU Run Key 自启、自定义卸载清理。
   - 是否支持可选删除 %LocalAppData%\WUJI 数据目录。
   - 未签名情况下安装体验如何（SmartScreen、杀软误报、用户信任）。
2. MSIX / WiX 优先评估，但如果出现以下情况，允许直接 fallback 到 Inno Setup：
   - 当前用户安装受限或需要额外配置。
   - 自定义卸载逻辑（保留 / 删除数据选项）实现困难。
   - 未签名包无法被用户正常安装。
   - 自启注册命令调用受沙箱或权限限制。
3. 最终选型必须在阶段 12.3 完成说明中记录理由和 spike 验证结果。
```

# 阶段 12.1：发布配置与 self-contained win-x64 输出

## 阶段目标

让 WPF App 和 Agent 可以通过 `dotnet publish` 输出为稳定的 self-contained win-x64 发布目录，版本号统一，输出目录固定。

优先目标：

```text
self-contained win-x64 发布目录稳定
App 和 Agent 同目录输出
路径可靠
发布后的 App 能启动 Agent
发布后的 App 能用 --from-autostart --start-hidden 隐藏到托盘
```

可选目标：

```text
单文件输出，如体积和路径行为可接受
```

## 行为要求

```text
1. 新增 publish profile 或 MSBuild 目标，支持：
   - dotnet publish -c Release
   - 自包含 .NET 运行时
   - win-x64 目标平台
   - 单文件输出作为可选目标（不强制）
2. App 和 Agent 必须输出到同一 publish 目录，但 App 不新增对 Agent 项目的项目引用（ReferenceOutputAssembly=false 现状保持不变）。
   - 实现方式：使用 publish script 或 MSBuild target 先 publish App，再 publish Agent，最后把 Agent publish 产物复制到 App publish 目录。
   - 禁止直接复制 Debug / obj / bin 输出作为发布产物；发布目录中的 Agent 必须是 Release / win-x64 / self-contained publish 产物。
3. 版本号统一来自 Directory.Build.props 或共享 AssemblyInfo.cs，并写入 App 和 Agent 的 Assembly / File 版本。
4. 先检查当前项目 publish 后的实际 exe 文件名（当前默认可能是 QuantifiedSelf.Windows.App.exe / QuantifiedSelf.Windows.Agent.exe）。
5. 决定是否通过 `AssemblyName` 或 publish 配置将 exe 重命名为 WUJI.exe / WUJI.Agent.exe；如改名，需同步更新 AgentProcessService 查找逻辑和 StartupCommandBuilder 自启 command 构建。
6. 输出目录结构稳定，例如：
   publish/
   ├── QuantifiedSelf.Windows.App.exe（或 WUJI.exe）
   ├── QuantifiedSelf.Windows.Agent.exe（或 WUJI.Agent.exe）
   └── ...
7. 发布后的 App exe 可通过 --from-autostart --start-hidden 启动到托盘。
8. 发布后的 Agent exe 可被 App 正常启动。
9. AgentProcessService 的 Agent exe 路径解析必须同时兼容发布目录和开发目录：
   - 优先查找 AppContext.BaseDirectory 下的 Agent exe。
   - 其次读取环境变量 QUANTIFIEDSELF_WINDOWS_AGENT_EXE。
   - 最后 fallback 到开发目录推导路径。
   - 找不到时返回安全错误，不抛未处理异常。
10. 不使用 Assembly.Location 定位当前 App exe；StartupCommandBuilder 继续使用 Environment.ProcessPath / Process.MainModule.FileName。
```

## 验收标准

- `dotnet publish` 0 warning / 0 error。
- publish 目录包含 App 和 Agent 可执行文件。
- 发布后的 App 可手动启动并显示主窗口。
- 发布后的 App 可启动 Agent。
- 如决定改名，AgentProcessService 和 StartupCommandBuilder 中引用的 exe 名与实际 publish 输出一致。

# 阶段 12.4：安装时可选自启与卸载清理

## 阶段目标

让安装包支持可选的开机自启，并确保卸载时清理注册表和快捷方式。

## 行为要求

```text
1. 安装时提供可选选项：
   - 开机自动启动 WUJI（默认不勾选或勾选，需在完成说明中明确）。
2. 如果用户勾选，安装包必须优先通过 App exe 命令行接口注册自启：
   - 阶段 12.4 先新增 `<AppExeName> --register-autostart` / `--unregister-autostart` 命令行入口（如 WUJI.exe 或 QuantifiedSelf.Windows.App.exe），内部复用阶段 11 的 StartupRegistrationService。
   - 该命令必须是 headless：不创建主窗口、不创建托盘图标、不启动 status polling、不触发 AutoStartAgentWhenAppStarts、不启动 Agent；执行成功后立即退出，返回 exit code 0，失败返回非 0。
   - 命令内部发生错误时，输出安全文案，不得泄露完整路径、用户名、SID 等敏感信息。
   - 安装包调用该命令完成安装时自启注册 / 取消注册。
   - 只有当命令行接口暂未实现或安装器技术限制时，才允许安装包直接写 HKCU Run Key。
   - 如果安装包直接写，必须完全复用 StartupCommandBuilder 的 command 规则，并在完成说明中记录风险。
3. 卸载前应检测 WUJI App / Agent 是否正在运行：
   - MVP 可提示用户先退出 WUJI。
   - 不得默认静默强杀 Agent。
   - 如需强制关闭，必须由用户明确确认。
   - 卸载不应在 App / Agent 仍运行时删除正在使用的 exe。
4. 卸载时删除 HKCU Run Key 中的 WUJI value。
5. 卸载时删除开始菜单快捷方式。
6. 卸载时删除安装目录。
7. 卸载时默认保留 %LocalAppData%\WUJI\WindowsAgent 数据目录。
8. 提供可选"同时删除用户数据"复选框，默认不勾选。
```

补充要求：

```text
删除用户数据必须是显式选项，默认不勾选。
卸载程序不得静默删除 SQLite / JSONL / app-settings.json / windows-agent.json。
如果用户选择删除数据，完成说明必须记录删除范围。
```

## 验收标准

- 安装时勾选自启后，HKCU Run Key 出现 WUJI value。
- 安装时不勾选自启后，HKCU Run Key 不出现 WUJI value。
- `<AppExeName> --register-autostart` / `--unregister-autostart` 命令执行时不创建主窗口、不创建托盘图标、不启动 Agent、不启动 status polling。

- 命令错误输出不包含完整路径、用户名、SID。
- 卸载后 HKCU Run Key 中 WUJI value 被删除。
- 卸载后安装目录被删除。
- 卸载后开始菜单快捷方式被删除。
- 卸载后数据目录默认保留。
- build/test 通过。
