## Findings（按严重程度排序）

### Finding 1 — HIGH — MainWindowViewModel 全局 Refresh 覆盖 Settings 编辑表单 — ✅ 已修复

**文件/行号**: `MainWindowViewModel.cs:362-366`

**问题**: `MainWindowViewModel.RefreshAsync()` 由 `DispatcherTimer` 每 N 秒触发。当用户在 Settings 页编辑表单时，定时器触发的 `LoadAsync()` 会用磁盘值覆盖所有编辑器绑定属性，并通过 `IsDirty = false` 清除脏标记。

**修复**: `MainWindowViewModel.cs:362` — Settings 分支加入 `IsDirty` 守卫：

```csharp
case "Settings":
    if (!_settingsViewModel.IsDirty)
    {
        await _settingsViewModel.LoadAsync(cancellationToken);
        ApplyAppSettings(_settingsViewModel.AppSettings);
    }
    break;
```

> 已知副作用：编辑期间 Settings 页的 Agent 状态（Reload 按钮可用性）不会随定时刷新更新，但不阻塞核心交互。后续可拆出只刷新 Agent 状态、不覆盖表单的轻量方法。

### Finding 2 — MEDIUM — `AgentStateMachine.InitializeAsync` 不验证 options，与 ReloadConfig 口径不一致 — ✅ 已修复

**文件/行号**: `AgentStateMachine.cs:156-169`

**问题**: 启动时直接读取并应用 options，不经过 `AgentOptionsValidator`。如果 `windows-agent.json` 包含无效值，Agent 会使用它们运行，直到 ReloadConfig 时才被拒绝。

**修复**（两轮迭代）:

第一轮只是调了 `Validate()` 但仍使用 `NormalizedOptions`（其只归一化隐私规则，不修正非法数值）。第二轮改为非法时 **fallback 到 `new WindowsAgentOptions()`**，确保非法配置不进入运行态：

```csharp
_options = await _optionsStore.ReadAsync(_paths.AgentOptionsPath, cancellationToken)
    ?? new WindowsAgentOptions();
var startupValidation = _optionsValidator.Validate(_options);
if (!startupValidation.IsValid)
{
    _logger.LogWarning(
        "Agent options validation failed on startup, falling back to defaults: {Errors}",
        string.Join("; ", startupValidation.Issues.Select(issue => issue.SafeText)));
    _options = new WindowsAgentOptions();
}
else
{
    _options = startupValidation.NormalizedOptions;
}
```

**补充测试**: `DataFlowTests.cs` — `AgentStateMachine_InitializeAsync_FallsBackToDefaultsForInvalidConfig_UsesNormalizedForValidConfig`
- 非法配置（`samplingIntervalSeconds=0`, `idleThresholdSeconds=5`）启动 → 校验日志含 "falling back to defaults" → KeePass（默认排除项）被排除
- 合法配置含 `ExcludedProcesses=["notepad.exe"]` 启动 → 归一化为 `["notepad"]` → Notepad 样本被排除

### Finding 3 — MEDIUM — 测试未证明 "ConfigReloaded observed"，只证明命令已排队

**文件/行号**: `DataFlowTests.cs:3272-3326`（`SettingsViewModel_SaveAndReloadSavesThenRequestsReload`）

```csharp
var viewModel = new SettingsViewModel(
    ...
    null,  // getRecentAgentEventsAsync = null → PollForReloadConfigResultAsync 短路

```

当 `_getRecentAgentEventsAsync` 为 null 时，`PollForReloadConfigResultAsync` 只显示：
```
"ReloadConfig command queued. Agent event store is unavailable; check Diagnostics for the result."
```

测试断言也只验证了 `"ReloadConfig command queued"`，没有覆盖成功/失败的完整 polling 路径。

同样的问题也出现在：
- `SettingsViewModel_ReloadConfigDisabledWhenAgentNotRunning` — 只测 NotRunning 状态文本
- `SettingsViewModel_ReloadConfigFailureShowsSafeStatus` — 测的是 `requestReloadConfigAsync` 抛异常，不是 Agent 端 `CommandFailed`
- `SettingsViewModel_RestoreBackupDoesNotReloadAutomatically` — 测的是不写 control file

**生产代码**中 `PollForReloadConfigResultAsync` 有完整的 polling 逻辑（检查 `CommandFailed` → `CommandCompleted` → `ConfigReloaded`，最多等 15 秒），但测试未覆盖成功路径。

**建议修复**: 新增测试 `SettingsViewModel_PollsUntilConfigReloadedObserved`，提供真实的 `getRecentAgentEventsAsync` 回调：
1. 前几次返回空列表（模拟 polling 中间状态）
2. 第 N 次返回包含 `ConfigReloaded` 事件 → 验证显示 success
3. 或返回 `CommandFailed` 事件 → 验证显示 failed + errorCode

**影响**: 中。生产代码路径未被测试覆盖，但逻辑本身正确。建议在 6.6 或 6.7 中补充。

### Finding 4 — LOW — `lastSelectedPage` 可编辑但文档标注为只读

**文件/行号**: `SettingsView.xaml:128-134`, `SettingsViewModel.cs:429-439`, `TryBuildAppSettings:1193-1196`

```xml
<ComboBox Grid.Row="2" Grid.Column="1"
          ItemsSource="{Binding LastSelectedPageOptions}"
          SelectedItem="{Binding LastSelectedPageText, Mode=TwoWay}"
```

文档 `02-阶段6.2-AppSettings编辑.md` 明确写：

> 只读展示：
> lastSelectedPage

实际代码中：
1. XAML 用 ComboBox + TwoWay 绑定，用户可以修改
2. `LastSelectedPageText` setter 标记 `IsDirty = true`
3. `SaveAppSettingsAsync` 会持久化它（通过 `TryBuildAppSettings` 校验合法性）
4. 但是 `MainWindowViewModel.SelectedTabIndex` setter **也会**每次切 Tab 时写 `_appSettings.LastSelectedPage` 并调 `PersistAppSettingsAsync()`（`MainWindowViewModel.cs:218-222`）

存在双写竞争：用户在 Settings 中把 `lastSelectedPage` 设为 "Diagnostics" 并保存，切换到 Dashboard Tab 后，`MainWindowViewModel` 立刻写回 "Dashboard"。

**建议修复**: 两个方向二选一：
- **方向 A**: 恢复文档要求的只读 — 把 ComboBox 改为 TextBlock 或 `IsReadOnly=True`
- **方向 B**: 保留可编辑，更新文档 — 但需解决 MainWindowViewModel 和 SettingsViewModel 的双写竞争

**影响**: 低。不会崩溃或丢数据，但用户体验困惑（改了切 tab 就没了）。建议 6.6 中决定方向并统一。

### Finding 6 — LOW — `PollForReloadConfigResultAsync` 中 ConfigReloaded 事件匹配无 requestId 关联

**文件/行号**: `SettingsViewModel.cs:928-931`

```csharp
var reloadedEvent = events.FirstOrDefault(e =>
    e.EventType == AgentEventType.ConfigReloaded &&
    e.EventTimeUtc >= requestTime);
```

`ConfigReloaded` 事件不携带 `requestId`，polling 用 `requestTime - 2s` 作为时间窗口。如果两个 reload 请求在 15 秒内先后发出，第二个请求的 polling 可能匹配到第一个请求的 `ConfigReloaded`。

**影响**: 低。生产环境中短时间多次 ReloadConfig 极少见。后续增强项。
