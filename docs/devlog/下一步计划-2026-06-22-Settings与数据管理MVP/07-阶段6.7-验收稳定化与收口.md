# 阶段 6.7：验收、稳定化与收口

## 阶段目标

对 Settings 与配置应用 MVP 做最终验收，确认它没有破坏采集、诊断、Dashboard 和数据浏览链路。

本阶段只收口配置闭环，不实施真实数据清理。

## 自动化验收

完成后应满足：

```text
1. dotnet build 0 warning / 0 error
2. dotnet test 全部通过
3. SettingsView 能显示 App 配置
4. SettingsView 能显示 Agent 配置
5. SettingsView 能编辑 App 配置
6. SettingsView 能编辑 Agent 基础配置
7. 配置校验能拦截无效值
8. 保存失败不破坏旧配置
9. Restore Backup 能恢复文件但不自动宣称生效
10. ReloadConfig 成功 / 失败有 Diagnostics 证据
11. 隐私规则修改后对后续采集生效
12. Agent 未运行时 Reload 不可用且提示下次启动生效
13. Dashboard / Apps / Sessions / Samples / Diagnostics 不回归
```

## 手动验收流程

建议手动验证：

```text
1. 打开 Settings，确认 App Settings / Agent Options 显示正常
2. 修改 refreshIntervalSeconds，保存后确认自动刷新间隔变化
3. 修改 samplingIntervalSeconds，Save
4. 确认保存后不宣称 Agent 已应用
5. 点击 Save and Reload
6. 观察 Diagnostics 中 ReloadConfig / ConfigReloaded
7. 修改 idleThresholdSeconds，观察后续 idle 判断变化
8. 开启 maskWindowTitles，确认 Samples 不显示真实标题
9. 添加 excludedProcesses=notepad，确认 Notepad 不进入 samples / sessions
10. 添加 excludedTitlePatterns，确认命中标题不落库
11. Restore Backup，确认文件恢复但 UI 提示仍需 ReloadConfig / 下次启动
```

## 阶段 7 边界确认

本阶段不做：

```text
PruneData
ClearHistory
Maintenance 状态
真实 SQLite / JSONL 删除
```

阶段 7 开始前必须先补：

```text
Maintenance 状态与清理命令骨架
PruneData
ClearHistory
ClearHistory 双确认 + 输入 CLEAR 确认词
清理后 runtime_state / health_state 可观测
```
