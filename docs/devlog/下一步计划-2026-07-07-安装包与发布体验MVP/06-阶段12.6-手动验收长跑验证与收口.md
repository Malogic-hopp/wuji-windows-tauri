## 自动化验收

完成后应满足：

```text
1. build 0 warning / 0 error
2. test 全部通过
3. publish 输出包含 App 和 Agent
4. 安装包可构建
5. 阶段 11 开机自启测试不回归
6. 阶段 10 托盘测试不回归
7. 阶段 9 RefreshService / status polling 测试不回归
8. 阶段 8 IPC 测试不回归
9. 阶段 7 PruneData / ClearHistory 测试不回归
```

建议命令：

```powershell
dotnet build QuantifiedSelf.Windows.sln --no-restore -p:BaseOutputPath=.codex/build-output/
dotnet test QuantifiedSelf.Windows.sln --no-restore -p:BaseOutputPath=.codex/test-output/
dotnet publish src/QuantifiedSelf.Windows.App/QuantifiedSelf.Windows.App.csproj -c Release -r win-x64 --self-contained
```

测试后清理 `.codex` 输出目录。

## 手动验收

建议至少验证：

```text
1. 安装包可在干净 Windows 环境运行。
2. 安装后安装目录包含 App exe 和 Agent exe（名称与 12.1 最终确定一致）。
3. 安装后开始菜单出现 WUJI 快捷方式。
4. 从开始菜单启动 WUJI 后托盘图标出现（目标 exe 以 12.1 最终确定为准）。
5. 安装时勾选"开机自启"后，HKCU Run Key 出现 WUJI value（command 指向实际 App exe 路径）。
6. 安装时不勾选"开机自启"后，HKCU Run Key 不出现 WUJI value。
7. 安装后 Settings 中 StartAppOnWindowsLogin 状态与安装时选择一致。
8. 安装后 Agent 可启动、暂停、恢复、停止。
9. 卸载后 HKCU Run Key 中 WUJI value 被删除。
10. 卸载后安装目录被删除。
11. 卸载后开始菜单快捷方式被删除。
12. 卸载后默认保留 %LocalAppData%\WUJI\WindowsAgent 数据目录。
13. 再次安装后原有配置和数据可读取（升级场景）。
14. 手动启动 App exe 仍显示主窗口。
15. 自启参数启动 App exe 仍隐藏到托盘。
16. 托盘 Show / Exit / Start / Pause / Resume / Stop 不回归。
17. CloseToTray / MinimizeToTray 不回归。
18. Exit App 后托盘图标不残留，Agent 不被误停。
19. Settings dirty 时等待 status polling，不覆盖编辑草稿。
20. 应用图标在窗口、任务栏、托盘均显示正常。
21. 安装包版本号与 App 版本号一致（如 About 页面已实现，则同时与 About 页面一致）。
22. App exe 和 Agent exe 文件名与 12.1 最终确定一致，安装包快捷方式目标正确。
23. 重复启动 App exe 不会产生双托盘 / 双窗口 / 状态漂移；如出现异常，阶段 12 不应收口，需将轻量 single-instance 提升为前置修复。
```

## 长跑验证

建议做：

```text
1. 安装 WUJI，启用开机自启，重启 Windows 后观察 WUJI 是否自动启动到托盘。
2. 安装后常驻运行 15-30 分钟，托盘状态不漂移。
3. Pause / Resume / Stop / Start 从托盘循环 3-5 次。
4. 卸载后重新安装，验证原有数据是否保留（如默认保留）。
5. 升级安装（旧版本基础上安装新版本），验证配置和数据是否保留。
6. 安装、使用、卸载全流程循环 2-3 次，无残留注册表项。
```

## 风险复核

补充要求：

```text
1. 阶段 11 状态以《阶段11-完成说明-2026-07-06.md》和《阶段11-验收清单-2026-07-06.md》为准：build 0 warnings / 0 errors，test 356/356 passed，手动验收 21/21 通过，长跑验证 6/6 通过。
2. 阶段 12.1 优先保证 self-contained win-x64 发布目录稳定；单文件发布为可选，不得为了单文件输出牺牲 App / Agent 路径可靠性。
3. 阶段 12.1 必须修复 AgentProcessService 的 Agent exe 路径解析，使发布目录和开发目录同时可用。Agent exe 查找顺序：
   - AppContext.BaseDirectory 下的 Agent exe（如 QuantifiedSelf.Windows.Agent.exe 或 WUJI.Agent.exe，以实际 publish 输出为准）
   - 环境变量 QUANTIFIEDSELF_WINDOWS_AGENT_EXE 指定路径
   - 开发目录 fallback
   - 找不到时返回安全错误，不抛未处理异常。
4. 阶段 12.1 不实现 --register-autostart / --unregister-autostart 命令行入口；该入口留到阶段 12.4。
5. 查找当前 App exe 时，StartupCommandBuilder 继续使用 Environment.ProcessPath / Process.MainModule.FileName；不要使用 Assembly.Location，因为 single-file 下它可能为空。
6. 12.1 不引入 MSIX / WiX / Inno Setup 配置，不新增 installer/ 目录；安装包选型留到 12.3。
7. 安装包默认不写 HKCU Run Key。阶段 12.4 优先新增 `<AppExeName> --register-autostart` / `--unregister-autostart` 命令行入口（如 WUJI.exe 或 QuantifiedSelf.Windows.App.exe），内部复用阶段 11 StartupRegistrationService；安装包调用该命令完成自启注册 / 取消注册。若安装器技术限制导致无法调用命令，才允许直接写 HKCU Run Key，并必须复用 StartupCommandBuilder 的 command 规则。
8. 卸载前应检测 WUJI App / Agent 是否正在运行；MVP 可提示用户先退出，不应静默强杀或在进程运行时删除正在使用的文件。
9. 卸载默认保留 %LocalAppData%\WUJI 数据；删除用户数据必须是显式选项，默认不勾选。
10. 发布产物目录名、安装包文件名、安装包版本、App 显示版本、Agent 版本应来自同一版本源。
11. 如果安装包未签名，发布说明和完成说明必须记录 SmartScreen / 杀软误报 / 用户信任风险，并标注为 unsigned MVP installer。
```

补充约束：

```text
1. 阶段 12.1 不新增 App -> Agent 项目引用；App 和 Agent 同目录发布应通过 publish 脚本或 MSBuild target 显式完成，避免破坏双进程边界。
2. 阶段 12.1 发布目录中的 Agent 必须来自 Release / win-x64 / self-contained publish 产物，不允许复制 Debug 输出作为发布产物。
3. 阶段 12.3 安装包选型必须先验证当前用户安装、HKCU Run Key、自定义卸载清理、未签名安装体验；如 MSIX / WiX 阻力过大，MVP 可转 Inno Setup，并在完成说明记录原因。
4. 阶段 12.4 的 --register-autostart / --unregister-autostart 必须是 headless 命令：不显示窗口、不创建托盘、不启动 Agent、不启动刷新 timer，执行后立即退出并返回明确 exit code；错误输出不得泄露完整路径、用户名、SID。
5. 阶段 12.6 必须复测重复启动；如出现双托盘 / 双窗口 / 状态漂移，single-instance 应提升为阶段 12 收口前置修复，阶段 12 不应收口。
```

收口前需要确认：

```text
1. 安装包不会把 App 或 Agent 安装到需要管理员权限才能写入的目录（默认）。
2. 安装包不会默认启用需要管理员权限的功能。
3. 卸载时 HKCU Run Key 中的 WUJI value 被删除。
4. 卸载时不会误删其他软件的注册表项。
5. 安装后的 App exe 路径稳定，StartupCommandBuilder 不会因路径变化注册错误。
6. 安装包版本号与 App 版本号一致。
7. 数据目录与安装目录分离，卸载默认保留数据。
8. 阶段 11 自启逻辑不回归。
9. 阶段 10 托盘语义不回归。
10. 阶段 9/8/7 不回归。
11. 安装包不破坏 Agent 是唯一 SQLite 写入者的原则。
12. 安装包不泄露完整路径、SID、用户名目录到日志或发布说明。
13. 重复启动行为已评估，single-instance 是否作为后续前置项已有结论。
```
