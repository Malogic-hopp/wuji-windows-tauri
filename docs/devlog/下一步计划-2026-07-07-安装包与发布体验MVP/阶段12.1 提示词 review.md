# 建议补强的小点

## 1. publish 脚本的最终目录名建议更明确

现在要求默认输出到 `.codex\publish`，并示例查看：

```powershell
Get-ChildItem .codex\publish\App
```

建议补一句：

```text
最终合并目录固定为 .codex\publish\App，Agent 临时发布目录为 .codex\publish\Agent；完成后 App 目录是最终可运行发布目录。
```

这样 agent 不会把 `.codex\publish`、`.codex\publish\App`、`.codex\publish\final` 搞出多个标准。

## 2. publish 脚本不要清理最终产物

提示词后面有 `.codex` 清理建议，但 12.1 需要人工查看 publish 结果。建议补一句：

```text

```

否则 agent 可能跑完 publish 后把产物清掉，导致无法验收。

## 3. “不泄露完整路径”在开发日志里可以区分一下

你要求错误日志不泄露完整用户路径、SID、用户名。这个原则对，但路径解析失败时开发者有时需要知道候选路径类型。建议补一句：

```text
错误文案可以显示候选来源类型，例如 BaseDirectory / EnvVar / DevelopmentFallback，但不要显示完整用户目录路径。
```

这样兼顾安全和可诊断性。
