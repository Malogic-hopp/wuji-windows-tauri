# 三、阶段 9 可以收口的理由

阶段 9 已经完成了这几件关键事：

```text id="n6brv6"
1. RefreshService 成为刷新协调入口。
2. 2 秒 status polling 独立于页面数据刷新。
3. status/page refresh 使用独立 gate。
4. 旧 sequence 不覆盖新状态。
5. MainWindow 和 Settings 共用 AgentStatusSnapshot。
6. Settings IsDirty 不被自动刷新覆盖。
7. Diagnostics 能看到 IPC 状态和 RefreshHealth。
8. Agent Stop/Start、断连重连、Stale 恢复、Maintenance、ClearHistory 等关键路径通过验收。
```

总完成说明也列出阶段 9 没有做的内容：真正长连接状态流、Named Pipe subscribe/stream、托盘、自启、安装包、趋势图、导出、应用分类、分页、RefreshHealth 持久化等都没有被提前混入。这个边界保持得很好。

---

# 四、仍然需要注意的遗留点

## 1. Diagnostics 的 RefreshHealth 目前是单行文本

当前实现是单行综合展示，优点是改动小，缺点是可读性一般。这个不影响阶段 9 收口，但后续做产品体验时可以拆成几行或小卡片。

建议后续不要单独开大阶段处理，可以在托盘/后台运行阶段顺手做一个小 UI polish。

---

## 2. 禁用按钮的视觉状态不明显

阶段 9.6 手动验收里提到 Pause/Resume 功能正确，但“按钮禁用态 UI 不明显”，原因是 `SecondaryButtonStyle` 没有 disabled 触发器。

这个不是逻辑 bug，但属于用户体验问题。建议下一阶段开始前或 10.1 里先补：

```text id="gd19ai"
SecondaryButtonStyle disabled visual state
```

否则后面托盘/后台运行阶段继续强化状态体验时，用户仍可能觉得“按钮没反应”。

---

## 3. 真正状态流仍未实现

阶段 9 文件名虽然曾含“状态流订阅”，但实际范围是集中状态轮询。总完成说明也明确真正 Named Pipe status stream / subscribe protocol 留到后续增强。

这不是问题。现在还不建议马上做真正状态流，因为托盘和后台运行更接近产品闭环，收益更直接。

---

# 六、为什么下一步适合做托盘

现在 WUJI 已经具备：

```text id="rwg7zc"
采集
诊断
数据浏览
配置
数据清理
Named Pipe 控制
RefreshService 状态刷新
断连重连恢复
```

用户真实使用时，下一步最自然的问题会变成：

```text id="k7t0kj"
我能不能关闭主窗口但 Agent 继续运行？
我能不能从系统托盘看到 Running / Paused？
我能不能从托盘 Pause / Resume / Stop？
Agent 出错时我能不能从托盘看到提示？
```

这些都属于托盘与后台运行 MVP。

# 七、阶段 10 推荐目标

一句话目标：

```text id="x8jsrq"
让 WPF App 支持关闭到托盘、托盘显示 Agent 状态，并能通过托盘执行 Start / Pause / Resume / Stop / Show / Exit 等基础操作。
```

建议边界：

```text id="qso3iu"
托盘只控制 App 窗口和 Agent 基础命令；
不做开机自启；
不做安装包；
不做 Windows Service；
不做复杂通知中心；
不做真正状态流；
不删除现有主窗口控制入口。
```

# 九、阶段 10 的关键设计原则

## 1. 关闭主窗口不等于停止 Agent

建议语义：

```text id="1htiq3"
点击窗口 X：
    默认隐藏到托盘，Agent 继续运行

托盘 Exit App：
    退出 WPF App，但不强制停止 Agent

托盘 Stop Agent：
    明确请求停止 Agent

托盘 Exit App + Stop Agent：
    后续增强，不在 MVP 必做
```

不要让“关闭 App”默认杀 Agent，否则会破坏后台监控的产品预期。

---

## 2. 托盘状态复用阶段 9 的状态快照

托盘不要自己另开一套状态查询逻辑。应该复用：

```text id="7be0re"
RefreshService
AgentStatusSnapshot
AgentCommandAvailability
AgentIpcStatusService
```

避免 MainWindow 显示 Running，托盘菜单显示 Paused。

---

## 3. 托盘命令继续走现有服务

托盘菜单点击：

```text id="gub6f3"
Start Agent → AgentProcessService
Pause / Resume / Stop → AgentControlService / AgentProcessService
```

不要在 TrayService 里重新实现控制逻辑。

---

## 4. 托盘不要引入 Windows Service / 自启 / 安装包

这些应放后续：

```text id="6yswfm"
阶段 11：开机自启 MVP
阶段 12：安装包 / 发布体验
```

托盘先把“后台运行体验”跑通。

---

# 十、阶段 10 验收标准建议

完成阶段 10 后至少满足：

```text id="61fbpf"
1. build 0 warning / 0 error。
2. test 全部通过。
3. App 启动后出现托盘图标。
4. 托盘 tooltip 能显示 Agent 当前状态。
5. 关闭主窗口后 App 隐藏到托盘，Agent 不被停止。
6. 托盘 Show 能恢复主窗口。
7. 托盘 Exit App 能退出 WPF App。
8. 托盘 Start / Pause / Resume / Stop 使用现有控制服务。
9. Maintenance 中托盘高风险命令禁用。
10. MainWindow 和托盘菜单状态不漂移。
11. Agent 停止 / 重启后托盘状态能恢复。
12. Settings dirty 不受托盘状态刷新影响。
```
