## 阶段目标回顾

阶段 9 的目标是把 WPF App 的 Agent 状态刷新从当前页数据刷新中解耦出来，形成统一、可取消、可观测、不会覆盖未保存编辑的刷新机制。

本阶段实际完成后，WPF 状态体验从：

```text
分散定时刷新 + 页面刷新顺手带状态
```

推进为：

```text
RefreshService 协调刷新
2 秒 IPC GetStatus 轻量状态轮询
runtime_state / health_state fallback
status refresh 与 page refresh 独立 gate
MainWindow / Settings 共用 AgentStatusSnapshot 派发按钮状态
Diagnostics 展示 IPC 状态与 RefreshHealth
```

本阶段仍然没有实现真正长连接推送式状态流；阶段 9 MVP 的执行范围是集中状态轮询。

## 核心实现

### RefreshService

新增 / 扩展：

```text
src\QuantifiedSelf.Windows.App\Services\RefreshService.cs
src\QuantifiedSelf.Windows.App\Services\RefreshResult.cs
src\QuantifiedSelf.Windows.App\Services\RefreshHealthSnapshot.cs
src\QuantifiedSelf.Windows.App\Services\RefreshOptions.cs
```

实现要点：

```text
RefreshAsync:
    刷新 Agent status + process info
    返回 RefreshResult
    记录 RefreshSequence / StartedAtUtc / CompletedAtUtc

RefreshStatusAsync:
    status-only 刷新
    用于 2 秒轮询
    不刷新 Dashboard / Apps / Sessions / Samples / Diagnostics / Settings 页面数据

RefreshHealthSnapshot:
    status refresh 与 page refresh 分别记录 success / error / skipped / refreshing
    错误文本保持安全短句
```

### MainWindowViewModel

主要行为：

```text
2 秒 status polling timer
status polling latest-wins
status poll 不调用页面数据服务
手动 Refresh = status + 当前页数据
status/page 独立 gate
Settings IsDirty 时不覆盖配置草稿
Diagnostics 页实时更新 RefreshHealthText
```

关键修复：

```text
ApplyStatusRefreshResult 只检查 LastStatusRefreshError。
page refresh error 不再阻止后续 status poll 更新顶部状态和按钮状态。

ApplyStatusRefreshResult 使用 RefreshSequence guard。
旧低 sequence 状态不会覆盖新高 sequence 状态。
```

### AgentCommandAvailability

新增：

```text
src\QuantifiedSelf.Windows.App\Services\AgentCommandAvailability.cs
```

统一规则：

```text
Running:
    Pause / Stop / ReloadConfig / PruneData / ClearHistory 可用

Paused:
    Resume / Stop / ReloadConfig / PruneData / ClearHistory 可用

Maintenance:
    控制命令和数据清理命令禁用

NotRunning / Stopped:
    Start 可用
    ReloadConfig 保留“下次启动生效”语义
    PruneData / ClearHistory 不可用

Stale + IsRunning=true:
    Stop 可用
    Start 不可用

Stale + IsRunning=false:
    Start 可用
```

`Stale + IsRunning=false` 修复覆盖了真实问题：Agent 退出后 `runtime_state.json` / `health_state.json` 残留 Running，App 下次启动显示 Stale 但应允许 Start。

### Diagnostics

Diagnostics 保留 IPC 状态展示，并新增 RefreshHealth：

```text
IPC connected / unavailable / fallback
DisplayPipeName
Last IPC success / error
Refresh loop: Healthy / Degraded / Refreshing / Ready
Status refresh: last success / safe error / skipped count
Page refresh: last success / safe error / skipped count / page
Intervals: status polling 2s / page refresh N seconds
```

安全约束：

```text
不显示 FullPipeName
不显示完整 SID
不新增路径、SQL、窗口标题、原始 JSON 泄露
RefreshHealth 错误展示走 DiagnosticMessageSanitizer
```

## 重要修复记录

阶段 9 审核中修复的关键问题：

```text
1. RefreshService 路径绕过外层 refresh gate。
2. status 失败时默认 AgentStatusSnapshot 覆盖真实 UI 状态。
3. status polling 和 full refresh 共用 gate，导致状态轮询被页面刷新阻塞。
4. 取消中的 status poll 被记为错误。
5. 完整刷新旧 sequence 可能覆盖新状态。
6. status/page refresh health 未拆分，错误互相污染。
7. page refresh gate 被外层 refresh gate 包住，skipped count 无法记录。
8. IsPageRefreshing 未置 true。
9. ConfirmClearHistoryCommand 未随 CanExecuteDataCleanup 变化通知。
10. Diagnostics RefreshHealth 不随 status polling 更新。
11. Stale + IsRunning=false 时 Start Agent 被禁用。
12. page error 残留阻止后续 status poll 应用。
13. latest-wins 测试未真实覆盖低 sequence 晚到场景。
```

以上均已修复并补测试或手动验收。
