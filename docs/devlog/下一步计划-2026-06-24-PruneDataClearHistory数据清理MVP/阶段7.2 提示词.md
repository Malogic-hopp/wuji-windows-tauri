3. cutoff 口径必须明确：

SQLite 删除使用 UTC cutoff：

- foreground_samples.sample_time_utc < cutoffUtc
- app_sessions.ended_at_utc IS NOT NULL AND ended_at_utc < cutoffUtc
- agent_events.event_time_utc < cutoffUtc

JSONL 删除使用本地文件日期 cutoff：

- 按本地文件日期解析 agent_events_YYYYMMDD.jsonl
- 按本地文件日期解析 foreground_samples_YYYYMMDD.jsonl（如果存在）
- 只删除 fileDateLocal < cutoffLocalDate 的文件

不要用 UTC 日期解释 JSONL 文件名。

4. SQLite 删除必须使用事务：

逻辑等价于：

BEGIN TRANSACTION
DELETE FROM foreground_samples WHERE sample_time_utc < cutoffUtc
DELETE FROM app_sessions WHERE ended_at_utc IS NOT NULL AND ended_at_utc < cutoffUtc
DELETE FROM agent_events WHERE event_time_utc < cutoffUtc
COMMIT

任一 DELETE 失败必须 ROLLBACK。

如果表缺失：
- 可以安全返回 0，或用清晰错误处理。
- 不要让 Agent / 测试因为旧库缺表直接崩掉。
- 参考现有查询服务和 AgentEventRepository 对缺表的处理方式。

5. JSONL 删除规则：

目标文件名：
- agent_events_YYYYMMDD.jsonl
- foreground_samples_YYYYMMDD.jsonl

只删除：
- fileDateLocal < cutoffLocalDate

必须保留：
- 当前日期 JSONL
- cutoffLocalDate 当天 JSONL
- 非目标文件
- 配置文件
- runtime 文件
- 数据库文件本体
- SQLite WAL / SHM

JSONL 删除失败时：
- 不做复杂补偿。
- 返回失败或错误计数，后续阶段由 Agent 写 CommandFailed。
- safeMessage 不包含完整路径。
- payload / result 不记录完整路径。

6. 不删除 open session：

app_sessions 中 ended_at_utc IS NULL 的记录不能删除。

7. 不做 VACUUM：

SQLite 删除大量数据后文件大小不变是可接受的，阶段 7.2 不做数据库压缩。
