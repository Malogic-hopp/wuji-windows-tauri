# 建议补强 1：明确字段命名和 JSON 兼容性

建议加一句：

```text id="9sd83f"
StartAppOnWindowsLogin 应保持普通 System.Text.Json 属性序列化兼容，不需要自定义 converter；旧配置缺字段时默认 false，新保存配置应包含该字段或能稳定 round-trip。
```

这能避免 agent 做不必要的序列化改造。

---

# 建议补强 2：`--start-hidden` 单独出现时不要视为 AutoStart

你已经建议测试：

```text id="2r8t9q"
StartupLaunchOptions_ParsesOnlyStartHiddenWithoutFromAutostart
```

建议再明确预期：

```text id="n9ycn0"
只有 --from-autostart 才将 LaunchMode 设为 AutoStart；单独 --start-hidden 只表示 StartHidden=true，但 Mode 仍为 Manual。
```

这样语义更清晰。后续如果用户手动用 `--start-hidden` 启动，可以保留扩展空间，但不会误认为来自 Windows 自启。

---

# 建议补强 3：启动参数大小写策略要明确

建议加一句：

```text id="g5f7ta"
启动参数解析建议大小写不敏感，例如 --FROM-AUTOSTART 与 --from-autostart 等价；但输出 RawArgs 保留原值。
```

Windows 命令行参数一般用户可能大小写混用，大小写不敏感更稳。

---

# 建议补强 4：不要把 RawArgs 写入日志或 UI

你提到 `RawArgs` 可选用于调试/日志。考虑后续可能有路径/参数隐私，建议补一句：

```text id="l4vzrv"
RawArgs 仅用于测试或内部调试，本阶段不要把完整 RawArgs 展示到 UI、Diagnostics 或日志。
```

这样可以避免未来把完整命令行参数暴露出去。

---

# 建议补强 5：App.xaml.cs 解析结果目前可以只保存在字段里

为了避免 agent 过度接入，建议补一句：

```text id="huhm9q"
App.xaml.cs 中解析得到的 StartupLaunchOptions 本阶段可以只保存在私有字段，或仅用于完成代码路径验证；不得传入 TrayService / MainWindowViewModel 改变行为。
```

你已经写了不要改变行为，这句可以更细化。

# 建议补强 6：SettingsViewModel 预支持不要触发注册逻辑
