# 建议补强 1：LaunchMode 来源要固定，避免每次重新解析全量命令行

提示词里说“复用阶段 11.1 的 StartupLaunchOptions 获取当前 LaunchMode”。建议加一句：

```text id="lhvfx9"
LaunchMode 应来自 App 启动时已解析并保存的 StartupLaunchOptions / provider；Diagnostics 不应在刷新时反复调用 Environment.GetCommandLineArgs() 并重新解析。
```

这样可以避免不同组件各自解析参数，导致状态不一致。

---

# 建议补强 2：自启状态刷新频率要低风险

Diagnostics 页面刷新时读取注册表可以接受，但不要每 2 秒 status polling 都读。你已经写“不新增高频轮询”，建议更明确：

```text id="lt2wqf"
自启状态只在 Diagnostics 页面刷新 / Settings 显式刷新 / App 启动初始化时读取；不要接入 2 秒 status polling 的每次 tick。
```

否则 `GetStatusAsync()` 可能频繁读注册表。

---

# 建议补强 3：不要让 Diagnostics 刷新改变 Settings 草稿

虽然 11.5 是只读展示，但它可能复用 Settings 状态文本。建议补一句：

```text id="c5pj9z"
Diagnostics 刷新自启状态不得修改 SettingsViewModel 的 StartAppOnWindowsLogin 草稿值，也不得触发 Settings IsDirty。
```

这延续 11.3 的 dirty 规则。

---

# 建议补强 4：StartupRegistrationStatus 到展示文案最好集中转换

现在提示词说“安全摘要文案由 StartupRegistrationStatus 安全转换而来”。建议更具体：

```text id="v5o4aa"
建议新增 StartupRegistrationDisplayModel / StartupRegistrationStatusFormatter 之类纯模型，把 Enabled / Disabled / Mismatch / Error / Unsupported 转换为安全展示文案；Diagnostics 和 Settings 复用同一转换，避免两处文案不一致。
```

这样 Diagnostics 和 Settings 的状态文本不会漂移。

---

# 建议补强 5：UnsupportedInCurrentLaunchMode 也要展示

11.2 设计了 `UnsupportedInCurrentLaunchMode`。11.5 的提示词主要写了 Enabled / Disabled / Mismatch / Error，建议补上：

```text id="86t3re"
如果 StartupRegistrationStatus 为 UnsupportedInCurrentLaunchMode，应显示安全摘要，例如 Registration unavailable in current launch mode，不显示当前进程路径。
```

否则 Debug / dotnet run 场景可能状态展示不完整。

---

# 建议补强 6：Settings 简短状态是否改 UI 要明确

提示词说 Settings 中“可保留简短状态文本”，但 11.3 已经做过 Settings 状态文本。为了避免重复改 Settings UI，建议明确：

```text id="ca2s80"
如果阶段 11.3 已经在 Settings 中展示 StartupRegistrationStatusText，本阶段只复用/微调安全文案，不重构 Settings UI。
```

这样 11.5 主要聚焦 Diagnostics。
