## 第 1 步：真实采样连续运行测试

先运行 30-60 分钟。

观察这些文件和表：

```text
runtime_state.json
health_state.json
foreground_samples
app_sessions
```

重点检查：

```text
1. 是否持续 heartbeat
2. 是否持续写 sample

5. app_sessions 是否出现异常超长 open session
6. Pause 后是否不再写 sample
7. Resume 后是否继续写 sample

```

建议手动覆盖窗口：

```text
Visual Studio
Edge / Chrome
Explorer
Windows Terminal / PowerShell
桌面
任务栏 / 开始菜单
管理员权限窗口
空标题窗口
```

## 第 2 步：补 Win32 采样失败分类

`Win32ForegroundSampleProvider` 需要明确区分失败情况。

建议错误码：

```text
NoForegroundWindow
WindowTitleUnavailable
ProcessNotFound
ProcessAccessDenied
ExecutablePathUnavailable
UnknownError
```

不要全部吞成一个 `Unknown`。

可考虑在 `ForegroundSample` 或内部 capture result 中保留：

```text
capture_status
capture_error_code
```

注意：

```text
错误详情不要包含敏感窗口标题。
```

建议第一版做法：

```text
1. ForegroundSample 增加 CaptureStatus / CaptureErrorCode
2. SQLite foreground_samples 表增加 capture_status / capture_error_code
3. Win32ForegroundSampleProvider 对不同失败分支写不同 error_code
4. Dashboard 暂时不展示这些字段
5. Diagnostics / SamplesView 后续再展示
```

如果暂时不想改表，也可以先定义内部 capture result 和 health message，但最终建议进入 samples 表，方便后续排查。

## 第 3 步：处理 Explorer / 桌面 / 空窗口

真实使用中经常会遇到：

```text
explorer
Shell_TrayWnd
Program Manager
WorkerW
空标题窗口
桌面窗口
任务栏
开始菜单
```

MVP 建议口径：

```text
前台窗口句柄为 0：
    不写 sample，只更新 heartbeat

process 有值但 title 为空：
    允许写 sample
    window_title 保持 null 或 "[Desktop]"

process_name = explorer 且 title 为空：
    可以视为桌面 / Explorer 活动
```

原因：

```text
句柄为 0 时写 Unknown sample 容易污染统计。
process 有值但 title 为空时仍有统计价值，不应直接丢弃。
```

---

## 第 4 步：权限不足处理规范

`Process.MainModule.FileName` 很容易因为权限不足抛异常。

当前方向是对的：

```text
ExecutablePath 失败则 null
不要因为路径失败丢弃整个 sample
```

固定字段优先级：

```text
process_name：
    核心字段，必须尽量有

executable_path：
    增强字段，失败可以 null

window_title：
    隐私敏感字段，必须先过滤 / 脱敏再落库
```

验收：

```text
1. 管理员窗口读不到 MainModule 时，sample 仍可写入
2. executable_path 为 null 不影响 session 合并
3. health_state 不因为路径不可读进入 Error
```

---

## 第 5 步：固定 idle 统计口径

当前已有 `WindowsIdleDetector`。

本阶段固定口径：

```text
idleSeconds < idleThresholdSeconds
    => Active

idleSeconds >= idleThresholdSeconds
    => Idle
```

session 聚合口径：

```text
Active sample 增加 active_duration_seconds
Idle sample 增加 idle_duration_seconds
Unknown sample 增加 unknown_duration_seconds
```

MVP 对 idle 归属的判断：

```text
idle sample 仍然归属当前前台应用。
```

例如：

```text
用户停留在 Chrome 不动 5 分钟
    => Chrome 增加 idle 时长
```

这个口径简单、稳定、可解释。

## 第 6 步：真实采样稳定后做 agent_events / JSONL

真实采样稳定后，下一步建议做：

```text
agent_events + JSONL 审计日志
```

原因：

当前已有很多关键动作：

```text
AgentStarted
AgentStopped
AgentPaused
AgentResumed
CommandReceived
CommandConsumed
CommandInvalidJson
PrivacyFiltered
CaptureFailed
SessionStarted
SessionClosed
ConfigReloaded
```

如果只靠 `runtime_state.json` / `health_state.json`：

```text
只能看到当前状态
难以追踪历史
难以定位长期运行中的偶发问题
```

建议后续落地：

```text
1. SQLite 增加 agent_events 表
2. logs 增加 agent_events_YYYYMMDD.jsonl
3. AgentStateMachine / SessionAggregator / ControlFileStore 关键动作写事件
4. Diagnostics 展示最近事件和最近错误
```
