## 1. 实施范围

本批只完成阶段 5B“Rust Commands”：

- 增加固定语义 Tauri command：`settings_get`、`settings_update`；
- 加入 Rust invoke handler 白名单；
- 加入 React command 白名单与 typed client 方法；
- 为只读和保存操作设置不同的外层 timeout；

本批没有实现 React Settings 表单，没有增加默认值、范围校验或设置合并，也没有修改 5A schema、Application/Bridge 业务语义、WPF、IPC、SQLite、Agent 状态机或发布流程。

## 2. 固定语义 Commands

Rust invoke handler 新增：

```text
settings_get
settings_update
```

对应唯一 Bridge method：

```text
settings_get     -> settings.get
settings_update  -> settings.update
```

签名直接使用 schema 生成类型：

```text
SettingsGetResult
SettingsUpdateParams
SettingsUpdateResult
```

`settings_get` 通过现有无参数 typed request 读取；`settings_update` 接收完整 `SettingsUpdateParams` 并通过新增的 `request_with_params` 原样序列化到 JSON-RPC `params`。Rust 不拆解字段、不补默认值、不检查范围，也不合并当前设置。

## 3. Supervisor timeout 与错误语义

Bridge 内层 timeout 在 5A 分别为读取 10 秒、保存 15 秒。Tauri Supervisor 外层 timeout 设置为：

```text
settings.get      12 秒
settings.update   18 秒
```

外层窗口略大于 Bridge 内层窗口，正常情况下由 Bridge 先返回明确的 `request_timeout`。`settings.get` 无副作用，超时可重试；`settings.update` 可能已经落盘，超时返回 `retryable: false`，提示调用方重新读取设置，不允许盲目重复保存。

`CommandError` 新增可选生成类型 `SettingsFieldError[]`。Bridge 的 `validation_failed`、固定字段名和安全消息可以到达 React；Rust 不解释、重写或扩展校验错误，其他本地 transport 错误不携带字段数据。

## 4. Rust 与 React 白名单

Rust `COMMAND_WHITELIST` 和 `tauri::generate_handler!` 现在精确包含十个命令：

```text
app_initialize
agent_get_status
agent_start
agent_pause
agent_resume
agent_stop
activity_get_overview
settings_get
settings_update
bridge_retry
```

React `commandWhitelist` 同步加入两个 Settings command，并提供：

```text
bridgeClient.getSettings()
bridgeClient.updateSettings(settings)
```

React 只向 Tauri 传入 `{ request: { settings } }`，其中 `request` 与 `settings` 均受生成 TypeScript 类型约束。WebView 仍没有通用 Bridge method、shell、文件、SQL、HTTP、进程、路径或配置文件能力。

## 5. Query 失效

新增固定 query key：

```text
['settings', 'current']
```

既有 `refreshQueriesAfterBridgeReady` 在 Bridge generation 进入 ready 时会同时：

- reset initialize query；
- reset Agent status query；
- invalidate Dashboard Overview query；
- invalidate Settings current query。

因此 Bridge 自动恢复或用户点击重新连接后，5C 接入的 Settings query 不会继续展示旧 Bridge generation 的缓存。保存成功后的精确 mutation 失效留给 5C 表单实现。

## 6. 架构边界

自动门禁确认：

- `settings_get/settings_update` 只存在于固定 Rust/React 白名单；
- command 使用生成 request/result 类型；
- Supervisor 只负责 JSON-RPC 封装、关联 ID、timeout 和 transport 错误；
- Settings 参数序列化前后结构完全一致；
- Rust 中没有 Core 默认值、范围常量、Settings validator 或 merge 函数；
- Bridge 字段错误原样保留，但不会把底层异常补充进响应；
- Bridge ready 明确失效 Settings query。
