## 架构原则

### 1. 关闭主窗口不等于停止 Agent

建议 MVP 语义：

```text
点击窗口 X:
    如果 CloseToTray=true:
        Hide 主窗口
        App 继续运行
        Agent 不受影响

托盘 Exit App:
    真正退出 WPF App
    不默认 Stop Agent

托盘 Stop Agent:
    明确请求停止 Agent

Exit App + Stop Agent:
    后续增强，不在 MVP 必做
```

这样用户不会因为关闭窗口而误停后台采集。

### 2. 托盘状态复用阶段 9 的状态快照

托盘不要另开一套状态查询逻辑。应复用：

```text
RefreshService
AgentStatusSnapshot
AgentCommandAvailability
AgentIpcStatusService
MainWindowViewModel 当前已应用状态
```

目标是避免：

```text
MainWindow 显示 Running
托盘 tooltip 显示 Paused
Settings 认为 Maintenance
```

### 3. 托盘命令复用现有控制服务

托盘菜单点击继续走已有服务：

```text
Start Agent:
    AgentProcessService.StartAgentAsync / MainWindowViewModel.StartAgentCommand 等价路径

Pause / Resume:
    AgentControlService.PauseAsync / ResumeAsync 等价路径

Stop:
    AgentProcessService.StopAgentGracefullyAsync / MainWindowViewModel.StopAgentCommand 等价路径
```

不要在 TrayService 中重新实现 IPC、file fallback 或进程控制。

### 4. TrayService 是 UI shell 服务，不是业务服务

TrayService 可以负责：

```text
创建 / 销毁托盘图标
托盘菜单
tooltip
窗口显示 / 隐藏
Exit App
把菜单点击转给 ViewModel 或 command bridge
根据 AgentCommandAvailability 更新菜单可用性
```

TrayService 不负责：

```text
直接查询 SQLite
直接读写 runtime_state / health_state
直接写 agent_control.json
直接实现 Agent 命令协议
直接修改 Settings 草稿
直接做 RefreshService 之外的高频轮询
```

推荐边界：

```text
TrayService:
    ShowRequested
    ExitRequested
    StartRequested
    PauseRequested
    ResumeRequested
    StopRequested
    UpdateMenuState(TrayMenuState state)

App.xaml.cs / MainWindowViewModel / command bridge:
    负责窗口 Show / Hide
    负责调用现有 Agent 命令
    负责把 AgentStatusSnapshot / AgentCommandAvailability 转成 TrayMenuState
```

TrayService 不应直接持有大量 ViewModel 业务状态；它应该是托盘图标、菜单和事件转发层。

### 5. 复用已有 AppSettings 字段

当前 `AppSettings` 已有：

```text
AutoStartAgentWhenAppStarts
MinimizeToTray
CloseToTray
RefreshIntervalSeconds
Theme
LastSelectedPage
```

阶段 10 可以复用：

```text
MinimizeToTray
CloseToTray
```

本阶段不需要新增 schema。  
`AutoStartAgentWhenAppStarts` 不在本阶段扩大实施，开机自启也不在本阶段做。

### 6. 托盘依赖选择要保守

可选方案：

```text
H.NotifyIcon.Wpf
System.Windows.Forms.NotifyIcon
```

建议：

```text
MVP 优先使用 System.Windows.Forms.NotifyIcon。
理由是不新增第三方依赖，Windows 桌面托盘场景成熟稳定，适合先跑通生命周期、Show、Exit、Dispose。
如果 agent 选择 H.NotifyIcon.Wpf 或其他 NuGet，必须说明原因、版本号、发布影响和替代方案。
托盘 icon 应使用现有品牌/应用资源；若暂无资源，先使用简单内嵌图标或应用图标，不引入复杂资产流程。
```

如果使用 `System.Windows.Forms.NotifyIcon`，必须注意：

```text
项目需要显式启用或引用 Windows Forms。
NotifyIcon 必须在 Exit App / App shutdown 时 Dispose。
Dispose 前先设置 NotifyIcon.Visible=false。
ContextMenuStrip 点击回调如果需要触碰 WPF 对象，必须安全切回 WPF Dispatcher。
如果 Dispatcher 已 shutdown 或窗口已释放，菜单回调应安全忽略，不抛出未处理异常。
Dispose 必须幂等，避免重复退出时异常。
```

图标资源 fallback：

```text
如果已有应用图标资源可用，优先复用。
如果没有正式 .ico 资源，不引入复杂资产流程，先使用系统默认 / 简单内嵌图标 / 最小可用 fallback。
不要因为图标资源阻塞 TrayService 生命周期实现。
托盘阶段重点是生命周期和状态，不是图标设计。
```

### 7. 隐藏窗口不改变页面刷新语义

阶段 10 MVP 不改变阶段 9 的页面自动刷新语义：

```text
CloseToTray / MinimizeToTray 后：
    status polling 继续运行。
    page refresh timer 暂按现有语义继续。
    不在本阶段新增“窗口隐藏后暂停 page refresh”的资源优化。

后续如果需要省资源：
    可单独评估隐藏后暂停 page refresh，只保留 status polling。
```

这样可以避免托盘阶段顺手改刷新生命周期，引入新的 Settings dirty 或页面数据刷新回归。

## 行为要求

```text
App 启动后创建托盘图标。
```

# 阶段 10.3：CloseToTray / MinimizeToTray / Show / Exit 语义

## 阶段目标

实现后台运行基础语义：关闭或最小化主窗口时隐藏到托盘，而不是直接退出 App。

## 行为要求

```text
CloseToTray=true:
    点击窗口 X 时 Hide 主窗口。
    Cancel Closing。
    App 继续运行。
    Agent 不被停止。
    status polling 继续运行。
    不 Dispose TrayService。
    不 Shutdown App。

MinimizeToTray=true:
    主窗口最小化时 Hide 主窗口。
    App 继续运行。
    status polling 继续运行。
    托盘 Show 可恢复窗口。

Show Main Window:
    Show()。
    WindowState 从 Minimized 恢复为 Normal。
    Activate()。
    Bring to foreground 尽力即可，不做强制前台 hack。

Exit App:
    设置显式退出标记。
    允许窗口真正关闭。
    StopStatusPolling。
    Dispose TrayService。
    Application.Shutdown。
    不默认 Stop Agent。
```

## 验收标准

- 关闭窗口后 App 仍在进程中。
- Agent 不被停止。
- 托盘 Show 能恢复窗口。
- Show 恢复时 WindowState 从 Minimized 变为 Normal。
- Show 不引入复杂 Win32 强制前台 hack。
- Exit App 后 WPF App 退出。
- App 退出时不会误发 Stop Agent。
- AppSettings 中 `CloseToTray` / `MinimizeToTray` 生效。
- CloseToTray / MinimizeToTray 不停止 status polling。
- 阶段 10 不改变页面自动刷新语义；隐藏窗口后 page refresh 是否暂停留到后续优化。

## 建议测试

```text

MainWindow_ExitAppAllowsClose
TrayService_ShowRestoresHiddenWindow
CloseToTray_DoesNotStopAgent
CloseToTray_DoesNotStopStatusPolling
MinimizeToTray_HidesWindowWhenEnabled
ExitApp_DoesNotSendAgentStopCommand
```

## 不做什么

- 不做开机自启。
- 不做 Exit App + Stop Agent 组合操作。
- 不新增 Settings UI 配置项，除非现有 Settings 页面已有入口且改动很小。

## 风险与对策

### 托盘生命周期导致 App 退出不干净

风险：

```text
Close 被取消后，App 仍持有窗口和托盘资源；Exit App 时没有释放 NotifyIcon。
```

对策：

```text
明确 _isExitRequested 或等价标记。
CloseToTray 只 Hide，不 Dispose。
Exit App 路径统一 StopStatusPolling + Dispose TrayService + Shutdown。
CloseToTray / MinimizeToTray 不停止 status polling。
NotifyIcon Dispose 前先设置 Visible=false。
TrayService.Dispose 幂等。
```

### 关闭窗口误停 Agent

风险：

```text
用户点击 X 后误触 Stop Agent，破坏后台采集预期。
```

对策：

```text
CloseToTray 不调用 StopAgent。
Exit App 不默认 StopAgent。
Exit App 不调用 StopAgentCommand、StopAgentGracefullyAsync、Pause、ClearHistory 或任何 Agent 命令。
Stop Agent 只由明确菜单项触发。
手动验收覆盖关闭主窗口后 Agent 仍运行。
手动验收覆盖 Exit App 后 Agent 不被误停。
```

### 托盘状态和主窗口状态漂移

风险：

```text
托盘自己维护状态，和 MainWindow / Settings 不一致。
```

对策：

```text
托盘复用 AgentStatusSnapshot 和 AgentCommandAvailability。
状态变化由 MainWindowViewModel 或统一状态服务派发。
托盘不新增状态轮询。
测试同一快照下 MainWindow / Settings / Tray 三方一致。
```

### 托盘命令重复实现控制逻辑

风险：

```text
TrayService 直接写 agent_control.json 或自己调用 IPC，绕过现有 fallback / requestId / timeout 逻辑。
```

对策：

```text
TrayService 只调用现有 commands 或 command bridge。
AgentControlService / AgentProcessService 仍是唯一执行入口。
```

### 托盘通知刷屏

风险：

```text
2 秒 status polling 失败时反复弹通知。
```

对策：

```text
只在状态转换时通知。
同类错误节流。
重复 fallback 不弹。
第一版可只更新 tooltip，不弹 toast。
如果实现通知，只对状态转换通知，不对每次轮询失败通知。
```

### 新依赖引入发布风险

风险：

```text
托盘库与 WPF / .NET 8 / single file 发布不兼容。
```

对策：

```text
先选择最小依赖方案。
新增依赖必须说明原因。
build/test 覆盖。
手动验收托盘图标显示和 Dispose。
```

### Settings dirty 被托盘刷新覆盖

风险：

```text
托盘状态更新触发 MainWindow refresh，间接重载 Settings 草稿。
```

对策：

```text
继续复用阶段 9 的 IsDirty 守卫。
托盘状态更新不调用 Settings LoadAsync。
手动和自动测试覆盖 Settings dirty。
```
