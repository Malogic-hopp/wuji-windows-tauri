## 建议规则列表

### Rule 1: 高切换建议 (Switch / Warning)

| 项目 | 内容 |
|---|---|
| 触发条件 | `ContextSwitchCount >= 20` 且 ≥ 7 天平均 × 1.3 |
| Title | 今天切换较频繁 |
| Message | 今天下午切换较频繁，可以尝试安排一个 25 分钟单任务块。 |
| EvidenceText | 今天共切换 N 次（近 7 天平均 N 次） |
| ActionText | 试试：关掉非必要的通知，专注于一个应用 25 分钟。 |

### Rule 2: 专注不足建议 (Focus / Warning)

| 项目 | 内容 |
|---|---|
| 触发条件 | `TotalActiveDurationSeconds >= 600`（10 分钟）且无 ≥15 分钟的专注段 |
| Title | 今天缺少连续专注 |
| Message | 今天缺少较长连续专注段，建议挑一个低打扰时间段做深度任务。 |
| EvidenceText | 今日活跃 X 分钟，最长连续专注仅 X 分钟（或"未检测到完整专注段"） |
| ActionText | 试试：找一个 30 分钟内不会被中断的时间块处理最重要的事。 |

### Rule 3: App 用量异常建议 (AppUsage / Neutral)

| 项目 | 内容 |
|---|---|
| 触发条件 | 今日 Top1 App 活跃时长 ≥ 300 秒且 ≥ 7 天平均活跃 × 1.5，且该 App 近 7 天不是频繁 Top1（< 4 天） |
| Title | 今日 {AppName} 使用较多 |
| Message | 今天 {AppName} 的活跃时长明显高于近期平均，可以复盘是否符合预期。 |
| EvidenceText | {AppName} 今日活跃 X 分钟，近 7 天日均活跃 X 分钟 |
| ActionText | 如果这是计划内的深度工作，很好；如果是被动消耗，可以考虑设个时间限制。 |

### Rule 4: 开始较晚建议 (Schedule / Neutral)

| 项目 | 内容 |
|---|---|
| 触发条件 | `FirstSeenAtUtc` 的本地时间小时 ≥ 10 |
| Title | 今天开始较晚 |
| Message | 今天最早活动在 HH:mm，开始明显偏晚，建议明天提前安排第一块工作。 |
| EvidenceText | 今日最早记录时间 HH:mm |
| ActionText | 试试：明天安排一个 9:00-9:30 的固定启动时间块。 |

### Rule 5: 正向反馈 (Focus / Positive)

| 项目 | 内容 |
|---|---|
| 触发条件 | 有 ≥ 15 分钟的专注段 且（≥ 近 7 天平均 × 1.3 或 ≥ 30 分钟） |
| Title | 今天有不错的专注段 |
| Message | 今天最长专注段达到 X 分钟，主要在 {App} 上。保持这个节奏！ |
| EvidenceText | 最长专注段 X 分钟（近 7 天平均 X 分钟） |
| ActionText | 继续保持这个节奏，明天可以尝试把最困难的任务安排在这个时间段。 |

## 阈值汇总

| 常量 | 值 | 用途 |
|---|---|---|
| `MinActiveSecondsForInsight` | 600 (10 min) | 最低数据量门槛 |
| `HighSwitchAbsoluteThreshold` | 20 | 切换绝对阈值 |
| `HighSwitchRatio` | 1.3 | 切换 vs 平均比率 |
| `AdequateFocusSeconds` | 900 (15 min) | 最低专注时长 |
| `AppSpikeRatio` | 1.5 | App 用量异常比率 |
| `LateStartHour` | 10 | 晚开始判断小时 |
| `MaxSuggestions` | 3 | 最多建议条数 |

## 文案原则

- 所有文案温和、不评判人格
- 不包含"差"、"糟糕"、"效率低"、"失败"等羞辱性词汇
- 每条建议至少包含 EvidenceText（数据依据）和 ActionText（可执行行动）
- 同类别每天最多 1 条
- Dashboard 最多显示 3 条

## Dashboard 展示变化

Suggestions 区域位于 Summary Text 和 7-Day Trend 之间。每条建议左侧有颜色条区分 Severity：
- 🟢 Positive（绿色）：正向反馈
- 🟠 Warning（橙色）：提醒注意
- ⚪ Neutral（灰色）：中性提示

## 数据不足时的行为

- `TotalActiveDurationSeconds < 600` 且无 Session → 返回空列表，不编造建议
- Trend 为 null 时：Rule 1（高切换）仍可基于绝对阈值触发；Rule 3（App 异常）、Rule 5（正反馈）不触发
- 建议生成失败不影响 Dashboard 基础统计展示

## 风险与后续建议

1. **Threshold tuning**: 当前阈值基于经验设定，实际使用中可能需要根据用户反馈调整。建议在阶段 13.7 长跑验证中收集建议准确率。
2. **App spike false positives**: 如果用户某天专门做深度开发，Code 占比异常高是正常的。Rule 3 已通过 "近 7 天 Top1 频率 < 4 天" 做初步过滤，但不完美。
3. **Late start detection**: 仅基于 `FirstSeenAtUtc`，如果 WUJI 晚启动但用户早就在工作会误判。未来可结合 `app_sessions` 的 `started_at_utc` 改进。
