# 阶段 13.6：洞察明细与可解释性

## 阶段目标

为 Dashboard 洞察提供轻量明细入口，让用户能理解每条洞察来自哪些数据，而不是只看到结论。

一句话目标：

```text
让每个洞察都能被追溯和信任。
```

## 实施范围

可选实现方式：

```text
1. Dashboard 中展开每条建议的 EvidenceText。
2. 点击 Top App 跳转或筛选到 Apps / Sessions。
3. 点击 Focus Session 展示对应时间段和主要应用。
4. Diagnostics 或 Dashboard 显示统计数据更新时间。
```

MVP 优先：

```text
先做 EvidenceText 和轻量明细，不做复杂 drilldown 页面。
```

## 行为要求

```text
1. 每条建议必须展示可读依据。
2. 依据不得泄露敏感完整窗口标题。
3. 明细入口不能触发重型全库查询。
4. 页面失败时保留上一份明细或显示安全错误。
5. 跳转 / 筛选如实现，必须保持现有页面语义。
6. 不新增嵌套卡片式复杂布局。
7. 不引入大型图表或路由系统。
8. 不把 Diagnostics 变成统计页面。
9. 不改 Samples / Sessions / Apps 的核心查询语义。
10. 不影响 status polling。
```

## 验收标准

```text
1. Dashboard 建议展示 EvidenceText。
2. 用户能看懂建议依据。
3. 敏感标题不裸露。
4. 统计更新时间可见。
5. 查询失败安全展示，不崩溃。
6. build/test 通过，0 warnings / 0 errors。
```

## 建议测试

```text
InsightEvidence_RendersForSuggestions
InsightEvidence_RedactsSensitiveTitles
InsightEvidence_ShowsGeneratedAt
InsightEvidence_FailureDoesNotCrashDashboard
Dashboard_InsightDetailsDoNotTriggerStatusRefresh
```

## 不做什么

```text
不做复杂 drilldown 新页面
不做全量报表
不做导出
不做图表库
不做 AI 解释
```
