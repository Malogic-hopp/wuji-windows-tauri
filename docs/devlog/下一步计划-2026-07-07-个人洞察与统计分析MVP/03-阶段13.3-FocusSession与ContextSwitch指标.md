# 阶段 13.3：Focus Session 与 Context Switch 指标

## 阶段目标

新增“连续专注段”和“上下文切换”指标，让 WUJI 不只统计时间总量，也能反映注意力质量。

一句话目标：

```text
让用户知道今天是连续推进，还是频繁切换。
```

## 指标定义建议

MVP 可采用简单、可解释规则：

```text
Context Switch
    相邻有效 foreground sample 的 App 或主窗口标题发生变化，即记一次切换。

Focus Session
    一段连续 active 时间；
    中间没有超过阈值的 idle / gap；
    切换次数低于阈值；
    持续时长达到最小专注阈值。

Fragmented Time
    active 但切换频繁、连续段较短的时间。
```

阈值建议先放在代码常量或配置模型中：

```text
MinimumFocusMinutes = 10
MaxGapMinutes = 3
MaxSwitchesPerFocusBlock = 3
FragmentedWindowMinutes = 30
```

实际阈值应在完成说明中记录。

## 行为要求

```text
1. Focus / Context Switch 计算放在统计服务或独立分析服务中，不放 ViewModel。
2. 指标必须基于已有 samples / sessions，不新增 Agent 写入。
3. 规则必须可解释，不引入黑盒分数。
4. 空数据返回 0 / 空列表。
5. 时间 gap、idle、跨日边界必须有明确处理策略。
6. Dashboard 可显示：最长专注段、切换次数、碎片化提示。
7. 不做打扰式提醒。
8. 不做目标管理或番茄钟。
9. 不把窗口标题原文暴露到不该展示的位置。
10. 查询和计算不得阻塞 status polling。
```

## 验收标准

```text
1. 能计算今日 context switch count。
2. 能计算今日 longest focus session。
3. 能识别碎片化时间或高切换状态。
4. Dashboard 可展示至少两个注意力质量指标。
5. 指标计算对空数据、跨 gap、idle 场景稳定。
6. build/test 通过，0 warnings / 0 errors。
```

## 建议测试

```text
FocusMetrics_ComputesContextSwitchCount
FocusMetrics_ComputesLongestFocusSession
FocusMetrics_BreaksSessionOnLargeGap
FocusMetrics_BreaksSessionOnIdle
FocusMetrics_MarksFragmentedTimeWhenSwitchesAreHigh
FocusMetrics_HandlesNoSamples
Dashboard_ShowsFocusAndSwitchMetrics
```

## 不做什么

```text
不做 AI 判断
不做效率分
不做强提醒
不做窗口截图
不做手动标注
不做复杂图表
```
