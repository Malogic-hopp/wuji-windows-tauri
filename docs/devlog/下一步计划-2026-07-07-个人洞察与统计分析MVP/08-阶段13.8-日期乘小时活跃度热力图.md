# 阶段 13.8：日期×小时 活跃度热力图

## 阶段目标

参照旧项目 `web/overview` 中的 Plotly 热力图，在 WUJI WPF Dashboard 中用纯 WPF 方式实现 "24 小时 × 7 天" 活跃度热力图，让用户一眼能看出哪天活跃、哪个时段活跃、作息是否规律。

一句话目标：

```text
让用户知道自己什么时间段最活跃，作息是否规律。
```

## 背景

旧项目（`C:\Users\WangZhenchi\work\QuantifiedSelf\windows`）的 web overview 中用 Python + Plotly 画了一个 "24 小时 × 7 天" 的活跃度热力图，核心就是：

```text
"日期 × 小时" 的二维矩阵
每个单元格的活跃率用颜色深浅表示
再用背景带把一天分成四个阶段（睡觉/上午/下午/晚上）
```

信息密度高、直观，但不需要复杂图表库。

## 实施范围

### 数据模型

```csharp
// Core.Models/DailyHourActivityPoint.cs
public sealed class DailyHourActivityPoint
{
    string Date          // "2026-07-06"
    int Hour             // 0-23
    int ActiveSamples
    int IdleSamples
    int UnknownSamples
    int TotalSamples => ActiveSamples + IdleSamples + UnknownSamples
    double ActiveRatio   // within-hour active proportion: ActiveSamples / TotalSamples
    double ActiveIntensity // normalized for heatmap color: ActiveSamples / maxActiveInPeriod
}
```

颜色由 `ActiveIntensity` 驱动（而非 `ActiveRatio`），这样颜色反映的是"这个小时相对于 7 天内最忙小时的活跃量"，避免 1 个 active 样本和 60 个 active 样本显示相同颜色。

### 计算引擎

```csharp
// App.Services/HourActivityHeatmapCalculator.cs
public static class HourActivityHeatmapCalculator
{
    // 输入 7 天的 ForegroundSample 列表，输出 168 个 DailyHourActivityPoint
    public static IReadOnlyList<DailyHourActivityPoint> Compute(
        IReadOnlyList<ForegroundSample> weekSamples, DateOnly today);
}
```

逻辑：
1. 每个样本的 `SampleTimeUtc` → `ToLocalTime()`
2. 提取 `localDate` + `localHour`
3. 按 `(date, hour)` 分组，计数 active/idle/unknown
4. 补全所有 7×24=168 个格子（缺失填 0）
5. 按 date ASC、hour ASC 排序返回

### 查询层

`DailyStatsQueryService` 新增一次查询取 7 天样本的方法：

```sql
SELECT ... FROM foreground_samples
WHERE sample_time_utc >= $start_utc AND sample_time_utc < $end_utc
ORDER BY sample_time_utc ASC;
```

| 1.0 | 深蓝 | `#1d4ed8` |

### 技术要点

1. **UTC→Local 转换**：在 C# 侧做，SQLite 不做时区转换
2. **颜色在 C# 生成**：Brush 在 ViewModel 创建时预计算，XAML 直接绑定
3. **WPF 类型名冲突**：`UseWindowsForms=true` 导致 `Color`/`Brushes`/`SolidColorBrush` 在 `System.Drawing` 和 `System.Windows.Media` 间冲突，用 `using Media = System.Windows.Media` 解决
4. **单次查询**：7 天样本一次 SQL 取回，< 5000 条

## 行为要求

```text
1. 7 天基于本地日期。
2. 缺失日期/小时补 0 点。
3. 热力图计算仍是只读，不写 SQLite。
4. Dashboard 展示轻量，不做复杂图表库。
5. 查询失败时保留旧热力图（不替换为空图）。
6. 2 秒 status polling 不触发热力图刷新。
7. 纯 WPF UniformGrid + Border 实现，零额外依赖。
```

## 不做什么

```text
不引入第三方图表库（Plotly、OxyPlot、LiveCharts 等）
不做交互式缩放/平移
不做历史日期范围选择
不做点击单元格跳转详情
不做 idle/unknown 热力图分面
不做时间段背景带叠加（Phase bands 留到后续优化）
不导出图片
```

## 已知限制

```text
1. 热力图基于样本计数而非精确秒级时长
2. 颜色不可自定义（硬编码 4 阶蓝色渐变）
3. 不显示悬停时的完整窗口标题（隐私过滤）
4. WPF 纯色单元格，无 Plotly 的渐变平滑效果
```
