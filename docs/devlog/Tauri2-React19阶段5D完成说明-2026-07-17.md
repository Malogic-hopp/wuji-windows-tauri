## 1. 实施范围

阶段 5D 完成 Settings parity 与验收收口：

- 使用真实 WPF `SettingsViewModel` 和真实 `.NET Client.Bridge` 对照十二个安全字段；
- 验证初始值、Core/Application 默认值、双向合法保存和重启持久化；
- 验证 WPF 与 Tauri 对越界值、非法整数语义及 stale/heartbeat 关系均拒绝写入；
- 注入 Bridge 进程退出并验证重新连接、重试和持久化结果；
- 保存成功后统一失效 Settings、Agent status 和 Dashboard query；
- 验证 React Error、断线重试、字段错误、dirty 保留和显式重试；
- 递归检查成功/错误 DTO，不允许路径、数据库、注册表、IPC、自由文本隐私字段或异常详情；
- 复核主 bundle、Dashboard route 和 Settings route 的 raw/gzip 预算；
- 对真实 prod 设置执行前后只读指纹对照，确认全程未修改。

本批没有修改 IPC、SQLite、Agent 状态机、WPF `App.xaml.cs`、默认 WPF Shell 或发布流程，也没有启动、停止或 reload 任何真实 Agent。

## 2. 可重复的隔离 dev parity

新增工具：

```text
tools/QuantifiedSelf.Windows.SettingsParity
```

新增一键命令：

```powershell
pnpm smoke:settings-parity
```

最初尝试直接使用默认 dev 根目录时，工具正确检测到已有 dev Agent 正在运行并阻止修改。为了让验收不依赖停止正在记录的 Agent，最终采用以下确定性模型：

```text
唯一临时 data root
  + channel 固定为 dev
  + WPF SettingsViewModel
  + Bridge --channel dev
  + 同一份设置文件
  → finally 恢复并删除整个临时工作区
```

临时 data root 只位于 `%TEMP%/WUJI.Smoke/settings-parity-workspace-*`。工具在删除前验证绝对路径仍位于该固定临时父目录，且目录名具有固定前缀；不会删除默认 dev 或 prod 目录。

真实 prod 的 `app-settings.json`、`windows-agent.json` 及其 `.tmp/.bak` 状态只在内存中做前后指纹对照，报告不记录路径、文件内容或哈希。默认 dev 设置完全不参与读写，因此已有 dev Agent 可继续运行。

## 3. WPF 与 Tauri 双向对照

验收工具先通过 Application 设置用例写入一份非默认初始快照，再执行：

1. WPF `SettingsViewModel.LoadAsync()` 读取十二个 allowlist 字段；
2. Bridge `settings.get` 读取同一快照；
3. 对照双方初始值；
4. Bridge `settings.update` 保存第一份合法变更，WPF 重新读取；
5. WPF 分别保存 App 与 Agent 合法变更，新 Bridge 重新读取；
6. 结束 Bridge 进程并创建新 generation，再次读取持久化结果；
7. finally 恢复初始文件状态并删除临时工作区。

## 4. 非法值、错误和恢复

WPF 与 Tauri 使用同一组非法输入：

- `refreshIntervalSeconds = 0`；
- `samplingIntervalSeconds = 0`；
- `heartbeatIntervalSeconds = 30`；
- `staleThresholdSeconds = 30`。

WPF `SettingsViewModel` 报告 App/Agent 校验失败且不写入。Bridge 返回固定 `validation_failed`，字段错误至少包含刷新间隔、采样间隔和 stale 阈值；非法请求前后的设置文件内容与时间戳完全一致。

React 测试补充覆盖：

- 初次 `settings.get` 断线时显示安全 Error，并可点击“重试”恢复 Ready；
- 保存校验失败时保留草稿与 dirty 状态；
- 修正字段后只在用户显式操作时重试；
- 服务端字段错误不显示底层消息；
- Bridge ready 后失效 Settings query。

工具还会直接结束自己创建的 Bridge，启动新 Bridge 并重新执行 `settings.get`，确认断线后可以恢复且合法设置未丢失。

## 5. Agent 与 query 失效语义

保存成功后新增统一失效函数：

```text
Settings current
Agent status
Dashboard activity overview
```

这能防止 UI 继续展示保存前的 Settings、Agent 或活动查询缓存。Bridge 重连仍通过既有 `refreshQueriesAfterBridgeReady` 失效对应 generation 的缓存。

阶段 5 不新增 Agent reload command，也不隐式停止、启动或 reload Agent。该行为与 WPF 现有语义一致：普通 Agent 设置保存只写配置文件，运行中的 Agent 需要显式 ReloadConfig 或下次启动才应用。WPF 回归中的 `SettingsViewModel_SaveAgentOptionsDoesNotReloadAgent` 继续通过。

## 6. 隐私和安全边界

验收工具递归检查 `settings.get` 与 `validation_failed` 响应，禁止：

- 数据目录、数据库和 Agent executable 路径；
- Named Pipe、mutex 和 channel 内部标识；
- 注册表键值；
- `StartAppOnWindowsLogin`；
- 排除进程和标题自由文本；
- process/window 原始信息；
- exception、stack trace 或路径形态字符串。

报告只包含固定验收项和 PASS/FAIL，不包含设置文件内容、用户名、绝对私有路径、哈希或异常正文。
