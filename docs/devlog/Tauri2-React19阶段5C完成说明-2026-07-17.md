## 1. 实施范围

本批将 React Settings 占位页替换为真实安全表单，完成：

- Loading、Ready、Saving、Success、Error；
- 十二个 allowlist 字段的读取、编辑和保存；
- 本地整数格式校验与 Bridge 字段级业务错误；
- dirty 状态、未保存导航/关闭提醒；
- 保存、重试、恢复默认值、放弃修改；
- 保存期间冻结表单并防止重复提交；
- 键盘、焦点管理、读屏和 live region；
- Light/Dark、High Contrast、reduced-motion；
- locale-aware 整数展示；
- React 文件/注册表/SQLite/通用 invoke 架构门禁。

本批没有增加高风险设置，没有修改 IPC、SQLite、Agent 状态机、WPF `App.xaml.cs`、默认 WPF Shell 或发布流程。

## 2. 安全默认值补充

原 `settings.get` 只返回已保存快照，无法在不复制 Core 默认值的前提下实现“恢复默认值”。本批将 `SettingsGetResult` 安全扩展为：

```text
settings   当前安全快照
defaults   Core/Application 默认安全快照
```

Application 新增纯计算 `GetDefaultClientSettings()`，使用 `new AppSettings()`、`new WindowsAgentOptions()` 和既有安全投影生成默认快照，不读取设置文件。Client 只转发该用例；Bridge 只解析一次 `IWujiClient.Settings` facade，再读取当前值与默认值。

默认快照与当前快照使用同一个 `SettingsSnapshot` allowlist，因此不会引入路径、注册表、数据库、排除列表、IPC 标识或任意配置容器。三端合同已从 schema 重新生成。

React 的“恢复默认值”只把 `defaults` 填入草稿并标记 dirty，不会自动保存。用户仍需明确点击“保存设置”。

## 3. 页面状态

页面状态行为：

```text
Loading  initialize/settings.get 尚未完成
Ready    已加载，可编辑
Saving   settings.update 进行中，fieldset 与操作禁用
Success  保存成功，缓存更新并重新获取 settings.get
Error    读取失败、客户端格式错误、服务端字段错误或保存失败
```

读取失败提供安全重试。保存失败保留全部草稿，不用服务端返回值覆盖用户输入；字段错误清除后可直接重试。保存成功使用 Bridge 返回的规范化快照重建 baseline，并失效 `['settings', 'current']` query。

## 4. 字段与校验

表单按四组呈现：

1. 外观与刷新：主题、界面刷新间隔；
2. 应用行为：打开应用时自动启动 Agent；
3. Agent 采集参数：采样、空闲、心跳、过期阈值和保留天数；
4. 记录与隐私：JSONL、Agent event journal、session merge、window title masking。

React 只执行输入层校验：

- 必填；
- 十进制整数格式；
- JavaScript safe integer。

React 不复制 Core 最小值、最大值或跨字段关系。范围、主题规范化、stale/heartbeat 关系、隐藏字段保留和最终保存仍由 Application 负责。Bridge `validation_failed.fieldErrors` 只接受十二个固定字段名，React 再映射为固定“请检查此设置值。”，不会展示底层路径或异常细节。

## 5. dirty 与未保存保护

草稿和最后一次成功/读取 baseline 做结构比较。dirty 时：

- 页头显示“有未保存修改”；
- “放弃修改”可恢复 baseline；
- `beforeunload` 阻止窗口直接关闭；
- React Router `useBlocker` 阻止路由跳转；
- 显示 `role="alertdialog"` 的未保存提示；
- 默认焦点落在“留下继续编辑”；
- Esc 留在当前页；
- Tab/Shift+Tab 在两个决策按钮间循环；
- 明确点击“放弃并离开”后才继续导航。

页面级测试真实触发 data router blocker 和 `beforeunload`，不是只检查静态文本。

## 6. 保存与重复提交

保存前解析当前草稿。若存在格式错误：

- 不调用 `settings_update`；
- 标记具体字段；
- 通过 `aria-invalid` 与 `aria-describedby` 关联错误；
- 将焦点移动到第一个错误字段。

保存开始后：

- mutation 状态立即进入 Saving；
- fieldset、恢复默认值、放弃修改和保存操作被禁用；
- submit handler 同时检查 `save.isPending`；
- 连续点击只产生一次 `settings_update`。

更新 timeout 的不确定结果仍遵循 5B：不自动重试，保留草稿，提示用户重新读取或显式重试。

## 7. 可访问性与主题

本批依据 `ui-styling` 的表单可访问性规则实现：

- 原生 `form`、`fieldset`、`legend`、`label`、`select`、`input`、`checkbox`、`button`；
- label 与 helper/error 分离，避免读屏把整段说明当作控件名称；
- helper/error 使用 `aria-describedby`；
- Loading/Saving/Success 使用 polite live region，Error 使用 alert；
- 所有交互元素保留统一可见焦点；
- 按 DOM 顺序提供完整键盘操作；
- forced-colors 使用系统 Canvas/CanvasText/Highlight 和明确边框；
- `prefers-reduced-motion` 将旋转、入场和 transition 降到近零；
- 已保存整数通过 `Intl.NumberFormat(locale)` 展示。

没有引入 Tailwind、shadcn 或新的 UI runtime；继续复用现有 CSS semantic tokens。

## 8. 底层能力边界

React Settings 只调用：

```text
bridgeClient.getSettings()
bridgeClient.updateSettings(settings)
```

页面、View 和 model 不包含：

- `invoke()`；
- Tauri fs/sql plugin；
- `readTextFile` / `writeTextFile`；
- `Database.load`；
- registry 命令；
- SQLite、数据库路径或设置文件路径；
- localStorage 配置旁路。

React 不能绕过 Rust command 白名单和 Bridge/Application 校验。

## 9. Bundle

```text
主 bundle       344.32 KiB raw / 107.50 KiB gzip
Dashboard route 19.36 KiB raw /   5.44 KiB gzip
Settings route  16.60 KiB raw /   5.08 KiB gzip
```
