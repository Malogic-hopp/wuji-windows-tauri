# 阶段 5.5：导航与页面收口

## 阶段目标

把新页面接入现有 WPF App，同时避免大规模 UI 架构重构。

重点是让 Dashboard、Apps、Sessions、Samples、Diagnostics、Settings 能以清晰顺序共存，并保持现有控制栏不回归。

## 前置条件

以下页面 MVP 已完成：

```text
SamplesView
SessionsView
AppsView
```

## 开发顺序与导航顺序

开发顺序仍然建议：

```text
Samples
Sessions
Apps
```

原因：

```text
Samples 验证底层采样
Sessions 验证 session 合并
Apps 验证应用级聚合
```

导航顺序建议面向用户视角：

```text
Dashboard
Apps
Sessions
Samples
Diagnostics
Settings
```

原因：

```text
用户通常先看总览，再看应用排行，再看会话，最后才看原始采样和诊断。
Samples 更偏底层，不适合放在 Apps / Sessions 前面。
```

## 推荐结构

新页面建议直接拆成独立 View + ViewModel：

```text
src/QuantifiedSelf.Windows.App/Views/SamplesView.xaml
src/QuantifiedSelf.Windows.App/Views/SessionsView.xaml
src/QuantifiedSelf.Windows.App/Views/AppsView.xaml

src/QuantifiedSelf.Windows.App/ViewModels/SamplesViewModel.cs
src/QuantifiedSelf.Windows.App/ViewModels/SessionsViewModel.cs
src/QuantifiedSelf.Windows.App/ViewModels/AppsViewModel.cs
```

Dashboard 和 Diagnostics 可以暂时不拆。  
但不要把 Samples / Sessions / Apps 全部继续塞进 `MainWindow.xaml`。

如果现有项目结构暂时不适合完整 MVVM，本阶段至少拆出 UserControl。

## 保持不回归

必须保留：

```text
顶部 Agent 控制栏
Start Agent
Stop Agent
Pause
Resume
Refresh
Open Settings
Dashboard 原统计
Diagnostics 原事件和错误展示
```

## Refresh 语义

Refresh 应刷新当前页面数据。

建议：

```text
Dashboard：刷新 Dashboard summary / top apps / recent sessions
Apps：刷新今日应用排行
Sessions：刷新当前范围的 sessions
Samples：刷新最近 samples
Diagnostics：刷新 runtime / health / recent events / recent errors
```

不要让单个页面刷新影响 Agent 状态机或写入链路。

## 验收标准

- 页面切换正常
- 导航顺序为 Dashboard / Apps / Sessions / Samples / Diagnostics / Settings
- Refresh 能刷新当前页面数据
- Dashboard 不回归
- Diagnostics 不回归
- Agent 控制按钮不回归
- 新页面不显著增加 `MainWindow.xaml` 复杂度
- 大量数据下切换页面不卡顿

## 建议测试

```text
MainWindowViewModel_NavigatesToAppsSessionsSamples
MainWindowViewModel_RefreshesCurrentPage
NavigationOrder_IsDashboardAppsSessionsSamplesDiagnosticsSettings
```

## 不做什么

- 不做完整 UI 架构重构
- 不拆 Dashboard / Diagnostics 的既有实现，除非实现新导航必须
- 不做动画
- 不做复杂主题系统
