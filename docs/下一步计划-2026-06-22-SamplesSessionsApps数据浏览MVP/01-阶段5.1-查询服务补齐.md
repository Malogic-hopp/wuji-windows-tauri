## 解决的问题

- 当前 Dashboard 只能展示摘要，缺少数据浏览页所需的独立查询服务。
- ViewModel 不应直接写 SQL。
- Data Views 查询必须明确只读，避免破坏“Agent 唯一写入者”边界。
- SessionsView 的 Today 查询必须按本地日重叠，而不是按 started_at 日期简单过滤。
- AppsView 排行必须固定 active duration 口径和稳定排序。

## 查询连接要求

所有 Data Views 查询服务必须使用只读连接：

```text
SqliteConnectionFactory.OpenReadOnlyAsync
```

代码审查时确认这些服务不会使用：

```text
ReadWrite
ReadWriteCreate
```

相关服务：

```text
SampleQueryService
SessionQueryService
AppUsageQueryService
DiagnosticsQueryService
```

## Samples 查询

第一版支持：

```text
GetRecentSamplesAsync(limit = 200)
```

字段：

```text
id
sample_time_utc
process_name
display_name
window_title
executable_path
idle_seconds
activity_state
```

排序：

```sql
ORDER BY sample_time_utc DESC, id DESC
LIMIT $limit
```

## Sessions 查询

第一版支持：

```text
GetRecentSessionsAsync(limit = 200)
GetSessionsForLocalDayAsync(localDate, limit = 200)
```

`GetSessionsForLocalDayAsync` 必须按“与本地当天时间区间有重叠”查询：

```text
session.started_at_utc < local_day_end_utc
AND COALESCE(session.ended_at_utc, now_utc) > local_day_start_utc
```

排序：

```sql
ORDER BY started_at_utc DESC, id DESC
LIMIT $limit
```

## Apps 查询

第一版支持：

```csharp
GetAppUsageForLocalDayAsync(DateOnly localDate, int limit = 50)
```

排行口径：

```text
active_duration_seconds DESC
total_duration_seconds DESC
process_name ASC
```

展示名 fallback：

```text
display_name -> process_name -> Unknown
```

实现说明：

```text
AppUsageQueryService 当前使用 SQL CTE 在 SQLite 层完成：
1. 本地日重叠 session 筛选
2. overlap / span 比例切分
3. 按 process_name 聚合
4. active / total / process_name 稳定排序
5. LIMIT $limit
```

这满足 Data Views 的性能约束：

```text
AppsView 不读取当天全部 app_sessions 后再在内存里聚合。
```

短期接受的技术债：

```text
OverviewQueryService 当前仍在 C# 内存中做本地日重叠切分和 Top Apps 聚合。
AppUsageQueryService 已经改为 SQL CTE 聚合。
两者口径设计一致，但实现载体不同，未来可能因 ROUND、时间解析、open session 的 nowUtc 取值时机产生 1 秒级差异。
```

后续统一方向：

```text
如果 Dashboard Top Apps 与 AppsView Today 排行出现明显差异，
优先让 Dashboard 复用 AppUsageQueryService.GetAppUsageForLocalDayAsync(DateOnly, limit)，
或抽出共享统计查询实现，避免长期维护两套重叠切分逻辑。
```
