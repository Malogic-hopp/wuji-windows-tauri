# 阶段 11 修复记录：Stopped 残留进程阻塞启动（2026-07-06）

Build: `0 warnings / 0 errors` | Test: `356 / 356 passed`

## 背景

手动验证时发现：

```powershell
dotnet build .\QuantifiedSelf.Windows.sln
dotnet run --project .\src\QuantifiedSelf.Windows.App\QuantifiedSelf.Windows.App.csproj
```

启动 App 后，`AutoStartAgentWhenAppStarts=true` 但 Agent 没有明显自启动反馈；点击 Start 也看起来没有反应。

排查本机运行态时发现：

```text
QuantifiedSelf.Windows.Agent.exe 进程仍存在
runtime_state.json state = "Stopped"
health_state.json actualState = "Stopped"
app-settings.json autoStartAgentWhenAppStarts = true
```

也就是说，Agent 状态已经进入 Stopped，但宿主进程仍残留并锁住 Debug 输出 exe。App 侧看到 Agent 进程存在后不再启动新 Agent，而 UI 又根据 Stopped 状态禁用了/弱化了启动路径，最终表现为“自动启动和 Start 都没反应”。

## 根因

### 1. Agent Worker 停止采样循环后没有停止 Host 进程

`AgentStateMachine.TickAsync()` 在 `ActualState == Stopped` 时返回 `false`。旧的 `Worker.ExecuteAsync()` 收到 `false` 后只 `return`，这只结束 Worker 这个 HostedService，不会停止整个 .NET Host。

阶段 8 引入的 IPC server HostedService 仍在运行，因此进程继续存活，形成：

```text
state = Stopped
process still alive
```

### 2. App 侧把残留进程当成“Agent 正在运行”

`AgentProcessService.StartAgentAsync()` 先检查现有 Agent 进程。只要发现进程存在，就直接返回 existing，不会启动新 Agent。

这对 Running / Paused 是正确的，但对 `runtime_state.json state=Stopped` 且同 PID 进程残留的情况，会阻塞恢复。

### 3. 按钮可用性没有覆盖 Stopped+process-alive 边界

`AgentCommandAvailability.CanStart` 原先主要按 `!status.IsRunning` 判断。Stopped 状态如果仍检测到进程存在，Start 不可用或不可执行，进一步放大了问题。

## 修复内容

### Agent 侧：Stopped 后关闭 Host 进程

修改文件：

- `src/QuantifiedSelf.Windows.Agent/Worker.cs`

`Worker` 注入 `IHostApplicationLifetime`。当状态机返回 `keepRunning=false` 时：

```csharp
_lifetime.StopApplication();
return;
```

这样 Stop 命令最终会让整个 Agent Host 退出，不再留下只剩 IPC server 的残留进程。

同时将原乱码中文日志改为 ASCII 英文日志，减少 PowerShell 编码差异导致的阅读和 patch 困扰。

### App 侧：Stopped 残留进程可恢复

修改文件：

- `src/QuantifiedSelf.Windows.App/Services/AgentProcessService.cs`

`StartAgentAsync()` 现在会读取 runtime state。若发现：

```text
runtime_state.state == Stopped
existing process id == runtime_state.processId
```

则先终止这个残留进程，再按正常流程启动新的 Agent。

这只针对明确的 Stopped 同 PID 残留；Running / Paused / Maintenance / Stale 等情况仍沿用原有保护逻辑。

### UI 可用性：Stopped 可 Start

修改文件：

- `src/QuantifiedSelf.Windows.App/Services/AgentCommandAvailability.cs`

`CanStart` 扩展为：

```text
非 Maintenance，且：
  - 没有运行中进程；或
  - 状态明确为 NotRunning / Stopped
```

这样 UI 不会在 `Stopped + process alive` 的边界状态下挡住 Start。

## 手动复测建议

1. 确认没有残留 Agent 进程：

```powershell
Get-Process QuantifiedSelf.Windows.Agent -ErrorAction SilentlyContinue
```

2. 正常启动 App：

```powershell
dotnet run --project .\src\QuantifiedSelf.Windows.App\QuantifiedSelf.Windows.App.csproj
```

3. 若 `WUJI 启动后自动启动 Agent=true`：

预期：

- App 启动后 Agent 自动进入 Running。
- 不弹 Agent 调试窗口，除非使用 `--show-agent-console`。
- Start 按钮不会卡在不可恢复状态。

4. 点击 Stop Agent：

预期：

- Agent 状态变为 Stopped。
- 稍后 `QuantifiedSelf.Windows.Agent.exe` 进程退出。
- 再点击 Start 可以重新启动 Agent。

5. 调试窗口启动方式：

```powershell
dotnet run --project .\src\QuantifiedSelf.Windows.App\QuantifiedSelf.Windows.App.csproj -- --show-agent-console
```

如果同时验证自启隐藏：

```powershell
dotnet run --project .\src\QuantifiedSelf.Windows.App\QuantifiedSelf.Windows.App.csproj -- --from-autostart --start-hidden --show-agent-console
```

## 结论

本次问题不是 `--show-agent-console` 参数本身导致，而是默认后台启动后，Agent 控制台不可见，使已有的 `Stopped + process alive` 残留状态更容易被误认为“点击没反应”。修复后，Agent Stop 会真正退出 Host；App 也能识别并恢复 Stopped 残留进程。
