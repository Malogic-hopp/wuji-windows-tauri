任务目标：

实现“阶段 11.4：登录自启启动到托盘”。

本阶段在阶段 11.3 的 Settings 自启开关与保存同步基础上，让 App 通过自启参数（`--from-autostart --start-hidden`）启动时默认隐藏到托盘，并继续运行阶段 10 的托盘和状态刷新链路。手动启动仍保持显示主窗口。自启隐藏由启动策略决定，不通过模拟 `Window.Closing` / `CloseToTray` 来绕过阶段 10 逻辑。

尤其注意本阶段不做：

- 不做安装包启动入口。
- 不做 Windows Service。
- 不做复杂 single-instance 激活。
- 不改变托盘命令。
- 不改变 Agent 控制链路。
- 不做 Diagnostics 自启状态展示（阶段 11.5）。
- 不做手动验收 / 收口（阶段 11.6）。
- 不改 Settings UI。
- 不改 StartupRegistrationService。
- 不改阶段 10 CloseToTray / MinimizeToTray / Exit App / 托盘命令语义。
- 不改阶段 8 IPC 协议。
- 不改 AgentStateMachine 业务语义。
- 不改 PruneData / ClearHistory 规则。
- 不改 ClearHistory 的 `CLEAR` 二次确认。
- 不回退阶段 9.6 的 Stale + IsRunning=false 时 Start 可用修复。

补充要求：

```text
1. 只有同时满足 --from-autostart 和 --start-hidden 时，才进入 AutoStartHidden 策略；如果只有 --start-hidden 而没有 --from-autostart，本阶段仍按手动启动显示主窗口处理。
2. 自启隐藏模式下仍应创建并设置 Application.Current.MainWindow = window，确保托盘 Show 恢复的是同一个窗口；不得创建第二个 MainWindow 或重新创建 MainWindowViewModel。
3. 自启隐藏模式下 status polling 启动路径应与手动启动保持一致，只是跳过 window.Show()；不得新增 hidden-mode 专用 polling 或 timer。
4. AutoStartAgentWhenAppStarts=true/false 的测试应使用 fake ViewModel / fake AgentProcessService 记录是否调用启动路径，不启动真实 Agent。
5. 本阶段不新增 Diagnostics 自启展示；自启模式启动期错误可以复用现有安全日志 / 状态文本，不新增 Diagnostics UI 字段。
6. WindowStartupPolicy 应是纯逻辑，不依赖 Window / Dispatcher / NotifyIcon；输入 StartupLaunchOptions，输出是否显示主窗口、是否隐藏启动。
7. 自启隐藏后的托盘 Show Main Window 必须复用阶段 10 的 Show() + WindowState=Normal + Activate() 逻辑，不得创建新窗口或重新创建 ViewModel。
```
