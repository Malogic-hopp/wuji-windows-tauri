## 一、重构方案概述

《QuantifiedSelf Windows 端完整重构方案》将项目规划为基于 **C#/.NET 8 + WPF + Agent 双进程** 的本地屏幕使用监控系统，并分三版推进：

| 版本 | 范围 |
|------|------|
| 第一版 MVP | WPF 主窗口、导航、Agent 控制、状态机、V0 JSON fallback、Dashboard 今日统计、Top 5 应用、最近 5 条会话、Diagnostics 基础页、15 秒刷新、隐私脱敏 |
| 第二版增强 | Named Pipe 主控通道、状态流订阅、ScottPlot 图表、近 7 天趋势、应用分类、完整 Settings、托盘图标、开机自启、数据清理 |
| 第三版产品化 | 安装包、自动更新、崩溃日志、Windows 11 风格 UI、CSV 导出、数据备份、周报月报、使用目标、本地加密、Windows Service 评估 |

最终技术组合建议：WPF + Worker Host + SQLite + WAL + CommunityToolkit.Mvvm + ScottPlot + Named Pipe/gRPC。

## 六、与原方案的关键偏差

### 6.1 控制通道选择

- **原方案**：V0 JSON fallback → V1 Named Pipe / gRPC over Named Pipes
- **实际**：V0 JSON fallback → V1 裸 Named Pipe，未引入 gRPC
- **评估**：当前裸 Named Pipe 已满足控制需求，gRPC 可作为未来增强项，不影响 MVP。

### 6.2 图表库选择

- **原方案**：ScottPlot.WPF
- **实际**：未引入任何图表库，7 天趋势用 XAML 文本展示
- **评估**：当前效果足够 MVP，但长期来看 ScottPlot/LiveCharts2 仍是推荐方向。

### 6.3 自动刷新频率

- **原方案**：15 秒自动刷新
- **实际**：RefreshService 2 秒 IPC GetStatus 轻量轮询 + 页面数据独立刷新
- **评估**：显著优于原方案，状态更实时，且不会过度刷新页面数据。

### 6.4 托盘与自启

- **原方案**：放在第二版增强
- **实际**：阶段 10/11 已完成，早于原方案顺序
- **评估**：产品体验更完整，用户可以先体验托盘和自启。
