## 1. 目的与强度

本文档是 WUJI v2 产品术语、指标口径和 UI 展示门禁的第一权威来源。数据库字段、Rust 类型、Tauri command 和页面文案不得改变本文定义。

本文使用 [README.md](./README.md#3-规范用语) 的规范用语。标记为“延期”的能力不进入第一版 Schema 或普通 UI。

## 2. 基本原则

### 2.1 事实与结论分离

前台窗口、进程身份、采集时间和输入空闲属于事实；项目、任务上下文、中断和任务切换属于可重建结论。规则升级可以创建新结果世代，不得修改原始事实的历史含义。

### 2.2 三条并行派生路径

```text
Foreground Observation → Activity Segment → App Usage
                                      ├──→ Work Block
                                      └──→ Classification → Context Segment → Switch/Interruption
```

Work Block 只依赖活动连续性事实，不依赖 Context 分类。任务切换不会结束 Work Block，分类变化也不得改变 Work Block 边界。

### 2.3 不确定不是零

证据不足必须输出 `unknown`、低置信度或“不适用”。例如标题被完全屏蔽时，窗口切换不可识别，页面不得将其显示为零。

### 2.4 高级指标必须可解释

Context、Interruption 和 Effective Context Switch 必须能解释使用的 Segment、规则、置信度和版本。未形成结论时必须保存稳定的负向原因码，例如 `InsufficientSafeFeatures`、`BelowCommitDuration`、`EndOfRangeBeforeCommit`（稳定集合见 03 §8），不要求为每个理论候选保存自然语言。

### 2.5 隐私优先于重建完整性

排除规则命中时不持久化标题、路径、PID 或派生提示，只保存不含敏感内容的数据质量区间。产品必须同时显示当前数据可重建等级，不能承诺从未保存的特征重建未来算法。

## 3. 核心术语

### 3.1 Foreground Observation

一次当前用户会话前台活动的持久化采样事实。它包含采集序号、UTC 时间、稳定 App Identity、Activity State、隐私模式、安全标题特征引用和采集质量；第一版不持久化 PID、完整路径或原始标题。

Observation 不表示持续时间。到下一条 Observation 的间隔只有在 gap cap、同一时间 epoch 和质量允许时，才能归属给前一条。

### 3.2 App Identity

进程名、签名/产品映射和本机盐化路径 fingerprint 标准化后的应用身份。

- `app_key` 只在一个 Identity Generation 内是稳定历史键，完整逻辑键为 `(identity_generation_id, app_key)`；无法识别时必须映射为该世代的 `app:unknown`；
- 产品显示名称可更正，普通 UI 对历史数据使用当前 canonical 名称；
- 高级详情可以显示持久化的 normalized process name，不显示完整路径；
- 显示名称变化不得改变该世代内的历史聚合键；
- 盐轮换或丢失后不得仅凭同名或新 fingerprint 自动宣称同一应用。只有受信任运行时连续性或用户确认形成的 Identity Link，才允许跨世代合并查询。

Apps、Top Apps、Hourly/Daily App Usage 使用其 Projection Result Set 固定的 Identity Resolution Generation，把有可信 Link 的 App Identity 归并到同一个 canonical App Identity。未建立 Link 的身份保持分离，即使显示名相同也不得静默合并；UI 可以显示相同名称，并用不含路径的“独立历史记录”标识区分。新增 Link 会创建新的 Identity Resolution Generation 并重建受影响的 App 投影，不改写 Observation、Activity Segment、Work Block 或旧 Sealed Result Set。

### 3.3 Activity State

第一版枚举：`Active`、`Idle`、`Unknown`。一个 Activity Segment 只能有一种 Activity State；状态变化必须切段。

### 3.4 Activity Segment

相邻 Observation 在同一稳定 Activity Key、同一 Activity State、同一隐私状态和允许 gap 内形成的连续区间。

Activity Key 由 `app_key`、稳定窗口/文档 key、隐私状态和 key schema version 组成，**不包含 Activity State**。状态作为独立切段维度。Segment 保存一种状态及一种 `duration_ms`，不得同时保存 Active/Idle/Unknown 三种时长。

### 3.5 Project Hint 与安全特征

Project Hint 是从短暂内存中的窗口标题、文档名、仓库名或规则映射提取的项目证据，不等于最终 Context。持久化只能保存经 allowlist 处理的安全特征及 `feature_schema_version`，不能用“支持重建”为理由保存原文。

### 3.6 Context Key 与稳定身份

Context Key 表示用户正在推进的稳定任务上下文，例如 `project:wuji`、`topic:wpf`、`activity:communication` 或 `unknown`。

Context 的稳定身份由 `context_id` 承载，显示 key/名称可重命名。alias 必须显式、版本化且有生效区间：

- rename：同一 `context_id` 更改显示名称；
- merge：旧 Context 指向新的 canonical Context，保留来源；
- split：创建新 Context，不追溯猜测旧数据，除非新分析世代重新分类；
- parent/child 或 topic/project 默认不等价；只有同一 canonical `context_id` 或显式 alias 才等价。

### 3.7 Context Segment

相邻 Activity Segment 经分类、继承和去抖后，被判定为同一 canonical Context 的连续区间。它可以跨 App，是可重建分析结论，不反向修改 Observation、Activity Segment 或 Work Block。

### 3.8 Work Block

当前用户会话中没有长 Idle、未知 gap、隐私排除、暂停、停止、休眠或时间 epoch 中断的连续工作区间。

- 第一个 Active Activity Segment 开始 Work Block；
- 短 Idle 可以留在同一 Work Block，但不计入 Active 时长；
- 当 Idle 累计达到 `work_block_break_idle`，Work Block **回溯结束于 Idle 开始时刻/最后输入时刻**，不是阈值确认时刻；
- 恢复 Active 后创建新 Work Block；
- Context 切换不结束 Work Block；
- Work Block 可以没有任何可信 Context，也可以包含多个 Context；
- Work Block 表示连续工作，不等于专注。

### 3.9 Raw App Switch

相邻有效 Activity Segment 的 `app_identity_id` 不同。UI 名称为“应用切换”，不得命名为“任务切换”。Identity Generation 轮换本身是强制质量边界，不跨边界产生应用切换；后续 Identity Link 只影响 Apps 聚合，不追溯改写已发布的切换事件。Unknown、质量 gap 和时间 epoch 边界同样不跨界计数。

Rebuild v0.1 以相邻 Observation 粒度实现（无去抖时与本定义等价），见 09 §6.6 与 §15 偏离登记。

### 3.10 Raw Window Switch

相邻有效 Activity Segment 的稳定窗口/文档 key 不同。只有标题/窗口特征覆盖率达到门禁时可展示；无标题模式下值为“不适用/低覆盖”，不得写成零。

### 3.11 Candidate Context Transition

上下文出现变化但尚未满足稳定时间或返回判断的内部候选。Candidate 不进入任务切换计数，必须有决策状态和原因码。

### 3.12 Interruption

规范序列为 `A → B → A'`：

- `A'` 与 `A` 的 canonical Context 等价；
- B 未达到 `context_commit_duration`；
- 中间没有质量 gap、长 Idle 或 Work Block 边界。

第一版不再设置独立的 `interruption_return_window`：B 在 Context 提交前返回才是 Interruption，提交后返回产生两次 Switch。独立 return window 在该状态机中是冗余参数；未来若要允许“已达 commit 后仍可撤销”，必须另行定义 provisional switch 生命周期。满足上述条件时生成一次 Interruption，任务切换数不增加。不得使用“B 未形成单独长工作区间”作为判定条件。

### 3.13 Effective Context Switch

从一个稳定 Context 真正转入另一个稳定 Context。第一版决策闭合如下：

- `A → B`：B 达到 commit duration 时，在 B 开始处确认一次 `A → B`；
- `A → B → A'`：若 B 未达 commit 且 `A' ≡ A`，生成 Interruption；若 B 已达 commit，则生成 `A → B` 和 `B → A` 两次切换；
- `A → B → C`：若 B 已达 commit，生成 `A → B`，随后按 C 单独判断；若 B 未达 commit 且 `C ≢ A`，B 标为 transient/noise，待 C 达 commit 后直接生成 `A → C`；
- 质量 gap、Unknown 或低置信度不能自动产生切换。

完整算法与负向原因码见 [03-上下文识别与算法版本规范.md](./03-上下文识别与算法版本规范.md)。

### 3.14 Focus Block（延期）

第一版不定义、不持久化、不展示 Focus Block，也不包含 `focus_block_count`、`longest_focus_block_duration_ms` 或 `fragmented_seconds`。Focus 规则被单独接受后，必须通过 migration 新增区间实体和读模型字段，不能用 Work Block 冒充。

## 4. 时间与日历语义

### 4.1 UTC 与时间 epoch

事实使用 UTC epoch milliseconds。若捕获时间倒退或无法与上一条建立单调关系，必须关闭当前时间 epoch 并记录质量 gap，禁止产生负时长或跨 epoch 补算。

### 4.2 显式报告时区

产品设置 `reporting_time_zone` 决定 Today、Timeline、Trends、小时桶和日期桶。首次运行默认当前系统时区，之后**不随旅行或系统时区改变自动切换**。用户显式修改后创建新的 Calendar Generation 并重建仍可重建范围。

Windows ID、IANA ID、映射版本和 tzdb/规则版本必须随 Calendar Generation 保存。DST 导致同一本地小时重复或跳过时，小时桶由 UTC 起点唯一标识；一个本地日可以包含多个 offset。

### 4.3 时区变化类型

- 旅行或手动系统时区变化：只提示，不自动改变 reporting zone；
- 用户显式更改 reporting zone：创建新 Calendar Generation，重建全部仍保留事实覆盖的范围；
- tzdb/映射规则更新：比较旧/新规则，仅重建 UTC offset 或本地日期边界发生变化的区间；无法精确比较时重建全部可重建范围。

超出事实保留期、无法按新报告时区重投影的原生 v2 Daily 数据继续使用旧 Calendar Generation，Snapshot Slice 必须返回旧报告时区并在 UI 标记“历史日历口径”。它不得与新 Calendar 下同名 `local_date` 静默相加。

### 4.4 当前日和历史日

当前日可以 provisional，并显示统一 `consistent_through`。历史日只能在返回窗口、队列和分析水位越过日界后 finalization。算法升级仍可创建新 generation 重建历史；不能重建的范围保留原版本并显示“历史算法结果，当前规则不可重算”。

## 5. 候选参数

以下仅用于第一轮黄金样本校准，不是 Accepted 产品常量。修改会提升相应版本并触发受影响层重建。Rebuild v0.1 的 gap cap、work break 等实际取值以 09 §5.1 为准，本表候选值不作为 v0.1 实现输入（差异见 09 §15 偏离登记）。

| 参数 | 候选值 | 版本归属 |
|---|---:|---|
| `activity_change_confirm_duration` | 2 s | segmentation |
| `activity_change_min_samples` | 2 | segmentation |
| `observation_gap_cap` | 60 s | segmentation |
| `context_commit_duration` | 90 s | analysis |
| `work_block_break_idle` | 600 s | analysis |
| `minimum_context_confidence` | 0.60 | classifier/product gate |

去抖必须同时满足时间阈值和最少样本数，不能只按样本数，否则更改采样间隔会改变产品含义。

## 6. 指标词典

### 6.1 时间指标

| 指标 | 定义 | 第一版 UI |
|---|---|---|
| `active_seconds` | 可归属的 Active Segment 时长 | 活跃时长 |
| `idle_seconds` | 可归属的 Idle Segment 时长 | 离开时长 |
| `unknown_seconds` | 已知跟踪范围内无法归类的时长 | 仅诊断 |
| `work_block_count` | 与日期有 Active overlap 的 Work Block 数 | 连续工作区间数 |
| `longest_work_block_seconds` | 按报告日裁剪后的最长 Work Block Active 时长 | 最长连续工作 |

### 6.2 切换指标

| 指标 | 定义 | 展示条件 |
|---|---|---|
| `raw_app_switch_count` | 相邻有效 Segment 的 App 变化 | App 覆盖有效 |
| `raw_window_switch_count` | 稳定窗口 key 变化 | 标题/窗口覆盖达到门禁 |
| `effective_context_switch_count` | 经 commit/返回规则确认的任务变化 | Context 覆盖达到门禁 |
| `interruption_count` | 确认的短暂离开并返回 | Context 覆盖达到门禁 |
| `interruption_seconds` | Interruption 的持续时间 | 同上 |

### 6.3 数据质量指标

质量指标不再使用含义模糊的“理论可采集时长”。分母由版本化 Tracking Expectation Interval 构造：只有 `Expected` 区间进入 `expected_tracking_seconds`；`UserPaused`、`UserStopped`、`ScheduledOff`、`ExclusiveMaintenance`、`SystemSleepOrLogoff` 和无法判定的 `UnknownEligibility` 不进入分母。Agent 意外退出后，如果上次持久化意图仍为 Expected，则离线 gap 仍进入分母并计为 AgentUnavailable。

Tracking Expectation 表达用户意图和系统是否应采集；Data Quality 只表达 Expected 期间的缺失/降级或采集管线事实。`UserStopped`、`UserPaused`、`ScheduledOff`、`ExclusiveMaintenance` 和 `SystemSleepOrLogoff` 不生成同名 Data Quality kind。稳定 Data Quality kind 为 `CaptureFailure | QueueDrop | OutOfOrder | TimeEpochBreak | PrivacyExcluded | AgentUnavailable | TitleUnavailable`：其中 `AgentUnavailable` 仅表示 expectation 仍为 Expected、但 Agent 未能提供采集；不存在 `AgentStopped` kind。

隐私排除发生在 Expected 区间内，因此进入采集管线覆盖，但不进入可分类时长。产品同时区分：

- `runtime_availability_ratio`：Agent 可运行采集时长 / expected tracking；
- `capture_pipeline_coverage_ratio`：正常事实 + 安全隐私排除 / expected tracking；
- `analysis_usable_coverage_ratio`：可用于对应分析的时长 / expected tracking。

| 指标 | 定义 |
|---|---|
| `expected_tracking_seconds` | Tracking Expectation 为 Expected 的时长；无法判定资格的区间单列 |
| `runtime_availability_ratio` | Agent 实际处于可采集状态的时长 / expected tracking |
| `capture_pipeline_coverage_ratio` | 正常事实与安全隐私排除时长 / expected tracking |
| `analysis_usable_coverage_ratio` | 对目标指标可用的时长 / expected tracking |
| `title_feature_coverage_ratio` | 具备可用安全标题特征的可归属时长占比 |
| `context_classifiable_seconds` | 有足够安全特征、允许进入分类器的时长 |
| `context_classified_seconds` | 达到最低置信度并获得非 Unknown Context 的时长 |
| `context_coverage_ratio` | classified / classifiable；分母为零时不可用 |
| `privacy_excluded_seconds` | 被排除且不含敏感内容的质量区间时长 |
| `queue_drop_seconds` | 可由相邻捕获序号界定的丢弃/缺口时长；无法界定时只计事件数 |

普通 UI 展示任务切换时，必须同时展示或可访问数据质量。候选门禁：`capture_pipeline_coverage_ratio ≥ 0.90`、`analysis_usable_coverage_ratio ≥ 0.70` 且 `context_coverage_ratio ≥ 0.70`；未通过时显示“数据不足”，不显示误导性的零。

## 7. 数据可重建等级

每个查询范围返回 `rebuild_capability`：

- `SafeFeaturesOnly`：保留 Observation 和版本化安全特征，可用兼容特征的算法重建；
- `IdentityOnly`：只保留 App/状态，不能重建依赖标题的 Context；
- `SummaryOnly`：只有旧聚合，不能重建明细、切换或 Context；
- `Excluded`：隐私排除，无可重建业务事实；
- `Mixed`：范围内包含多种等级，必须附分项覆盖率。

查询不得把旧算法或 SummaryOnly 数据静默标成当前版本。UI 对不可重建历史使用“历史算法结果”标签，并提供原因而不是警告式错误。

每个查询范围还必须返回 `explanation_capability`：

- `FullEvidence`：源 Segment、Classification、安全特征引用和规则命中仍在保留期；
- `DecisionSummary`：源明细已清理，但保留安全的规则 ID、版本、边界摘要、reason 和 confidence；
- `MetricOnly`：只有聚合指标，不能解释单个事件；
- `None` 或 `Mixed`：无解释能力或范围内能力不同。

产品所称“可解释”受保留期约束。超过明细保留期后必须明确降级，不得继续声称可逐 Segment 追溯。

## 8. UI 语义门禁

| 已具备能力 | 允许显示 | 禁止显示 |
|---|---|---|
| App/Activity | 应用时长、应用切换 | 任务、专注 |
| 版本化 Context + 质量门禁 | 上下文时长、任务切换、中断 | 低置信项目名 |
| Work Block | 连续工作、最长连续工作 | 专注、深度工作 |
| Focus 规则与 Schema 均 Accepted | 后续定义的 Focus 指标 | 规则接受前预埋假数据 |

## 9. 版本可解释性

产品层所称“结果携带版本”是指结果可以通过 Query Snapshot 的一个或多个不重叠 Slice，解析出各时间范围实际使用的 segmentation、work、feature、rule、classifier、analysis、calendar 和 Schema 版本。行级不要求重复保存全部版本字符串。

查询必须同时返回：`query_snapshot_id`、当前尾部的 `published_through_utc`、各 Slice 的时间范围/版本、`is_final`、`data_quality`、`rebuild_capability` 和 `explanation_capability`。一个 Snapshot 可以组合原生 v2 的多个历史世代和 Legacy Summary，但 Slice 时间范围必须全局不重叠；原生 v2 覆盖存在时，Snapshot Builder 必须裁剪或排除重叠 Legacy 范围。页面不得自行拼接来自不同 Query Snapshot 的指标。

## 10. 明确延期与评审记录

第一版明确延期：Focus Block、`fragmented_seconds`、Plaintext 标题持久化、ML、云同步、跨设备身份和用户手工 split 历史回写。

以下仍待产品接受：候选参数、90 天事实保留期、质量展示门槛、默认安全标题特征集合。决定记录在本文状态变更或独立 ADR 中；在此之前保持 Draft，不得宣称为稳定语义。
