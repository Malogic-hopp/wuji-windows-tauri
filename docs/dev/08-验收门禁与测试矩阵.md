## 1. 目的与判定规则

本文把 01–07 的强制约束转换成可执行验收项。某项只有同时具备“固定输入/环境、可复现步骤、明确断言、可定位输出”才算测试；口头确认和一次偶然成功不算证据。

结果使用以下状态：

| 状态 | 含义 |
|---|---|
| NotRun | 尚未执行，不能用于放行 |
| Passed | 在记录的候选版本和环境中满足全部通过条件 |
| Failed | 至少一个强制断言失败 |
| Blocked | 前置设计、fixture、环境或工具未就绪 |
| Waived | 仅 P2 可限时豁免，必须有负责人、理由、补测日期和风险 |

阻断级别：

- **P0：** 数据正确性、隐私、安全、所有权、迁移可恢复性或架构不变量；不得豁免；
- **P1：** 核心功能、兼容、性能、稳定性、无障碍或发布操作性；prod 切换和退役不得带未关闭 P1；
- **P2：** 不影响正确性和安全的非核心质量项；只有书面限时豁免才可放行。

测试通过只对证据中记录的 commit、artifact、依赖锁、Schema checksum、协议版本、Profile/算法版本和环境有效。任一关键输入变化都必须重跑受影响门禁。

## 2. 发布里程碑门禁

| Gate | 放行动作 | 必须满足 | 批准角色 |
|---|---|---|---|
| G-ADR | 将 ADR-002 从 Proposed 转为 Accepted | 产品术语/领域不变量接受；候选与延期项明确；进程、所有权、隐私、版本和回滚边界无 P0 冲突 | 产品、技术、数据/隐私 |
| G-DDL | 冻结首版 SQLite v2 migration DDL | `schema-v2-manifest.yaml` 完整；具体组件 Result Set FK、复合 Fact Boundary、Identity Resolution、空 Snapshot 和三态 Lease/GC 已进入 manifest；逻辑 Schema/DDL drift 为零；migration、约束、事务和故障测试通过 | Storage 负责人、测试 |
| G-DEV | dev 默认切换至 bridge-free Tauri + Rust Agent | M1–M8 自动门禁全绿；shadow 差异已裁决；Desktop binary/session capability、可信原生确认、完整 UI/故障/升级回滚/soak 通过 | 技术、测试、产品 |
| G-PROD | 开始或扩大 prod canary，并最终设为默认 | G-DEV 稳定；生产候选签名固定；备份/导入/回滚演练；无 P0/P1；支持与停止条件就绪 | 产品、技术、测试、发布负责人 |
| G-RETIRE | 停止打包并删除旧系统 | prod 稳定观察期完成；恢复演练、兼容政策和归档完成；Rust 覆盖接替旧风险；明确退役批准 | 产品、技术、测试、支持/发布 |

G-ADR 不等于 G-DDL，G-DEV 不等于 G-PROD。任一上游 Gate 因规范变化重新打开时，下游 Gate 自动失效，直到影响分析和补测完成。

## 4. Parity 放行规则

旧系统的 `ForegroundSample → AppSession` 与 v2 的 `Observation → Activity → Work/Context` 语义不同，禁止用“每个旧指标数值完全相等”作为唯一验收。

必须同时检查：

1. **输入可比性：** 比较窗口、采样质量、时区和隐私规则是否一致；
2. **事实守恒：** UTC 覆盖范围、active/idle/gap/filtered 时长和 App 分布是否闭合；
3. **语义差异：** v2 去抖、Work、Context、Interruption、Switch 与旧 Session 的定义差异有黄金样本或决策依据；
4. **质量显式：** 丢采样、超时、权限不足不得被补算成工作时长；
5. **安全不退化：** DB/WAL/log/DTO 不增加敏感信息；
6. **能力不伪造：** Legacy 范围不展示其无法支持的 Context/Work/Event 明细；
7. **差异闭环：** 每个非预期差异都有分类、负责人和结论，未裁决差异阻断切换。

## 5. 证据包规范

每个 Gate 的证据包至少包含：

```text
gate-id/
  manifest.json
  automated-tests/
  golden-and-parity/
  migration-and-recovery/
  performance-and-capacity/
  ui-manual-checklist/
  issues-and-waivers.md
  approvals.md
```

`manifest.json` 必须记录：commit、构建时间、artifact checksum、OS/架构、依赖锁摘要、channel、数据库 generation、Schema/migration checksum、协议版本、Settings/Profile/算法/Calendar 版本、fixture 版本和测试命令。手工证据记录显示/DPI/主题/输入法/读屏环境。

P0/P1 失败的日志可以保存安全错误码、request ID、计数和时间，但必须移除原始标题、路径、SID、用户名和真实数据库内容。
