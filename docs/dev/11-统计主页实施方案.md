# 11. 统计主页实施方案

状态：实施方案（2026-08-03，基于 [10-统计主页设计定稿](./10-统计主页设计定稿.md)）。

## 背景

实施 `docs/dev/10-统计主页设计定稿.md` — 新的统计主页替代今日页成为默认入口 `/`。页面通过 5 个区块回答"我的工作状态是什么"：状态摘要卡、7/14/30 天活跃趋势图（含 7 日均线）、12 周趋势 + 本周进度、工作惯性 + 应用构成、长期里程碑 + 近 6 月月度均值。

这是 Rebuild v0.1 基线建立以来最大的单次新增功能。设计文档是权威来源，所有 P0 正确性约束（同时刻比较、样本数阈值、槽位分配、ISO 周聚合、摘要/惯性推导规则）必须满足。

## 架构概览

全部变更遵循现有分层模式：
```
Rust: wuji-core (DTO) → wuji-storage (Reader/SQL) → desktop/src-tauri (QueryService → Command)
TS:   自动生成类型 → bridge/client.ts → StatsPage + 图表组件（纯 CSS/SVG）
```

## 阶段一：Rust DTO（`crates/wuji-core`）

### 1a. 在 `dto.rs` 中新增 DTO 类型

遵循现有 `#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize, Type)] #[serde(rename_all = "camelCase")]` 模式，新增设计文档 §5.3 的全部类型：

- `SameTimeComparisonDto { activeDurationMs, deltaFraction, sampleDays }` — deltaFraction 为 null 表示无基线或噪声遮蔽
- `SummaryDto { direction, primaryPeriod }` — direction: "up"|"upSlight"|"flat"|"downSlight"|"down"|null, primaryPeriod: "morning"|"afternoon"|"evening"|"night"|null
- `StatusDto { todayActiveMs, workBlockCount, cutoffLocalTime, yesterdaySame?, last7AvgSame?, summary }`
- `TrendPointDto { localDate, activeDurationMs, workBlockCount, hasData, isToday }`
- `WeeklyPointDto { weekStartDate, activeDurationMs, isCurrentWeek, completedDays, currentWeekDailyAvgMs }`
- `TopEntryDto { app: AppDto, activeDurationMs }`
- `AppPaletteEntryDto { app: AppDto, slot: u32 }` — slot ∈ {0,1,2}，绝不返回颜色字符串
- `CompositionBucketDto { startDate, endDate, bucketKind, apps: Vec<TopEntryDto>, othersActiveMs }`
- `HourlyPointDto { localHour, avgActiveMs, fraction }`
- `InertiaDto { startHour, peakHour, endHour, lunchLowestHour, effectiveDays, totalDays, reliability }` — reliability: "preliminary"|"normal"|null
- `MilestoneDto { totalRecordedDays, longestConsecutiveDays, firstRecordedMonth }`
- `MonthlyPointDto { month, activeDurationMs, recordedDays, avgActiveMsPerRecordedDay }`
- `StatsHomeDto { localDate, reportingTimeZoneId, status, trend, weekly, composition, palette, hourlyProfile, inertia, milestone, monthly }`

所有毫秒时长字段使用 `Int64String`，日期使用现有 `LocalDate` 或 String。

### 1b. 在 `bindings.rs` 中注册

所有新 DTO 加入 `type_collection()`。运行 `WUJI_UPDATE_BINDINGS=1 cargo test -p wuji-core bindings` 重新生成两个副本的 `wuji-core.ts`。

### 1c. 领域类型

`SummaryDto.direction` 和 `InertiaDto.reliability` 使用 `Option<String>`，不需要新增领域枚举。

**涉及文件：**
- `crates/wuji-core/src/dto.rs` — 新增 DTO
- `crates/wuji-core/src/bindings.rs` — 注册类型
- `crates/wuji-core/bindings/wuji-core.ts` — 重新生成
- `apps/desktop/src/types/wuji-core.ts` — 重新生成（逐字节一致）

## 阶段二：Storage Reader（`crates/wuji-storage`）

在 `reader.rs` 中新增 6 个方法，全部遵循现有模式（打开只读连接、返回 Result<Dto>）。

### 2a. 同时刻截断辅助函数

同时刻比较的核心逻辑（供后续方法复用）：
- 今日截止时刻：`now_utc_ms` → 本地时刻 → 同一本地时刻对应的 UTC 时间
- 昨日同时刻：昨天同一本地时刻 → UTC
- 近 7 个历史有效日同时刻：从昨天向前找最近 7 个 `hasData=true` 的日期（不含今日），每个截断至当日同一时刻后取均值
- 计算时必须使用 DB 的 reporting 时区，DST 感知

### 2b. `stats_hourly_profile(&self, days: u32) -> Result<(Vec<HourlyPointDto>, InertiaDto)>`

- 查询最近 `days` 天（固定 14 天用于惯性）的 `hourly_app_usage`
- 按 `localHour` 0-23 聚合：每个小时的 `avgActiveMs` = 有数据日期的 SUM(active) / 有数据的 DISTINCT 日期数
- `fraction` = 该小时 avgActiveMs / 所有小时 avgActiveMs 总和
- 从 24 点剖面推导 InertiaDto：
  - peakHour = avgActiveMs 最大的小时
  - startHour = 首个活跃占比 ≥ 峰值 30% 的小时
  - endHour = 最后一个活跃占比 ≥ 峰值 30% 的小时
  - lunchLowestHour = 12-14 点区间 avgActiveMs 最小的小时
  - effectiveDays = 有数据的不同日期数
  - reliability: <3 → null, 3-6 → "preliminary", ≥7 → "normal"

### 2c. `stats_trend(&self, days: u32) -> Result<Vec<TrendPointDto>>`

- 遍历最近 `days` 个自然日（含今日）：
  - 查询 `daily_work_metrics` 对应行
  - 有行：hasData=true, 填入 active/workBlock
  - 无行：hasData=false, active=0, workBlock=0
  - isToday = (date == today)
- 按 localDate 升序排列

### 2d. `stats_weekly(&self) -> Result<Vec<WeeklyPointDto>>`

- 计算以本周为终点的最近 12 个 ISO 周
- 每周：SUM(active_duration_ms) 来自 `daily_work_metrics` 中落在该 ISO 周范围内的日期
- 当前周：isCurrentWeek=true, completedDays=完整过去日数, currentWeekDailyAvgMs=已完成完整日的均值(completedDays=0 时为 null)
- 历史周：completedDays=7(全满), currentWeekDailyAvgMs=null

### 2e. `stats_composition(&self, days: u32, top_n: u32) -> Result<(Vec<CompositionBucketDto>, Vec<AppPaletteEntryDto>)>`

- 整周期 Top N 应用：整段日期范围内 SUM(active) 排序，取前 N → palette 向量（slot 0..N-1）
- days ∈ {7, 14}：每天一个桶（bucketKind: "day"），查询当天的 `daily_app_usage`，Top N 应用 + 其余聚合为 other
- days == 30：按 ISO 周分组（bucketKind: "week"），Top N 仍按整段 30 天固定，不按周重新排名。当前不完整周照常返回一个桶
- **关键**：palette 从整段范围计算，每个 day/week 桶复用同一槽位顺序

### 2f. `stats_monthly(&self) -> Result<Vec<MonthlyPointDto>>`

- 最近 6 个完整自然月 + 当前月
- 每月：activeDurationMs=总量, recordedDays=有数据的 DISTINCT 日期数, avgActiveMsPerRecordedDay=总量/recordedDays（recordedDays=0 时为 null）
- 当前月：标注当前进行中的天数，不做全量预估

### 2g. `stats_milestone(&self) -> Result<MilestoneDto>`

- totalRecordedDays = `SELECT COUNT(DISTINCT local_date) FROM daily_work_metrics`
- firstRecordedMonth = `MIN(local_date)` 格式化为 YYYY-MM
- longestConsecutiveDays：对 `daily_work_metrics` 中排序后的 distinct 日期做连续天数计算（扫描一遍取最大值）

**涉及文件：**
- `crates/wuji-storage/src/reader.rs` — 6 个新方法 + 同时刻辅助

## 阶段三：QueryService + Command（`apps/desktop/src-tauri`）

### 3a. QueryService 方法（`query.rs`）

新增聚合方法，打开 Reader 后委托给对应方法：

- `stats_status_dto(&self) -> Result<StatusDto, SafeError>` — 编排同时刻查询，组装 yesterdaySame、last7AvgSame、SummaryDto
- `stats_trend(&self, days: u32) -> Result<Vec<TrendPointDto>, SafeError>`
- `stats_weekly(&self) -> Result<Vec<WeeklyPointDto>, SafeError>`
- `stats_composition(&self, days: u32) -> Result<...>`
- `stats_hourly_profile(&self) -> Result<(Vec<HourlyPointDto>, InertiaDto), SafeError>`
- `stats_monthly(&self) -> Result<Vec<MonthlyPointDto>, SafeError>`
- `stats_milestone(&self) -> Result<MilestoneDto, SafeError>`

**SummaryDto 计算规则**（在 Rust 侧，不外推到前端）：
- direction：近 7 自然日窗口（不含今日）有数据日 vs 前 7 自然日窗口有数据日均值比较
  - delta > +10% → "up"；+5% < delta ≤ +10% → "upSlight"；|delta| ≤ 5% → "flat"；对称向下
  - 任一窗口有效日 < 3 → null
- primaryPeriod：从惯性 hourlyProfile 峰值小时映射：6–12→"morning", 12–18→"afternoon", 18–24→"evening", 0–6→"night"
  - 惯性 reliability 为 null 时 → null

新增一个顶层方法组装最终 DTO：
```rust
pub fn stats_home(&self, days: u32) -> Result<StatsHomeDto, SafeError>
```
它调用上述 6 个方法并包装成 `StatsHomeDto`。

### 3b. Command（`commands.rs`）

```rust
#[tauri::command]
pub async fn stats_get_home(
    services: State<'_, AppServices>,
    days: Option<i32>,
) -> Result<StatsHomeDto, SafeError> {
    let days = days.unwrap_or(14);
    let days = match days { 7 => 7, 14 => 14, 30 => 30, _ => 14 };
    services.query.stats_home(days)
}
```

### 3c. 注册（`lib.rs`）

`invoke_handler` 中加入 `stats_get_home`（命令数 15 → 16）。

## 阶段五：StatsPage + 图表组件

### 5a. StatsPage.tsx（页面容器）

遵循 HeatmapPage 的 **判别联合模型** 模式：

```ts
type StatsModel =
  | { phase: 'loading' }
  | { phase: 'ready'; stats: StatsHomeDto; days: number; generation: number }
  | { phase: 'error'; error: SafeError; days: number }
```

- `useState` 管理 model，`useRef` 管理 generation 计数器
- `refresh(days)` → `bridgeClient.statsGetHome(days)`，generation 防迟到覆盖
- `usePolling(refresh, 5000, visible)` — 5s 轮询（今天数据实时更新）
- 7/14/30 切换：set days → 触发 refresh，查询期间保留旧图不闪空，generation 防串
- `PageStateView` 处理 loading / empty / error / ready 四态
- 空状态（完全无数据）：引导文案"还没有记录数据，启动吾迹并保持打开即可开始"

页面布局（自上而下）：
```
<div className="page stats-page">
  <标题 + 记录覆盖信息>
  <StatusCard status={stats.status} />                    ← ① 状态摘要
  <TrendChart trend={stats.trend} days={days} ... />     ← ② 活跃趋势
  <div className="stats-row">                             ← ③ 长期趋势（双列）
    <WeeklyChart weekly={stats.weekly} />
    <WeekProgress weekly={stats.weekly} />
  </div>
  <div className="stats-row">                             ← ④ 工作模式（双列）
    <InertiaCurve profile={stats.hourlyProfile} inertia={stats.inertia} />
    <AppComposition composition={stats.composition} palette={stats.palette} />
  </div>
  <Milestones milestone={stats.milestone} monthly={stats.monthly} />  ← ⑤ 里程碑
</div>
```

### 5b. StatusCard.tsx（区块 ①）

- 主数字行："今日截至 HH:MM 活跃 XhYm · N 个工作块"
- 比较行（带方向箭头）：
  - "较昨日同时刻 ▲ +8%" — yesterdaySame 不存在（昨日无数据）时不显示此行
  - "较近 7 日均同时刻 ▲ +5%（基于 N 个有效日）" — sampleDays < 3 时显示"历史样本不足"
- deltaFraction 为 null（|delta| ≤ 5%）时前端不渲染箭头
- 一行自然语言摘要（由 Rust SummaryDto 组装，前端直接展示）：
  - direction 映射：up→"总量明显上升"、upSlight→"总量略有上升"、flat→"总量基本持平"、downSlight→"总量略有下降"、down→"总量明显下降"、null→不生成摘要
  - primaryPeriod 映射：morning→"上午"、afternoon→"下午"、evening→"晚上"、night→"凌晨"

### 5c. TrendChart.tsx（区块 ②）

- 7/14/30 三按钮切换器，紧贴图表标题区
- **SVG 实现**：每根柱子为 `<rect>`，均线为 `<polyline>`
  - SVG 能精确控制柱定位、斜纹 pattern、折线叠加，无需脆弱的 CSS hack
- 柱高度按系列中最大 active 占比计算
- 今日柱：半透明填充 + SVG `<pattern>` 斜纹，"截至 HH:MM" 标签，图例"今日进行中"
- 无数据日期：空位 + 虚线边框 + 说明（"暂停记录""未记录"）
- **7 日均线叠线**（前端从 trend 数据计算）：
  - 只使用 `hasData=true` 的完整历史日，今日不进均线
  - 窗口 = 7 个自然日，窗口内有效点 < 3 时不画该点（折线断开）
  - 7 天视图下只有第 7 天一个点，如实只画一个点
- X 轴：日期标签（MM-DD），Y 轴：小时刻度
- 无障碍：`role="img"`，`aria-label` 携带数值
- v0.1 只有 7 日均线，**不做 30 日均线**

### 5d. WeeklyChart.tsx + WeekProgress.tsx（区块 ③）

**WeeklyChart（左列）：**
- 12 根柱子（SVG），每柱 = 一周活跃总量
- 当前周柱：实心部分 = 已完成完整日总量 + 今日截至当前时刻（今日部分弱化/斜纹），标注"进行中"
- 虚框参考线：高度 = `currentWeekDailyAvgMs × 7`（completedDays = 0 时不显示虚框）
  - 虚框顶部标注"按当前日均延展的参考值"
  - completedDays = 0 时显示文字"本周进行中，暂无稳定参考"
- 上周锚点线辅助对比

**WeekProgress（右列，小卡）：**
- "本周截至今日 XhYm"
- "较上周同期 ▲ +X%"（上周截至本周同一周序日、同一时刻累计值）
- 当前周总记录天数

### 5e. InertiaCurve.tsx（区块 ④ 左列）

- SVG 面积/折线图：24 个数据点（0-23 小时）
- X 轴标注：6, 9, 12, 15, 18, 21, 24
- reliability == null → 不画曲线，显示"有效记录日不足，无法显示工作惯性"
- reliability == "preliminary" → 正常画曲线，标注"初步模式"徽章
- 标注点：startHour（开工）、peakHour（高峰）、endHour（收工）、lunchLowestHour（午休低谷）
- 底部说明："开工约 9:00 · 高峰 10–11 点 · 收工约 19:00 · 午休低谷 12 点"
- 标注"有效天数 N/14"

### 5f. AppComposition.tsx（区块 ④ 右列）

- **日桶**（7/14 天）：横向堆叠条，每天一行
  - 每段宽度百分比 = 该应用时长 / 当日总量 × 100%
  - 颜色来自 `var(--chart-app-N)`（N = palette 中 slot+1）
- **周桶**（30 天）：纵向堆叠柱，每 ISO 周一柱（4-5 根）
  - 色值同样走槽位映射
- 其余应用聚合为"其他"，用 `--chart-other`
- 配色固定：同一应用在同范围所有日期保持同一槽位颜色（Rust 决定的 palette）
- 分离图例：Top 3 应用名 + 色块
- 悬停/焦点：显示应用名与此时长
- 切换器切换范围时同步重查

### 5g. Milestones.tsx（区块 ⑤，底部轻量区）

- 一行里程碑："累计记录 N 天 · 自 X 年 X 月起 · 最长连续数据区间 N 天"
  - 无强边框、无勋章式高亮，使用 `--text-dim` 小号文字
- 6 根月度柱（极简样式，SVG 或 thin CSS 条）
  - 主值 = `avgActiveMsPerRecordedDay`（每有效记录日均值），格式化为小时
  - 悬停显示："Xh / N 个有效日"
  - 当前月标注"进行中"，只显示已完成日口径均值

### 5h. statsModel.ts（纯函数工具模块）

- `computeMovingAverage(trend: TrendPointDto[], window: number): (number | null)[]` — 7 日滑动均线
- `formatDurationMs(ms: Int64String): string` — 格式化时长
- `formatDeltaPercent(fraction: number | null): string` — 格式化变化百分比
- `mapDirectionText(direction: string | null): string` — 方向文本映射
- `mapPeriodText(period: string | null): string` — 时段文本映射
- `mapReliabilityText(reliability: string | null): string` — 可靠性文本映射

## 关键风险与缓解

| 风险 | 缓解措施 |
|---|---|
| 同时刻比较的夏令时正确性 | 使用 chrono_tz + `local_day_range_utc_ms` 模式（热力图中已验证）；编写跨夏令时边界的测试用例 |
| ISO 周聚合复杂度 | 使用 `chrono::IsoWeek`；测试跨月、跨年边界 |
| 5s 轮询 + 图表渲染性能 | 整个页面一次查询（1 个 DTO），非 N 个请求；generation 防重复渲染 |
| 4 类图表的 CSS/SVG 体积 | 纯 CSS/SVG = 零框架依赖；复用热力图的自定义属性模式控制柱高度；SVG inline 保证无障碍 |
| 均线计算在前端 | 对预先排序的 trend 数组做简单滑动窗口；在 statsModel.test.ts 中独立测试 |
