## 1. 背景与目标

打开 App 第一眼看到**"我最近的工作是什么状态"**——工作总量在变多还是变少、工作主要发生在什么时候、时间花在哪、长期是否稳定。

核心问题拆成四层：

1. **状态**：我今天到目前为止是什么状态？
2. **趋势**：最近几天是在增加、下降，还是波动？
3. **长期**：这种变化是否已经持续一段时间？
4. **模式**：我的工作通常在什么时候发生？时间花在哪里？

表述一律使用中性方向词（上升/下降/稳定/波动），不加价值判断（"变好/变差"）——活跃时长增加可能是加班，工作块增加可能是碎片化，软件不替用户解读。v0.1 没有"集中/分散"类指标（工作块数量不等于碎片化），不使用这类措辞；待后续版本引入平均工作块时长、中断次数等连续性指标后再启用。

## 2. 设计原则

- **状态优先于统计**：页面回答"我处于什么状态"，不是陈列数字；
- **可比优先于绝对值**：进行中的数据只与历史同时刻比（今日 = 截至当前时刻 vs 昨日同期），已完成的数据才能完整比较；进行中的柱/周/桶必须用"进行中"样式与完整数据视觉区分；
- **中性描述**：涨跌用中性色（非红/绿），趋势用"上升/下降"非"变好/变差"；
- **诚实数据**：无数据日期留空并斜纹标注，文案统一为中性的"当日无记录数据"（无法从 `hasData=false` 推断缺失原因，不伪造"暂停记录"等说法）；惯性少于最低有效天数不画，有数据天数明确标注；样本不足时宁可不显示比较，也不显示低置信百分比；"无基线""变化很小""零基线新增"三种情况必须可区分；文案口径与计算口径一致（日均就说"日均"，不说"总量"）；不做平滑伪造、不做数值预测（仅"按当前日均延展的参考值"这类明确命名的参考标记）；
- **直观**：纯 CSS/SVG 图表，零前端依赖；配色与热力图/今日页同一令牌主题，适配 forced-colors 与键盘焦点；
- **口径在 Rust**：所有统计语义（同时刻截断、比较方向、7 日均线、Top N 固定槽位、周/月聚合、摘要规则）在 Rust 计算，前端只渲染与格式化，不重算；纯视觉归一化（柱高映射）属渲染职责，可留在前端。

## 4. 区块详细设计

### 4.1 ① 状态摘要卡

回答：我今天到目前为止是什么状态？

| 内容 | 说明 |
|---|---|
| 今日截至 HH:MM 活跃时长 + 工作块数 | 主数字，随轮询实时更新（与顶栏同一拍，走轻量命令 `stats_get_status`，见 5.4） |
| 较昨日同时刻 ▲▼ +X% | 截至同一时刻的可比数，"昨日"为昨日同时刻；昨日无数据时 `direction = "unavailable"`（`unavailableReason = "noData"`），不显示百分比；昨日同期为 0 而今日 > 0 时 `direction = "upFromZero"`，显示"较昨日同期新增 N 分钟" |
| 较近 7 日均同时刻 ▲▼ +X%（基于 N 个有效日） | 分母为最近 7 个历史有效日（不含今日）各自同时刻的均值；始终标注样本数；`sampleDays < 3` 时 `direction = "unavailable"`（`unavailableReason = "insufficientSamples"`），前端仅显示"历史样本不足" |
| 一行自然语言摘要 | 由 Rust 按确定性规则生成（见 5.3 `SummaryDto`），v0.1 只输出"方向 + 主要活跃时段"两部分；方向 = 窗口**有效记录日日均值**比较，文案必须说"日均活跃"不得说"总量"（缺失日数量不同时两者差异巨大），详细口径（有效记录日）放 aria/tooltip；**两部分来自不同窗口（方向 = 7 日窗口，时段 = 14 日惯性），文案不得暗示同一窗口**，例："最近 7 日日均活跃略有上升；通常主要活跃在上午"；**不生成波动描述**（波动指标定义稳定前暂缓） |
| ▲▼ 使用中性色（非红非绿） | 活跃时长上升不等于"好"——仅代表方向 |

**上升/下降判决规则**（昨日/近 7 日/上周同期/摘要窗口统一适用）：阈值 ±5%（噪声遮蔽，避免 1-2 分钟变动产生 ▲▼）。

- 基线 > 0：正常计算 `deltaPercent`（四舍五入整数百分数，有基线时始终携带实际值）；|delta| > 5% → `up` / `down`，|delta| ≤ 5% → `stable`（前端显示"基本持平"，不渲染箭头）；
- 基线 = 0 且当前 = 0 → `stable`，`deltaPercent = 0`；
- 基线 = 0 且当前 > 0 → `upFromZero`，`deltaPercent = null`，前端显示"较 X 同期新增 N 分钟"，**不得伪造百分比**；
- 无基线 / 样本不足 → `unavailable` + `unavailableReason`（`"noData"` / `"insufficientSamples"`），`deltaPercent = null`。

比较对象 DTO **始终存在**（不用外层 `Option` 表达不可用），"是否可用"只由 `direction` / `unavailableReason` 单轨表达。

### 4.2 ② 活跃趋势

回答：最近几天是在增加、下降，还是波动？

- 柱状 7 / 14 / 30 天切换器（三按钮），默认 14 天；
- **今日柱 = 进行中样式**：半透明/斜纹填充，柱顶不做任何数值预测，标签显示"截至 HH:MM"，图例标注"今日进行中"——避免与完整历史日直接视觉比较；
- 无数据日期留空 + 斜纹，附中性说明"当日无记录数据"（不推断缺失原因）；
- **7 日滑动均线 overlay**：在柱状上叠一条折线，平滑日间噪声后回答"趋势方向"。**由 Rust 计算**并随 `TrendPointDto` 返回（`movingAvg7ActiveMs` + `movingAvg7SampleDays`），口径：
  - 窗口 = 7 个自然日，仅对窗口内 `hasData=true` 的**完整历史日**求均值；
  - **今日不进入均线**，今日点 `movingAvg7ActiveMs = null`；
  - 窗口内有效点 < 3 时该点均线值为 `null`（折线断开）；
  - `stats_trend(days)` 内部多读 6 天隐藏 lookback（如 7 天视图实际读 13 天），使**每个可见完整历史日都携带均线值**，7 天视图也能画出完整线段；
  - 这是视觉辅助，不是新的统计口径，与 v0.1 边界"不做多周滑动平均对比"不冲突；v0.1 只有 7 日均线，**没有 30 日均线**；
- 切换器重新查询 ② 与 **④**（应用构成随范围联动），查询期间保留旧图，generation 防串。

### 4.3 ③ 长期趋势

回答：这种变化是否已经持续一段时间？

**左侧 —— 近 12 周活跃柱状**：

- 12 周柱状（固定），每柱 = 该周活跃总量；
- **当前周进行中样式**：实心部分 = 已完成完整日总量 + 今日截至当前时刻部分（今日部分弱化样式）；文字标注"进行中"；
- **虚框参考值**：高度 = **已完成且有记录的完整日的日均 × 7**（`currentWeekDailyAvgMs` = 这些日期总活跃 ÷ `completedRecordedDays`；无记录日不计入分母，与惯性 `effectiveDays" 同一"缺失不补零"原则），命名为"按当前日均延展的参考值"——不是预测，只是参照线；**当前周尚无已完成有记录日（`completedRecordedDays = 0`，如周一下午）时不显示虚框**，仅显示"本周进行中，暂无稳定参考"；
- 上周标注锚点（视觉参照线），帮助对比。

**右侧 —— 本周进度小卡**：

- 本周截至今日总量 + 较上周同期 ▲▼（上周同期 = 上周截至本周今日同一周序日、同一时刻的累计值；由独立的 `StatsHomeDto.weekProgress` 承载，**不混入 `weekly` 序列点**）；
- **`weekProgress` 在当前周存在时始终返回**，仅对比基线可空：上周同期无数据时 `lastWeekSame.unavailableReason = "noData"`，卡片仍显示本周总量与记录天数，只隐藏比较行；
- 当前周总记录天数。

### 4.4 ④ 工作模式

回答：我的工作通常在什么时候发生？时间花在哪里？

此区块为**双列**：左列工作惯性，右列应用构成。

**左列 — 工作惯性**：

- **惯性窗口 = 最近 14 个完整本地日 `[today-14, today-1]`，明确排除今日**——含今日会让未来小时补 0（伪造晚间衰退）或使各小时分母不一（上午 15 个样本、晚间 14 个样本）；固定 14 天，不随切换器变化；`totalDays = 14`，`effectiveDays` = 窗口内有效记录日期数；
- **统一分母规则**：每个有效日补齐 24 小时、无活动小时按 0 计入；每个 `localHour` 的 `avgActiveMs` = 全部有效日该小时总和 ÷ `effectiveDays`——**不得只对"该小时有非零记录"的日期求均值**（否则偶发的晚间工作会被放大成"通常晚间活跃"）；
- **有效日定义**：窗口内存在当日工作统计投影的日期；完全无数据日不计入；部分记录日（如只记录了十分钟）v0.1 无法可靠识别，作为已知限制，由 `effectiveDays / 14` 标注兜底；
- 输出 24 个整点值（`localHour: 0–23`，**保持小时粒度**，不使用分钟级标注）；
- 派生标准（含边界与并列的确定性规则）：
  - 开工 ≈ 首个活跃占比 ≥ 当日峰值 30% 的小时（**整点标注：如 9:00**；并列取最早）；
  - 高峰 ≈ 占比最大的小时（如"10-11 点"；**并列取最早小时**）；
  - 收工 ≈ 最后一个活跃占比 ≥ 峰值 30% 的小时（并列取最晚）；
  - 午休低谷 ≈ 12-14 点区间均值最小的小时，**且该值严格低于 11 点与 15 点的均值**（真实局部低谷才标注，不强行从无午休的数据里选一个小时；不满足时为 `null`；并列取最早）；
  - **全零边界**：24 小时均值全为 0（峰值 = 0）时，30% 阈值失去意义——`startHour` / `peakHour` / `endHour` / `lunchLowestHour` 全部为 `null`，`SummaryDto.primaryPeriod` 也为 `null`，不得伪造开工 0:00 / 收工 23:00；
  - `reliability = null`（有效日 < 3）时以上派生字段同样均为 `null`；
- **最低有效天数**：
  - < 3 天：不画曲线，提示"有效记录日不足，无法显示工作惯性"；
  - 3–6 天：正常画曲线，标注"初步模式"；
  - ≥ 7 天：正常显示；
  - 同时标注"有效天数 N/14"与缺失日期数；
- v0.1 不做工作日/周末拆分（后续版本如需再做，届时再扩 DTO，当前合同不预留字段）。

**右列 — 应用构成**：

- 随切换器范围联动（7/14/30 天）；
- 配色规则：**统计范围内整体 Top 3 应用固定槽位**（不在每天独立排名取色）——同一应用在同范围所有日期保持同一槽位；其余应用聚合成"其他"；Rust 只返回 `slot: 0|1|2`，槽位 → 色值由前端 CSS 令牌映射（`--chart-app-1/2/3`、`--chart-other`），从而自动适配浅色/深色/forced-colors 主题；
- 展示形式随范围变化，**聚合桶由 Rust 直接返回，前端只渲染**：
  - **7 天**：逐日横向堆叠条（`bucketKind: "day"`）；
  - **14 天**：逐日横向堆叠条，紧凑（`bucketKind: "day"`）；
  - **30 天**：按周聚合纵向堆叠柱，4-5 根（`bucketKind: "week"`）——周起点为 ISO 周一，跨月周保持单桶不拆分，当前不完整周照常返回一个桶；Top 3 仍按整个 30 天范围固定，不按周重新排名；
- **当前桶进行中语义**：7/14 天视图的今日桶、30 天视图的当前不完整周桶，`isCurrent = true`，使用弱化样式（与今日柱/当前周一贯），悬停/焦点标注"截至 HH:MM"——不得把当前桶画成完整桶；
- 悬停/焦点显示应用名与此时长；图例分离显示 Top 3 应用 + 颜色。

### 4.5 ⑤ 长期追踪入口

回答：这是否已经形成长期模式？

**里程碑条**（一行，低视觉权重：底部轻量区、无强边框、无勋章式高亮）：
- 累计记录 N 天（自首次记录以来总有效日期数）；
- 自 X 年 X 月起（首次记录月份）；
- 最长连续数据区间 N 天（中性文案，不用"连续记录"的签到化表述）。

**近 6 月月度活跃柱状**：
- 固定 6 根 = **包含当前月在内的最近 6 个本地日历月**（前 5 个为完整月，当前月 `isCurrentMonth = true`，标"进行中"）；
- **主值 = 每有效记录日平均活跃时长**（`avgActiveMsPerRecordedDay`）——避免记录覆盖不足污染"长期趋势"读数；总量与有效记录天数为辅助标注（如"70h / 12 个有效日"）；
- **当前月口径一致性**：`recordedDays` 与均值只计**完整有效记录日（不含今日进行中）**；`activeDurationMs` 总量含今日截至当前时刻，但当前月必须标"进行中"——均值与 `recordedDays` 不得在是否含今日上口径不一；
- 极简样式，不随 ② 切换器变化，下方常驻；
- 月度柱不补当前进行中月份的全量预估。

## 5. 数据契约

全部只读投影查询，**无 Schema 改动**。

### 5.1 数据来源

| 区块 | 表 | 说明 |
|---|---|---|
| ① 状态摘要 | `daily_work_metrics` + 同时刻查询 | 今日/昨日/近 7 个历史有效日截至当前时刻的活跃时长 |
| ② 趋势 | `daily_work_metrics` | 按日聚合；`hasData` 由当日行存在与否判定；均线由 Rust 计算（多读 6 天 lookback） |
| ③ 长期 | `daily_work_metrics` | 按周 SUM；当前周取同时刻；参考值分母 = 已完成且有记录日；上周同期累计独立查询 |
| ④ 惯性 | `hourly_app_usage` | 按 `localHour` 均值（窗口 `[today-14, today-1]` 排除今日、仅统计有效日、统一分母） |
| ④ 构成 | `daily_app_usage` | 周期固定 Top 3；7/14 天返回日桶，30 天在 Rust 内按 ISO 周聚合为周桶；当前桶 `isCurrent` |
| ⑤ 月度 | `daily_work_metrics` | 包含当前月在内最近 6 个本地日历月；均值/recordedDays 仅计完整有效日（不含今日） |
| ⑤ 里程碑 | `daily_work_metrics` + `foreground_observations` | `SELECT COUNT(DISTINCT local_date)`, `MAX(/* 连续日 */)` |

### 5.2 同时刻查询规则

今日与对比对象的截止时刻对齐：

- 今日截至 `nowUtcMs`；
- 昨日同时刻 = 昨日 `localDate` 中 ≤ 昨日对应 UTC 时间戳的数据（Same local-time offset）；
- 近 7 日均同时刻 = 自昨日向前寻找**最近 7 个 `hasData=true` 的历史日（明确不含今日）**，各自截断至当日同时刻后求均值；**有效日 < 3 时 `direction = "unavailable"`、`unavailableReason = "insufficientSamples"`**（对象仍返回，`sampleDays` 如实携带）；
- 上周同期 = 上周与今日同一周序日、截至同一时刻的累计值；上周完全无数据时 `lastWeekSame.unavailableReason = "noData"`（`weekProgress` 仍返回）；
- 所有比较统一适用 §4.1 判决规则（±5% 阈值 + 零基线 `upFromZero`）。

### 5.3 DTO（wuji-core，specta 生成，双副本 drift 门禁）

仓库全部 DTO 统一 derive `PartialEq, Eq`，而 `f64` 不实现 `Eq`——**所有比例字段一律用整数表达**，不得引入浮点。

```text
StatsHomeDto {
  hasAnyData,                  // false = 首次使用（无任何数据），前端显示整页引导空状态，其余区块不渲染
  localDate,
  reportingTimeZoneId,
  status: StatusDto {
    todayActiveMs, workBlockCount,
    cutoffLocalTime,             // 截止时刻（本地时间 HH:MM）
    yesterdaySame: SameTimeComparisonDto,   // 对象始终存在，不可用由 direction/unavailableReason 表达
    last7AvgSame: SameTimeComparisonDto,
    summary: SummaryDto,
  },
  trend: [ TrendPointDto {
    localDate, activeDurationMs, workBlockCount, hasData, isToday,
    movingAvg7ActiveMs: Option<Int64String>,
    // 7 日均线（Rust 计算，stats_trend 内部多读 6 天 lookback）；
    // 今日与窗口有效点 < 3 的历史日为 null
    movingAvg7SampleDays: i32,   // 该点窗口内有效完整日数（供前端 aria/调试）
  } ],
  weekly: [ WeeklyPointDto {
    weekStartDate,
    activeDurationMs,            // 当前周 = 截至同时刻总量，历史周 = 完整周
    isCurrentWeek,
    completedRecordedDays,       // 当前周已完成且 hasData=true 的完整日数（0 时不显示虚框参考值）
    currentWeekDailyAvgMs: Option<Int64String>,
    // 当前周 = 已完成有记录日总活跃 ÷ completedRecordedDays（无记录日不计入分母）；
    // completedRecordedDays = 0 或历史周为 null
  } ],
  weekProgress: WeekProgressDto,
  // 右侧本周进度卡专用，当前周存在时始终返回；仅对比基线（lastWeekSame）可空
  composition: [ CompositionBucketDto {
    startDate, endDate,
    bucketKind: "day" | "week",  // 7/14 天 = day；30 天 = week（ISO 周，跨月不拆分）
    isCurrent,                   // 今日桶 / 当前不完整周桶：弱化样式 + "截至 HH:MM"
    apps: [ TopEntryDto { app: AppDto, activeDurationMs } ],
    othersActiveMs,
  } ],
  palette: [ AppPaletteEntryDto { app: AppDto, slot } ],
  // 周期内整体 Top 3 → 稳定槽位（0|1|2）；槽位→色值由前端 CSS 令牌映射，Rust 不返回具体颜色字符串
  hourlyProfile: [ HourlyPointDto { localHour, avgActiveMs } ],
  // 不返回归一化比例——柱高归一化（最大值映射 100%）是前端渲染职责，不是统计口径
  inertia: InertiaDto {
    startHour: Option<i32>, peakHour: Option<i32>,
    endHour: Option<i32>, lunchLowestHour: Option<i32>,
    // reliability = null（有效日 < 3）或 24 小时均值全零（峰值 = 0）时，以上派生字段均为 null
    effectiveDays,               // 有效记录日数（窗口 [today-14, today-1]，不含今日）
    totalDays,                   // 总日数（14）
    reliability: "preliminary" | "normal" | null,  // preliminary = 3-6天, null = <3天不画
  },
  milestone: MilestoneDto {
    totalRecordedDays, longestConsecutiveDays,
    firstRecordedMonth: Option<String>,   // YYYY-MM；无任何有效记录时为 null（禁止用空字符串表示无数据）
  },
  monthly: [ MonthlyPointDto {
    month, activeDurationMs, recordedDays,
    isCurrentMonth,              // 当前月：进行中样式；recordedDays/均值不含今日
    avgActiveMsPerRecordedDay: Option<Int64String>,
    // 月度柱主值 = 完整有效记录日总活跃 ÷ recordedDays；recordedDays = 0 时为 null
  } ],
}

SameTimeComparisonDto {
  activeDurationMs: Option<Int64String>,
  // 对比对象的有效活跃时长；无基线（noData / insufficientSamples）时为 null
  deltaPercent: Option<i32>,
  // 相对变化的整数百分数（8 = 相对增加 8%，-12 = 相对减少 12%），四舍五入；
  // 基线 > 0 时始终携带实际值（即使 |delta| ≤ 5%）；
  // 基线 = 0 且当前 = 0 时为 0；基线 = 0 且当前 > 0（upFromZero）或无基线时为 null
  direction: "up" | "down" | "stable" | "upFromZero" | "unavailable",
  sampleDays: i32,               // 纳入均值的历史有效日数；yesterdaySame 恒为 1（无基线时为 0）
  unavailableReason: "noData" | "insufficientSamples" | null,
  // noData = 对比日/上周同期无数据；insufficientSamples = 有效样本 < 3；
  // direction ≠ unavailable 时为 null
}

WeekProgressDto {
  currentActiveMs,               // 本周截至今日总量
  lastWeekSame: SameTimeComparisonDto,
  // 上周同期比较，复用同一合同（sampleDays 恒为 1；上周无数据时 unavailableReason = "noData"）
  recordedDays,                  // 当前周有记录天数
  cutoffLocalTime,               // 截止时刻（本地时间 HH:MM）
}

SummaryDto {
  direction: "up" | "upSlight" | "flat" | "downSlight" | "down" | null,
  // 近 7 自然日窗口 vs 前 7 自然日窗口的有效记录日（hasData=true，不含今日）日均值比较：
  //   delta > +10% → up；+5% < delta ≤ +10% → upSlight；|delta| ≤ 5% → flat；对称 down；
  //   任一窗口有效日 < 3 → null（前端不生成方向句）；
  //   零基线同样适用 §4.1 规则：前窗口日均 = 0 且后窗口 > 0 → up；均为 0 → flat；
  //   前端文案用"日均活跃"（如"最近 7 日日均活跃略有上升"），不得说"总量"
  primaryPeriod: "morning" | "afternoon" | "evening" | "night" | null,
  // 由惯性 hourlyProfile 峰值小时映射：6–12 morning，12–18 afternoon，18–24 evening，0–6 night；
  // 惯性 reliability 为 null 或曲线全零时为 null（前端不生成时段句）
  // 前端文案：两段来自不同窗口（方向 = 7 日，时段 = 14 日惯性），
  // 用"最近 7 日日均活跃…；通常主要活跃在…"句式，不得暗示同一窗口
}

TrendPointDto { ... }
  // hasData: false 的日期柱留空+斜纹，文案"当日无记录数据"；isToday: true 的柱用进行中样式，且不进入 7 日均线
WeeklyPointDto { ... }
  // isCurrentWeek: 进行中样式 + 文字标注"进行中"；completedRecordedDays = 0 时不显示虚框参考值
MilestoneDto { ... }
  // firstRecordedMonth: Option<String>——无任何有效记录时为 null，禁止用空字符串表示无数据；
  // 整页首次使用空状态由 StatsHomeDto.hasAnyData = false 表达
```

`Int64String` 规则不变（时长毫秒用字符串）；`AppDto` 复用现有应用身份类型。

### 5.4 命令、查询与刷新策略

- `stats_get_home(days: Option<i32>)`：`days ∈ {7, 14, 30}`，非法或缺失规范化回 14；返回 `StatsHomeDto`（无任何数据时 `hasAnyData = false`，整页空状态）。**调用时机：首次进入页面、跨日期（`localDate` 变化）、切换范围**——不随轮询调用；
- `stats_get_status()`：轻量轮询命令，返回 `StatsStatusDto { status: StatusDto, weekProgress: WeekProgressDto, todayTrendPoint: TrendPointDto }`——状态卡主数字、本周进度、今日趋势点随顶栏同一拍更新，**不触发趋势/惯性/月度/里程碑等重查询**；
- 新增 2 个 Tauri 命令，命令总数 15 → 17（实现时同步 CLAUDE.md 与 09 §8.3）；
- **轻量轮询同步边界**：`stats_get_status` 只更新 `status` / `weekProgress` / `todayTrendPoint`；其中 `weekProgress.currentActiveMs` **同步覆盖 ③ 左侧当前周柱的实际高度**（实心已完成部分与今日弱化部分随之更新），避免"右侧本周进度已更新而左侧当前周柱仍停留在旧值"的不一致；应用构成当前桶与月度当前月总量属于低频快照，保持页面首次加载值，在页面重新聚焦、跨日期（`localDate` 变化）或用户切换范围时随 `stats_get_home` 刷新；
- 不采用"单命令 + Rust 缓存稳定部分"方案：缓存键（`localDate`/时区/`days`/projection generation）与失效逻辑的复杂度高于命令分离，且仓库已有"状态轮询 vs 页面查询"分离的既有模式。

QueryService 新增 6 个只读方法：`stats_status_dto()`（两个命令共用）、`stats_trend(days)`（内部读 `days + 6` 天以计算均线 lookback）、`stats_weekly()`（含 `weekProgress` 与上周同期）、`stats_composition(days, top_n)`（内含 30 天 ISO 周聚合）、`stats_hourly_profile()`、`stats_monthly()`。同时刻截断在 SQL 参数化（UTC 关键时间点传入，不动态拼接时刻）。所有查询走现有只读连接与时区口径（`reporting_time_zone_id`）。摘要（`SummaryDto`）、比较方向与零基线判定（`direction` / `unavailableReason`）、7 日均线、槽位分配（`palette`）、惯性标注在 Rust 计算，前端不重算。

## 7. 明确不做（v0.1 边界）

- 自定义目标/阈值与达成度；
- 预测与建议（当前周虚框仅为"按当前日均延展的参考值"，不是预测）；
- 任意日期范围选择器（固定 7/14/30 与 12 周）；
- 工作日/周末拆分（v0.1 不做，届时再扩 DTO，当前合同不预留字段）；
- 开工收工漂移趋势图（P2，后续版本的主力长期功能——当前只展示固定 14 天均值的静态标注）；
- 波动度的自然语言描述（"波动较大/较稳定"）——变异系数等指标阈值需先用真实数据观察分布后定义，v0.1 摘要只输出方向与时段；
- "集中/分散"类节奏指标与措辞（工作块数量不等于碎片化；待引入平均工作块时长、中断次数等连续性指标后启用）；
- 30 日均线（v0.1 仅 7 日均线）；
- 缺数据原因的推断（`hasData=false` 只呈现"当日无记录数据"，不区分暂停/未运行/清理/异常）；
- 部分记录日的识别与剔除（v0.1 无法可靠判定"只记录了十分钟"的日期，作为已知限制由 `effectiveDays / 14` 兜底）；
- 导出、分享、深链接。

## 9. 关键正确性约束（P0 — 实现必须满足）

1. 今日只与历史同时刻比较（截至同一 local-time 时刻），不得与完整历史日天数比较；
2. `last7Avg` 分母为最近 7 个历史有效日（**明确不含今日**）各自同时刻的均值；DTO 必带 `sampleDays`；比较对象 DTO **始终存在**，不可用只由 `direction` / `unavailableReason` 单轨表达（禁止外层 `Option` 与内部 `unavailable` 双轨）；`sampleDays < 3` → `unavailable` + `"insufficientSamples"`，前端显示"历史样本不足"；
3. **零基线规则**（昨日/近 7 日/上周同期/摘要窗口统一）：基线 = 0 且当前 = 0 → `stable`（`deltaPercent = 0`）；基线 = 0 且当前 > 0 → `upFromZero`（`deltaPercent = null`，前端显示"新增 N 分钟"）；**不得伪造百分比或返回极大值**；
4. 今日趋势柱必须使用进行中样式（半透明/斜纹 + "截至 HH:MM" 标签 + 图例"今日进行中"），**且不进入 7 日均线**；**均线由 Rust 计算**（`stats_trend` 内部多读 6 天 lookback），今日与窗口有效点 < 3 的点为 `null`（折线断开）；
5. 当前周柱状使用进行中样式；虚框参考值 = **已完成且有记录日均 × 7**（`completedRecordedDays` 为分母，无记录日不计入），命名"按当前日均延展的参考值"；`completedRecordedDays = 0` 时不显示虚框，标注"本周进行中，暂无稳定参考"；不得与完整周直接并列 SUM；`weekProgress` 在当前周存在时**始终返回**，仅对比基线可空；
6. 应用构成使用**周期固定 Top 3 槽位**——`palette` 由 Rust 在整个天数范围预算（App 身份 → 槽位一对一映射），**只返回 `slot`，不返回具体颜色字符串**；槽位 → 色值由前端 CSS 令牌映射；30 天周桶在 Rust 内按 ISO 周聚合，Top 3 不按周重新排名；**当前桶（今日 / 当前不完整周）必须 `isCurrent = true` 并用进行中样式**，不得画成完整桶；
7. 惯性窗口 = 最近 14 个完整本地日 `[today-14, today-1]`（**明确排除今日**）；每个有效日补齐 24 小时、无活动小时按 0，所有 `localHour` 统一以 `effectiveDays` 为分母，不得只对该小时有非零记录的日期求均值；
8. 惯性标注使用整点（小时粒度），不得暗示分钟精度；**24 小时均值全零（峰值 = 0）时派生字段全部 `null`**，不得伪造开工/收工；高峰并列取最早小时；午休低谷必须为真实局部低谷（严格低于 11 点与 15 点均值），否则 `null`；有效天数 < 3 时不画曲线（`reliability: null`，派生字段全为 `null`），3-6 天标"初步模式"（`"preliminary"`）；
9. 所有涨跌提示使用中性色，不引导"好或坏"的价值判断；缺数据日期文案统一为"当日无记录数据"，不推断缺失原因；摘要文案说"日均活跃"不说"总量"；
10. 月度柱主值为每有效记录日均值，不得只显示受记录天数污染的总量；月度窗口 = 包含当前月在内最近 6 个本地日历月；当前月 `isCurrentMonth = true` 标进行中，其 `recordedDays` 与均值只计完整有效日（不含今日）；
11. 所有比例字段（`deltaPercent` 等）一律整数表达，不得引入 `f64`（仓库 DTO 统一 derive `Eq`，`f64` 不实现 `Eq`）。
