## 1. 背景与目标

打开 App 第一眼看到**"我最近的工作是什么状态"**——工作总量在变多还是变少、节奏在集中还是分散、时间花在哪、长期是否稳定。

核心问题拆成四层：

1. **状态**：我今天到目前为止是什么状态？
2. **趋势**：最近几天是在增加、下降，还是波动？
3. **长期**：这种变化是否已经持续一段时间？
4. **模式**：我的工作通常在什么时候发生？时间花在哪里？

表述一律使用中性方向词（上升/下降/集中/分散/稳定/波动），不加价值判断（"变好/变差"）——活跃时长增加可能是加班，工作块增加可能是碎片化，软件不替用户解读。

## 2. 设计原则

- **状态优先于统计**：页面回答"我处于什么状态"，不是陈列数字；
- **可比优先于绝对值**：进行中的数据只与历史同时刻比（今日 = 截至当前时刻 vs 昨日同期），已完成的数据才能完整比较；进行中的柱/周必须用"进行中"样式与完整数据视觉区分；
- **中性描述**：涨跌用中性色（非红/绿），趋势用"上升/下降"非"变好/变差"；
- **诚实数据**：无数据日期留空并斜纹标注，`hasData=false` 如实呈现；惯性少于最低有效天数不画，有数据天数明确标注；样本不足时宁可不显示比较，也不显示低置信百分比；不做平滑伪造、不做数值预测（仅"按当前日均延展的参考值"这类明确命名的参考标记）；
- **直观**：纯 CSS/SVG 图表，零前端依赖；配色与热力图/今日页同一令牌主题，适配 forced-colors 与键盘焦点；
- **口径在 Rust**：所有统计语义（同时刻截断、Top N 固定槽位、周/月聚合、摘要规则）在 Rust 计算，前端只渲染与格式化，不重算。

## 4. 区块详细设计

### 4.1 ① 状态摘要卡

回答：我今天到目前为止是什么状态？

| 内容 | 说明 |
|---|---|
| 今日截至 HH:MM 活跃时长 + 工作块数 | 主数字，随轮询实时更新（与顶栏同一拍） |
| 较昨日同时刻 ▲▼ +X% | 截至同一时刻的可比数，"昨日"为昨日同时刻；昨日无数据则不显示此项 |
| 较近 7 日均同时刻 ▲▼ +X%（基于 N 个有效日） | 分母为最近 7 个历史有效日（不含今日）各自同时刻的均值；始终标注样本数；`sampleDays < 3` 时不显示百分比，仅显示"历史样本不足" |
| 一行自然语言摘要 | 由 Rust 按确定性规则生成（见 5.3 `SummaryDto`），v0.1 只输出"总量方向 + 主要活跃时段"两部分，例："最近 7 日总量略有上升，主要活跃时段集中在上午"；**不生成波动描述**（波动指标定义稳定前暂缓） |
| ▲▼ 使用中性色（非红非绿） | 活跃时长上升不等于"好"——仅代表方向 |

**上升/下降判决规则**：阈值 ±5%（噪声遮蔽，避免 1-2 分钟变动产生 ▲▼），|delta| ≤ 5% 时 `deltaFraction = null`，前端不渲染箭头。

### 4.2 ② 活跃趋势

回答：最近几天是在增加、下降，还是波动？

- 柱状 7 / 14 / 30 天切换器（三按钮），默认 14 天；
- **今日柱 = 进行中样式**：半透明/斜纹填充，柱顶不做任何数值预测，标签显示"截至 HH:MM"，图例标注"今日进行中"——避免与完整历史日直接视觉比较；
- 无数据日期留空 + 斜纹，`hasData=false` 的点附说明文字"暂停记录""未记录"等；
- **7 日滑动均线 overlay**：在柱状上叠一条折线，平滑日间噪声后回答"趋势方向"。口径必须明确：
  - 窗口 = 7 个自然日，仅对窗口内 `hasData=true` 的**完整历史日**求均值；
  - **今日不进入均线**（今日是未完成日）；
  - 窗口内有效点 < 3 时不绘制该点（折线断开）；
  - 7 天视图下只有第 7 天一个均线点，如实只画一个点；
  - 这是视觉辅助，不是新的统计口径，与 v0.1 边界"不做多周滑动平均对比"不冲突；v0.1 只有 7 日均线，**没有 30 日均线**；
- 切换器重新查询 ② 与 **④**（应用构成随范围联动），查询期间保留旧图，generation 防串。

### 4.3 ③ 长期趋势

回答：这种变化是否已经持续一段时间？

**左侧 —— 近 12 周活跃柱状**：

- 12 周柱状（固定），每柱 = 该周活跃总量；
- **当前周进行中样式**：实心部分 = 已完成完整日总量 + 今日截至当前时刻部分（今日部分弱化样式）；文字标注"进行中"；
- **虚框参考值**：高度 = **已完成完整日的日均 × 7**，命名为"按当前日均延展的参考值"——不是预测，只是参照线；**当前周尚无完整日（如周一下午）时不显示虚框**，仅显示"本周进行中，暂无稳定参考"；
- 上周标注锚点（视觉参照线），帮助对比。

**右侧 —— 本周进度小卡**：

- 本周截至今日总量 + 较上周同期 ▲▼（上周同期 = 上周截至本周今日同一周序日、同一时刻的累计值）；
- 当前周总记录天数。

### 4.4 ④ 工作模式

回答：我的工作通常在什么时候发生？时间花在哪里？

此区块为**双列**：左列工作惯性，右列应用构成。

**左列 — 工作惯性**：

- 近 14 天 `hourly_app_usage` 按 `localHour` 均值（固定 14 天，不随切换器变化）；
- 输出 24 个整点值（`localHour: 0–23`，**保持小时粒度**，不使用分钟级标注）；
- 派生标准：
  - 开工 ≈ 首个活跃占比 ≥ 当日峰值 30% 的小时（**整点标注：如 9:00**）；
  - 高峰 ≈ 占比最大的小时区间（如"10-11 点"）；
  - 收工 ≈ 最后一个活跃占比 ≥ 峰值 30% 的小时；
  - 午休低谷 ≈ 12-14 点区间最小占比的小时；
- **最低有效天数**：
  - < 3 天：不画曲线，提示"有效记录日不足，无法显示工作惯性"；
  - 3–6 天：正常画曲线，标注"初步模式"；
  - ≥ 7 天：正常显示；
  - 同时标注"有效天数 N/14"与缺失日期数；
- v0.1 不做工作日/周末拆分——但 DTO 预留 `weekdaySampleDays` 与 `weekendSampleDays` 供后续版本。

**右列 — 应用构成**：

- 随切换器范围联动（7/14/30 天）；
- 配色规则：**统计范围内整体 Top 3 应用固定槽位**（不在每天独立排名取色）——同一应用在同范围所有日期保持同一槽位；其余应用聚合成"其他"；Rust 只返回 `slot: 0|1|2`，槽位 → 色值由前端 CSS 令牌映射（`--chart-app-1/2/3`、`--chart-other`），从而自动适配浅色/深色/forced-colors 主题；
- 展示形式随范围变化，**聚合桶由 Rust 直接返回，前端只渲染**：
  - **7 天**：逐日横向堆叠条（`bucketKind: "day"`）；
  - **14 天**：逐日横向堆叠条，紧凑（`bucketKind: "day"`）；
  - **30 天**：按周聚合纵向堆叠柱，4-5 根（`bucketKind: "week"`）——周起点为 ISO 周一，跨月周保持单桶不拆分，当前不完整周照常返回一个桶；Top 3 仍按整个 30 天范围固定，不按周重新排名；
- 悬停/焦点显示应用名与此时长；图例分离显示 Top 3 应用 + 颜色。

### 4.5 ⑤ 长期追踪入口

回答：这是否已经形成长期模式？

**里程碑条**（一行，低视觉权重：底部轻量区、无强边框、无勋章式高亮）：
- 累计记录 N 天（自首次记录以来总有效日期数）；
- 自 X 年 X 月起（首次记录月份）；
- 最长连续数据区间 N 天（中性文案，不用"连续记录"的签到化表述）。

**近 6 月月度活跃柱状**：
- 固定 6 根，**主值 = 每有效记录日平均活跃时长**（`avgActiveMsPerRecordedDay`）——避免记录覆盖不足污染"长期趋势"读数；总量与有效记录天数为辅助标注（如"70h / 12 个有效日"）；
- 极简样式，不随 ② 切换器变化，下方常驻；
- 月度柱不补当前进行中月份的全量预估——当前月标"进行中"，只显示已完成日口径的均值与总量。

## 5. 数据契约

全部只读投影查询，**无 Schema 改动**。

### 5.1 数据来源

| 区块 | 表 | 说明 |
|---|---|---|
| ① 状态摘要 | `daily_work_metrics` + 同时刻查询 | 今日/昨日/近 7 个历史有效日截至当前时刻的活跃时长 |
| ② 趋势 | `daily_work_metrics` | 按日聚合；`hasData` 由当日行存在与否判定 |
| ③ 长期 | `daily_work_metrics` | 按周/月 SUM；当前周取同时刻；月度取前 N 个完整月 + 每有效日均值 |
| ④ 惯性 | `hourly_app_usage` | 按 `localHour` 均值（14 天固定、仅统计有数据日期） |
| ④ 构成 | `daily_app_usage` | 周期固定 Top 3；7/14 天返回日桶，30 天在 Rust 内按 ISO 周聚合为周桶 |
| ⑤ 里程碑 | `daily_work_metrics` + `foreground_observations` | `SELECT COUNT(DISTINCT local_date)`, `MAX(/* 连续日 */)` |

### 5.2 同时刻查询规则

今日与对比对象的截止时刻对齐：

- 今日截至 `nowUtcMs`；
- 昨日同时刻 = 昨日 `localDate` 中 ≤ 昨日对应 UTC 时间戳的数据（Same local-time offset）；
- 近 7 日均同时刻 = 自昨日向前寻找**最近 7 个 `hasData=true` 的历史日（明确不含今日）**，各自截断至当日同时刻后求均值；**有效日 < 3 时不生成此项比较**（DTO 为 `None` 或前端按 `sampleDays < 3` 显示"历史样本不足"）。

```text
  direction: "up" | "upSlight" | "flat" | "downSlight" | "down" | null,
  // 近 7 自然日窗口 vs 前 7 自然日窗口的有效日（hasData=true，不含今日）均值比较：
  //   delta > +10% → up；+5% < delta ≤ +10% → upSlight；|delta| ≤ 5% → flat；对称 down；
  //   任一窗口有效日 < 3 → null（前端不生成方向句）
  primaryPeriod: "morning" | "afternoon" | "evening" | "night" | null,
  // 由惯性 hourlyProfile 峰值小时映射：6–12 morning，12–18 afternoon，18–24 evening，0–6 night；
  // 惯性 reliability 为 null 时为 null（前端不生成时段句）
}

TrendPointDto { ... }
  // hasData: false 的日期柱留空+斜纹；isToday: true 的柱用进行中样式，且不进入 7 日均线
WeeklyPointDto { ... }
  // isCurrentWeek: 进行中样式 + 文字标注"进行中"；completedDays = 0 时不显示虚框参考值
```

`Int64String` 规则不变（时长毫秒用字符串）；`AppDto` 复用现有应用身份类型。

### 5.4 命令与查询

- `stats_get_home(days: Option<i32>)`：`days ∈ {7, 14, 30}`，非法或缺失规范化回 14；返回 `StatsHomeDto`。
- 新增 1 个 Tauri 命令，命令总数 15 → 16（实现时同步 CLAUDE.md 与 09 §8.3）。

QueryService 新增 6 个只读方法：`stats_status_dto()`、`stats_trend(days)`、`stats_weekly()`、`stats_composition(days, top_n)`（内含 30 天 ISO 周聚合）、`stats_hourly_profile()`、`stats_monthly()`。同时刻截断在 SQL 参数化（UTC 关键时间点传入，不动态拼接时刻）。所有查询走现有只读连接与时区口径（`reporting_time_zone_id`）。摘要（`SummaryDto`）、槽位分配（`palette`）、惯性标注在 Rust 计算，前端不重算。

## 7. 明确不做（v0.1 边界）

- 自定义目标/阈值与达成度；
- 预测与建议（当前周虚框仅为"按当前日均延展的参考值"，不是预测）；
- 任意日期范围选择器（固定 7/14/30 与 12 周）；
- 工作日/周末拆分——但 DTO 惯性字段预留 `weekdaySampleDays`/`weekendSampleDays`；
- 开工收工漂移趋势图（P2，后续版本的主力长期功能——当前只展示固定 14 天均值的静态标注）；
- 波动度的自然语言描述（"波动较大/较稳定"）——变异系数等指标阈值需先用真实数据观察分布后定义，v0.1 摘要只输出方向与时段；
- 30 日均线（v0.1 仅 7 日均线）；
- 导出、分享、深链接。

## 9. 关键正确性约束（P0 — 实现必须满足）

1. 今日只与历史同时刻比较（截至同一 local-time 时刻），不得与完整历史日天数比较；
2. `last7Avg` 分母为最近 7 个历史有效日（**明确不含今日**）各自同时刻的均值；DTO 必带 `sampleDays`；`sampleDays < 3` 时不生成比较（返回 `None`），前端显示"历史样本不足"；
3. 今日趋势柱必须使用进行中样式（半透明/斜纹 + "截至 HH:MM" 标签 + 图例"今日进行中"），**且不进入 7 日均线**；均线窗口内有效点 < 3 时不绘制该点；
4. 当前周柱状使用进行中样式；虚框参考值 = **已完成完整日均 × 7**（不含今日进行中数据），命名"按当前日均延展的参考值"；当前周无完整日（`completedDays = 0`）时不显示虚框，标注"本周进行中，暂无稳定参考"；不得与完整周直接并列 SUM；
5. 应用构成使用**周期固定 Top 3 槽位**——`palette` 由 Rust 在整个天数范围预算（App 身份 → 槽位一对一映射），**只返回 `slot`，不返回具体颜色字符串**；槽位 → 色值由前端 CSS 令牌映射；30 天周桶在 Rust 内按 ISO 周聚合，Top 3 不按周重新排名；
6. 惯性标注使用整点（小时粒度），不得暗示分钟精度；
7. 惯性有效天数 < 3 时不画曲线（`reliability: null`），3-6 天标"初步模式"（`"preliminary"`）；
8. 所有涨跌提示使用中性色，不引导"好或坏"的价值判断；
9. 月度柱主值为每有效记录日均值，不得只显示受记录天数污染的总量。
