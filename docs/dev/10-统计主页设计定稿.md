审核输入：[review-1](./10-统计主页设计定稿-review-1.md)、[review-2](./10-统计主页设计定稿-review-2.md)。

## 1. 背景与目标

打开 App 第一眼看到**"我最近的工作是什么状态"**——工作总量在变多还是变少、节奏在集中还是分散、时间花在哪、长期是否稳定。

核心问题拆成四层：

1. **状态**：我今天到目前为止是什么状态？
2. **趋势**：最近几天是在增加、下降，还是波动？
3. **长期**：这种变化是否已经持续一段时间？
4. **模式**：我的工作通常在什么时候发生？时间花在哪里？

表述一律使用中性方向词（上升/下降/集中/分散/稳定/波动），不加价值判断（"变好/变差"）——活跃时长增加可能是加班，工作块增加可能是碎片化，软件不替用户解读。

## 2. 设计原则

- **状态优先于统计**：页面回答"我处于什么状态"，不是陈列数字；
- **可比优先于绝对值**：进行中的数据只与历史同时刻比（今日 = 截至当前时刻 vs 昨日同期），已完成的数据才能完整比较；
- **中性描述**：涨跌用中性色（非红/绿），趋势用"上升/下降"非"变好/变差"；
- **诚实数据**：无数据日期留空并斜纹标注，`hasData=false` 如实呈现；惯性少于最低有效天数不画，有数据天数明确标注；不做平滑伪造；
- **直观**：纯 CSS/SVG 图表，零前端依赖；配色与热力图/今日页同一令牌主题，适配 forced-colors 与键盘焦点。

## 4. 区块详细设计

### 4.1 ① 状态摘要卡

回答：我今天到目前为止是什么状态？

| 内容 | 说明 |
|---|---|
| 今日截至 HH:MM 活跃时长 + 工作块数 | 主数字，随轮询实时更新（与顶栏同一拍） |
| 较昨日同时刻 ▲▼ +X% | 截至同一时刻的可比数，"昨日"为昨日同时刻 |
| 较近 7 日均同时刻 ▲▼ +X% | 分母为近 7 个有效日的各自同时刻均值（不含今日）；DTO 带 `sampleDays` 供前端标注 |
| 一行自然语言摘要 | 例："最近 7 日总量略增，日间波动较大，主要活跃时段集中在上午" |
| ▲▼ 使用中性色（非红非绿） | 活跃时长上升不等于"好"——仅代表方向 |

**上升到下降判决规则**：阈值 ±5%（噪声遮蔽，避免 1-2 分钟变动产生 ▲▼）。

### 4.2 ② 活跃趋势

回答：最近几天是在增加、下降，还是波动？

- 柱状 7 / 14 / 30 天切换器（三按钮），默认 14 天；
- 今日柱高亮；
- 无数据日期留空 + 斜纹，`hasData=false` 的点附说明文字"暂停记录""未记录"等；
- **7 日滑动均线 overlay**：在柱状上叠一条折线，平滑日间噪声后回答"趋势方向"——成本极低（数据已在 DTO 内，前端算均值），与 v0.1 边界中"不做多周滑动平均对比"不冲突（这是视觉辅助，不是新的统计口径）；
- 切换器重新查询 ② 与 **④**（应用构成随范围联动），查询期间保留旧图，generation 防串。

### 4.3 ③ 长期趋势

回答：这种变化是否已经持续一段时间？

**左侧 —— 近 12 周活跃柱状**：

- 12 周柱状（固定），每柱 = 该周活跃总量；
- **当前周可比口径**：当前周柱状按"截至今日日均 × 7"虚框显示预估总高度，实心填充 = 已完成日的总量；同时显示已完成部分的日均值；
- 上周标注锚点（视觉参照线），帮助对比。

**右侧 —— 本周进度小卡**：

- 本周截至今日总量 + 较上周同期 ▲▼；
- 当前周总记录天数。

### 4.4 ④ 工作模式

回答：我的工作通常在什么时候发生？时间花在哪里？

此区块为**双列**：左列工作惯性，右列应用构成。

**左列 — 工作惯性**：

- 近 14 天 `hourly_app_usage` 按 `localHour` 均值（固定 14 天，不随切换器变化）；
- 输出 24 个整点值（`localHour: 0–23`，**保持小时粒度**，不使用分钟级标注）；
- 派生标准：
  - 开工 ≈ 首个活跃占比 ≥ 当日峰值 30% 的小时（**整点标注：如 9:00**）；
  - 高峰 ≈ 占比最大的小时区间（如"10-11 点"）；
  - 收工 ≈ 最后一个活跃占比 ≥ 峰值 30% 的小时；
  - 午休低谷 ≈ 12-14 点区间最小占比的小时；
- **最低有效天数**：
  - < 3 天：不画曲线，提示"有效记录日不足，无法显示工作惯性"；
  - 3–6 天：正常画曲线，标注"初步模式"；
  - ≥ 7 天：正常显示；
  - 同时标注"有效天数 N/14"与缺失日期数；
- v0.1 不做工作日/周末拆分——但 DTO 预留 `weekdaySampleDays` 与 `weekendSampleDays` 供后续版本。

**右列 — 应用构成**：

- 随切换器范围联动（7/14/30 天）；
- 配色规则：**统计范围内整体 Top 3 应用固定取色**（不在每天独立排名取色）——同一应用在同范围所有日期保持同一颜色；其余应用聚合成"其他"（灰色）；
- 展示形式随范围变化：
  - **7 天**：逐日横向堆叠条；
  - **14 天**：逐日横向堆叠条（紧凑）；
  - **30 天**：**按周聚合纵向堆叠柱**（4-5 根），每周一根，避免 30 根日的条拉太长页；
- 悬停/焦点显示应用名与此时长；图例分离显示 Top 3 应用 + 颜色。

### 4.5 ⑤ 长期追踪入口

回答：这是否已经形成长期模式？

**里程碑条**（一行）：
- 累计记录 N 天（自首次记录以来总有效日期数）；
- 自 X 年 X 月起（首次记录月份）；
- 最长连续记录 N 天。

**近 6 月月度活跃柱状**：
- 固定 6 根，每根 = 当月活跃总量 + 有效记录天数（副轴点数）；
- 极简样式，不随 ② 切换器变化，下方常驻。
- 月度柱不补当前进行中月份的全量预估——当前月标"进行中"，只显示已完成日总和。

## 5. 数据契约

全部只读投影查询，**无 Schema 改动**。

### 5.1 数据来源

| 区块 | 表 | 说明 |
|---|---|---|
| ① 状态摘要 | `daily_work_metrics` + 同时刻查询 | 今日/昨日/近 7 日截至当前时刻的活跃时长 |
| ② 趋势 | `daily_work_metrics` | 按日聚合；`hasData` 由当日行存在与否判定 |
| ③ 长期 | `daily_work_metrics` | 按周/月 SUM；当前周取同时刻；月度取前 N 个完整月 |
| ④ 惯性 | `hourly_app_usage` | 按 `localHour` 均值（14 天固定、仅统计有数据日期） |
| ④ 构成 | `daily_app_usage` | 按日按占比取 Top N（周期固定 Top 3，非每日独立） |
| ⑤ 里程碑 | `daily_work_metrics` + `foreground_observations` | `SELECT COUNT(DISTINCT local_date)`, `MAX(/* 连续日 */)` |

### 5.2 同时刻查询规则

今日与对比对象的截止时刻对齐：

- 今日截至 `nowUtcMs`；
- 昨日同时刻 = 昨日 `localDate` 中 ≤ 昨日对应 UTC 时间戳的数据（Same local-time offset）；
- 近 7 日均同时刻 = 每个历史有效日截断至该日对应时刻后的均值（分母含今日自身时额外加注，实现时的精确合同由 `StatsHomeDto.sampleDays` 说明分母口径）。

### 5.3 DTO（wuji-core，specta 生成，双副本 drift 门禁）

```text
StatsHomeDto {
  localDate,
  reportingTimeZoneId,
  status: StatusDto {
    todayActiveMs, workBlockCount,
    cutoffLocalTime,             // 截止时刻（本地时间 HH:MM）
    yesterdaySame: Option<SameTimeComparisonDto>,
    last7AvgSame: Option<SameTimeComparisonDto>,  // sampleDays 含分母
  },
  trend: [ TrendPointDto { localDate, activeDurationMs, workBlockCount, hasData } ],
  // 7 日与 30 日均线在前端从 trend 计算，不在 DTO 内
  weekly: [ WeeklyPointDto {
    weekStartDate,
    activeDurationMs,            // 当前周 = 截至同时刻总量，历史周 = 完整周
    isCurrentWeek,
    currentWeekDailyAvgMs,       // 当前周日均（供前端预估高度），历史周为 null
  } ],
  dailyTop: [ DailyTopDto {
    localDate,
    apps: [ TopEntryDto { app: AppDto, activeDurationMs } ],
    othersActiveMs,
  } ],
  palette: [ AppColorEntryDto { app: AppDto, color: String } ],
  // 周期内整体 Top 3 应用 → 颜色映射（天数范围内预计算，前端不重算）
  hourlyProfile: [ HourlyPointDto { localHour, avgActiveMs, fraction } ],
  inertia: InertiaDto {
    startHour, peakHour, endHour, lunchLowestHour,
    effectiveDays,               // 有效记录日数
    totalDays,                   // 总日数（14）
    reliability: "preliminary" | "normal" | null,  // preliminary = 3-6天, null = <3天不画
  },
  milestone: MilestoneDto {
    totalRecordedDays, longestConsecutiveDays,
    firstRecordedMonth,          // YYYY-MM
  },
  monthly: [ MonthlyPointDto { month, activeDurationMs, recordedDays } ],
}

SameTimeComparisonDto {
  activeDurationMs,              // 对比对象的有效活跃时长
  deltaFraction,                 // 相对变化（null 表示无基线/不足 ±5% 噪声遮蔽用 null）
}

TrendPointDto { ... }
  // hasData: false 的日期柱留空+斜纹
WeeklyPointDto { ... }
  // isCurrentWeek: 柱状用虚框预估高度 + 文字标注"进行中"
```

`Int64String` 规则不变（时长毫秒用字符串）；`AppDto` 复用现有应用身份类型。

### 5.4 命令与查询

- `stats_get_home(days: Option<i32>)`：`days ∈ {7, 14, 30}`，非法或缺失规范化回 14；返回 `StatsHomeDto`。
- 新增 1 个 Tauri 命令，命令总数 15 → 16（实现时同步 CLAUDE.md 与 09 §8.3）。

QueryService 新增 6 个只读方法：`stats_status_dto()`、`stats_trend(days)`、`stats_weekly()`、`stats_daily_top(days, top_n)`、`stats_hourly_profile()`、`stats_monthly()`。同时刻截断在 SQL 参数化（UTC 关键时间点传入，不动态拼接时刻）。所有查询走现有只读连接与时区口径（`reporting_time_zone_id`）。

## 6. 交互与视觉

- 切换器：7 / 14 / 30 三个按钮，紧贴 ② 趋势图标题区域，提示作用范围（"切换将同时更新趋势图与应用构成"）；切换 re-query；查询期间保留旧图不闪空，generation 防串；
- 空状态：完全无数据（首次使用）→ 整页引导文案"还没有记录数据，启动吾迹并保持打开即可开始"；
- 图表可访问性：柱/条/曲线 aria-label 携带数值；forced-colors 保留（HC 系统色）；键盘 focus 可达；
- 主题：令牌色；图表配色由 Rust 预算的 `palette` 字段固定（应用身份 → 色值的一对一映射），前端不重算。

## 7. 明确不做（v0.1 边界）

- 自定义目标/阈值与达成度；
- 预测与建议；
- 任意日期范围选择器（固定 7/14/30 与 12 周）；
- 工作日/周末拆分——但 DTO 惯性字段预留 `weekdaySampleDays`/`weekendSampleDays`；
- 开工收工漂移趋势图（P2，后续版本的主力长期功能——当前只展示固定 14 天均值的静态标注）；
- 导出、分享、深链接。

## 9. 关键正确性约束（P0 — 实现必须满足）

1. 今日只与历史同时刻比较（截至同一 local-time 时刻），不得与完整历史日天数比较；
2. 当前周柱状使用虚框预估（日均 × 7），文字标注"进行中"，不得与完整周直接并列 SUM；
3. `last7Avg` 分母为近 7 个有效日的各自同时刻均值（不含今日），DTO 必带 `sampleDays`；
4. 应用构成使用**周期固定 Top 3 取色**——`palette` 由 Rust 在整个天数范围预算（App 身份 → 色值一对一映射），不按每天独立排名着色；
5. 惯性标注使用整点（小时粒度），不得暗示分钟精度；
6. 惯性有效天数 < 3 时不画曲线（`reliability: null`），3-6 天标"初步模式"（`"preliminary"`）；
7. 所有涨跌提示使用中性色，不引导"好或坏"的价值判断。
