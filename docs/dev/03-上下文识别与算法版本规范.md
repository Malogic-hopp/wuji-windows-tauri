## 1. 目的

本文冻结第一版规则引擎的输入、输出、去抖、上下文等价、事件判定、版本和重建触发条件。候选阈值仍需黄金样本评审，算法状态因此保持 Draft。

## 2. 处理阶段

```text
Raw Observation
  → privacy decision
  → App normalization
  → safe feature extraction
  → Activity segmentation
  → Context classification
  → Context stabilization
  → transition decision
  → hourly/daily projection
```

每一步只能读取前一步的安全输出。任何阶段不得回读原始标题日志或从 UI 提交的任意规则脚本。

## 3. 安全特征

第一版安全特征采用固定 allowlist，例如：

```text
known_app_key
known_project_token_id
repository_fingerprint
document_type
domain_category
title_available
privacy_boundary
```

每组特征绑定 `feature_schema_version` 和 `rebuild_capability`。完整标题、完整路径、任意 n-gram 或可逆 hash 不属于安全特征。

Fingerprint 盐：

- 每个 runtime channel 首次创建随机盐；
- 由 Windows DPAPI CurrentUser 保护；
- 数据保存 `fingerprint_key_version`，不保存盐；
- 正常轮换先持久化新 Identity Generation，旧/新映射只能由仍在内存中的可信身份或用户确认建立；
- 盐丢失后不猜测旧 fingerprint，不建立跨设备等价。

Identity Generation 变化是 Activity/Context/Work 的强制连续性边界，不把轮换前后的 App Identity 直接比较为 Raw App Switch。可信 Identity Link 只进入新的 Identity Resolution Generation 与 App 读模型重投影，不追溯改变已发布 Segment、Work、Context 或 Switch。

## 4. Activity 去抖与尾部重写

候选 Activity Key 变化在同时满足以下条件后提交：

```text
candidate_elapsed >= activity_change_confirm_duration
candidate_sample_count >= activity_change_min_samples
```

提交边界回溯到候选的第一条 Observation。若候选消失，则该候选被视为噪声，原 Segment 延续。实现必须重建最近的有界 tail，范围至少覆盖 `confirm_duration + observation_gap_cap`。

Activity State 变化不使用窗口 key 去抖：Idle 的开始时间由 `capturedAtUtc - reportedIdleDuration` 估算，并裁剪到当前 Time Epoch 和上一有效输入之后。Idle 达 Work Block 阈值时，Work Block 回溯结束于该 Idle 开始时刻。

Rebuild v0.1 不做 last-input 反推：Idle 起点取首条达阈值 Observation 时刻，active 侧保留至多一个阈值的宽限期。见 09 §6.5 与 §15 偏离登记。

## 5. Context 分类顺序

按优先级执行：

1. 用户显式规则和 Context alias；
2. 已知项目/仓库安全 token；
3. 已知应用语义规则；
4. 有界时间窗口内从前后稳定 Context 继承；
5. 粗粒度 topic/activity；
6. `unknown`。

分类输出必须包括 `context_id?`、confidence、reason code、规则命中引用和是否继承。继承不能跨 Work Block、质量 gap、隐私边界或超过继承窗口；继承必须降低 confidence。

## 6. Context 等价

在某一 Analysis Generation 中，`X ≡ Y` 仅当：

- 二者具有相同 `context_id`；或
- 生效期内的 Context Alias 将二者解析到同一 canonical `context_id`。

相同显示名、相同父级、同属“开发”、topic 与 project 相关，都不足以等价。rename 不改变身份；merge 在新 generation 生效；split 创建新身份并只通过重建改变旧分类。

## 7. Context 稳定与事件判定

令 A 为最后一个 committed Context，B 为候选，C 为 B 之后的候选。

### 7.1 `A → B`

- B 未达 `context_commit_duration`：Decision 为 `Pending/BelowCommitDuration`；
- B 达阈值：从 B 开始时刻生成一次 `A → B` Effective Context Switch；
- B 置信度不达门禁：`Unknown/LowConfidence`，不生成事件。

### 7.2 `A → B → A'`

- `A' ≡ A` 且 B 未达 commit：一次 Interruption；
- `A' ≡ A` 且 B 已达 commit：`A → B` 与 `B → A` 两次 Switch，不是 Interruption；
- `A' ≢ A`：按 `A → B → C` 处理。

### 7.3 `A → B → C`

- B 已达 commit：确认 `A → B`，再以 B 为 committed Context 判断 C；
- B 未达 commit 且 `C ≡ A`：按 Interruption；
- B 未达 commit 且 `C ≢ A`：B 为 `Noise/TransientContext`；C 达 commit 后直接确认 `A → C`；
- C 也未达 commit：保持 bounded Pending，直到后续证据或 finalization；finalization 时标为 `Noise/EndOfRangeBeforeCommit`。

### 7.4 强制边界

长 Idle、质量 gap、隐私排除、Pause、Stop、Sleep、Time Epoch/Identity Generation 变化或 Clear 会终止候选链。跨边界不生成 Interruption、Context Switch 或 Raw App Switch，Decision 使用相应 `Boundary*` reason code。

## 8. 决策原因码

首版稳定集合：

```text
CommittedByDuration
ReturnedToEquivalentContext
BelowCommitDuration
TransientContext
LowConfidence
InsufficientSafeFeatures
TitleUnavailable
EndOfRangeBeforeCommit
BoundaryIdle
BoundaryQualityGap
BoundaryPrivacy
BoundaryPauseStop
BoundaryTimeEpoch
SupersededByRebuild
```

错误合同可以增加安全错误码，但不得改变上述业务原因含义。自然语言由 UI 本地化，不持久化为业务真相。

## 9. Work Block 算法

Work Block 状态机只消费 Activity Segment 和质量边界：

```text
Closed + Active            → Open(at active.start)
Open + Active              → extend active duration
Open + short Idle          → retain block, add short idle
Open + Idle reaches limit  → close retroactively at idle.start
Open + hard boundary       → close at boundary.start
Closed + Idle/Unknown      → remain Closed
```

Context 分类、alias、任务切换和 Interruption 不参与边界计算。Work Block 属于独立 Work Generation；它只绑定 Segmentation Generation 和 Work Profile，不属于 Analysis Generation。

## 10. Out-of-order、丢弃和崩溃

- Capture Sequence 在捕获尝试时分配；
- Writer 只接受比当前 Runtime Instance 的 committed capture sequence 大且时间不早于当前 Time Epoch 水位的 Observation；
- 迟到/重复记录拒绝进入事实表并写质量事件；
- sequence gap 关闭连续性，不能用采样周期填补；
- 接受的事实由 Writer 分配数据库全局 Fact Cursor；所有跨重启水位都使用 Fact Cursor；
- 崩溃恢复只重建最后已提交 Observation 之前可确认的 tail；最后 Observation 到进程恢复之间均为未知 gap。

## 11. 版本归属

| 改动 | 提升版本 | 最小重建范围 |
|---|---|---|
| App/key 组成、去抖、gap cap | Segmentation | Activity、Work、App 及全部下游 |
| 安全特征集合 | Feature Schema | 仅有兼容事实的 Segmentation/Analysis；否则降级 capability |
| Context 规则/alias | Rule | Analysis 与 Context/事件/质量 |
| 分类顺序或 confidence | Classifier | Analysis 与下游 |
| Context commit 阈值 | Analysis Algorithm | Transition/事件及相关日指标 |
| Work Idle/边界规则 | Work Algorithm/Profile | Work Block 与 daily work metrics，不重建 Context |
| Identity Link/canonical App 归并 | Identity Resolution Generation | App Hourly/Daily/Top Apps 投影；事实、Segment、Work、Context、Switch 不变 |
| reporting zone/tzdb mapping | Calendar | Hourly/Daily 投影 |

算法版本集中保存在 Segmentation/Work/Analysis Generation；跨世代 App 查询映射保存在 Identity Resolution Generation。查询可见行属于不可变 Result Set；Query Snapshot 通过复合 Fact Boundary 不重叠 Slice 解析每段历史的完整版本链，避免逐行版本漂移和旧历史复制。

## 12. 增量与历史结果一致性

在线算法与历史重建必须调用同一纯领域函数。当前 staging 尾部可以 provisional，但越过 `max(activity confirm duration, context commit duration, gap cap, work idle threshold)` 后，同一输入和版本必须得到相同结果。第一版没有独立 interruption return window。

尾部修正使用 bounded delete/rebuild 或等价的可逆贡献机制。第一版在 staging 中选择 bounded delete/rebuild；发布时 Seal 一个不可变 Result Set。已被 Query Snapshot 引用的 Result Set 不得原地删除或更新。

## 13. 黄金样本门禁

至少包含：

- 单个窗口噪声与采样间隔变化；
- 同项目跨 VS Code/Edge/Codex/Obsidian；
- `A→B→A` 的阈值前后两侧；
- `A→B→C` 的 B committed/uncommitted；
- 低 confidence、无标题和 privacy boundary；
- Idle 起点回溯、跨午夜、DST、休眠和 UTC 倒退；
- queue drop、out-of-order 和崩溃尾部；
- alias rename/merge/split；
- online 与 batch 对同一输入逐行一致。

黄金样本保存脱敏输入、期望 Segment/Decision/Event、所有版本和质量结果。任何语义变更必须更新版本并由产品评审接受期望差异。

## 14. 首版延期

Focus Block 和 `fragmented_seconds` 没有 Accepted 规则，不在本文预定义占位算法。机器学习分类加入时必须保留相同输入安全边界、版本链、置信度和可解释原因合同。
