## 1. 范围

本文冻结 Desktop↔Agent Named Pipe、React↔Tauri command、Settings reload、实时状态、版本兼容、副作用幂等和升级/卸载合同。

## 2. 信任边界

- React 是不受信任表现层，只能调用白名单语义 command；
- Tauri Host 校验 DTO、权限和范围；破坏性动作必须经过 Rust/Win32 原生确认，不能由 React 获取或消费确认能力；
- Agent 只接受通过进程身份、签名清单和会话能力认证的 Tauri Host；同用户、同 Session 只是必要条件，不是充分授权；
- SQLite 只读查询不替代控制协议；
- 任意路径、SQL、shell、pipe name、channel 或 executable 参数不得从 React 透传。

## 3. Named Pipe 安全与客户端认证

Pipe 名由受信任 channel 和用户身份派生，不暴露给 React。创建时必须：

- 使用当前 logon SID 的显式 DACL 和拒绝低完整性写入的 mandatory label，并拒绝 Everyone/Anonymous/Network；
- 验证客户端进程 token 的 user SID 与 server 相同；
- 验证客户端 Session ID 与 Agent 当前交互 Session 相同；
- 通过 `GetNamedPipeClientProcessId` 等内核来源取得 client PID，不接受 envelope 里自报的 PID；保持 process/file handle 直到认证结束，校验 token、canonical image path、file identity、版本 manifest 和 binary hash；
- production 只允许固定受信任安装根下、Authenticode 链/发布者/产品标识与随 Agent 签名的兼容清单匹配的 Desktop binary；仅文件名、路径或同用户签名均不足；
- dev unsigned binary 只允许 dev channel，并必须匹配构建时固定 hash/受控开发路径；该例外不得进入 prod artifact；
- 业务 Desktop 必须以预期的非提升完整性运行；低完整性 WebView 子进程和任意未列入清单的同用户进程一律拒绝，提升的 updater 使用独立协议，不复用业务 Pipe；
- 禁用远程 pipe client，限制实例数、连接率、消息大小和并发 request 数。

进程验证成功后，Agent 才在该连接的 bootstrap 阶段生成至少 256-bit CSPRNG session capability；它只保存在 Tauri Rust Host 与 Agent 内存中，不进入 React DTO、命令参数、日志、文件、环境变量或命令行。业务帧绑定连接、desktop instance、单调消息序号和 capability proof；重连必须重新执行进程验证并获得新 capability，旧 capability 立即失效。知道/枚举 Pipe 名不能完成握手。

提升权限的 Desktop 不自动获得绕过身份/Session/签名验证的能力。管理员、能够向已认证进程注入代码或能够调试读取其内存的攻击者超出本地进程认证可防御的边界；产品不得因此把普通同用户进程视为可信。安装/升级使用独立受控 updater，不复用业务 Pipe。

## 4. 帧与消息

协议使用长度前缀 UTF-8 JSON：

```text
u32 little-endian payload length
JSON payload (<= negotiated max; hard ceiling applies before allocation)
```

通用 envelope：

```text
protocolVersion
messageType
requestId            // ULID
sentAtUtc
authSessionId?       // Ready 后必填，不是 capability 本身
messageSequence?     // Ready 后按连接单调增加
capabilityProof?     // Ready 后对 envelope + payload 的 proof
payload
```

Ready 后三个认证字段必须全部存在；`capabilityProof = HMAC-SHA-256(sessionCapability, proofInput)`，`proofInput` 按协议版本固定为长度前缀标量字段与 RFC 8785/JCS 规范化 payload 的拼接，比较使用 constant-time。proof 覆盖 protocol、message type、request ID、时间、session ID、sequence 和 payload；重复/倒退 sequence 或 proof 不匹配立即关闭连接。禁止未知超大字段、重复 JSON key、NaN/Infinity 和任意多态类型标签。解析失败返回安全错误后关闭连接。

## 5. 连接状态机

```text
Connected
  → BootstrapHello{protocol range, desktop version, channel, capabilities}
  ← kernel PID/token/image/signature verification
  ← ServerHello{selected protocol, agent version, instance, limits, challenge}
  → ClientReady{challenge proof/session binding}
  ← issue in-memory session capability to verified Rust Host connection
  ← ServerReady{state, supported commands, compatibility}
  → Ready requests/responses
  → Closing
```

握手完成前只接受 BootstrapHello/Ready/Close。channel、用户、Session、完整性、binary identity、签名清单或 challenge 任一不匹配立即拒绝并限速；不得向未认证连接泄露业务能力、状态或数据库信息。协议范围无交集返回 `ProtocolIncompatible`，不得尝试猜测旧 JSON 结构。

每个 request 恰好一个接受响应：查询返回最终结果；副作用先返回 `Accepted/AlreadyCompleted/Rejected`，最终状态通过 `GetCommandStatus` 查询。

## 6. 兼容矩阵

使用协议范围和 Schema reader range，不用“版本看起来接近”的猜测：

| 场景 | 行为 |
|---|---|
| 新 Desktop + 旧 Agent，协议有交集 | 只启用 ServerReady 声明的命令；新功能禁用 |
| 新 Desktop + 旧 Agent，无交集 | 历史只读若 Schema 支持则可用；控制禁用并提示升级 Agent |
| 旧 Desktop + 新 Agent，协议有交集 | Agent 选择旧协议，绝不返回旧协议未知必填字段语义 |
| 旧 Desktop + 新 Agent，无交集 | Agent 拒绝控制；不得降级数据库 |
| 旧 Desktop 读取新 Schema | 仅当 `reader_schema_min/max` 覆盖且 Query API 兼容；否则不打开 DB |
| 旧 Agent 打开新 Schema | 写入前拒绝；不得自动降级/清空 |
| 新 Agent 打开旧兼容 Schema | 由 Agent 执行受支持向前 migration 后 Ready |
| major/import Schema | 进入受控离线 migrator 流程 |

Desktop 必须分别呈现“历史可读”“Agent 可控”“需要升级”，不能把它们合并成一个模糊 Offline 状态。

## 7. 进程控制与采集控制

Desktop Process Controller 的本地动作与 Agent IPC 命令必须分开：

```text
EnsureAgentProcess / StartAgentProcess   // Tauri Host 本地创建进程，不走 Pipe
CaptureStart                            // Ready/Paused → Running，经 Pipe + receipt
CapturePause / CaptureResume
CaptureStop                             // 停止采集但 Agent 进程和 Pipe 保持
ShutdownAgent                           // 安全持久化终态后退出进程
```

`StartAgentProcess` 验证固定受信任 binary、channel 和单实例，创建进程后等待 Hello/Ready；它没有 Agent receipt，因为进程尚不存在，其结果由进程 handle、握手和启动超时共同确认。普通用户“开始记录”由 Tauri 编排 `EnsureAgentProcess → Hello/Ready → CaptureStart`，但协议层仍是两个动作。

`CaptureStop` 不退出进程，因此可以继续通过 Pipe 查询 receipt。`ShutdownAgent`、`PrepareUpgrade` 会退出进程：Agent 必须先将终态 receipt 和最后状态提交 SQLite，返回 `WillExit` 后才关闭 Pipe。Pipe 已消失时，Desktop 使用固定只读 `command_receipt_get(request_id)` 查询最终状态，并结合进程 handle 退出结果；不得要求向不存在的 Agent 调 `GetCommandStatus`。

## 8. 命令分类

### 8.1 查询命令

`GetStatus`、`GetCapabilities`、`GetCommandStatus` 无副作用，可重试。状态响应包含 runtime instance、actual state、last capture/commit、queue summary、active settings revision、active Query Snapshot、compatibility 和 safe error。

### 8.2 副作用命令

`CaptureStart`、`CapturePause`、`CaptureResume`、`CaptureStop`、`ShutdownAgent`、`ReloadSettings`、`Prune`、`Clear`、`BeginMaintenance`、`PrepareUpgrade` 使用持久化 Command Receipt。Process Controller 的 `StartAgentProcess` 不属于本表。`Clear` 和隐私削弱只能由 Tauri Host 在可信原生确认完成后直接发送，Agent 还必须要求 envelope 携带由已认证 session capability 派生、绑定动作摘要/request ID/短期有效期的 trusted-action proof；React 无法申请或构造该 proof。

处理规则：

- 新 request ID：事务写 `Accepted` receipt 后才执行；
- 相同 ID + 相同 command/payload digest：返回已有状态/结果；
- 相同 ID + 不同 digest：`RequestIdConflict`；
- timeout/disconnect 不取消已接受操作；
- receipt 在 Agent 重启后仍有效，保留期覆盖 UI/installer 的最大重试窗口；
- Clear/Upgrade receipt 不得在操作仍可能重试时被自身清理。

### 8.3 超时后的最终状态

Desktop timeout 后必须用原 request ID 查询：Pipe 可用时调用 `GetCommandStatus`；Pipe 不可用时调用 Tauri Storage 的 `command_receipt_get`：

```text
Unknown | Accepted | Running | Succeeded | Failed | NeedsAttention
```

`Unknown` 只表示 receipt 不存在/已过保留期，不等于命令失败。CaptureStop/Pause/Shutdown/Clear/Prune/Upgrade 的 UI 不得仅凭本地 timeout 宣称成功或失败。

## 9. Settings 合同

Desktop 是 Settings JSON 的唯一写入者：

1. 从当前完整文档应用用户修改；
2. 验证全部字段与跨字段约束；
3. 写同目录临时文件、flush，并原子替换；
4. revision 单调增加并包含 content digest；
5. 调用 `ReloadSettings(revision)`；
6. 只有 Agent 返回 Active revision 后，UI 才显示“已应用到采集器”。

扩大采集范围、关闭既有排除或降低标题/路径隐私级别属于隐私削弱。Tauri 必须先走 12.1 的原生确认，再在同一 Rust 控制流中写 Settings 并发送 Reload；React 提交的 patch 不能携带 `confirmed`、token 或 trusted-action proof。收紧隐私可以直接应用，但仍需完整 DTO/Settings 校验。

Agent reload 失败时旧 revision 全量继续生效。响应：

```text
requestedRevision
activeRevision
state = Applied | Rejected | PendingRebuild
fieldErrors[]
safeError
affectedProfiles[]
affectedGenerations[]
effectivityState = PendingFirstFact | Effective | NotApplicable
```

禁止部分字段成功。Agent 离线时 Desktop 可以保存设置，但 UI 必须显示“已保存，待 Agent 应用”。Agent 每次启动都必须对账文件最新 revision/digest 与数据库，而不能依赖 Desktop 一定成功发送 Reload；完整流程见[运行时启动对账](./05-Rust-Agent运行时设计.md#13-启动与崩溃恢复)。

## 10. 实时状态与 Stale

状态来源优先级：

1. 当前连接的成功 IPC `GetStatus`；
2. 最近一次成功 IPC 状态（标记 age）；
3. SQLite `agent_runtime` 的 last-known 快照；
4. Unknown。

候选 Stale 阈值为 `max(3 × heartbeat_interval, 15s)`，须在产品评审后接受。超过阈值：

- 有 IPC 失败：显示“无法连接 Agent，最后响应于 …”；
- 只有 SQLite heartbeat：显示“最后记录状态 …”，不得显示实时 Running；
- Desktop 本地发过 CaptureStop/Shutdown 但 receipt 未确认：显示“正在确认最终结果”。

Runtime Instance 变化会使旧内存状态立即 stale。

## 11. 错误合同

跨边界错误固定结构：

```text
code
kind = Validation | Compatibility | Authorization | Conflict |
       Unavailable | Storage | Internal
retryable
safeMessageKey
requestId
fieldErrors[]?
details?              // allowlisted safe values only
```

禁止传递 raw exception、SQL、路径、SID、PID、pipe name、标题和 stack trace。日志可用同一 request ID 关联，但仍需隐私清洗。

稳定错误码至少包括：`ProtocolIncompatible`、`SchemaIncompatible`、`UnauthorizedClient`、`ClientBinaryUntrusted`、`SessionCapabilityInvalid`、`TrustedConfirmationRequired`、`InvalidPayload`、`InvalidState`、`RequestIdConflict`、`CommandInProgress`、`AgentUnavailable`、`StorageDegraded`、`SnapshotProtectionUnavailable`、`MaintenanceRequired`、`SettingsRejected`、`HistoryNotRebuildable`。

## 12. Tauri command 合同

React 只可调用：

```text
agent_process_ensure_running / agent_process_shutdown
capture_start / capture_pause / capture_resume / capture_stop
agent_get_status / command_receipt_get
activity_get_today / activity_get_timeline / activity_get_trends
activity_get_apps / activity_get_contexts / activity_get_quality
settings_get / settings_update
privacy_prune / privacy_clear_history_request / privacy_export_request
maintenance_get_status
```

Writer Healthy 时，每个查询由 Tauri 经 IPC 获取 Query Snapshot Lease，并在一个 SQLite read transaction 中执行该 command 的全部 SQL；Desktop 只读连接不得写 lease。Agent 离线时没有 Writer/GC，可直接读取 Active Snapshot。IPC 在线但 Writer Degraded/Faulted 时，只有 Agent 状态明确返回 `snapshotProtection=GcSuspended` 才允许无 Lease 只读；Writer 恢复后返回 `RecoveryGrace{resumeNotBefore}`，Desktop 必须在宽限期内重新获取 Lease。若既无 Lease、又无离线/GC suspension 保证，则返回 `SnapshotProtectionUnavailable`，不得冒险分页。

分页携带同一 Snapshot ID；保护期结束且旧 Snapshot 已回收时返回 `SnapshotExpired` 并刷新。DTO 返回 Snapshot Slice、完整 Fact Boundary、具体组件 Result Set、Identity Resolution、Calendar、质量、rebuild/explanation capability、nullable `publishedThrough*` 和 empty reason。禁止 `execute_sql`、`read_file`、`invoke_agent_method` 或任意 path command。

### 12.1 可信原生确认

Clear、导出、卸载删除数据和隐私削弱必须由 Tauri Rust Host 打开独立于 WebView DOM 的 Win32 原生模态确认（或后续经安全评审的系统凭据确认），展示固定动作类型、影响范围和不可逆性。仅原生窗口收到真实用户确认后，Rust Host 才创建内存中的 `TrustedActionCapability` 并在**同一控制流**直接执行动作；能力不返回 React，React 也没有 `confirmation_create/consume` command。

若内部实现使用 nonce/token，它必须绑定 Desktop instance、认证 IPC session、request ID、规范化动作摘要和短过期时间，单次消费；取消、超时、窗口失焦/宿主退出即销毁。React 只可发起“请求显示原生确认”，并接收 Cancelled/最终安全结果，不能提交 `confirmed=true`、token、路径或二阶段 consume 调用。重复唤起必须限速，原生确认不得由 WebView 自动化事件完成。

导出目标通过 Tauri 打开的系统文件选择器返回到 Rust 内存，路径不暴露给 React；Clear/隐私命令的 trusted-action proof 由已认证 IPC session capability 派生。原生确认失败或无法创建时操作拒绝，不降级为 HTML 弹窗。

## 13. Desktop 数据库 reader 生命周期

- 普通查询使用短生命周期只读 pool；
- 一个语义 command 的 Snapshot 解析与数据 SQL 必须使用同一 connection/read transaction；
- Agent 通知 `DatabaseWillChange` 后，Desktop 停止新查询、等待现有查询有界完成、关闭 pool 并回复 `ReadersClosed`；
- pointer 切换后必须收到 `DatabaseReady{databaseGeneration, schemaVersion}` 才重新打开；
- 旧查询可以完成或返回 `MaintenanceRequired`，不能跨文件拼接结果；
- Desktop 崩溃/无响应时 migrator 不强制替换被占用文件，操作进入 NeedsAttention。

## 14. 升级与卸载

### 14.1 升级顺序

```text
compatibility preflight
→ Agent PrepareUpgrade receipt
→ pause capture + close Work Block + drain writer
→ seal terminal state + persist ReadyForUpgrade receipt
→ return WillExit and verify receipt through read-only query if needed
→ Desktop closes readers
→ Agent exits and releases binary/DB handles
→ updater atomically installs versioned binaries
→ run required offline migrator
→ start new Agent and complete Hello/Ready
→ reopen Desktop readers
→ keep rollback binaries/database pointer until health gate passes
```

Windows 上不得覆盖正在运行的 Agent binary。若新版本不健康且 Schema 未发生不可逆 major upgrade，可以回滚 binary/pointer；否则进入 NeedsAttention，不自动用旧 Agent 打开新 Schema。

### 14.2 卸载顺序

显式确认 → ShutdownAgent receipt 终态成功（Pipe 消失时读 SQLite receipt）→ 验证进程 handle 已退出 → 注销自启动 → 关闭 Desktop/reader → 删除 binary。用户数据默认保留，只有用户单独确认“同时删除数据”才执行 Clear/删除数据目录。无法确认 Agent 已停止时不得静默删除正在使用的文件。

## 15. 协议测试门禁

- Hello/Ready 的每个非法顺序、版本无交集和 payload 上限；
- 同 SID/异 SID、同/异 Session、低/中/高完整性、WebView 子进程、伪造 client PID/token、同名复制、路径替换、签名/发布者/hash/manifest 不匹配；
- 已认证 Tauri Host 的 capability 建立、逐帧 proof/序号、重连失效和 React DTO/日志/环境不泄漏；
- request receipt 重启、重复、冲突、timeout 后查询；
- Agent 不存在时 Process Start、CaptureStart 编排，以及 Shutdown/Upgrade 后只读 receipt 查询；
- Desktop/Agent/Schema 的兼容矩阵逐格测试；
- Settings 原子替换、拒绝、Agent 离线和 pending rebuild；
- Stale、runtime instance 变化和 SQLite last-known 文案；
- Writer Healthy/Degraded/Faulted 与 Agent 离线时 Lease、GC suspension、恢复宽限和分页；
- 原生确认的确认/取消/超时/重复唤起、无 React token/consume command、trusted-action proof 绑定与系统文件选择器路径隔离；
- reader close/database pointer 切换/崩溃恢复；
- 升级/卸载在每个 crash point 可恢复。
