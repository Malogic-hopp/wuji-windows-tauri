## 3. Application/Client 统一停止用例

新增 `AgentStopResult` 和：

```text
IAgentProcessService.StopAgentAsync()
```

统一流程：

```text
graceful stop
  -> 成功：返回 IsStopped=true / UsedKillFallback=false
  -> 超时：Application 内部执行 KillAgentAsFallbackAsync
       -> 再检查进程最终状态
       -> 返回 IsStopped / UsedKillFallback=true
```

边界变化：

- `IAgentProcessService` 对 UI/Bridge 只暴露统一 `StopAgentAsync()`；
- `StopAgentGracefullyAsync()` 和 `KillAgentAsFallbackAsync()` 不再暴露在该接口上；
- WPF `MainWindowViewModel` 只调用统一停止方法；
- Bridge `agent.stop` 也只调用统一停止方法；
- WPF、Bridge、React/Rust 不拥有 graceful/kill 编排规则。

回归覆盖 Agent 已停止、graceful 未退出、kill fallback、fallback 后最终状态确认。

## 4. Bridge Agent 合同

新增白名单方法：

| method | Client 入口 | timeout | side effect |
|---|---|---:|---:|
| `agent.getStatus` | `Agent.Status.GetStatusAsync` | 5 秒 | 否 |
| `agent.start` | `Agent.Process.StartAgentAsync` | 15 秒 | 是 |
| `agent.pause` | `Agent.Control.RequestPauseAsync` | 10 秒 | 是 |
| `agent.resume` | `Agent.Control.RequestResumeAsync` | 10 秒 | 是 |
| `agent.stop` | `Agent.Process.StopAgentAsync` | 20 秒 | 是 |

Agent 方法必须先完成 hello 和 initialize；否则返回 `handshake_required` 或 `initialization_required`。

合同由 `contracts/wuji-bridge/v1/bridge.schema.json` 唯一生成。新增类型包括：

- `AgentState`；
- `AgentStatus`；
- `CommandResult`；
- 五个空参数 DTO。

生成物仍为：

```text
src/QuantifiedSelf.Windows.Client.Bridge/Generated/BridgeContracts.g.cs
contracts/wuji-bridge/v1/generated/typescript/bridge-contracts.generated.ts
contracts/wuji-bridge/v1/generated/rust/bridge_contracts.generated.rs
```

## 5. 安全投影

Bridge 使用 `BridgeAgentMapper` 显式投影，不直接序列化 `AgentStatusSnapshot`、`AgentProcessInfo`、`RuntimeState` 或内部 `AgentCommandResult`。

`AgentStatus` 仅包含：

- actual state；
- running / healthy / stale；
- heartbeat/sample UTC 时间。

`CommandResult` 仅包含：

- accepted / completed；
- actual state；
- 是否使用 stop fallback；
- 受控中文 message；
- 白名单化 error code。

以下信息不会进入 Bridge JSON：PID、用户名、机器名、绝对路径、data root、Agent executable、SQLite/日志/runtime/control 路径、完整 Pipe 名、内部 request id、raw exception、stack trace 和内部 runtime/health 对象。

## 6. timeout、去重与 retry

- request id response cache 上限仍为 128；
- 新增 5 分钟 TTL，过期记录可回收；
- 同一 request id + method 在窗口内返回原响应，不重复 start/pause/resume/stop；
- 同一 request id 被其他 method 复用仍返回 `invalid_request`；
- 查询超时可重试；
- side-effect 超时返回 `retryable=false`，提示先查询 Agent 状态，禁止上层盲目自动重试；
- Application 内部 IPC timeout 继续保持“命令可能已执行”的既有语义，并投影为安全 `ipc_timeout`。

没有修改 Named Pipe 协议、内部 timeout、fallback 文件格式或 Agent request id 规则。

## 7. 生命周期不变量

自动测试已冻结：

- 显式 `agent.stop` 才调用统一停止用例；
- Bridge shutdown 不停止 Agent；
- stdin EOF 不停止 Agent；
- Agent 请求异常和 Bridge Dispose 不停止 Agent；
- side-effect timeout 不触发第二次执行；
- Agent 未运行时 Bridge 仍可 hello/initialize/status/shutdown；
- Agent 运行状态由 fake Client 验证，不从普通测试启动真实 Agent。

这保持了 Bridge、Tauri Shell 和 Agent 三进程生命周期相互独立的 ADR 约束。
