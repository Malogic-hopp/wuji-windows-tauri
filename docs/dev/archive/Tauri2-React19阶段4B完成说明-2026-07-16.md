## 1. 实施范围

本批只完成阶段 4B“Rust command”：

- 增加 `activity_get_overview` Tauri command；
- 将 command 加入 Rust invoke handler 和 Rust/React 固定白名单；
- 通过 `BridgeSupervisor` 请求 `activity.getOverview`；
- 返回 schema 生成的 `ActivityOverviewResult`；
- 为该只读请求设置 12 秒 Rust 外层 timeout；
- Bridge ready 或手动重连后自动使 Dashboard Overview query 失效；
- 增加 Rust、React 和 .NET 架构门禁。

本批没有实现 Dashboard 页面四态或数据展示，没有修改 Bridge 聚合、Application 查询语义、Infrastructure/SQLite、IPC、Agent、WPF 或发布流程。

## 2. 调用链

```text
React bridgeClient.getActivityOverview()
  → activity_get_overview
  → BridgeSupervisor.request<ActivityOverviewResult>("activity.getOverview")
  → .NET Bridge
  → IWujiClient.Activity.Overview
```

Rust command 没有输入参数，也不允许 WebView 传入 Bridge method。结果直接反序列化为生成 DTO，不引入第二份手写 Dashboard 合同。

## 3. timeout 边界

`activity.getOverview` 在 .NET Bridge 内仍使用 10 秒查询 timeout。Rust Shell 使用 12 秒外层只读 timeout，使 Bridge 有机会先返回稳定的 `request_timeout`，并为 stdio 与任务调度保留有限余量。

该请求无副作用，因此 Rust timeout 错误标记为可重试。Agent start/pause/resume/stop 的副作用重试规则没有改变，`agent.stop` 继续使用独立 22 秒外层预算。

## 4. 缓存恢复

React 定义稳定 query key：

```text
['activity', 'overview']
```

BridgeSupervisor 自动恢复并发布 `ready` 时，常驻的 Agent 顶栏容器调用统一刷新函数：

- reset initialize query；
- reset Agent status query；
- invalidate Dashboard Overview query。

用户点击“重新连接”成功后也调用同一刷新函数。这样旧 Bridge generation 的 Dashboard 缓存会被标记为 stale；阶段 4C 接入真实 `useQuery` 后，活动页面会自动重新获取数据。

## 5. 业务语义边界

Rust 与 React 本批均不执行以下操作：

- 不累加或换算时长；
- 不计算 Top Apps 排名；
- 不排序 Bridge 返回的数组；
- 不推导 Agent 或会话状态；
- 不访问 SQLite、Named Pipe、runtime 文件、注册表或进程；
- 不暴露通用 shell、文件、HTTP、SQL 或任意 Bridge method forwarding。

所有聚合、排序和安全映射仍由 Application/Client/Bridge 既有链路负责。
