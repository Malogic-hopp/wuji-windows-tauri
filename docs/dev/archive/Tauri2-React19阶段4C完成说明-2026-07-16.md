## 2. 状态模型

Dashboard 使用显式联合状态：

```text
Loading
Empty
Ready
Error
```

- initialize 或 Overview 首次查询尚未完成时显示 Loading；
- 摘要 duration/session count 全为零且两个列表都为空时显示 Empty；
- 有任何摘要或列表数据时显示 Ready；
- initialize 或 Overview 返回错误时显示 Error。

Error 只显示 `toCommandError` 收口后的安全消息，不展示异常、路径、数据库或内部 Bridge 信息。重试不会停止或改变 Agent，只重新建立 initialize（如必要）并读取 Overview。

## 3. 第一版信息结构

Ready 页面只包含：

1. 今日有效使用时长；
2. 今日采样 / 会话摘要；
3. Top Apps；
4. 最近活动会话；
5. 最后更新时间与手动刷新。

Top Apps 使用语义化有序列表，保持 Bridge/Application 已确定的顺序。第一版不根据前端数据绘制比例条或推导图表，避免在 React 重算排名或引入未经领域模型支持的语义。

## 4. 显示格式化

- duration 使用 `Intl.NumberFormat` unit 与 `Intl.ListFormat`；
- session count 使用 `Intl.NumberFormat`；
- UTC 时间通过 `Intl.DateTimeFormat` 转换到系统本地时区；
- 无效或缺失时间使用安全占位文本；
- duration 拆成小时、分钟和秒只属于显示格式，不改变 Bridge 数值。

## 5. 刷新与恢复

```text
页面可见：15 秒
页面隐藏：60 秒
```

`useDocumentVisibility` 监听 `visibilitychange`。TanStack Query 开启低频 background interval，窗口隐藏时不会继续使用前台频率。BridgeSupervisor 进入 ready 或手动重连成功后，阶段 4B 建立的规则仍会自动 invalidate `['activity', 'overview']`。

正常手动刷新只请求 Overview；initialize 未成功时，先重试 initialize，再读取 Overview。

## 6. 可访问性与主题

- Loading 使用 `role="status"`、`aria-live="polite"` 和 `aria-busy`；
- Error 使用 `role="alert"`；
- 刷新状态通过 atomic live region 通知读屏；
- 所有操作均为原生 `button`，支持 Tab、Enter、Space 和 visible focus；
- Top Apps 使用 `ol`，最近会话使用 `ul`，模块由 heading/aria-labelledby 命名；
- High Contrast 使用 `forced-colors: active`、系统色、明确边界且移除阴影依赖；
- reduced-motion 将动画和 transition 收口到近零时长；
- 1080、860、620 像素断点逐步从双列变为单列，保持窄窗口可读。

本批使用 `ui-styling` 技能的可访问性、主题和响应式规则进行实现，但沿用仓库现有原生 CSS token，没有引入 Tailwind、shadcn 或新的前端依赖。
