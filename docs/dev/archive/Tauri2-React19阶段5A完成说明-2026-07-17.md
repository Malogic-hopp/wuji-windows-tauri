## 2. WPF 编辑面盘点与 v1 allowlist

WPF Settings 当前可编辑字段包括：

- App：主题、刷新间隔、App 启动时自动启动 Agent、Windows 登录启动；
- Agent：采样间隔、空闲阈值、心跳间隔、过期阈值、保留天数、JSONL 日志、Agent 事件日志、会话合并、窗口标题遮罩、排除进程、排除标题模式。

Settings v1 仅批准以下字段：

```text
appSettings.theme
appSettings.refreshIntervalSeconds
appSettings.autoStartAgentWhenAppStarts
agentOptions.samplingIntervalSeconds
agentOptions.idleThresholdSeconds
agentOptions.heartbeatIntervalSeconds
agentOptions.staleThresholdSeconds
agentOptions.retentionDays
agentOptions.enableJsonlJournal
agentOptions.enableAgentEventJournal
agentOptions.enableSessionMerge
agentOptions.maskWindowTitles
```

第一版明确排除：

- `StartAppOnWindowsLogin`，因为它会产生注册表副作用；
- `ExcludedProcesses`、`ExcludedTitlePatterns`，因为自由文本可能携带路径或敏感内容；
- `LastSelectedPage`、`MinimizeToTray`、`CloseToTray` 等 UI 内部状态；
- `UseMockCapture`、`IdleSummaryIntervalMinutes` 等非普通用户设置；
- 数据目录、数据库路径、Agent 可执行文件路径；
- Named Pipe、channel、mutex 等运行标识；
- 注册表键和值；
- 清空或迁移数据等破坏性操作；
- 任意键值、通用 JSON 或底层配置文件接口。

## 4. Application 设置用例

Application 新增 `ClientSettingsSnapshot` 及字段级校验结果，并在 `ISettingsService` 提供：

```text
GetClientSettingsAsync
UpdateClientSettingsAsync
```

实现遵循以下规则：

- App 与 Agent 设置可并行读取；
- 使用 Core `AppSettingsValidator` 与既有 `AgentOptionsValidator`；
- 已存 allowlist 字段损坏时，读取投影回退到 Core 默认值；
- 更新仅校验和覆盖 allowlist 字段；
- 未开放字段使用当前值重建并原样保存；
- 历史排除列表即使不合法，也不会阻止安全标量更新，更不会被规范化重写；
- 校验失败时不写任一设置文件；
- 先对 Agent 设置执行带 backup 保存，再保存 App 设置；
- App 保存失败时使用独立清理 token 尝试恢复 Agent backup，并保留最初的保存异常供 Bridge 映射为安全错误。

`WujiClient.Settings` 只转发上述 Application 用例，没有在 Client 或 Bridge 重复默认值和业务校验。

## 5. Bridge 边界与错误安全

Bridge 增加固定 capability：

```text
settings.get
settings.update
```

两者都要求 hello 和 initialize。读取使用 10 秒 timeout，更新使用 15 秒 timeout；`settings.update` 被标记为有副作用，超时后不可由上层盲目重试。

handler 的业务入口只有：

```text
IWujiClient.Settings.GetClientSettingsAsync
IWujiClient.Settings.UpdateClientSettingsAsync
```

参数反序列化禁止未知成员。缺失字段、未知字段、错误枚举或错误类型会在访问 Client 前返回安全 `invalid_request`。

Bridge 使用显式 mapper，不序列化底层 AppSettings/WindowsAgentOptions。字段错误只保留固定 allowlist 字段名；错误正文统一为“设置值无效。”，即使底层错误意外包含路径、数据库、注册表或异常详情也不会透传。其他异常仍映射为固定 `internal_error`，日志只记录 method 与 correlation id。

## 7. 下一步

阶段 5B 增加两个固定语义 Tauri command：

```text
settings_get
settings_update
```

它们应继续通过 BridgeSupervisor typed request 使用生成 DTO，加入 Rust 与 React command 白名单，并分别设置读取和有副作用更新 timeout。保存成功及 Bridge 重连后应失效 Settings query。Rust 不重新计算默认值、不复制校验范围、不解释 Agent reload 或设置状态语义。
