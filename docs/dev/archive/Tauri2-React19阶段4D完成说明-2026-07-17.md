## 2. 验收工具

新增 `tools/QuantifiedSelf.Windows.DashboardParity`。工具固定执行以下流程：

```text
channel=dev
  → 阻止在 dev Agent 运行时读取
  → WPF：DailyStats + Sessions
  → Bridge：hello + initialize + activity.getOverview
  → 对照语义并生成脱敏临时报告
  → shutdown Bridge，不停止 Agent
```

阻止 Agent 运行时验收，是为了避免 WPF 与 Bridge 顺序读取期间数据库继续变化导致假差异。工具只接受固定 Bridge 可执行文件路径，Bridge 本身仍固定使用 `--channel dev`；报告不写数据库路径、原始窗口标题、进程名、异常或堆栈。

Tauri 项目新增一键命令：

```powershell
pnpm smoke:dashboard-parity
```

该命令依次准备固定 dev Bridge、构建 route chunks、检查 bundle、运行 React 状态测试、运行 WPF Today 状态测试，并对照同一 dev 数据。

## 4. 确定性非空 parity

`DashboardParityTests` 使用唯一临时目录和 `channel=dev` 路径，初始化一份 SQLite 数据库并写入：

- 一个跨本地午夜的会话；
- 五个当日应用会话，构造不同 active/total duration；
- 六个可供最近会话查询排序的记录。

随后用同一数据库分别执行：

```text
WPF：DailyStatsService + SessionsDataService
Tauri 数据源：OverviewDataService
```

断言结果覆盖：

- 今日 total/active/idle/unknown 四项均为非零且在两个查询路径完全一致；
- 今日会话数为 6；
- Top Apps 非空且顺序为 Atlas、Browser、Terminal、Notes、Mail；
- 每项 total/active/idle/unknown、session count 和 last-used 时间一致；
- 最近 5 个会话的顺序、UTC 起止时间和 duration 一致；
- Bridge summary 的 UTC 日期转换到本地后为当天 00:00；
- 跨午夜会话只按当天重叠部分计入。

该用例标记为 `Category=Integration`，不启动真实 Agent，也不读写 prod 数据。
