# 测试 Agent 进程隔离与回收修复

日期：2026-07-16

状态：已完成

实施分支：`codex/application-client-sdk`

## 1. 问题

普通 Integration 测试通过 `AgentTestServices.CreateProcess()` 创建了真实的 `WindowsAgentProcessController`。当 `MainWindowViewModel` 自动启动配置为 true 时，测试会从 `AppContext.BaseDirectory` 启动测试输出目录中的 `QuantifiedSelf.Windows.Agent.exe`。

ViewModel 使用 fire-and-forget 启动，测试没有持有或回收子进程。测试结束后 Agent 继续运行并锁定同目录的 Agent、Core、Infrastructure 等 DLL，导致后续 build/test 无法覆盖旧输出。

本次处理前确认并终止了 PID 45168。终止前已验证其 executable 位于 `tests/QuantifiedSelf.Windows.Tests/bin/Debug/`，没有按进程名终止 prod/dev Agent。

## 2. 普通测试隔离

`AgentTestServices.CreateProcess()` 现在只创建 `FakeAgentProcessController`：

- 不调用 `Process.Start()`；
- 记录 `StartCount` 和 `KillCount`；
- 保存当前 fake `AgentProcessInfo`；
- 未设置 fake 状态时仍可读取测试 runtime state，以保持既有状态查询测试语义；
- 自动启动测试明确断言 `StartCount == 1`、`KillCount == 0`。

真实 Windows controller 只能通过名称明确的 `CreateWindowsProcessController()` 创建，现有 start-info/locator 测试只解析启动信息，不执行进程。

## 3. Agent Runtime 类库

新增：

```text
src/QuantifiedSelf.Windows.Agent.Runtime/
```

Agent 的 Worker、状态机、事件和运行时服务已迁入这个无 apphost 的类库，命名空间保持不变。`QuantifiedSelf.Windows.Agent` 可执行项目只保留 `Program.cs` 组合根，并引用 Runtime。

普通 mixed 测试项目现在引用 `QuantifiedSelf.Windows.Agent.Runtime`，不再引用 `QuantifiedSelf.Windows.Agent` executable project。因此其输出目录不再包含：

```text
QuantifiedSelf.Windows.Agent.exe
QuantifiedSelf.Windows.Agent.deps.json
QuantifiedSelf.Windows.Agent.runtimeconfig.json
```

专用 `QuantifiedSelf.Windows.Agent.Tests` 同时引用 Runtime 和 Agent executable，只在该项目中允许真实进程生命周期测试。

## 4. 专用生命周期测试

新增 `AgentProcessLease : IAsyncDisposable`：

1. 为每次测试生成唯一 run id；
2. 将完整 Agent 测试输出复制到 `%TEMP%/WUJI.Tests/<run-id>/Agent/`；
3. 从临时副本启动 Agent，严禁直接运行 `tests/**/bin/**` 或 `src/**/bin/**`；
4. 设置唯一 test channel、`QUANTIFIEDSELF_WINDOWS_AGENT_ROOT` 和 `WUJI_TEST_RUN_ID`；
5. 等待该 PID 的 runtime state 后才把 Agent 视为 ready；
6. Dispose 时先通过唯一 Named Pipe 请求 graceful stop；
7. 超时或 IPC 失败后只对租约记录的 PID 执行 `Kill(entireProcessTree: true)`；
8. `WaitForExitAsync()` 完成后删除自己的临时目录。

正常 lifecycle 测试同时断言 graceful stop 成功且没有使用 kill fallback。

## 5. Job Object 兜底

生命周期测试为 Agent 创建 Windows Job Object，并设置：

```text
JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE
```

Agent 启动后立即加入该 Job Object。即使断言失败、测试取消或 testhost 异常退出，Job handle 关闭也会由 Windows 终止 Agent 进程树。

独立回归测试验证关闭 Job Object 会终止分配的子进程树。

## 6. 架构门禁

新增门禁：

- 除 `QuantifiedSelf.Windows.Agent.Tests` 外，测试项目不得引用 Agent executable project；
- 普通测试源码不得调用 `Process.Start()`；
- mixed 测试输出不得包含 `QuantifiedSelf.Windows.Agent.exe`；
- Agent.Runtime 必须是无 UI 的 `net8.0-windows` 类库；
- Agent.Runtime 只引用 Core 和 Infrastructure。
