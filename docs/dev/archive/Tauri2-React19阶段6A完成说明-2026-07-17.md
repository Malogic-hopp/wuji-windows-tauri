## 1. 实施范围

阶段 6A 完成宿主生命周期与托盘骨架：

- 冻结窗口关闭、隐藏到托盘和真正退出三种不同语义；
- 新增 Rust `HostLifecycle` 状态机和固定、安全的 lifecycle 事件；
- 增加只含“显示吾迹”“退出吾迹”的 dev 托盘骨架，双击托盘图标可恢复主窗口；
- 窗口关闭按钮统一 `prevent_close`：无 dirty 时隐藏到托盘，有 dirty 时通知 React 确认；
- 真正退出先关闭 Bridge，再结束 Tauri 宿主，不调用 `agent.stop`；
- Bridge shutdown 区分 graceful、forced 和 already-exited，并等待 supervisor worker 结束；
- Bridge graceful shutdown 超时后 kill 并 wait/reap，保留 `kill_on_drop` 最终兜底；
- Settings dirty 状态通过固定 typed command 同步给 Rust；
- 原生关闭与托盘退出复用可访问的 `alertdialog`，支持安全默认焦点、Esc、Tab/Shift+Tab；
- 增加 Rust、React 与 .NET 架构测试。

本批没有修改 IPC、SQLite、Agent 状态机、WPF `App.xaml.cs`、默认 WPF Shell、WPF 托盘实现或发布流程，也没有启动或停止真实 Agent。

## 2. 冻结的宿主语义

| 用户动作 | Settings clean | Settings dirty | Bridge | Agent |
|---|---|---|---|---|
| 点击窗口关闭按钮 | 隐藏到托盘 | 阻止关闭并确认 | 保持运行 | 保持运行 |
| 托盘“显示吾迹”/双击 | 显示、恢复并聚焦 | 显示、恢复并聚焦 | 保持运行 | 保持运行 |
| 托盘“退出吾迹” | 真正退出 | 阻止退出并确认 | graceful shutdown，超时强制回收 | 保持运行 |
| dirty 对话框“留下继续编辑” | 不适用 | 取消宿主关闭请求 | 保持运行 | 保持运行 |
| dirty 对话框“放弃并隐藏/退出” | 不适用 | 丢弃草稿后执行原意图 | 按隐藏/退出语义处理 | 保持运行 |

阶段 6A 不在托盘菜单加入 Agent start/pause/resume/stop；该能力属于后续阶段 6B，避免在宿主生命周期骨架中混入 Agent 业务控制。

## 3. Rust 生命周期状态

状态机包含：

```text
Visible
HiddenToTray
ExitConfirmationPending
ShuttingDown
Exited
```

固定事件仅包含状态或意图枚举：

```text
host://lifecycle
host://close-requested
```

事件不包含 PID、路径、channel、Named Pipe、数据库位置或内部异常。React 不能传入可执行文件路径、任意命令、进程 ID 或退出代码。

新增五个固定 command：

```text
app_set_unsaved_changes
window_show
window_hide
app_request_exit
app_cancel_close
```

Rust invoke handler 与 React command allowlist 均显式列出以上命令，总白名单由 10 个扩展为 15 个。

## 4. Bridge 收尾与孤儿防护

BridgeSupervisor 的 shutdown 现在具有三类结果：

- `graceful`：Bridge 响应 `bridge.shutdown` 并在等待窗口内自行退出；
- `forced`：协议响应或退出超时，宿主执行 kill 并 wait/reap；
- `already_exited`：Bridge/worker 原本已退出，shutdown 保持幂等。

Supervisor 额外维护 `worker_stopped` watch；宿主不仅等待 shutdown response，还会等待 worker 真正结束。子进程始终使用 `kill_on_drop(true)`，所有正常与强制路径均执行 `Child.wait()`，避免已结束 Bridge 留下未回收句柄或孤儿状态。

Rust 测试使用短命 `cmd.exe` 验证 graceful 路径，并使用只执行 `Start-Sleep` 的临时 PowerShell 子进程验证 forced kill 后已被 reap。测试不创建真实 Bridge 或 Agent。

## 5. Settings dirty 原生关闭确认

Settings 保留原有 React Router blocker 与 `beforeunload`，并新增宿主协议：

1. React 将 dirty 布尔值同步到 Rust；
2. Rust 收到原生 CloseRequested 或托盘退出；
3. dirty 时 `prevent_close` 并发出固定 intent（`hide`/`exit`）；
4. React 显示 `role="alertdialog"`；
5. 默认焦点停在“留下继续编辑”；
6. Esc 取消，Tab/Shift+Tab 在两个操作间闭环；
7. 用户确认后只调用对应固定 command；
8. UI 明确说明隐藏/退出都不会停止 Agent。

确认失败只显示安全中文错误，不暴露底层异常。React 不直接使用 Tauri window/process API，也不访问文件、注册表、SQLite 或 Named Pipe。
