# WUJI v2 第三轮设计审核回应

状态：审核跟踪记录，不定义产品语义
回应日期：2026-07-18
审核范围：第三轮提出的 2 个 P0 候选、6 个 P1 与文档核验限制

## 1. 结论

第三轮指出的问题成立。两个 P0 候选均按 P0 处理并在文档合同层闭合；六个 P1 也已逐项补入其分域权威文档。核心变化是：

```text
Generation 版本一致
  不再足以证明发布一致
        ↓
Projection 必须绑定具体组件 Result Set
        ↓
Slice 必须与 Projection 来源逐项相等

UTC coverage + 并列 cursor
        ↓
Fact Boundary(epoch ordinal, UTC, fact cursor)

同用户 Pipe
        ↓
DACL + Desktop binary/signature manifest
+ process token + in-memory session capability

WebView confirmation token
        ↓
独立 Win32 原生确认 + Rust 内存单次能力
```

这些修改仍是 Draft 逻辑合同，不是已实现能力，也不是最终 DDL。`schema-v2-manifest.yaml` 门禁继续保留；ADR-002 仍为 Proposed。

## 2. 新 P0 回应

### 2.1 Projection 组件一致性细节

- `result_kind` 只表达 Segmentation/Work/Analysis/Projection 组件；
- Projection 用 dependency mask 声明实际需要的组件，mask 内 source Set ID 必填、mask 外必须为空；
- source ID 是对 `result_sets` 的延迟 FK，Seal/激活 trigger 和 manifest 测试校验 source kind/state/coverage；
- Projection 不得自引用或形成依赖环；
- Query Snapshot Slice 引用的组件必须与 Projection source ID 完全相等；
- NativeV2Summary 压缩按组件分别创建 Set，Projection 指向本次新建的具体 Summary 组件；
- 新增 [DB-014](./08-验收门禁与测试矩阵.md#32-schema迁移与存储发布) 专门注入同 Generation 的 W90/W100 错误组合。

### 2.2 受信任控制链细节

- Pipe 名、同一 SID 和同一 Session 只负责缩小攻击面，不再被描述为完整授权；
- production Agent 只接受固定安装根和签名兼容清单内的 Desktop binary；dev unsigned 例外只能存在于 dev channel；
- WebView 子进程、同名复制、路径替换、伪造 PID、签名/发布者/hash 不匹配均必须拒绝；
- 进程验证成功后，Agent 才为连接发放随机 session capability；业务帧绑定连接、Desktop instance、单调序号和 proof；
- 破坏性动作的 trusted-action proof 从已认证 IPC session capability 派生，并绑定 request ID、动作摘要和短期有效期；
- 原生确认取消、超时、失焦或宿主退出都会销毁内存能力，不能降级为 HTML confirm。

管理员或能够向已认证进程注入代码/读取内存的攻击者明确列为本地进程认证的边界外能力；这不再成为信任普通同用户进程的理由。

本轮已把最新 [README.md](./README.md) 与 [migration-status.md](./migration-status.md) 纳入同一工作区核验：

- 当前仓库真实路径仍是 React/Tauri → BridgeSupervisor → `.NET Bridge` → C#；
- build/test/smoke/soak 未因文档修改而标为 Passed。

## 6. 当前阶段判断

当前可以安全开展以下隔离合成原型：

- Fact Cursor + Fact Boundary；
- Profile/Generation；
- 具体组件绑定的 Result Set/Projection；
- Snapshot Slice、空 Snapshot 和 Lease/GC 三态；
- Identity Resolution App Projection；
- Desktop binary/signature/session capability；
- Win32 原生确认与 trusted-action proof。

当前仍不得：

- 冻结正式 DDL 或通过 G-DDL；
- 把 ADR-002 转为 Accepted；
- 在 prod 实装破坏性 Clear/Privacy 信任链；
- 开始 dev/prod cutover；
- 删除 WPF、C# Agent、Infrastructure 或 `.NET Bridge`。

正式 DDL 仍必须等待 `schema-v2-manifest.yaml` 将本轮新增的复合 boundary、self-FK/dependency mask、Identity Resolution、空 Snapshot、枚举和 Lease/GC 状态变成机器可验证约束。
