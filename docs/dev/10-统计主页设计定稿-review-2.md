看完了这份定稿。整体方向很对：把"趋势、对比、惯性"放在"此时此刻"之前，诚实留空缺数据日，派生标注在 Rust 侧算好——这些都踩在了点上。围绕你最关心的三件事（工作状态、变化趋势、长期追踪），我的意见如下：

## 一、工作状态：对比卡有一个"进行中当天"的坑

① 对比卡的主数字是**今日活跃**，但今日是进行中的——上午 10 点打开 App，3h42m vs 昨日 4h05m 永远显示 ▼，这个对比在一天的大部分时间里是误导性的。

建议二选一：
- **对齐时刻比较**：今日 vs 昨日**同时刻**（截至 10:00 各是多少），这才是可比的；
- 或者主数字换成**昨日（已完成日）**，今日降级为"进行中"小字标注。

另外，▲▼ 建议用中性色而不是红绿——活跃时长变长不一定是"好事"（也可能是加班变多），趋势软件不该替用户做价值判断。

## 二、变化趋势：加一条均线，回答"在变好还是变差"

纯柱状图噪声很大，用户盯着 14 根高低不一的柱子其实看不出"趋势"。建议在 ② 上叠一条 **7 日滑动平均线**——成本极低（数据已在 DTO 里），但它才是"趋势在变好还是变差"这个问题的直接答案。§6 里"不做多周滑动平均"指的是对比口径，视觉 overlay 不冲突，值得放进 v0.1。

③ 周对比有个可比性问题：**当前周只有 2~3 天，SUM 必然远低于完整周**，标了"进行中"但视觉上仍是一根矮柱，容易被误读为"这周状态崩了"。建议进行中的周改用**日均**或斜纹+虚框到预估高度。

## 三、长期追踪：这是当前方案最弱的一块

你最在意长期追踪，但方案里最长的时间尺度只有 30 天（②）和 8 周（③）。建议：

1. **③ 周对比扩到 12 周或加月度视图**——8 周看不到季节性、看不到"我这半年是不是越来越忙"。月度总量柱状（近 6~12 个月）数据量小、查询便宜；
2. **加一行累计/里程碑条**：累计记录 N 天、自 X 年 X 月起、最长连续记录——成本几乎为零，但它是"长期追踪"的心理锚点，也呼应你们"诚实数据"原则；
3. **开工/收工时间本身做趋势**。⑤ 的 14 天均值曲线回答"我的节奏长什么样"，但回答不了"**我最近是不是越开越晚**"——后者才是惯性的核心问题。可以加一个小图：近 14 天每天开工/收工时刻的散点或带状区间，一眼看出漂移方向。

## 四、几个设计漏洞，建议定稿前补掉

1. **④ 的配色稳定性没定义**。"图例固定配色"说了色系来源，但没说**应用→颜色**的映射规则。Top 3 每天不同，如果按当天排名取色，VS Code 今天是蓝、明天是绿——而④的卖点恰恰是跨天横向比较。建议按应用身份哈希或全局高频应用表固定取色；
2. **`last7Avg` 的口径没写清**：含不含今日？分母是自然日 7 天还是"有数据的天数"？缺 3 天数据时两种算法差异巨大。建议明确为"近 7 个有数据日的均值"或"不含今日的自然日"，并在 DTO 里带 `sampleDays` 字段让前端可标注；
3. **周末混入会拉偏 ⑤ 的惯性曲线**。你们已把"工作日/周末拆分"列入后续版本，但考虑到周末两天会把 9 点高峰拉低约 30%，这个对"工作惯性"的准确性影响最大，建议优先级提前，至少曲线可切换"仅工作日"；
4. **切换器只作用 ②④ 是对的**，但建议在 UI 上让用户能感知作用范围（比如切换器紧贴趋势图标题），否则用户会疑惑为什么周对比不动。

## 优先级建议

| 优先级 | 改动 | 理由 |
|---|---|---|
| P0（v0.1 前必改） | 对比卡"进行中当天"口径；④配色映射规则；last7Avg 分母口径 | 都是正确性问题，不改会给出错误结论 |
| P1（v0.1 可加） | 趋势均线 overlay；进行中周改日均；累计里程碑条 | 成本低，直接命中你的三个诉求 |
| P2（v0.2） | 月度视图/12 周；开工收工漂移图；工作日/周末拆分 | 长期追踪的主力，值得单独立项 |

总评：这份定稿的骨架（五区块、数据契约、诚实数据、边界克制）是好的，不需要推翻；主要缺口在**长期尺度**和**进行中数据的可比性**这两处。需要的话，我可以把以上意见整理成对原文档的批注版或补充条款（§6 边界调整 + DTO 增补字段）。
