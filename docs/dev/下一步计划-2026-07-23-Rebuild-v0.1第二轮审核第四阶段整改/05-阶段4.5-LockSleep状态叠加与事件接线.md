# 阶段 4.5：Lock/Sleep 状态叠加与事件接线

## 阶段目标

关闭 P1-05：Lock/Sleep/Unlock/Resume 与用户 Start/Pause/Resume/Stop 形成可证明的
desired state + suppression + effective gate 状态模型。

## 必须实现

1. Lock/Sleep 通过 Coordinator 添加独立 suppression 并冻结 effective capture。
2. 在可靠 Barrier 后提交 SessionLocked/SystemSleep 边界并等待 Writer ack。
3. expected revision 来自当前 applied revision，不得硬编码。
4. Unlock/Resume 只移除对应 suppression。
5. 仅 desired=Running、无 suppression、Writer 健康时恢复采集。
6. Pause/Stop 不因 Unlock/Resume 自动恢复。
7. 重复、乱序和叠加事件幂等且可诊断。
8. 核实真实 Windows Suspend/Resume 的接收方式；message-only window 不可靠时更换 API/窗口形态。
9. 自动测试通过可注入事件源，不执行真实锁屏或休眠。

## 必测状态序列

- Lock→Unlock；
- Sleep→Resume；
- Lock→Sleep→Resume→Unlock；
- Sleep→Lock→Unlock→Resume；
- Pause→Lock→Unlock；
- Stop→Sleep→Resume；
- 重复 Lock/Sleep/Unlock/Resume；
- Barrier/Writer 失败时保持 suppression 和安全冻结。

## 验收标准

- 锁屏/休眠期间不会继续采样；
- 用户 Pause/Stop 不被系统恢复事件覆盖；
- ack 和错误进入 SharedState/Diagnostics；
- 自动状态机测试确定性通过；
- 真实 Lock/Sleep 仍在文档中标为 Pending。

## 明确不做

- 不伪造真实 Lock/Sleep 人工验收；
- 不运行 package/8h soak；
- 不进入 UI/DPI/无障碍门禁。
