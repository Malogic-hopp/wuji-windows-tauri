## 补充问题 1：排除窗口标题仍可能泄露到 health_state

严重级别：

```text
P1
```

问题说明：

`ForegroundSamplePrivacyFilter` 已经阻止被排除 sample 写入 SQLite，但当 `ExcludedTitlePatterns` 命中窗口标题时，当前 `Reason` 会包含原始窗口标题。

随后 `AgentStateMachine` 会把该 reason 写入 `health_state.json` 的 message。

也就是说，敏感标题不会进入：

```text
foreground_samples
app_sessions
```

但可能进入：

```text
runtime / health diagnostics
```

这仍然违反方案中的隐私边界：

```text
隐私规则必须在 Agent 采集阶段生效
UI 展示层脱敏不能替代 Agent 采集阶段脱敏
```

相关位置：

```text
src/QuantifiedSelf.Windows.Agent/Services/ForegroundSamplePrivacyFilter.cs
src/QuantifiedSelf.Windows.Agent/State/AgentStateMachine.cs
```

建议修复：

```text
1. ExcludedTitlePatterns 命中时，不把原始 WindowTitle 放入 Reason
2. Reason 改为泛化文本，例如：
   - Excluded title pattern matched
   - Excluded by title privacy rule
3. ExcludedProcesses 的 reason 可以保留进程名，进程名本身已是匹配对象
4. health_state / runtime_state / log message 中不得出现被标题规则排除的原始标题
```

建议测试：

```text
1. WindowTitle = "My Secret Notes"
2. ExcludedTitlePatterns = ["*Secret*"]
3. 执行 AgentStateMachine.TickAsync
4. foreground_samples 为空
5. app_sessions 为空
6. health_state.json 不包含 "My Secret Notes"
7. health_state.json 可以包含泛化 reason
```

验收：

```text
1. 标题规则命中后，SQLite 不写样本和 session
2. health_state.json 不出现原始窗口标题
3. runtime_state.json 不出现原始窗口标题
4. UI Diagnostics 不出现原始窗口标题
```

## 补充问题 2：WPF 诊断读取会消费坏 control 文件

严重级别：

```text
P2
```

问题说明：

`AgentControlFileStore.ReadAsync()` 当前职责包含：

```text
1. 读取 agent_control.json
2. 遇到坏 JSON 时重命名为 .bad
3. 返回 malformed result
```

这个行为适合 Agent 侧消费控制文件，但 WPF Diagnostics 也复用了同一个读取方法。

因此可能出现：

```text
1. 用户或外部写入坏 agent_control.json
2. WPF 自动刷新先读到该文件
3. WPF 将其重命名为 .bad
4. AgentStateMachine 下一次 TickAsync 已经看不到坏文件
5. Agent 不会写入 MalformedControlFile health 状态
```

这会让诊断读取变成有副作用的操作，破坏控制通道的所有权边界。

相关位置：

```text
src/QuantifiedSelf.Windows.Infrastructure/Control/AgentControlFileStore.cs
src/QuantifiedSelf.Windows.App/Services/AgentStatusService.cs
```

建议修复：

```text
1. 拆分 AgentControlFileStore 读取方法

   Agent 消费型读取：
       ReadForAgentAsync
       - 可解析命令
       - 遇坏 JSON 可隔离为 .bad
       - 返回 malformed 信息

   UI 诊断型读取：
       PeekAsync 或 ReadForDiagnosticsAsync
       - 不移动文件
       - 不删除文件
       - 不改变 agent_control.json
       - 可返回 raw text / parse error

2. AgentStateMachine 只使用消费型读取
3. AgentStatusService / Diagnostics 只使用无副作用读取
4. AgentControlService 写命令逻辑保持不变
```

可选模型：

```csharp
public sealed class AgentControlFileReadResult
{
    public AgentControlCommand? Command { get; init; }
    public bool WasMalformed { get; init; }
    public string? ErrorMessage { get; init; }
    public string? RawText { get; init; }
}
```

建议测试：

```text
1. 写入坏 agent_control.json
2. 调用 WPF diagnostics 使用的 peek 方法
3. 确认 agent_control.json 仍存在
4. 调用 Agent 使用的 read 方法
5. 确认 agent_control.json 被移动为 .bad
6. 确认 AgentStateMachine 会写入 MalformedControlFile health 状态
```

验收：

```text
1. WPF 自动刷新不会移动或删除 agent_control.json
2. 只有 Agent 消费控制文件时才会隔离坏文件
3. 坏 control 文件最终由 Agent 记录到 health_state
4. Diagnostics 仍能展示当前 control 文件原文或解析错误
```
