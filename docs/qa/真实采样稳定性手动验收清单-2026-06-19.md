# 真实采样稳定性手动验收清单（2026-06-19）

本文档用于手动验收 QuantifiedSelf Windows 当前的真实 Win32 采样 MVP。

目标不是验证 UI 美观，也不是验证完整产品能力，而是确认：

```text
真实前台窗口采样稳定
idle / active 判断可信
隐私过滤在写库前生效
Pause / Resume / Stop 不破坏 session 边界
SQLite 数据能支撑 Dashboard 统计
```

## 2. 前台窗口真实采样

步骤：


## 3. 隐私过滤验收

```sql
SELECT process_name, window_title

```

```text
[x] window_title 不包含真实窗口标题
[x] window_title 为 null 或统一脱敏值
[x] runtime_state.json 不包含真实窗口标题

```

实际结果：

### 3.2 排除进程

```json
  "excludedProcesses": [
```


## 4. Idle / Active 口径验收

建议临时配置：

```json
{
  "idleThresholdSeconds": 30
}
```

步骤：

```text
1. 启动 Agent
2. 打开 Chrome 或 Explorer 保持前台
3. 鼠标键盘不动超过 idleThresholdSeconds + 10 秒
4. 查询 foreground_samples
5. 移动鼠标或按键
6. 再等待一轮采样
7. 再次查询 foreground_samples
```

查询：

```sql
SELECT sample_time_utc, process_name, idle_seconds, activity_state
FROM foreground_samples
ORDER BY id DESC
LIMIT 30;
```

通过标准：

```text
[x] idleSeconds 小于阈值时 activityState = Active
[x] idleSeconds 大于等于阈值时 activityState = Idle
[x] 用户恢复输入后，新样本回到 Active
[x] Idle 样本归属当前前台应用
```

实际结果：
```text
msedge 样本中，idle_seconds = 0 时 activity_state = Active
msedge 样本中，idle_seconds = 138 / 141 时 activity_state = Idle
鼠标恢复后，新样本回到 Active
Idle 样本仍归属当前前台应用 msedge
```

Session 验收：

```sql
SELECT process_name, total_duration_seconds, active_duration_seconds, idle_duration_seconds, unknown_duration_seconds
FROM app_sessions
ORDER BY id DESC
LIMIT 10;
```

通过标准：

```text
[x] Active 样本增加 active_duration_seconds
[x] Idle 样本增加 idle_duration_seconds
[x] total_duration_seconds 随采样推进增长
[x] idle 不会导致 session 被错误关闭
```

实际结果：
```text
msedge session: total=147, active=90, idle=57, unknown=0
Code session: total=3, active=3, idle=0, unknown=0
DB Browser for SQLCipher session: total=9, active=9, idle=0, unknown=0
idle 时间被正确累计到 app_sessions，不会把 session 错误关掉
```

## 5. Session 边界验收

步骤：

按顺序切换窗口，每个窗口停留至少 2 个采样周期：

```text
1. Visual Studio
2. Chrome / Edge
3. Explorer
4. Terminal / PowerShell
```

查询：

```sql
SELECT started_at_utc, ended_at_utc, process_name, total_duration_seconds, close_reason
FROM app_sessions
ORDER BY id DESC
LIMIT 20;
```

通过标准：

```text
[x] 进程变化时旧 session 关闭
[x] 新进程开启新 session
[x] close_reason = ProcessChanged
[x] 当前前台应用最多只有一个 open session
[x] 不应出现多个 ended_at_utc IS NULL 的 open session
```

实际结果：
```text
切换 explorer / devenv / Codex / DB Browser / WindowsTerminal / msedge 时，旧 session 均按 ProcessChanged 关闭
最新一条 session 为 explorer，ended_at_utc 为空，close_reason = Open
当前数据库中 open session 数量为 1
```

Open session 检查：

```sql
SELECT COUNT(*)
FROM app_sessions
WHERE ended_at_utc IS NULL;
```

通过标准：

```text
[x] 运行中通常为 1
[ ] Paused 后为 0
[ ] Stopped 后为 0
```


通过标准：

```text
[x] runtime_state.json 中 state = "Paused"
[x] lastHeartbeatUtc 继续更新
[x] foreground_samples 不再新增
[x] 当前 open session 被关闭
[x] close_reason = Paused
```

实际结果：
```text
pause 后 foreground_samples 最大 id 停留在 1118，没有新增样本
runtime_state.json 中 state = Paused
lastHeartbeatUtc 从 03:32:33 继续更新到 03:32:59
pause 后 app_sessions 中 QuantifiedSelf.Windows.App session 已结束，close_reason = Paused
```

### 6.2 Resume

步骤：

```text
1. Agent Paused
2. 点击 Resume
3. 等待 10-15 秒
4. 查询 foreground_samples 和 app_sessions
```

通过标准：

```text
[x] runtime_state.json 中 state = "Running"
[x] foreground_samples 继续新增
[x] 新 session 能正常开启
```

实际结果：

```text
点击 Resume 后，runtime_state.json 中 state 已恢复为 Running
foreground_samples 继续新增，出现 10541 / 10542 / 10543 三条新样本
其中 QuantifiedSelf.Windows.App 恢复后先被采到，随后切到 WindowsTerminal
app_sessions 中新增 325 号 session（QuantifiedSelf.Windows.App，close_reason = ProcessChanged）
并继续进入 326 号 session（WindowsTerminal，total_duration_seconds = 120，active = 57，idle = 63，close_reason = ProcessChanged）
```

### 6.3 Stop

步骤：

```text
1. Agent Running
2. 点击 Stop Agent
3. 等待进程退出
4. 查询 app_sessions
```

通过标准：

```text
[x] Agent 进程退出
[x] WPF 最终显示 NotRunning 或 Stopped
[x] 当前 open session 被关闭
[x] close_reason = Stopped
[x] 不再新增 foreground_samples
```

实际结果：

```text
点击 Stop 后，Agent 终端自动关闭，符合进程退出预期
停止前最后写入的样本是 10964（WindowsTerminal）
app_sessions 中最后一条 session 为 369 号，process_name = WindowsTerminal，close_reason = Stopped
停止后未再新增 foreground_samples
```
