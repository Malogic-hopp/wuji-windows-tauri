## 下一阶段目标

下一阶段目标命名为：

```text
个人洞察与统计分析 MVP
```

阶段完成后，用户打开 WUJI 应该能快速获得：

```text
1. 今日时间去向：总活跃时间、Top Apps、Top Windows / Titles。
2. 今日注意力状态：连续专注段、碎片时间、上下文切换次数。
3. 最近趋势：过去 7 天活跃时间、专注时长、切换频率变化。
4. 异常提醒：今天是否比平时更分散、某类应用是否显著升高。
5. 行动建议：温和、具体、可执行的下一步建议。
```

这个阶段的产品定位是：

```text
像一面镜子一样反馈事实；
像一个温和教练一样给出建议；
不做训诫、不做打扰、不做云端分析。
```

## 产品原则

### 1. 洞察优先，不先堆图表

第一版不追求复杂可视化。优先让用户在 Dashboard 看到几个清晰结论：

```text
今天总共活跃多久
主要时间花在哪些应用
最长连续专注多长
今天切换是否频繁
相比过去 7 天是否异常
下一步建议是什么
```

### 2. 指标必须可解释

每个洞察都应能回到数据依据：

```text
来自 app_sessions
来自 foreground_samples
来自 today / last 7 days 聚合
来自明确阈值规则
```

避免出现用户无法理解的神秘分数。

### 3. 建议温和、克制、可执行

建议文案应像：

```text
“今天下午切换较频繁，可以尝试安排一个 25 分钟单任务块。”
```

不应像：

```text
“你今天效率很差。”
```

### 4. 默认本地、默认隐私

所有聚合和建议均在本地计算，不上传数据。

标题、进程名等敏感信息继续遵守现有隐私过滤和安全展示规则。

### 5. 先日统计，再趋势，再建议

不要一上来直接写 UI 建议。顺序应是：

```text
原始数据
每日聚合
今日摘要
7 天趋势
规则建议
可解释明细
```

## 阶段完成后的状态

阶段 13 **自动化已完成，手动验收未完成**。WUJI 已从：

```text
可后台运行、可自启、可发布的本地采集控制台
```

推进到：

```text
能在本地提供今日洞察、最近趋势和温和行动建议的个人时间反馈工具
```

用户每天打开 WUJI，不只是看到数据列表，而是能得到：

```text
今天发生了什么；
为什么感觉分散或专注；
哪些应用/窗口最影响时间分布；
接下来可以做一个什么小调整。
```

### 2026-07-07 趋势文案优化

实际使用中发现，“今日活跃时间显著低于近 7 天平均”会把未结束的今天当作完整日评价，容易造成误导。已调整为：

```text
1. 今日：显示“今日已活跃 / 距此前完整日均还差 / 已超过”的进度式文案。
2. 昨日：显示“昨日活跃 vs 此前 7 天日均”的完整日对比。
3. 本周：显示“本周至今 vs 上周同期”的同期对比。
```

验证结果：

```text
dotnet build .\QuantifiedSelf.Windows.sln --no-restore
0 warnings / 0 errors

dotnet test .\QuantifiedSelf.Windows.sln --no-restore
439 / 439 passed
```

## 软件定期维护事项

以下事项不作为下一阶段功能计划拆分，而作为 WUJI 长期使用过程中的定期维护机制：

```text
应用语境分类规则维护：
    定期扫描最近数据中的未分类进程 / 浏览器域名；
    温和提示用户补充分组；
    将用户确认后的分类写入本地自定义规则；
    后续统计和洞察优先使用用户规则。

约束：
    每天最多提示一次；
    不在 2 秒 status polling 中扫描数据库；
    不上传标题、域名或进程名；
    未分类项只显示安全摘要；
    用户规则必须可编辑、可删除、可重置。
```
