2. 修改 AgentStateMachine 中 PruneData 的处理逻辑：

当前阶段 7.1 中 PruneData 是 Maintenance skeleton。现在需要改为真实调用：

PruneData command
    ↓
CommandDetected（Tick 文件命令路径已有）
    ↓
CommandAccepted
    ↓
AgentActualState = Maintenance
    ↓
Persist runtime_state / health_state
    ↓
DataMaintenanceService.PruneDataAsync(_options.RetentionDays, DateTime.UtcNow, cancellationToken)
    ↓
成功：
        写 DataPruned 事件
        写 CommandCompleted
        恢复 PruneData 前状态 Running 或 Paused
    ↓
失败：
        写 CommandFailed
        errorCode 使用 result.ErrorCode 或 PruneDataFailed
        错误文本使用 result.SafeMessage 或安全默认文本
        finally 中退出 Maintenance，恢复 PruneData 前状态 Running 或 Paused

注意：
- PruneData 后恢复命令前状态：Running 回 Running，Paused 回 Paused。
- Maintenance 期间仍不执行普通 sample tick。
- 已有 AlreadyInMaintenance 防重复逻辑保留。
- ClearHistory 仍保持阶段 7.1 skeleton：进入 Maintenance，模拟完成，最终 Paused，不做真实删除。

3. DataPruned 事件：

新增真实写入 AgentEventType.DataPruned。

建议 payload：

{
  "retentionDays": 30,
  "cutoffUtc": "2026-05-25T00:00:00Z",
  "cutoffLocalDate": "2026-05-25",
  "foregroundSamplesDeleted": 1234,
  "sessionsDeleted": 56,
  "agentEventsDeleted": 20,
  "jsonlFilesDeleted": 3,
  "jsonlDeleteErrorCount": 0,
  "actualState": "Maintenance"
}

payload 白名单要按事件类型收紧，不要用一把大白名单。

DataPruned payload 不得包含：
- 窗口标题
- 完整文件路径
- 原始 JSONL 内容
- SQL 文本
- 异常原文

4. PruneData 自身事件语义：

必须确保：

- PruneData 先计算 cutoff，再执行删除，再写 DataPruned / CommandCompleted。
- DataPruned / CommandCompleted 永远在删除之后写入，因此不会被本次 PruneData 删除。
- 如果 DataMaintenanceService 删除了旧 agent_events，DataPruned 和 CommandCompleted 不应该被本次删除影响。

5. 错误处理：

如果 DataMaintenanceService 返回 Success=false：
- 写 CommandFailed。
- errorCode = result.ErrorCode ?? "PruneDataFailed"。
- message = result.SafeMessage ?? "PruneData failed."
- message 不得包含完整路径。
- result.SafeDetail 不要直接进入 UI / payload，除非已经确认安全并白名单允许。
- 退出 Maintenance，恢复命令前 Running / Paused。

如果 DataMaintenanceService 抛异常：
- 捕获异常。
- 用 DiagnosticMessageSanitizer 生成安全文本。
- 写 CommandFailed。
- 退出 Maintenance，恢复命令前 Running / Paused。

6. JSONL partial failure 语义：

阶段 7.2 中 JSONL 删除失败会让 PruneDataResult.Success=false，ErrorCode 可能是 JsonlDeletePartial。
阶段 7.3 应将它视为 PruneData 命令失败：
- 写 CommandFailed。
- 不写 DataPruned 或 CommandCompleted。
- 但 SQLite 删除可能已完成，不做复杂补偿。
- 错误文本不含完整路径。

7. Diagnostics 可见性：

Diagnostics Recent Events 应能看到：
- CommandDetected
- CommandAccepted
- DataPruned
- CommandCompleted

失败时应能看到：
- CommandFailed
- errorCode = PruneDataFailed / JsonlDeletePartial / PruneDataSqliteFailed / PruneDataJsonlFailed 等安全码
