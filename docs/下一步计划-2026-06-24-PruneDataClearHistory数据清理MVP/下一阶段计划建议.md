# 下一步建议：阶段 8「Named Pipe / gRPC 控制通道 MVP」

我建议下一阶段进入：

```text
阶段 8：Named Pipe / gRPC over Named Pipes 控制通道 MVP
```

一句话目标：

```text
把当前 agent_control.json 文件 fallback 升级为请求-响应式 IPC 主通道，让 Pause / Resume / Stop / ReloadConfig / PruneData / ClearHistory 具备明确的 accepted / completed / failed 响应。
```

完整重构方案中也明确了长期控制模型：V0 使用 `agent_control.json` 跑通闭环，V1 推荐使用 Named Pipe 或 gRPC over Named Pipes 作为主控制通道，`agent_control.json` 保留为 fallback 和 desired state 持久化来源。

# 五、为什么现在适合做 IPC

之前不建议早做 IPC，是因为产品主链路还不完整。

现在已经不同了。WUJI 已经有：

```text
Pause / Resume / Stop
ReloadConfig
PruneData
ClearHistory
Diagnostics
Settings
Data Views
```

这些命令已经越来越多，而且其中 `ClearHistory`、`PruneData` 这类命令需要更强的请求-响应语义。继续只靠文件 fallback，会有几个问题：

```text
1. UI 很难即时知道命令是否被 Agent 接收。
2. polling agent_events 虽然可用，但链路偏绕。
3. 命令失败、超时、重复点击、Maintenance 中拒绝等语义更适合 IPC。
4. 后续托盘和开机自启也需要更稳定的状态查询。
```

所以阶段 8 做 IPC 是合适的。

# 阶段 8 建议范围

## 8.1 先做 IPC 骨架

建议先只做：

```text
AgentCommandServer
AgentControlClient
NamedPipe transport
CommandResult response
```

先支持：

```text
GetStatus
Ping
```

不要一上来迁移所有命令。

验收：

```text
WPF 能通过 IPC 连接 Agent
GetStatus 能返回 actualState / heartbeat / lastSample / version
IPC 不可用时 UI 不崩溃
```

## 8.2 再迁移低风险命令

第二步迁移：

```text
Pause
Resume
Stop
ReloadConfig
```

保留 `agent_control.json` fallback。

语义：

```text
IPC 成功：走 IPC
IPC 失败：降级 agent_control.json
Diagnostics 记录 ipcStatus / fallbackUsed
```

## 8.3 最后迁移维护命令

最后再迁移：

```text
PruneData
ClearHistory
```

这两个风险更高，建议等普通控制命令稳定后再接入 IPC。

## 8.4 Diagnostics 增加 IPC 状态

Diagnostics 建议显示：

```text
IPC enabled
Pipe name
Last IPC success
Last IPC error
Fallback used
Recent command source: NamedPipe / FileFallback
```

## 8.5 安全边界

Named Pipe 要限制当前 Windows 用户访问。

建议计划里明确：

```text
Pipe 名称包含当前用户 SID hash
Agent 创建 Pipe 时限制 ACL
WPF 只连接当前用户 pipe
不允许跨用户控制 Agent
```

完整重构方案里也提到了 pipe 名称包含当前用户 SID hash、创建 pipe 时配置当前用户 ACL、Diagnostics 显示 pipe name 和最近 IPC 错误。

# 阶段 8 验收标准建议

完成后至少满足：

```text

2. test 全部通过
3. WPF 能通过 IPC 获取 Agent 状态
4. IPC 不可用时自动 fallback 到 agent_control.json
5. Pause / Resume / Stop 通过 IPC 成功执行
6. ReloadConfig 通过 IPC 成功 / 失败均有结果
7. PruneData / ClearHistory 通过 IPC 成功 / 失败均有结果
8. CommandSource 能区分 NamedPipe / FileFallback
9. Diagnostics 能显示 IPC 状态和最近 IPC 错误
10. IPC 超时不会卡 UI
11. Agent 退出后 WPF 能恢复到 NotRunning / fallback 状态
12. 当前用户外的 pipe 访问被拒绝或不可连接
```
