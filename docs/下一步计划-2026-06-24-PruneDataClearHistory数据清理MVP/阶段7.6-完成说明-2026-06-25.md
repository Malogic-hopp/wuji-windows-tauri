## 实现的行为

### 1. PruneData 按钮入口

- **Prune Old Data** 按钮出现在 Settings → Data Management 区域
- 点击后调用 `PruneDataAsync()`，通过 `_requestPruneDataAsync` 委托向 Agent 发出 `PruneData` 命令
- 结果通过 `PruneDataStatusText` 展示（成功排队 / 不可用 / 被拒绝）
- 成功后同步更新 `LastMaintenanceStatusText` 为 `"PruneData queued at HH:mm:ss"`

### 2. PruneData 按钮状态规则

| Agent 状态 | CanExecuteDataCleanup | 按钮可用 |
|---|---|---|
| Running | `true` | ✅ 可用 |
| Paused | `true` | ✅ 可用 |
| NotRunning | `false` | ❌ 禁用 |
| Stopped | `false` | ❌ 禁用 |
| Stale | `false` | ❌ 禁用 |
| **Maintenance** | **`false`** | **❌ 禁用** |

规则：`CanExecuteDataCleanup = status.IsRunning && (status.ActualState == Running || status.ActualState == Paused)`

### 3. 数据管理按钮联动

- `ClearHistoryCommand` 和 `PruneDataCommand` 的 `CanExecute` 均依赖 `CanExecuteDataCleanup`（而非 `CanReloadAgentConfig`）
- `CanReloadAgentConfig` 独立管理 Reload Config / Save and Reload 按钮
- Reload Config 按钮和数据管理按钮启用条件解耦，语义清晰

### 4. 状态属性

| 属性 | 类型 | 说明 |
|---|---|---|
| `CanExecuteDataCleanup` | `bool` | 数据清理操作可用性（setter 中通知 PruneDataCommand 和 ClearHistoryCommand） |
| `PruneDataStatusText` | `string` | 初始值："Prune expired data based on retentionDays." |
| `LastMaintenanceStatusText` | `string` | 初始值："No maintenance performed in this session." |
| `CurrentRetentionDaysText` | `string`（只读） | 显示当前保留策略或"Retention is disabled." |

### 5. 刷新联动

- `MainWindowViewModel.RefreshAsync` 中 Settings 页仅在 `!_settingsViewModel.IsDirty` 时调用 `LoadAsync`（阶段 6 dirty guard 保持不变）
- Dashboard、Samples、Sessions、Apps 在表为空时返回 0 值或空列表、不抛异常（已由现有测试覆盖，本阶段补 `RefreshAfterClearHistory_EmptyStateDoesNotThrow` 端到端验证）
- Diagnostics 本身支持空 agent_events 表

## 新增测试

### 1. `SettingsViewModel_DisablesDataCleanupWhenAgentNotRunning`
构造返回 `IsRunning=false, ActualState=NotRunning` 的 `getAgentStatusAsync`，LoadAsync 后断言 `CanExecuteDataCleanup` 为 `false`，两个数据管理命令 `CanExecute()` 均为 `false`。

### 2. `SettingsViewModel_DisablesDataCleanupDuringMaintenance`
构造返回 `IsRunning=true, ActualState=Maintenance` 的 `getAgentStatusAsync`，LoadAsync 后断言 `CanExecuteDataCleanup` 为 `false`，两个命令均不可执行。

### 3. `SettingsViewModel_DoesNotQueueDuplicateCleanupDuringMaintenance`
构造 Maintenance 状态后 LoadAsync，通过 captured bool 验证 `_requestPruneDataAsync` 不被调用。`PruneDataStatusText` 包含 `"Cannot prune data"` 提示。方法正常返回不崩溃。

### 4. `RefreshAfterClearHistory_EmptyStateDoesNotThrow`
使用 TempWorkspace 创建空数据库，分别构造 Dashboard（`GetDashboardSummaryAsync` 返回零值）、Sessions/Samples/Apps ViewModel（`LoadAsync` 返回空列表、`HasLoadError` 均为 false），验证均不抛异常。

### 5. `MainWindowViewModel_SettingsDirtyGuardStillWorksWithDataManagement`
通过 `CreateMainWindowViewModelAsync` 构造 MainWindowViewModel，Initialize 后使用反射设置 `IsDirty=true`，导航到 Settings 并 Refresh，断言 `LoadAsync` 未被调用、数据管理相关状态属性保持默认值不变。

## Bug 修复（阶段 7.5 遗留）

**BooleanToVisibilityConverter 缺失导致 App 启动崩溃。**

- 发现时间：2026-06-25，阶段 7.6 完成后首次启动 App 时触发。
- 现象：`XamlParseException` — 「无法找到名为 BooleanToVisibilityConverter 的资源」，位于 `SettingsView.xaml` 第 345 行。
- 根因：阶段 7.5 在 CLEAR 确认面板中使用了 `{StaticResource BooleanToVisibilityConverter}`，但未在任何 XAML 资源字典中注册该 Converter。
- 漏测原因：`dotnet build` 和 `dotnet test` 均不触发 WPF 运行时资源解析，141 个测试全部通过。
- 修复：在 `App.xaml` 的 `Application.Resources` 中注册 `<BooleanToVisibilityConverter x:Key="BooleanToVisibilityConverter" />`。
- 已在阶段 7.5 完成说明中补充已知问题记录。
