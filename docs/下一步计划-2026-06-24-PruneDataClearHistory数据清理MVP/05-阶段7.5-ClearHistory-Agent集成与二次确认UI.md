# 阶段 7.5：ClearHistory Agent 集成与二次确认 UI

## 阶段目标

把 `ClearHistory` 接入 Agent 命令，并在 WPF 中提供保守的二次确认入口。

这是阶段 7 风险最高的一步，因为它会真实清空历史数据。必须坚持：WPF 只发命令，真实清理由 Agent 执行。

## UI 建议

放在 Settings 页新增 Data Management 区域：

```text
Prune old data
Clear all history
```

Clear all history 必须二次确认：

```text
第一次：确认弹窗说明会清空历史采样、会话、应用排行和诊断事件
第二次：输入 CLEAR 才能继续
```

按钮文案建议：

```text
Clear all history
```

中文提示建议：

```text
这会清空本机历史采样、会话、应用排行和诊断事件。配置文件不会被删除。此操作不可撤销。
请输入 CLEAR 继续。
```

## Agent 集成语义

```text
ClearHistory 成功后 AgentActualState = Paused
用户需要手动 Resume 才继续采集
```

原因：

```text
清空后如果立刻恢复 Running，Agent 很快写入新 sample，用户可能误以为没有清空。
```

## Agent 流程

```text
ClearHistory command
    ↓
CommandDetected
    ↓
CommandAccepted
    ↓
AgentActualState = Maintenance
    ↓
关闭当前 open session
    ↓
DataMaintenanceService.ClearHistoryAsync()
    ↓
清空后重新写 HistoryCleared
    ↓
CommandCompleted
    ↓
AgentActualState = Paused
    ↓
写 runtime_state / health_state
```

失败时：

```text
CommandFailed
errorCode = ClearHistoryFailed
错误文本安全脱敏
finally 中退出 Maintenance
```

## HistoryCleared payload

建议 payload：

```json
{
  "foregroundSamplesDeleted": 1234,
  "sessionsDeleted": 56,
  "agentEventsDeleted": 20,
  "jsonlFilesDeleted": 3,
  "jsonlDeleteErrorCount": 0,
  "finalState": "Paused"
}
```

不得包含：

```text
窗口标题
完整文件路径
原始 JSONL 内容
SQL 文本
异常原文
```

## Diagnostics 语义

ClearHistory 清空 `agent_events` 后，只保留清空后的新事件是合理的。

要求：

```text
Recent Events 至少显示 HistoryCleared
Recent Errors 可以为空，但 UI 不报错
当天 agent_events JSONL 仍可定位
```

## 验收标准

- ClearHistory 不经过二次确认无法触发。
- 输入错误确认词不会发送命令。
- ClearHistory 命令只由 Agent 执行。
- 成功后 Samples / Sessions / Apps 显示空态。
- 成功后 Diagnostics 至少能看到 `HistoryCleared` 和 `CommandCompleted`。
- ClearHistory 后 Diagnostics Recent Events 至少显示 `HistoryCleared`。
- ClearHistory 后 Diagnostics Recent Errors 可以为空，但 UI 不报错。
- ClearHistory 后当天 agent_events JSONL 仍可定位。
- 成功后 Agent 显示 Paused。
- 失败后 `CommandFailed` 可见，错误文本安全。


## 不做什么

- 不做复杂进度条。
- 不做取消 ClearHistory。
- 不删除当天 JSONL。
- 不做数据库 VACUUM。
- 不做恢复已删除数据。
