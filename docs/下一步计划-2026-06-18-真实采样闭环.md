# 下一步计划（真实采样闭环，2026-06-18）

本文档作为当前阶段的开发指导。

当前项目已经进入：

```text
Mock 数据闭环 MVP
```

下一步最关键的目标是：

```text
真实前台窗口采样
真实 idle 判断
采集阶段隐私过滤
真实数据落 SQLite
Dashboard 继续沿用现有统计链路
```

本阶段不要优先做 IPC、托盘、美化、完整 Settings，也不要急着拆 AppsView / SessionsView。那些属于体验增强。现在真正决定软件能不能从原型走向可用产品的是：真实数据能否稳定、准确、安全地进入现有数据链路。

---

## 阶段目标

把当前链路：

```text
MockForegroundSampleProvider
    ↓
foreground_samples
    ↓
app_sessions
    ↓
Dashboard
```

替换为：

```text
Win32ForegroundSampleProvider
    ↓
IdleDetector
    ↓
PrivacyFilter
    ↓
foreground_samples
    ↓
app_sessions
    ↓
Dashboard
```

原则：

```text
后面的 SQLite、session 合并、Dashboard 尽量不改。
只替换数据来源和真实 idle 判断。
```

建议接口保持简单：

```csharp
using QuantifiedSelf.Windows.Core.Models;

namespace QuantifiedSelf.Windows.Core.Capture;

public interface IForegroundSampleProvider
{
    ForegroundSample Capture();
}
```

```csharp
namespace QuantifiedSelf.Windows.Core.Capture;

public interface IIdleDetector
{
    int GetIdleSeconds();
}
```

然后让当前的 `MockForegroundSampleProvider` 实现 `IForegroundSampleProvider`。

注意：

```text
Mock provider 继续保留，用于测试、演示、CI 和回归排查。
真实 Win32 provider 只替换运行时数据来源，不影响现有数据库和 Dashboard。
```

## 第 2 步：实现真实 idle 判断

新增：

```text
src/QuantifiedSelf.Windows.Infrastructure/Win32/WindowsIdleDetector.cs
```

核心使用 Win32 API：

```text
GetLastInputInfo
```

职责：

```text
返回当前用户距离最后一次键盘 / 鼠标输入过去了多少秒
```

Agent 根据配置判断：

```text
idleSeconds >= idleThresholdSeconds
    => Idle
else
    => Active
```

建议第一版配置增加：

```json
{
  "useMockCapture": false,
  "samplingIntervalSeconds": 3,
  "idleThresholdSeconds": 60
}
```

说明：

```text
当前代码里已有 SamplingIntervalSeconds / IdleThresholdSeconds。
本阶段只需要新增 UseMockCapture 或等价开关。
```

## 第 3 步：实现 Win32 前台窗口采样

新增：

```text
src/QuantifiedSelf.Windows.Infrastructure/Win32/NativeMethods.cs
src/QuantifiedSelf.Windows.Infrastructure/Win32/Win32ForegroundSampleProvider.cs
```

第一版只采集这些信息：

```text
GetForegroundWindow()
GetWindowText()
GetWindowThreadProcessId()
Process.GetProcessById(pid)
process.ProcessName
process.MainModule.FileName，失败则为 null
```

需要保守处理异常：

```text
1. GetForegroundWindow 可能返回 0
2. GetWindowText 可能为空
3. GetWindowThreadProcessId 可能拿不到有效 pid
4. Process.GetProcessById 可能失败
5. process.MainModule 可能权限不足
6. 管理员权限窗口可能读不到路径
7. UWP 应用可能显示为 ApplicationFrameHost
8. 锁屏 / 桌面切换 / 特殊 shell 窗口可能信息不完整
```

第一版不要追求完美识别：

```text
浏览器 tab
Edge / Chrome 网页标题结构化
UWP 真实应用映射
管理员进程完整路径
```

先把真实前台进程名、窗口标题、可选路径稳定采出来。

## 第 4 步：采集阶段隐私过滤继续放 Agent 侧

当前已经实现采集阶段隐私过滤，这个方向保持不变。

真实采样接入后的顺序必须是：

```text
Win32 捕获原始 sample
    ↓
IdleDetector 补 idleSeconds / activityState
    ↓
PrivacyFilter 过滤 / 脱敏
    ↓
写 foreground_samples
    ↓
合并 app_sessions
```

不要让原始敏感窗口标题先落库。

推荐逻辑：

```text
如果 processName 命中 excludedProcesses：
    不写 foreground_samples
    不进入 session aggregator

如果 title 命中 excludedTitlePatterns：
    按当前隐私策略排除或脱敏
    诊断信息不得包含原始标题

如果 maskWindowTitles = true：
    WindowTitle = null 或 "[Masked]"
```

注意：

```text
health_state / runtime_state / log message 也不能泄露被标题规则命中的原始窗口标题。
```

## 第 5 步：通过配置切换 Mock / Win32

不要删除 Mock。

在 `windows-agent.json` 对应的 options 中增加：

```json
{
  "useMockCapture": false
}
```

Agent 启动时：

```text
useMockCapture = true
    使用 MockForegroundSampleProvider

useMockCapture = false
    使用 Win32ForegroundSampleProvider
```

建议实现方式：

```text
1. WindowsAgentOptions 新增 UseMockCapture
2. Program.cs 注册 IIdleDetector
3. Program.cs 根据配置或工厂选择 IForegroundSampleProvider
4. Mock provider 和 Win32 provider 都实现 Core/Capture/IForegroundSampleProvider
```

如果直接在 DI 注册阶段读取配置不方便，可以先引入一个代理 provider：

```text
ConfiguredForegroundSampleProvider
    内部根据 options.UseMockCapture 委托给 Mock 或 Win32
```

这样后续 ReloadConfig 也更容易演进。

## 验收标准

真实采样接入后，按以下标准验收：

```text
1. dotnet build 0 warnings / 0 errors
2. dotnet test 全部通过
3. 启动 WPF App
4. 点击 Start Agent
5. 切换 VS / Chrome / Explorer / 桌面窗口
6. foreground_samples 中能看到真实 process_name
7. app_sessions 能按进程变化关闭旧 session、开启新 session
8. Dashboard Top Apps 从 Mock 应用变成真实应用
9. 鼠标键盘不动超过 idleThresholdSeconds 后，activityState 变成 Idle
10. 点击 Pause 后 heartbeat 继续，但不再写 sample
11. 点击 Resume 后继续写 sample
12. 点击 Stop 后当前 session close_reason = Stopped
13. excludedProcesses 命中时不落库
14. maskWindowTitles = true 时数据库里看不到真实窗口标题
15. 标题规则命中时 health_state / runtime_state / log 不泄露原始标题
```
