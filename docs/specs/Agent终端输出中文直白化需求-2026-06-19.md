# Agent 终端输出中文直白化需求（2026-06-19）

## 背景

当前 Agent 启动后在终端里打印的输出偏工程化，信息正确，但对人工调试和验收不够直观。  
在真实采样稳定化阶段，终端输出需要更容易被快速看懂。

## 需求目标

把 Agent 的关键终端输出调整为“中文直白 + 少量结构化字段”的表达方式，方便人工阅读、问题定位和验收。

## 设计原则

```text
1. 终端输出要短，尽量一眼能看懂
2. 成功路径优先中文表达
3. 保留少量关键字段，便于排查
4. 不输出真实窗口标题，继续遵守隐私要求
5. 不把内部实现细节全部堆到终端输出里
```

## 适用范围

本需求只针对 Agent 启动后的终端输出，不修改：

```text
runtime_state.json
health_state.json
SQLite 数据结构
现有隐私策略
```

## 需要覆盖的日志场景

```text
1. 采样成功
2. 心跳更新
3. 暂停
4. 恢复
5. 停止
6. 采样失败
7. 隐私过滤命中
```

## 建议日志风格

### 采样成功

```text
采样成功：状态=Running，前台=msedge，idle=141秒，已写入数据库
```

### 心跳更新

```text
心跳已更新：状态=Running
```

### 暂停

```text
已暂停采集：当前窗口不再写入样本，心跳仍继续
```

### 恢复

```text
已恢复采集：继续写入前台样本
```

### 停止

```text
已停止：open session 已关闭
```

### 采样失败

```text
采样失败：获取前台窗口失败，errorCode=ProcessNotFound
```

### 隐私过滤命中

```text
已跳过采样：命中标题隐私规则
```

## 建议保留的结构化字段

```text
state
processName
idleSeconds
sampleId
errorCode
```

## 禁止项

```text
1. 不要在普通成功日志里输出真实窗口标题
2. 不要把日志写成长篇英文技术句
3. 不要在正常采样里刷太多堆栈信息
4. 不要把隐私敏感内容写进 reason/message
```

## 验收标准

```text
1. 用户能直接看懂采样、心跳、暂停、恢复、停止的终端输出
2. 终端输出里不出现真实窗口标题
3. 关键状态字段仍然可以用于排查
4. 失败时能够快速定位到错误原因或错误码
5. 不影响现有采样、隐私、session 行为
```

## 备注

这份需求只定义“终端输出怎么说人话”，不定义新的事件体系。  
后续如果要做 `agent_events` 或 JSONL，再单独出事件需求。
