# WUJI 产品命名与前台显示需求（2026-06-19）

## 背景

当前 Windows App 在运行时仍然较多体现工程项目名：

```text
前台进程名：QuantifiedSelf.Windows.App
窗口标题：QuantifiedSelf Windows
```

这对开发调试是清晰的，但对产品体验不够友好。  
用户实际看到和采样记录里出现的名称，应该更多体现产品名：

```text
WUJI
吾迹
```

## 需求目标

把面向用户、面向验收、面向真实采样结果的可见命名，从工程名逐步调整为产品名。

核心目标：

```text
1. WPF 主窗口标题体现 WUJI / 吾迹
2. 自身 App 被采样时，前台应用名称更像产品名，而不是工程程序集名
3. 终端、Dashboard、手动验收时更容易确认“这是 WUJI 自己”
4. 不破坏现有项目结构、命名空间和程序集引用
```

## 命名建议

第一版建议采用：

```text
产品英文名：WUJI
产品中文名：吾迹
窗口标题：WUJI 吾迹
应用显示名：WUJI
```

如果需要更解释性的标题，可使用：

```text
WUJI 吾迹 - 本地使用记录
```

但 MVP 阶段优先保持简洁。

## 适用范围

本需求优先覆盖用户可见命名：

```text
1. WPF 主窗口 Title
2. App 程序集产品信息
3. Windows 进程描述 / 文件描述
4. Agent 终端输出里提到 App 产品名的文案
5. Dashboard / 状态区中展示自身应用时的名称
```

本需求暂不要求修改：

```text
1. C# 命名空间
2. 项目文件名
3. 解决方案名
4. NuGet 包名
5. 数据库表结构
6. 已有 JSON 契约
```

也就是说，内部工程仍可以继续叫：

```text
QuantifiedSelf.Windows.App
QuantifiedSelf.Windows.Agent
QuantifiedSelf.Windows.Core
QuantifiedSelf.Windows.Infrastructure
```

对外显示逐步切换为：

```text
WUJI
吾迹
```

## 推荐实现点

### 1. 修改 WPF 主窗口标题

目标：

```text
窗口标题从 QuantifiedSelf Windows 改为 WUJI 吾迹
```

可能位置：

```text
src/QuantifiedSelf.Windows.App/MainWindow.xaml
```

验收：

```text
启动 WPF App 后，窗口标题栏显示 WUJI 吾迹
Win32 采样到 WPF 主窗口时，window_title 中不再是 QuantifiedSelf Windows
```

### 2. 修改 App 程序集产品信息

目标：

```text
Windows 任务管理器 / 文件属性中尽量显示 WUJI
```

可能位置：

```text
src/QuantifiedSelf.Windows.App/QuantifiedSelf.Windows.App.csproj
Directory.Build.props
```

建议补充：

```xml
<Product>WUJI</Product>
<AssemblyTitle>WUJI</AssemblyTitle>
<Description>WUJI Windows App</Description>
```

注意：

```text
程序集名可以暂时不改，避免影响启动路径、测试和引用。
```

### 3. 处理采样展示名

真实 Win32 采样第一版拿到的 `process_name` 很可能仍是：

```text
QuantifiedSelf.Windows.App
```

因为这是可执行文件名或进程名。  
如果短期不改 exe 名，可以先在展示层做产品名映射：

```text
QuantifiedSelf.Windows.App -> WUJI
QuantifiedSelf.Windows.Agent -> WUJI Agent
```

建议优先放在查询 / ViewModel / Dashboard 展示层，不改原始采样入库数据。

这样可以同时保留：

```text
数据库原始 process_name：QuantifiedSelf.Windows.App
用户看到的 display_name：WUJI
```

### 4. 暂不急着改可执行文件名

如果要让采样到的 `process_name` 也变成：

```text
WUJI
```

通常需要改程序集名 / 输出文件名，例如：

```xml
<AssemblyName>WUJI</AssemblyName>
```

但这会影响：

```text
1. App 启动 Agent 的路径查找
2. 调试配置
3. 构建输出文件名
4. 测试里可能写死的路径
5. 后续安装包和升级路径
```

所以建议分两步：

```text
第一步：改窗口标题和展示名
第二步：稳定后再评估是否改 exe / AssemblyName
```

## 隐私与采样影响

需要注意：

```text
窗口标题是隐私敏感字段
```

因此即使窗口标题改成 `WUJI 吾迹`，仍要遵守现有规则：

```text
maskWindowTitles = true 时，数据库中不写真实窗口标题
excludedTitlePatterns 命中时，不写 sample
health_state.json / runtime_state.json 不泄露原始窗口标题
```

本需求不放宽任何隐私规则。

## 验收标准

```text
1. 启动 WPF App 后，主窗口标题显示 WUJI 吾迹
2. Windows 任务栏 / Alt+Tab 中优先看到 WUJI / 吾迹
3. Agent 真实采样 WPF App 时，window_title 不再出现 QuantifiedSelf Windows
4. Dashboard 展示自身应用时，用户看到的是 WUJI，而不是 QuantifiedSelf.Windows.App
5. 数据库原始 process_name 是否保留工程名，由实现阶段决定，但展示层必须产品化
6. dotnet build 0 warnings / 0 errors
7. dotnet test 全部通过
```

## 推荐开发顺序

```text
1. 修改 MainWindow 标题为 WUJI 吾迹
2. 补 App 程序集产品信息
3. 在 Dashboard / Top Apps 展示层增加自身进程名映射
4. 手动验证真实采样结果
5. 再评估是否需要改 AssemblyName / 输出 exe 名
```

## 暂不做

本阶段暂不做：

```text
1. 大规模重命名命名空间
2. 重命名解决方案和项目目录
3. 改数据库历史数据
4. 改 IPC / control 文件命名
5. 改安装包标识
```

## 结论

当前最稳的路线是：

```text
先把用户看得到的地方改成 WUJI / 吾迹
内部工程名暂时保持不动
真实采样和 Dashboard 展示先通过标题与 display name 体现产品名
```

这样既能快速提升产品感，也不会把已经稳定的采样、Agent 控制和测试链路打散。
