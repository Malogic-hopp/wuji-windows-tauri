任务目标：

实现“阶段 9.4：当前页数据刷新与 Agent 状态刷新解耦”。

本阶段目标是把当前页数据刷新作为独立任务管理，避免 Dashboard / Apps / Sessions / Samples / Diagnostics / Settings 的慢查询拖慢 2 秒 Agent 状态轮询。状态刷新继续高频轻量，页面数据刷新继续低频且只刷新当前页。

尤其注意本阶段不做：

- 不改变阶段 9.2 的 2 秒 status polling timer interval。
- 不改变阶段 9.2 的 latest-wins 状态应用语义。
- 不改变阶段 9.3 的按钮可用性规则。
- 不改变 Start / Pause / Resume / Stop / ReloadConfig / PruneData / ClearHistory 的命令执行链路。
- 不改变 ClearHistory 的 `CLEAR` 二次确认流程。
- 不改 AgentStateMachine。
- 不改 Named Pipe IPC 协议。
- 不把 Samples / Sessions / Apps 数据查询搬到 IPC。
- 不改 SQLite 查询服务语义。
- 不做后台预加载所有页。
- 不做分页、图表、托盘、自启、安装包。
- 不做真正长连接状态流或 subscribe 协议。

需要实现的范围：

1. 明确拆分 status refresh 和 page refresh。

当前阶段 9.2/9.3 后已有：

```text
RefreshService.RefreshStatusAsync(...) 负责 status/process/health
MainWindowViewModel.PerformStatusPollAsync / RefreshStatusOnlyAsync 负责 2 秒状态轮询
MainWindowViewModel.RefreshCurrentPageDataAsync(...) 负责当前页数据刷新
```

阶段 9.4 要求：

```text
status refresh:
    高频、轻量、短路径
    使用独立 status gate / CTS / latest-wins
    不等待页面查询
    不调用页面数据服务

page refresh:
    只按当前页刷新
    独立 page refresh gate
    防重入
    重入时跳过并记录 page skipped count
    页面错误只影响页面/刷新健康，不覆盖 Agent 状态
```

并发边界要求：

```text
status gate / status CTS 与 page refresh gate 必须完全独立。
任何等待 page refresh gate 的代码不得包裹或阻塞 status refresh 路径。
status polling 不得因为 page refresh 正在进行而等待或跳过。
page refresh 正在进行时，status refresh 仍应可以执行并应用最新状态。
```

2. 新增或扩展 page refresh gate。

建议在 `MainWindowViewModel` 中新增页面刷新专用 gate，例如：

```csharp
private readonly SemaphoreSlim _pageRefreshGate = new(1, 1);
```

要求：

```text
RefreshCurrentPageDataAsync 或其外层包装必须通过 _pageRefreshGate 防重入。
如果已有页面刷新正在进行，新的页面刷新请求直接跳过。
跳过时记录 page skipped count 或等价 RefreshHealth 信息。
跳过页面刷新不得跳过 status refresh。
页面刷新因重入被跳过时，只增加 SkippedPageRefreshCount。
页面刷新跳过不是错误，不更新 LastPageRefreshError，不把 Refresh 状态标记为 failed/error。
```

不要继续依赖 `_refreshGate` 把 status + page data 整次 Refresh 串死。手动 Refresh 可以顺序执行“状态刷新 -> 页面刷新”，但页面刷新慢时，2 秒 status polling 仍能继续进入 status-only 路径。
