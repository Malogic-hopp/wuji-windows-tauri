任务目标：

实现“阶段 9.3：ViewModel 状态派发与按钮可用性统一”。

尤其注意本阶段不做：

- 不改变 Start / Pause / Resume / Stop / ReloadConfig / PruneData / ClearHistory 的命令执行链路。
- 不改变 ClearHistory 的 `CLEAR` 二次确认流程。

- 不改变 AgentControlService 的 IPC-first / file fallback 语义。
- 不改 Named Pipe IPC 协议。
- 不改 2 秒 status polling timer 的 interval、启动/停止、latest-wins 和取消策略。
- 不改当前页数据刷新频率和范围。
- 不把 SQLite 查询搬到 IPC。
- 不改 WPF 页面布局。
- 不新增托盘、自启、安装包。
- 不做真正长连接状态流或 subscribe 协议。

1. 建立共享的 UI 命令状态判断。

建议新增一个轻量 helper / model，例如：

```text
src\QuantifiedSelf.Windows.App\Services\AgentCommandAvailability.cs
```

或放在 App 层更合适的位置。命名可按现有风格调整，但职责要清楚。

它应该基于同一份 `AgentStatusSnapshot` 产出按钮可用性，例如：

```csharp
public sealed class AgentCommandAvailability
{
    public bool CanStart { get; init; }
    public bool CanStop { get; init; }
    public bool CanPause { get; init; }
    public bool CanResume { get; init; }
    public bool CanReloadConfigNow { get; init; }
    public bool CanSaveAndReloadAgentOptions { get; init; }
    public bool CanPruneData { get; init; }
    public bool CanClearHistory { get; init; }
    public bool IsMaintenance { get; init; }
    public string ReloadConfigStatusText { get; init; } = "";
}
```

也可以用静态方法直接返回多个 bool，但必须能让 MainWindowViewModel 和 SettingsViewModel 复用同一套判断。

要求：

```text
AgentCommandAvailability 不应引用 MainWindowViewModel 或 SettingsViewModel。
AgentCommandAvailability 只接收 AgentStatusSnapshot、isBusy 等简单输入，返回可用性结果。
推荐签名类似：
    AgentCommandAvailability.FromStatus(AgentStatusSnapshot status, bool isBusy = false)
MainWindowViewModel 使用自身 IsBusy 计算主控制按钮。
SettingsViewModel 可在共享 availability 基础上叠加自身 IsLoading / IsSaving / 确认输入等 UI 条件。
不要让 MainWindow 的 IsBusy 强行写入 SettingsViewModel 状态字段，也不要让 Settings 的 IsSaving 影响 MainWindow 控制按钮。
```

推荐规则：

```text
Start:
    ActualState 为 NotRunning / Stopped
    且不在 Maintenance
    且 UI 不 busy

Stop:
    ActualState 为 Running / Paused / Stale
    且不在 Maintenance
    且 UI 不 busy

Pause:
    ActualState 为 Running
    且不在 Maintenance
    且 UI 不 busy

Resume:
    ActualState 为 Paused
    且不在 Maintenance
    且 UI 不 busy

ReloadConfig:
    Running / Paused 时可立即 Reload
    Maintenance 时不可用
    NotRunning / Stopped 时保持“下次启动生效”语义，不发送 ReloadConfig

Save and Reload Agent Options:
    只有 Running / Paused 且不在 Maintenance 时可用

PruneData / ClearHistory:
    Running / Paused 且不在 Maintenance 时可用
```

关于 Stale：

```text
Stale 的 MVP 策略固定为：
    Stop 可用，便于用户结束可能卡住的 Agent。
    Start 不可用，除非现有进程检查已经明确 NotRunning。
    Pause / Resume / ReloadConfig / PruneData / ClearHistory 不可用。
不要让 Start 在 status.IsRunning 为 true 或进程仍可能存在时可用，避免误导用户启动第二个 Agent。
```


```text

```

Settings 正在编辑时，status polling 仍应更新按钮可用性，但不能覆盖用户未保存草稿。
