2. `RefreshService` 第一版职责：

```text
提供 RefreshAsync(currentPage, cancellationToken)
内部调用 AgentStatusService.GetStatusAsync
内部调用 AgentProcessService.GetAgentProcessInfoAsync
记录 last success / error / skipped count
防止刷新重入
返回 RefreshResult
不直接写 ViewModel 属性
```

3. `RefreshResult` 第一版至少包含：

```text
long RefreshSequence
DateTime StartedAtUtc
DateTime CompletedAtUtc
AgentStatusSnapshot Status
AgentProcessInfo? ProcessInfo
RefreshHealthSnapshot Health
string CurrentPage
string StatusSource
bool PageDataRefreshed
bool PageRefreshSkipped
```

其中：

- `RefreshSequence` 必须单调递增，供后续阶段防止旧结果覆盖新状态。
- `StartedAtUtc` / `CompletedAtUtc` 使用 UTC。
- `StatusSource` 可以先从现有 IPC / fallback 状态推断，若阶段 9.1 不方便准确区分，可先保守返回 `Unknown` / `NamedPipe` / `FileFallback` 中最安全的值，但不要引入 UI 误导。
- `PageDataRefreshed` 在阶段 9.1 可以保持与现有 `RefreshAsync` 当前页刷新完成语义一致，或由 MainWindowViewModel 在应用结果时决定；不要让 RefreshService 直接更新页面集合。

4. `RefreshHealthSnapshot` 第一版建议包含：

```text
DateTime? LastRefreshSuccessUtc
DateTime? LastRefreshErrorUtc
string? LastRefreshError
int SkippedRefreshCount
bool IsRefreshing
string StatusText
```

也可以拆成 status / page 字段，但阶段 9.1 不要求完整区分 status refresh 和 page refresh。阶段 9.4 会继续细化。

注意：

- 错误文本必须走 `DiagnosticMessageSanitizer` 或等价安全格式化。
- 不要保存原始异常消息、本机路径、SQL、完整 pipe name、SID、原始 JSON。
- RefreshHealth 第一版只保存在 App 内存，不写 `agent_events`。
