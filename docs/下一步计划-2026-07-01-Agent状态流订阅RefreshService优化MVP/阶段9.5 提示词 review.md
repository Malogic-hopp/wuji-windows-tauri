# 建议补强 2：Healthy / Degraded 的错误清除语义要明确

你定义了：

```text
Degraded:
    LastStatusRefreshError 不为空
    或 LastPageRefreshError 不为空
```

这里有一个隐含问题：成功刷新后是否清空 error？如果不清空，Diagnostics 会一直 degraded；如果清空，又可能丢失最近错误信息。

建议固定 MVP 语义：

```text

最近一次 page refresh 成功后，可清空 LastPageRefreshError；
status 和 page 的错误互不清空。
```

也就是：

```text

page 成功不能清空 status error
```

这和阶段 9.4 的 status/page health 分离逻辑一致。

# 关于 Start 按钮修复的审核结论

这个修复本身建议保留，而且阶段 9.5 执行时必须防止回退。

修复后的判断：

```csharp
CanStart = !status.IsRunning && !isMaintenance
```

比只看 `ActualState` 更合理，因为 Start 的关键判断应该优先看“Agent 进程是否真实存在”。状态文件可能残留 Running，但进程探测为不存在时，应允许用户重新 Start。

建议阶段 9.5 的测试回归里继续保留：

```text
AgentCommandAvailability_AllowsStartWhenStaleButProcessGone
AgentCommandAvailability_HandlesStaleConservatively
```

也就是同时覆盖：

```text
Stale + IsRunning=false => CanStart=true
Stale + IsRunning=true  => CanStart=false, CanStop=true
```
