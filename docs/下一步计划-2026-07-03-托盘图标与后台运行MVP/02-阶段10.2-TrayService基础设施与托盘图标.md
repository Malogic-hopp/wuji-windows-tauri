# 阶段 10.2：TrayService 基础设施与托盘图标

## 阶段目标

新增托盘服务基础设施，让 App 启动后出现系统托盘图标，并能通过托盘 Show / Exit。

## 依赖选择

MVP 优先使用：

```text
System.Windows.Forms.NotifyIcon
```

原因：

```text
1. 不新增第三方依赖。
2. Windows 桌面托盘场景成熟稳定。
3. 适合先跑通生命周期、Show、Exit、Dispose。
4. 后续如果想更 MVVM 化，再评估 H.NotifyIcon.Wpf。
```

如果 agent 选择 `H.NotifyIcon.Wpf` 或其他 NuGet，必须在完成说明中说明：

```text
为什么引入该 NuGet
版本号
是否影响发布
替代方案
```

## 行为要求

```text
App 启动后创建托盘图标。
托盘 tooltip 初始显示 WUJI / Agent 状态。
双击托盘图标或菜单 Show 打开/激活主窗口。
菜单 Exit App 真正退出 WPF App。
App 退出时 Dispose 托盘图标，避免 Windows 残留图标。
ContextMenuStrip 事件回调如触碰 WPF window / ViewModel，必须通过 Dispatcher 或等价方式回到 UI 线程。
如果 Dispatcher 已 shutdown 或窗口已释放，菜单回调应安全忽略，不抛出未处理异常。
Dispose 必须幂等。
```

## 图标资源 fallback

```text
如果已有应用图标资源可用，优先复用。
如果没有正式 .ico 资源，不引入复杂资产流程，先使用系统默认 / 简单内嵌图标 / 最小可用 fallback。
不要因为图标资源阻塞 TrayService 生命周期实现。
托盘阶段重点是生命周期和状态，不是图标设计。
```

## Dispose 要求

```text
Dispose 前先将 NotifyIcon.Visible = false。
再调用 NotifyIcon.Dispose()。
Dispose 必须幂等。
Exit App / App shutdown / 重复 Dispose 都不能抛未处理异常。
```

## TrayService 边界

TrayService 可以负责：

```text
创建 / 销毁托盘图标
托盘菜单
tooltip
事件转发
UpdateMenuState(TrayMenuState state)
```

TrayService 不负责：

```text
直接查询 SQLite
直接读写 runtime_state / health_state
直接写 agent_control.json
直接实现 Agent 命令协议
直接修改 Settings 草稿
直接做 RefreshService 之外的高频轮询
```

## 验收标准

```text
App 启动后托盘图标可见
Show Main Window 可用
Exit App 可用
Exit App 不默认 Stop Agent
托盘 Dispose 不抛异常，不残留僵尸图标
Dispose 前设置 NotifyIcon.Visible=false
Dispatcher shutdown / window released 时，托盘回调安全忽略
build/test 通过
```

## 不做什么

```text
不做托盘 Agent 控制命令
不做状态实时绑定
不做 close/minimize to tray
不做开机自启
不做安装包
```
