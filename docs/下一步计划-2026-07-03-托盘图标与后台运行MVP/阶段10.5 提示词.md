任务目标：

实现“阶段 10.5：托盘基础控制命令 Start / Pause / Resume / Stop”。

尤其注意本阶段不做：

- 不做托盘异常提示 / 通知 toast（阶段 10.6）。
- 不把 PruneData / ClearHistory 放进托盘菜单。

- 不做开机自启、安装包、Windows Service。
- 不做真正 Named Pipe 状态流 / subscribe 协议。
- 不做复杂托盘通知中心。
- 不做 Exit App + Stop Agent 组合操作。
- 不新增托盘专用状态轮询。
- 不改阶段 9 的 2 秒 status polling interval。
- 不改阶段 9 的 status/page refresh gate 架构。
- 不改 Named Pipe IPC 协议。
- 不改 AgentStateMachine 业务语义。
- 不改 PruneData / ClearHistory 规则。
- 不改 ClearHistory 的 `CLEAR` 二次确认。
- 不回退阶段 9.6 的 Stale + IsRunning=false 时 Start 可用修复。
- 不直接写 `agent_control.json`。
- 不直接读写 `runtime_state` / `health_state`。

需要实现的范围：

1. 托盘命令执行链路。

托盘命令必须通过以下之一复用现有能力：

```text
现有 MainWindowViewModel 的 ICommand（StartAgentCommand / PauseAgentCommand / ResumeAgentCommand / StopAgentCommand）
或新增轻量 TrayCommandBridge，内部调用 AgentProcessService / AgentControlService 的现有方法
```

推荐做法：

```text
如果 MainWindowViewModel 的命令已经处理可用性、错误提示和异步编排，托盘直接调用这些命令。
如果需要解耦，可以新增 TrayCommandBridge，但它只能转发到现有服务，不能重新实现 IPC / fallback / 进程控制。
```

TrayService 不得直接：

```text
写 agent_control.json
调用 Named Pipe client
实现 IPC fallback
实现 requestId / timeout 逻辑
读写 runtime_state / health_state
直接查询 SQLite
直接修改 Settings 草稿
```

补充要求：

```text
1. 如果托盘命令复用 MainWindowViewModel 的 ICommand，必须通过 Dispatcher 在 UI 线程执行；异步命令不得阻塞托盘回调或 UI 线程。
2. 命令执行中应避免重复触发同一命令；可以复用 MainWindowViewModel 的 IsBusy / command CanExecute，也可以在 TrayCommandBridge 内做轻量 in-flight guard。
3. 本阶段命令失败时优先复用现有 MainWindowViewModel 错误处理 / StatusMessage；托盘侧最多更新安全 tooltip，不做 toast 通知。
4. 如果命令执行后触发一次 RefreshStatusOnlyAsync / PerformStatusPollAsync，必须继续遵守阶段 9 latest-wins；旧结果不得覆盖新状态。
5. 如果新增 TrayCommandBridge，它只能做可用性检查、调用现有命令/服务、记录安全错误和触发状态刷新；不得持久化状态，不得读写文件，不得自己判断 Agent 状态规则。
6. 如果无法直接断言未写 agent_control.json，可以通过 fake AgentControlService / AgentProcessService 验证托盘命令只调用既有服务接口，不触碰文件系统；不要为了测试引入额外文件监听或复杂 hook。
```


5. 菜单可用性守卫。

要求：

```text

Running 时 Pause / Stop 可用。
Paused 时 Resume / Stop 可用。
NotRunning / Stopped 时 Start 可用。
Stale + IsRunning=false 时 Start 可用。
Stale + IsRunning=true 时 Stop 可用，Start 不可用。
```
