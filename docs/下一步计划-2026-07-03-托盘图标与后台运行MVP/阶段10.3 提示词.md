任务目标：

实现“阶段 10.3：CloseToTray / MinimizeToTray / Show / Exit 语义”。

本阶段在阶段 10.2 的 TrayService 基础设施之上，实现后台运行核心语义：关闭或最小化主窗口时隐藏到托盘，App 继续运行；只有托盘 Exit App 才是真正退出 WPF App。本阶段不实现托盘 Agent 控制命令，也不把托盘状态绑定到 AgentStatusSnapshot。

尤其注意本阶段不做：

- 不做托盘状态实时绑定（阶段 10.4）。

- 不新增 Settings UI 配置项，除非现有 Settings 页面已有入口且改动很小。
- 不改变阶段 9 的 status polling / page refresh 语义。

需要实现的范围：

1. CloseToTray 语义。

当 `AppSettings.CloseToTray = true` 时：

```text
点击窗口 X 时：
    Cancel Closing。
    Hide 主窗口。
    App 继续运行。
    Agent 不被停止。
    status polling 继续运行。
    不 Dispose TrayService。
    不 Shutdown App。
```

当 `AppSettings.CloseToTray = false` 时：

```text
点击窗口 X 时按原有语义退出 App（阶段 10.2 行为）。
允许窗口真正关闭。
StopStatusPolling / Dispose TrayService / Application.Shutdown 可沿现有路径执行。
```

建议通过显式退出标记区分“关闭到托盘”与“真正退出”：

```text
_isExitRequested = false:
    Closing 事件拦截 -> Hide -> Cancel。

_isExitRequested = true:
    Closing 事件允许 -> 走正常退出流程。
```

补充要求：

```text
CloseToTray 拦截时必须设置 e.Cancel=true 并 Hide。
CloseToTray 拦截时不得调用 Close()。
CloseToTray 拦截时不得触发 Window.Closed 中的 StopStatusPolling / Dispose TrayService 清理路径。
CloseToTray=false 时，点击 X 的行为应与阶段 10.2 完成后完全一致。
CloseToTray=false 时不要额外弹确认、不要改为最小化、不要改变 StopStatusPolling / Dispose TrayService 的现有退出路径。
```

2. MinimizeToTray 语义。

当 `AppSettings.MinimizeToTray = true` 时：

```text
主窗口最小化时 Hide 主窗口。
App 继续运行。
status polling 继续运行。
托盘 Show 可恢复窗口。
```

补充要求：

```text
MinimizeToTray 处理时，如果窗口已经不可见，应直接返回，避免重复 Hide。
MinimizeToTray 处理时，如果正在显式退出，应直接返回，避免退出过程中误拦截。
MinimizeToTray 不得 Dispose TrayService。
MinimizeToTray 不得 StopStatusPolling。
```

当 `AppSettings.MinimizeToTray = false` 时：

```text
最小化保持原有行为（任务栏显示）。
```

注意：从 Minimized 恢复时，WindowState 应设为 Normal 后再 Show / Activate。

不要引入复杂 Win32 强制前台窗口 hack。

Show Main Window 只恢复当前已存在的 MainWindow。
