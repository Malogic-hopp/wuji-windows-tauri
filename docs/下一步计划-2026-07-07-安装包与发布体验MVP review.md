# 三、计划中写得好的地方

## 1. 阶段 12 的定位正确

计划把阶段 12 定位为：

```text
安装包与发布体验 MVP
```

而不是继续做趋势图、导出、应用分类，这是正确的。现在 WUJI 已经能托盘常驻、登录自启，下一步自然是解决普通用户如何安装、升级和卸载的问题。


这很好。安装和升级不应破坏用户数据；卸载默认保留数据，也比较稳。

# 四、需要补强的关键问题

## 1. 12.1 的“单文件”优先级要降低

计划写的是：

```text
阶段 12.1：发布配置与单文件/自包含输出
```

但我建议改成：

```text
阶段 12.1：发布配置与 self-contained win-x64 输出
```

单文件发布可以保留为可选项，不要作为硬目标。

原因是 WPF + Agent 双进程 + 图标资源 + SQLite + 托盘场景下，单文件发布可能增加路径解析和资源加载问题。阶段 12.1 最重要的是：

```text
App 和 Agent 在同一个稳定 publish 目录
发布后的 App 能启动 Agent
发布后的 App 能用 --from-autostart --start-hidden 隐藏到托盘
```

不是文件数量越少越好。

建议改成：

```text
优先目标：
    self-contained win-x64 发布目录稳定
    App 和 Agent 同目录输出
    路径可靠
    可启动 Agent

可选目标：
    单文件输出，如体积和路径行为可接受
```

---

## 2. 12.1 “不改 AgentProcessService 路径解析”可能冲突

计划 12.1 的“不做什么”里写了：

```text
不改 AgentProcessService 路径解析
```

但验收标准又要求：

```text
发布后的 App 可启动 Agent
```

如果现有 `AgentProcessService` 已经支持发布目录查找 Agent，那没问题。
但如果发布后 App 找不到 Agent，那么就必须允许最小修复。

建议改成：

```text
不大改 AgentProcessService 路径解析。
如果发布后的 WUJI.exe 无法找到 Agent.exe，允许做最小兼容：
优先查找 AppContext.BaseDirectory 下的 Agent exe；
再 fallback 到开发路径。
```

否则 12.1 可能出现“目标要求可启动 Agent，但提示词禁止改启动路径”的矛盾。

---

## 3. 安装包选型不要在 12.1 做

计划里安装包选型建议写得比较完整，包括 MSIX、WiX、Inno Setup、压缩包。这个可以保留。

但执行时必须严格保持顺序：

```text
12.1 只做 publish
12.2 做图标资源
12.3 才做安装包选型
```

不要在 12.1 就让 agent 研究 MSIX / WiX / Inno。

建议在 12.1 中加一句：

```text
本阶段不引入 installer/ 目录，不新增 MSIX / WiX / Inno Setup 配置。
```

---

## 4. 安装包默认不应写 HKCU Run Key

计划已经写“安装包不直接写 HKCU Run Key，除非用户明确选择安装时启用自启”。这个原则对。

但阶段 12.4 又写：

```text
如果用户勾选，推荐调用 WUJI.exe --register-autostart；
次选：安装包直接写入 HKCU Run Key。
```

这里建议更硬一点：

```text
优先且默认：调用 WUJI.exe --register-autostart / --unregister-autostart，复用阶段 11 StartupRegistrationService。
只有当命令行接口暂未实现或安装器技术限制时，才允许安装包直接写 HKCU Run Key。
如果直接写，必须完全复用 StartupCommandBuilder 的 command 规则，并在完成说明中记录风险。
```

否则安装脚本硬编码 Run Key，很容易绕过阶段 11 已经做好的 mismatch / command normalization / 安全边界。

---

## 5. 卸载前运行中进程处理还不够明确

安装包卸载阶段必须考虑：

```text
WUJI App 正在运行
Agent 正在运行
托盘图标仍存在
exe 文件被占用
```

计划里现在主要写“卸载后删除 Run Key、快捷方式、安装目录”，但还需要明确卸载前策略。

建议加：

```text
卸载前应检测 WUJI App / Agent 是否正在运行。
MVP 可以提示用户先退出 WUJI。
不得默认静默强杀 Agent。
如需强制关闭，必须由用户明确确认。
卸载不应在 App / Agent 仍运行时删除正在使用的 exe。
```

---

## 6. 数据删除选项要更保守

计划里写卸载默认保留数据，提供可选删除，这是对的。

建议补得更硬：

```text
删除用户数据必须是显式选项，默认不勾选。
卸载程序不得静默删除 SQLite / JSONL / app-settings.json / windows-agent.json。
如果用户选择删除数据，完成说明必须记录删除范围。
```

---

## 7. 未签名安装包风险要写进阶段 12.5 / 12.6

计划里说“签名证书如无法获得，使用未签名安装包并记录风险”。建议在验收标准里写清楚：

```text
如果安装包未签名，发布说明必须标注 unsigned MVP installer。
完成说明必须记录 SmartScreen / 杀软误报 / 用户信任风险。
不得声称这是正式生产发布包。
```
