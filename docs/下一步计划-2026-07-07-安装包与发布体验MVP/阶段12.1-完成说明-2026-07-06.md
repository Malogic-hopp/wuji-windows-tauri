## 发布烟测修复（2026-07-06）

后续实际发布烟测发现 1 个关键问题，已修复（build 0/0, test 374/374）：

### 问题：App / Agent self-contained 产物扁平合并导致 Agent 依赖冲突

复现路径：

1. 执行 `publish\scripts\publish.ps1`。
2. 直接运行 `.codex\publish\App\QuantifiedSelf.Windows.Agent.exe`，或从 App 点击 Start Agent。
3. Agent 进程启动后立即崩溃，runtime/health 仍停留在旧的 `Stopped`，App 显示未进入 Running。

错误现象：

```text
Unhandled exception. System.IO.FileNotFoundException:
Could not load file or assembly 'System.Diagnostics.EventLog, Version=10.0.0.0'
```

根因：

- App 与 Agent 都按 self-contained 发布。
- 旧脚本把 Agent 产物扁平合并到 App 根目录，并采用“同名文件跳过、App 版本优先”策略。
- App 根目录中的 `System.Diagnostics.EventLog.dll` 为 App publish 带出的 `8.0.28`，而 Agent 的 `QuantifiedSelf.Windows.Agent.deps.json` 需要 `System.Diagnostics.EventLog/10.0.9`。
- 同一目录只能存在一个同名 DLL，导致 Agent 使用了不匹配的依赖版本并在 Host 构建阶段崩溃。

修复：

1. `publish/scripts/publish.ps1` 不再把 Agent 文件扁平复制到 App 根目录，改为完整复制到 `App\Agent\`。
2. `AgentProcessService.ResolveAgentExecutablePath` 优先解析 `AppContext.BaseDirectory\Agent\QuantifiedSelf.Windows.Agent.exe`。
3. App 根目录中的旧 `QuantifiedSelf.Windows.Agent.*` 会在发布时清理，避免误点到旧扁平布局中的 Agent exe。
4. 保留 legacy co-located fallback，仅用于兼容旧布局；正式发布布局以 `App\Agent\` 为准。
5. 补充 `Path` / `PATH` 环境变量大小写重复去重，降低外部 shell/launcher 环境污染导致 `ProcessStartInfo` 启动失败的风险。

验证：

- `dotnet build QuantifiedSelf.Windows.sln --no-restore -p:BaseOutputPath=.codex/build-output/`：0 warning / 0 error。
- `dotnet test QuantifiedSelf.Windows.sln --no-restore -p:BaseOutputPath=.codex/test-output/`：374/374 passed。
- `publish\scripts\publish.ps1 -OutputPath publish-fixed` 成功，生成 `publish-fixed\App\Agent\QuantifiedSelf.Windows.Agent.exe`。
- 直接启动 `publish-fixed\App\Agent\QuantifiedSelf.Windows.Agent.exe`，3 秒后进程仍存活，不再出现 `System.Diagnostics.EventLog` 缺失异常。
- 后续将默认发布目录从 `.codex\publish` 调整为仓库根目录 `publish\release\`，并将 `publish/release/` 加入 `.gitignore`。发布脚本移动到可追踪的 `publish\scripts\`。

## Agent exe 路径解析策略

`ResolveAgentExecutablePath(baseDirectory?)` 按优先级：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | `AppContext.BaseDirectory\Agent` | 正式 publish 布局，Agent 自带独立 self-contained 依赖 |
| 2 | `AppContext.BaseDirectory` | legacy co-located publish 布局，仅兼容旧产物 |
| 3 | `QUANTIFIEDSELF_WINDOWS_AGENT_EXE` 环境变量 | 手动指定路径 |
| 4 | 开发目录 fallback | `{baseDir}/../../../../.. /src/.../bin/{Release\|Debug}/net8.0-windows/Agent.exe` |

找不到时返回 `null`，`ResolveStartInfo` 将其包装为 `FileNotFoundException`（安全消息，不含路径/SID）。

3. 清理 App 根目录中的旧 `QuantifiedSelf.Windows.Agent.*`
4. 完整复制 Agent publish 输出到 `publish/release/App/Agent`
5. 验证 App exe 和 `App/Agent` 下的 Agent exe / deps.json 存在

参数：`-Configuration`、`-RuntimeIdentifier`、`-OutputPath`（默认为 `publish/release`）。

## 风险与后续注意点

1. publish.ps1 最终策略：App 与 Agent 不再扁平合并。App 使用 `publish/release/App` 根目录依赖，Agent 使用 `publish/release/App/Agent` 子目录依赖，避免 self-contained 同名 DLL 版本冲突。
2. `ResolveAgentExecutablePath` 的开发 fallback 依赖相对路径结构（5 级上溯），如果项目目录结构调整需同步更新。
3. **publish 验收**：publish 脚本已在实际环境中跑通。旧的“仅追加 Agent 独有文件，不覆盖 App 已有文件”策略已被实测推翻，因为 Agent 可能需要与 App 同名但版本不同的 DLL。最终改为 `App\Agent\` 隔离布局。
4. 如果 `publish/release/App` 被正在运行的 App/Agent 锁定，默认发布目录无法删除覆盖；需先退出旧进程，再重新执行 `publish\scripts\publish.ps1`。
5. `publish/` 顶层保留为发布相关区域；`publish/scripts/` 存放可追踪发布脚本，`publish/release/` 存放本地发布产物并由 `.gitignore` 忽略。
