# 阶段 12.1：发布配置与 self-contained win-x64 输出

> 本文件属于 `下一步计划：安装包与发布体验 MVP（2026-07-07）` 的子阶段计划。
> 阶段总览、架构原则、安装包选型建议等共享内容见同目录 `README.md`。

## 阶段目标

让 WPF App 和 Agent 可以通过 `dotnet publish` 输出为稳定的 self-contained win-x64 发布目录，版本号统一，输出目录固定。

优先目标：

```text
self-contained win-x64 发布目录稳定
App 和 Agent 同目录输出
路径可靠
发布后的 App 能启动 Agent
发布后的 App 能用 --from-autostart --start-hidden 隐藏到托盘
```

可选目标：

```text
单文件输出，如体积和路径行为可接受
```

## 行为要求

```text
1. 新增 publish profile 或 MSBuild 目标，支持：
   - dotnet publish -c Release
   - 自包含 .NET 运行时
   - win-x64 目标平台
   - 单文件输出作为可选目标（不强制）
2. App 和 Agent 必须输出到同一 publish 目录，但 App 不新增对 Agent 项目的项目引用（ReferenceOutputAssembly=false 现状保持不变）。
   - 实现方式：使用 publish script 或 MSBuild target 先 publish App，再 publish Agent，最后把 Agent publish 产物复制到 App publish 目录。
   - 禁止直接复制 Debug / obj / bin 输出作为发布产物；发布目录中的 Agent 必须是 Release / win-x64 / self-contained publish 产物。
3. 版本号统一来自 Directory.Build.props 或共享 AssemblyInfo.cs，并写入 App 和 Agent 的 Assembly / File 版本。
4. 先检查当前项目 publish 后的实际 exe 文件名（当前默认可能是 QuantifiedSelf.Windows.App.exe / QuantifiedSelf.Windows.Agent.exe）。
5. 决定是否通过 `AssemblyName` 或 publish 配置将 exe 重命名为 WUJI.exe / WUJI.Agent.exe；如改名，需同步更新 AgentProcessService 查找逻辑和 StartupCommandBuilder 自启 command 构建。
6. 输出目录结构稳定，例如：
   publish/
   ├── QuantifiedSelf.Windows.App.exe（或 WUJI.exe）
   ├── QuantifiedSelf.Windows.Agent.exe（或 WUJI.Agent.exe）
   └── ...
7. 发布后的 App exe 可通过 --from-autostart --start-hidden 启动到托盘。
8. 发布后的 Agent exe 可被 App 正常启动。
9. AgentProcessService 的 Agent exe 路径解析必须同时兼容发布目录和开发目录：
   - 优先查找 AppContext.BaseDirectory 下的 Agent exe。
   - 其次读取环境变量 QUANTIFIEDSELF_WINDOWS_AGENT_EXE。
   - 最后 fallback 到开发目录推导路径。
   - 找不到时返回安全错误，不抛未处理异常。
10. 不使用 Assembly.Location 定位当前 App exe；StartupCommandBuilder 继续使用 Environment.ProcessPath / Process.MainModule.FileName。
```

## 验收标准

- `dotnet publish` 0 warning / 0 error。
- publish 目录包含 App 和 Agent 可执行文件。
- 发布后的 App 可手动启动并显示主窗口。
- 发布后的 App 可启动 Agent。
- 如决定改名，AgentProcessService 和 StartupCommandBuilder 中引用的 exe 名与实际 publish 输出一致。
- 发布后的 App 可通过自启参数隐藏到托盘。
- 版本号写入 Assembly / File 版本，可通过发布目录中 exe 文件属性或日志验证。
- publish 目录中的 Agent 来自 Release / win-x64 / self-contained publish，不是 Debug / 开发目录复制。
- 不改变开发时 `dotnet run` 行为。

## 不做什么

- 不做安装包。
- 不改图标资源。
- 不引入 MSIX / WiX / Inno Setup 配置，不新增 installer/ 目录。
- 不实现 `--register-autostart` / `--unregister-autostart` 命令行入口（留到阶段 12.4）。
- 不改阶段 11 自启注册逻辑。

补充：阶段 12.1 必须修复 AgentProcessService 的 Agent exe 路径解析，使发布目录和开发目录同时可用。Agent exe 查找顺序：
1. AppContext.BaseDirectory 下的 Agent exe（如 QuantifiedSelf.Windows.Agent.exe 或 WUJI.Agent.exe，以实际 publish 输出为准）
2. 环境变量 QUANTIFIEDSELF_WINDOWS_AGENT_EXE 指定路径
3. 开发目录 fallback
4. 找不到时返回安全错误，不抛未处理异常。

查找当前 App exe 时，StartupCommandBuilder 继续使用 Environment.ProcessPath / Process.MainModule.FileName；不要使用 Assembly.Location，因为 single-file 下它可能为空。
