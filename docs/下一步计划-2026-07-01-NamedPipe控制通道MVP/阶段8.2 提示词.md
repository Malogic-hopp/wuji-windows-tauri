- server 异常不能拖垮 Worker 采样循环。

建议文件：

- src\QuantifiedSelf.Windows.Infrastructure\Ipc\IAgentIpcServer.cs

- 支持单请求处理或循环监听，保持实现简单。
- 支持 `CancellationToken`。
- 不依赖 WPF。
- 不直接实现业务命令语义。

3. 支持 IPC command：`Ping`。

请求：

```text
AgentIpcRequest.Command = "Ping"
```

响应：

```text
ProtocolVersion = 1
RequestId = request.RequestId
Accepted = true
Completed = true
Message = "Pong"
ActualState = 当前 AgentActualState
StartedAtUtc / CompletedAtUtc 非默认值
ErrorCode = null
```

4. 支持 IPC command：`GetStatus`。

请求：

```text
AgentIpcRequest.Command = "GetStatus"
```

响应可以用 `AgentIpcResponse` 的基础字段，也可以在 response 中增加 `Status` 字段承载 `AgentIpcStatus`。

GetStatus 至少要能返回：

```text
actualState
desiredState
processId
startedAtUtc
lastHeartbeatUtc
lastSampleUtc
currentSessionId
version
isHealthy
```

如果需要调整 `AgentIpcResponse` 增加 `AgentIpcStatus? Status`，可以做；但不要把窗口标题、完整路径、SQL、异常原文放进去。

5. 状态来源。

优先复用 `AgentStateMachine.CreateRuntimeSnapshot()` 或现有状态属性，避免在 IPC server 中重复拼业务状态。

建议状态来源包括：

- AgentStateMachine.ActualState
- AgentStateMachine.DesiredState 或 runtime snapshot 中的 desired state
- AgentStateMachine.ProcessId
- AgentStateMachine.StartedAtUtc
- AgentStateMachine.LastHeartbeatUtc
- AgentStateMachine.LastSampleUtc
- AgentStateMachine.CreateRuntimeSnapshot().CurrentSessionId

如当前某些字段没有直接公开，优先通过现有 snapshot 方法取，不要为本阶段大改状态机。

6. 协议错误处理。

未知 protocolVersion：

```text
Accepted = false
Completed = false
ErrorCode = "UnsupportedProtocolVersion"
Message = safe message
```

未知 command：

```text
Accepted = false
Completed = false
ErrorCode = "UnsupportedIpcCommand"
Message = safe message
```

非法 JSON / truncated payload / payload too large：

- `NamedPipeProtocol` 会抛 `IpcProtocolException`。
- server 应捕获并返回安全错误（如果还能写 response），或安全记录后继续监听。
- 不要记录原始 payload。
- 不要让 Agent 崩溃。

7. Agent DI 注册。

- AgentCommandServerHostedService
- NamedPipeAgentCommandServer 或 IAgentIpcServer

- Agent 不因 IPC server 初始化失败而无法采样。
- IPC server 启动失败应写安全日志，采样仍可继续。
