## IPC client 超时规则

| 超时类型 | 默认值 | 用途 |
|---|---|---|
| ConnectTimeout | 1000ms | pipe 连接超时，通常可 fallback |
| RequestTimeout | 5000ms | request 已发送但 response 超时 |
| MaintenanceCommandTimeout | 30000ms | 预留，本阶段未使用 |

客户端层：request.TimeoutMilliseconds > 0 则使用请求指定的超时，否则使用 options.RequestTimeoutMilliseconds。

## AgentStatusService IPC-first + fallback

1. 尝试 IPC GetStatus → 成功返回 IPC Status 构造的 AgentStatusSnapshot
2. IPC 超时/异常/response 无效 → RecordIpcFallback(safeError) → 回退到 runtime_state/health_state 文件逻辑
3. fallback 后的状态判断语义（NotRunning/Stale/Stopped/Running）不回归

## AgentIpcStatusService 内存状态

- LastCommandSource: "NamedPipe" / "FileFallback" / "Unavailable"
- GetDisplayStatusText(): "IPC connected." / "IPC unavailable; using file fallback." / "IPC status unknown."
- FullPipeName 只用于内部连接，UI 方法不暴露

## 安全文案

- IPC unavailable → "IPC unavailable; using file fallback."
- IPC timeout → "IPC request timed out; using file fallback."
- IPC protocol error → "IPC protocol error; using file fallback."
- 不显示完整 SID、完整 pipe name、路径、异常原文
