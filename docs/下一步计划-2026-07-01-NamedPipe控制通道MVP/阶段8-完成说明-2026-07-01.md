## 最终命令通道语义

```
Ping / GetStatus                  → IPC
Pause / Resume / Stop / ReloadConfig → IPC 优先，file fallback
PruneData / ClearHistory          → IPC 优先，file fallback（30s timeout）
agent_control.json                → 保留，作为 file fallback
```

## requestId 防重与 timeout 策略

- IPC 路径：ProcessedRequestCache（capacity=100, ttl=10min，纯内存），重复返回 DuplicateRequest
- file fallback：写入时复用同一 `ipc-*` requestId
- 基础命令 timeout：5000ms
- 维护命令（PruneData/ClearHistory）timeout：30000ms
- IPC 超时：不 fallback（Agent 可能已执行），返回 IpcTimeout
- IPC 返回 Completed=false（Agent 已处理但拒绝）：不 fallback，直接映射结果
- 取消请求（OperationCanceledException）：不 fallback，返回 Cancelled

## Diagnostics IPC 状态展示

Diagnostics Overview 显示 IpcStatusText：IPC 连接状态、DisplayPipeName（安全截断）、命令来源、最后成功/错误/fallback 时间。LastIpcError 经 DiagnosticMessageSanitizer.CreateSafeText 二次脱敏。

## 安全与隐私复核

- pipe name 绑用户 SID hash，不同用户不可控
- UI 仅展示 DisplayPipeName（SID hash 前 12 位），不展示 FullPipeName/SID
- 错误文案均为固定安全短句，不泄露路径/异常/JSON
- Ping 未进入共享 AgentCommandType
- GetStatus.DesiredState = null 避免误判
- unsupported command 不回显原始命令
- ClearHistory CLEAR 二次确认未被绕过
