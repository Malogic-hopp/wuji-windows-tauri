# 阶段 8.3：WPF AgentControlClient 与 fallback 策略

## 阶段目标

在 WPF 侧新增 Named Pipe client，并让 App 服务具备：

```text
优先 IPC
失败 fallback 到 agent_control.json 或既有状态文件
```

本阶段先只接 `Ping` / `GetStatus` 或内部 smoke check，不迁移高风险命令。

## fallback 规则

IPC 成功：

```text
使用 IPC response
更新 lastIpcSuccessUtc
```

IPC 不可用：

```text
使用既有文件状态 / 文件命令
记录 fallbackUsed
更新 lastIpcError / lastFallbackUsedUtc
```

IPC 超时：

```text
不阻塞 UI
返回 safe message
必要时 fallback
```

## timeout 规则

```text
ConnectTimeoutMilliseconds = 1000
RequestTimeoutMilliseconds = 5000
MaintenanceCommandTimeoutMilliseconds = 30000
```

区别：

```text
ConnectTimeout:
    连接 pipe 超时，通常可以 fallback

RequestTimeout:
    request 已发送但 response 超时，需要谨慎 fallback，避免重复命令

MaintenanceCommandTimeout:
    PruneData / ClearHistory 这类维护命令允许更长等待
```

## 验收标准

- App 在 Agent 运行时能通过 IPC 获取状态。
- Agent 未运行时 App 不崩溃。
- IPC 不可用时仍能通过 runtime_state / health_state 显示状态。
- UI 状态文案能显示 IPC / fallback 状态。
- IPC 超时不会卡住 Refresh。
- App 内存中能记录 last IPC success / error / fallback used。
- 不显示完整 SID / 完整路径 / 异常原文。

## 不做什么

- 不迁移数据清理命令。
- 不迁移 Pause / Resume / Stop / ReloadConfig。
- 不删除文件 fallback。
- 不做 Diagnostics 完整 UI。
- 不做状态流订阅。
