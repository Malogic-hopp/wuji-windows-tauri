## 风险复核

- **IPC 可能卡 UI**：否。`AgentStatusService` 使用短 timeout IPC 调用，失败立即 fallback；`NamedPipeAgentControlClient` connect/request timeout 分离，不会长时阻塞。
- **双通道可能重复执行命令**：否。IPC 路径有 `ProcessedRequestCache` 防重；IPC 超时不 fallback；file fallback 复用同一 requestId；Agent 文件通道有 `_lastProcessedRequestId` 判断。
- **IPC 与 file fallback 语义一致**：是。两者均通过 `AgentControlCommand` + `ProcessCommandAsync` 执行，行为相同。
- **跨用户控制风险**：否。pipe name 绑定当前用户 SID hash，不同用户 pipe 不同，无法跨用户控制。
- **不破坏 agent_control.json 稳定链路**：确认。`IssueCommandAsync` 保留原样，PruneData/ClearHistory 仍然可走文件路径。
- **Diagnostics 不泄露敏感信息**：确认。仅展示 DisplayPipeName，LastIpcError 经 DiagnosticMessageSanitizer 脱敏，不展示 FullPipeName/SID/路径/异常原文/JSON。
- **AgentCommandServer 不拖垮采样**：确认。server 在独立 BackgroundService 中运行，外层 catch 防止 fault，异常后 1s delay，采样 Worker 独立。
- **Stop 不留 stale agent_control.json**：确认。IPC 发送成功后不再写文件；超时后先轮询确认未停止再写；已退出不写。
- **ClearHistory 仍需 CLEAR 二次确认**：确认。`ConfirmClearHistoryCommand` CanExecute 守卫和运行时检查均未移除。
