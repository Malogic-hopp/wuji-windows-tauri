## 阶段 2：事件写入链路

已完成：

- 新增 `AgentEventJournal`，按日期写入 `logs/agent_events_YYYYMMDD.jsonl`。
- 新增 `AgentEventWriter`，作为 Agent 侧统一事件写入入口。
- 新增 `AgentEventRateLimiter`。
- 新增 `enableAgentEventJournal` 配置项，用于独立控制 agent events JSONL。
- 事件写入采用 SQLite + JSONL best-effort 双写：
  - SQLite 写失败时仍尽量写 JSONL。
  - JSONL 写失败时不影响 SQLite。
  - 两者失败也不会让异常冒泡到 Agent 主循环。
  - 最近一次 SQLite / JSONL 写入错误进入 health state，不递归写事件。

## 阶段 3：隐私、Session 与 Diagnostics 增强

已完成：

- 新增 `PrivacyFiltered` 事件。

- `CaptureFailed` 按 `errorCode` 限流。
- payload 白名单按事件类型分别收紧。
- 新增统一诊断消息脱敏器：
  - Windows 路径脱敏为 `<path>`。
  - UNC 路径脱敏为 `<path>`。
  - 控制字符和多余空白会被规整。
- `AgentEventPayloadSanitizer` 不只过滤 key，也会对 string value 做脱敏。
- `AgentEventWriter.LastEventWriteError` / `LastJournalWriteError` 不再拼接原始异常消息。
- `PersistAsync` 写 health state 时也使用安全消息格式化。
- capture 失败不再增加 `_databaseWriteErrorCount`，只增加 `_captureErrorCount`。

## 隐私与安全收口

本轮已满足：

- 不写真实窗口标题到事件 message。
- 不写原始标题到 `payload_json`。
- 不写原始 JSON 到事件。
- 不写完整异常堆栈。
- 不写 Windows 用户路径和 UNC 路径。
- `PrivacyFiltered` 只写泛化原因。
- `CaptureFailed` 只写 `errorCode` / `exceptionType` / `shortMessage`。
- payload 采用事件类型白名单。

## Payload 白名单口径

命令事件 payload 正式允许以下诊断字段：

- `requestedBy`
- `requestedAtUtc`
- `waitForCompletion`
- `timeoutMilliseconds`

这些字段不包含窗口标题、路径、命令行、原始 JSON 或敏感内容，用于诊断命令来源、请求时间和等待语义。

当前处理结论：

- 保留现有代码实现。
- 总计划文档和 review 文档已同步加入命令事件 payload 白名单。
- 该项不再作为非阻塞备注或待确认事项。
