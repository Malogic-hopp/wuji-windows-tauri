# 阶段 1：事件基础设施

## 阶段目标

把“事件”这件事先定义清楚，让后续写入、查询、展示都有统一的基础模型。

这阶段只做事件数据结构、SQLite 表、查询服务和 Diagnostics 的空态骨架，不接 Agent 写入链路。

## 解决的问题

- Diagnostics 目前主要依赖 `runtime_state.json`、`health_state.json` 和采样表，缺少历史事件视角。
- 需要先建立一套稳定的事件定义，避免后面边做边改。
- 需要让 UI 先具备“能查最近事件 / 最近错误”的查询能力。

## 交付物

- `AgentEvent`、`AgentEventType`、`AgentEventLevel` 模型
- `agent_events` 表和索引
- `AgentEventRepository`
- `DiagnosticsQueryService`
- Diagnostics 页面空态 / 无数据态

## 实施范围

### Core 模型

建议新增：

- `src/QuantifiedSelf.Windows.Core/Events/AgentEvent.cs`
- `src/QuantifiedSelf.Windows.Core/Events/AgentEventType.cs`
- `src/QuantifiedSelf.Windows.Core/Events/AgentEventLevel.cs`

字段建议：

- `id`
- `event_time_utc`
- `event_type`
- `event_level`
- `message`
- `source`
- `request_id`
- `error_code`
- `process_name`
- `session_id`
- `payload_json`

### SQLite

建议新增：

- `agent_events` 表
- `idx_agent_events_time`
- `idx_agent_events_type`
- `idx_agent_events_level_time`

### 查询能力

Diagnostics 第一版只查询 SQLite，不解析 JSONL。

建议先支持：

- 最近 20 条事件
- 最近 10 条错误或告警
- 稳定排序：`event_time_utc DESC, id DESC`

## 验收标准

- `dotnet build` 通过
- `dotnet test` 通过
- `agent_events` 表可创建、可插入、可查询
- Diagnostics 能在空表时显示友好空态
- 事件查询不依赖 JSONL

## 不做什么

- 不接 Agent 写入
- 不做 JSONL 浏览器
- 不做复杂筛选和分页
- 不做事件 UI 美化
