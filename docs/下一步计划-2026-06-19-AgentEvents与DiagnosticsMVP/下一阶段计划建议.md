# Agent Events 与 Diagnostics MVP 后续整体规划指导

本文档不是新的阶段实施清单，而是 `Agent Events 与 Diagnostics MVP` 收口后的后续路线指导。

正式的下一阶段执行计划已经单独落盘为：

```text
docs/下一步计划-2026-06-22-SamplesSessionsApps数据浏览MVP.md
```

本文件用于回答更高一层的问题：

```text
Agent Events 与 Diagnostics MVP 完成后，WUJI 后续应该按什么顺序继续演进？
哪些能力现在做，哪些能力后置？
每个阶段的边界是什么？
```

---

## 当前阶段结论

`Agent Events 与 Diagnostics MVP` 已完成并可以收口。

当前 WUJI 已具备：

```text
真实 Win32 前台采样
idle / active 判断
采集阶段隐私过滤
foreground_samples 落库
app_sessions 合并
Pause / Resume / Stop 控制
Dashboard 基础统计
Diagnostics 最近事件 / 最近错误
agent_events SQLite 查询索引
agent_events_YYYYMMDD.jsonl 审计日志
事件限流、payload 白名单和路径脱敏
```

这意味着产品阶段已经从：

```text
真实采样 MVP
```

推进到：

```text
可诊断 MVP
```

当前系统已经能回答：

```text
Agent 当前是否运行？
采样是否持续发生？
命令是否被 Agent 消费？
隐私规则是否命中？
采样失败或写入失败发生在哪个阶段？
最近错误是什么？
事件审计文件在哪里？
```

下一步的重点应从“系统能否解释自己”转向“用户能否查看自己的历史使用明细”。

---

## 总体演进主线

后续建议按这条主线推进：

```text
1. 数据浏览
2. 设置与数据管理
3. IPC 与实时状态
4. 常驻体验
5. 长期统计与产品化
```

对应能力：

```text
数据浏览
    SamplesView / SessionsView / AppsView

设置与数据管理
    Settings 编辑、隐私规则编辑、PruneData、ClearHistory

IPC 与实时状态
    Named Pipe / gRPC、GetStatus、状态流订阅、RefreshService 优化

常驻体验
    托盘、关闭到托盘、开机自启、Agent 重启体验

长期统计与产品化
    7 天趋势、图表、导出、安装包、应用分类、浏览器网页级识别
```

这个顺序的核心判断是：

```text
先让已有数据可见、可信、可验证；
再让配置可编辑、历史可管理；
再升级控制通道和实时体验；
最后做产品化包装和高级分析。
```

## 下一阶段：Data Views MVP

推荐下一阶段正式立项为：

```text
Samples / Sessions / Apps 数据浏览 MVP
```

正式执行文档：

```text
docs/下一步计划-2026-06-22-SamplesSessionsApps数据浏览MVP.md
```

阶段目标：

```text
让 WUJI 不只“能采集、能诊断”，还要能查看、筛选和解释历史使用明细。
```

核心范围：

```text
SamplesView
    查看最近前台采样明细

SessionsView
    查看会话边界、持续时间和 close_reason

AppsView
    查看今日应用使用排行和应用级汇总
```

推荐顺序：

```text
1. 查询服务
2. SamplesView
3. SessionsView
4. AppsView
5. 导航与刷新收口
6. 验收和稳定化
```

为什么优先做它：

```text
1. 不需要改变 Agent 写入主链路
2. 能直接复用现有 foreground_samples / app_sessions
3. 能验证采样、session、隐私和统计口径是否真实可用
4. 用户感知价值高
5. 风险低于 IPC、托盘、安装包等产品化能力
```

本阶段暂不做：

```text
复杂图表
7 天趋势
CSV / Excel 导出
应用分类编辑
全文搜索
无限滚动
JSONL 浏览器
```

## 第二优先级：Settings 与数据管理 MVP

Data Views MVP 稳定后，建议进入：

```text
Settings 与数据管理 MVP
```

阶段目标：

```text
让用户能安全修改本地采集配置，并能管理历史数据。
```

建议范围：

```text
1. SettingsView 展示当前 windows-agent.json
2. 编辑 samplingIntervalSeconds
3. 编辑 idleThresholdSeconds
4. 编辑 maskWindowTitles
5. 编辑 excludedProcesses
6. 编辑 excludedTitlePatterns
7. 保存前校验配置
8. 保存后触发 ReloadConfig
9. 提供 PruneData
10. 提供 ClearHistory
```

关键边界：

```text
1. WPF 可以编辑表单，但采集域配置最终应由 Agent 校验和应用
2. WPF 不直接删除 SQLite 和 JSONL
3. PruneData / ClearHistory 必须由 Agent 执行
4. ClearHistory 后必须重写 runtime_state 并立即 heartbeat
5. 配置保存失败必须能在 Diagnostics 中看到原因
```

为什么不放在 Data Views 前：

```text
Settings 涉及写配置、热加载、错误回滚和用户误操作保护。
在数据浏览页完成前，用户还没有足够界面验证配置变更是否真正影响采样结果。
```

## 第三优先级：Named Pipe / gRPC IPC

Settings 与数据管理稳定后，再推进：

```text
Named Pipe / gRPC IPC
```

阶段目标：

```text
让控制命令从文件 fallback 升级为请求-响应式 IPC，提升交互确定性。
```

建议范围：

```text
1. AgentCommandServer
2. WPF AgentControlClient
3. Pause / Resume / Stop / ReloadConfig 走 IPC
4. agent_control.json 保留为 fallback
5. GetStatus 走 IPC
6. Diagnostics 展示 IPC 状态
7. IPC 失败时自动降级文件 fallback
```

关键边界：

```text
1. Start Agent 仍由 WPF ProcessStartInfo 完成
2. Stop / Pause / Resume 可以走 IPC
3. agent_control.json 不删除，继续作为 fallback 和调试入口
4. IPC 安全边界必须限制当前 Windows 用户
5. 命令事件语义保持不变，commandSource 从 FileFallback 扩展到 NamedPipe / Grpc
```

为什么后置：

```text
当前文件 fallback 已经足够支撑 MVP。
IPC 会引入连接生命周期、超时、ACL、安全边界、状态一致性等新复杂度。
应在数据浏览和设置能力稳定后再做。
```

## 第四优先级：常驻体验

IPC 稳定后，建议进入：

```text
常驻体验 MVP
```

阶段目标：

```text
让 WUJI 更像一个可以长期运行的 Windows 本地应用。
```

建议范围：

```text
1. 托盘图标
2. 最小化到托盘
3. 关闭到托盘
4. 托盘菜单显示 Agent 状态
5. 托盘菜单支持 Pause / Resume / Stop
6. UI 启动时可选择自动启动 Agent
7. 开机自启评估
```

关键边界：

```text
1. 关闭 UI 不等于停止 Agent
2. 真正退出 App 与停止 Agent 要明确区分
3. 托盘状态必须来自 Agent 状态，而不是按钮点击后的乐观状态
4. 开机自启第一版可先只支持 WPF App，自启动 Agent 由 App 配置控制
```

为什么后置：

```text
托盘和开机自启会改变用户对“应用是否还在运行”的感知。
在状态、数据浏览、诊断和 IPC 都稳定之前，不宜过早做常驻体验。
```

---

## 第五优先级：长期统计与产品化

常驻体验稳定后，再做更接近产品化的能力：

```text
长期统计与产品化
```

候选范围：

```text
1. 7 天趋势
2. 每小时趋势
3. 应用分类
4. 应用显示名编辑
5. CSV / Excel 导出
6. 安装包
7. 自动更新评估
8. 本地数据加密评估
9. 浏览器网页级识别
10. 周报 / 月报
```

建议原则：

```text
1. 趋势图要等日级数据口径稳定后再做
2. 导出要等用户能在 UI 中确认数据含义后再做
3. 安装包要等常驻、配置、清理和错误恢复体验稳定后再做
4. 浏览器网页级识别属于敏感能力，必须单独做隐私设计
```

## 暂缓事项

短期继续暂缓：

```text
Windows Service
云同步
跨设备同步
复杂权限提升
浏览器扩展
AI 总结
自动分类
团队版 / 多用户版
```

原因：

```text
当前项目最重要的是把本地单机采集、诊断、浏览、配置、控制这条主链路打稳。
过早引入云端、多用户、服务化或智能分析，会显著扩大问题维度。
```

从现在开始，建议正式按以下路线推进：

```text
1. Samples / Sessions / Apps 数据浏览 MVP
2. Settings 与数据管理 MVP
3. Named Pipe / gRPC IPC
4. 托盘与常驻体验 MVP
5. 长期统计与产品化
```

其中当前立即执行的是：

```text
docs/下一步计划-2026-06-22-SamplesSessionsApps数据浏览MVP.md
```

一句话总结：

```text
WUJI 现在已经“能采集、能诊断”。下一步不要急着产品化，先把已有数据变成用户能看懂、能验证、能信任的历史明细；再做设置、IPC、托盘和长期统计。
```
